# 任务驾驶舱 · 修改专用提示词（第二版）

**这是一份"改现有设计"的指令**，不是从零重做。请把下面这些改动应用到当前这个页面上。

本文只用日常语言，不含项目内部编号、内部术语、本机路径或代码。示例内容沿用原来的「给导出功能加上失败重试」。

---

## 可以直接粘贴的部分

## 0. 现在这版哪里不对

现在这版把结构做得很细，但用起来完全不是我要的。三个问题：

**问题 1 · 一个页面看不完，全被拆碎藏起来了。**
我要的是**在一个页面里把东西看完**。现在左侧菜单有三层，右侧九个区块默认全是收起的——想看一个工作包的来龙去脉，得先展开「计划与验收」、再展开「方案要点」、点进去、再逐个展开九个折叠区。**点太多次才能看到内容。**

**问题 2 · 左侧菜单的分类不对。**
左侧不应该按「要求与决定／计划与验收／改动与证据」这种文档分类来分。应该**按逻辑对象**分：

- **原始需求**：我当初提的每一条要求。
- **工作包**：为了满足这些要求，方案被拆成的一块块（每块是一组相关的决定）。点一个工作包，要能看见**它是由什么构成的**——来自哪几条原始需求、做了哪些调研、定了哪些决定。
- **Phase／Task**：做计划之后，把工作包落成一段段可执行的工作。点一个 Phase，要能看见**它来自哪些 spec 内容、来自哪些工作包**。
- **进度**：一眼看全整个任务走到哪了。

核心就一句话：**看一个具体需求或任务的整个逻辑链条，以及整个任务的进度。**

**问题 3 · 工具自身的概念占了太多位置。**
页头、只读声明条、来源下拉（指纹／字节统计／行数统计／来源检查）、底栏的来源检查弹窗、每个详情顶部的三组状态标签墙（"来源里的事实／验证与证据／页面自己的判断"）、"页面判断：已谈定／还在改／还没谈"——**这些东西占了首屏一大半，而任务本身的内容被挤到下面。** 页面核心位置应该给**任务内容**。

## 1. 改完应该是什么样

**一句话：左边选对象，右边把它整条链条一屏读完。**

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 给导出功能加上失败重试 · 写代码        本次更新 2 项 [x] [y]  我看过了 │  ← 页头一行
├────────────────┬─────────────────────────────────────────────────────┤
│ 原始需求 (4)   │                                                     │
│   要求 1 …     │   ① 上游：它从哪来                                   │
│   要求 2 …     │      原始需求 / 调研 / 决定 —— 每条一行，可点          │
│   要求 3 …     │                                                     │
│   要求 4 …     │   ② 本对象：它是什么                                 │
│ 工作包 (3)     │      标题 + 一句话 + 要点 + 涉及文件                  │
│   重试引擎     │                                                     │
│   状态面板     │   ③ 下游：它落到哪                                   │
│   取消入口     │      对应 Phase/Task · 真实改动 · 测试结果            │
│ Phase (2)      │                                                     │
│   P1 重试引擎  │                                                     │
│   P2 界面与取消│                                                     │
│ 进度           │                                                     │
└────────────────┴─────────────────────────────────────────────────────┘
```

三条硬要求：

1. **右侧默认全部展开**，一屏（或一次自然滚动）读完。**核心内容不许藏在折叠里**；只有"补充材料／来源路径"这类次要内容可以收起。
2. **左侧最多两层**：分组 → 对象。**不要第三层。**
3. **点一个对象就换右侧**，不再需要逐层展开才能到达。

## 2. 左侧对象清单（两层，按逻辑分组）

宽约 **260px**。分组标题（12px 次文字色，不可点）＋下面一行行对象（13px，可点）。**不要第三层。**

```text
原始需求 (4)
  要求 1 · 导出失败要自动重试三次
  要求 2 · 重试时看得见每次为什么失败
  要求 3 · 不想等的时候要能取消
  要求 4 · 只有网络类错误才重试
工作包 (3)
  工作包 1 · 重试引擎
  工作包 2 · 重试状态面板
  工作包 3 · 取消入口
Phase (2)
  P1 · 重试引擎
  P2 · 界面与取消
进度
```

- 每行右侧可以带一个**很小的状态点**（绿＝已完成／蓝＝进行中／灰＝未开始／红＝有问题），**不要放文字标签**，不要一行占 36px 那么高——**32px 就够**。
- 计数放在分组标题后面，形如 `原始需求 (4)`。
- **随阶段变化**（这一点很重要）：
  - 还在"定方向"阶段时，左侧只有：**原始需求 / 工作包 / 进度**（还没有 Phase）。
  - 进入"做计划"及以后，才出现 **Phase**（下面可以带 Task，但**仍然只占两层**：Phase 一行，Task 作为它后面的小字，不做第三层可展开节点）。
- 选中态：浅蓝底 ＋ 左侧 2px 蓝线。有更新的对象：左侧 2px 暖色线（不要额外文字标签）。

## 3. 右侧：三种对象的完整布局

右侧统一是**三段式**：**上游（它从哪来）→ 本对象（它是什么）→ 下游（它落到哪）**。

- 三段都用**卡片**（白底、1px 弱边、圆角 8px、内边距 20px、段间距 16px）。
- 每段标题 16px 加粗，右上角一个**很小的**计数或状态点。
- **三段之间是并列的，不是嵌套的**——不要做成"点开才能看下一层"。
- 段内每一条都是一行：**名称（可点，蓝色）＋ 一句结论（次文字色）**。行高 40px。
- 三段下面，一行**来源**（12px 次文字色）：`来源：决定记录 · 计划文件 · 改动清单`。**不要放指纹、字节数、行数。**

## 4. 「进度」页：一眼看全

点左侧的「进度」，右侧是一张**表**，**一行一条原始需求**，五列：

```text
要求                                  工作包             Phase / Task          真实改动                测试结果
要求 1 · 失败自动重试三次              重试引擎           P1 / 实现重试引擎       src/export/retry.ts     12 通过 / 1 失败
要求 2 · 看得见每次为什么失败          重试状态面板       P2 / 重试状态面板        src/export/panel.tsx    未执行
要求 3 · 不想等的时候要能取消          取消入口           缺：还没有实施任务       缺：还没有真实改动       未执行
要求 4 · 只有网络类错误才重试          重试引擎           P1 / 实现重试引擎       src/export/retry.ts     12 通过 / 1 失败
```

- 表格上方一行小结：`4 条要求：2 条已实现，1 条进行中，1 条还没有实施任务承接。`
- **缺的地方直接写「缺：……」，用失败色**，不要留空、不要画成灰色占位。
- 表格下面再给一段「实施任务」清单（五行：调研重试策略／实现重试引擎／重试状态面板／补测试／整体验收，各带状态和验收位置）。
- **不要在这里放进度条、完成百分比、圆环。** 用行和文字说清。

## 5. 要删掉或大幅缩小的东西

| 现在有的 | 怎么改 |
| --- | --- |
| 页头下那条 40px 的「本页是只读视图，不是进度权威…」整条 | **删掉整条**。把这句话缩成页头右侧一行 12px 小字：`只读视图` |
| 「来源 ▾」下拉里的 `来源指纹 / 字节统计 / 行数统计 / 来源检查` | **删掉这四项**。只留一行 12px 的来源说明，放到三段卡片下方 |
| 底栏的「来源检查说明」弹窗 | **删掉** |
| 每个详情顶部的三组状态标签墙（「来源里的事实／验证与证据／页面自己的判断」＋每条带"来源：…"） | **删掉整块**。状态改成**左侧树上的一个小圆点**＋标题右侧一个文字状态，最多两个 |
| 「页面判断：已谈定／还在改／还没谈」 | **删掉** |
| 独立占一条 36px 的「本次更新 N 项 …」带 | **并进页头那一行**，高度不超过页头 |

| 左侧的三层树（46 个节点） | 换成第 2 节的**两层清单**（约 11 行） |
| 面包屑里的「返回上一对象」 | 保留（一行的位置），但不再是主要导航方式 |

**判断标准**：页头＋页脚加起来**不超过 88px**；首屏右侧**至少 70% 的高度**是任务内容。

## 6. 要保留的东西

这些是好的，不要动：

1. **更新高亮**：有变化的对象在左侧树上有暖色线，右侧对应段落有浅暖底；**点「我看过了」清除高亮**，它不确认任何东西、不改任何状态。
2. **缺环必须显眼**：没承接、没实施、没测试的，直接写「缺」并用失败色。
3. **「真实改动」和「计划改动」必须分开**：计划要改的文件不能填进真实改动栏。
4. **矛盾并排显示**：任务声称完成但没有对应改动时，两边事实都留着。
5. **空状态要说清将来填什么**，例如 `尚未产生。实施后，这里显示实际改动过的文件及其对应要求。`；**不要画成空表格，也不要用「暂无」盖住所有含义。**
6. **两张测试卡必须标题不同**：`实施后测试`（12 通过 / 1 失败）和 `先写的测试（还没实现）`（6 项断言失败）——**不能都画成红色"失败"**。
7. **来源行不给行号**，用名称＋标题定位。
8. **只读**：没有「批准」「标为完成」「通过验收」这类按钮。

## 7. 视觉与交互

**温暖、清晰、安静的工程工作台**：靠排版、留白和少量色块表达层级。**避免**装饰性霓虹、玻璃模糊、发光连线、渐变 KPI 卡、圆环完成率、满屏表格线。

| 用途 | 颜色 |
| --- | --- |
| 页面底色 | `#F5F6F8` |
| 内容表面 | `#FFFFFF` |
| 主文字 | `#18212F` |
| 次文字 | `#596577` |
| 弱分隔 | `#E3E7ED` |
| 强调蓝（选中／可点） | `#315CCB`，浅底 `#EEF3FF` |
| 变化暖色（本次有更新） | `#9A6508`，浅底 `#FFF4D9` |
| 失败／缺环／不一致 | `#B53D42`，浅底 `#FFF0F0` |
| 未执行／未知 | `#687486`，浅底 `#F0F2F5` |
| 已完成 | `#277353`，浅底 `#EDF7F1` |

- 系统字体栈（中文优先系统无衬线），不加载远端字体。任务标题 20/28px，段标题 16/24px，正文 14/22px，辅助 12/18px；路径用系统等宽字体。
- 间距 4/8px 步长；卡片内 20px，卡片间 16px。圆角 6–8px。
- **颜色旁边必须有文字或图标**，红绿不能是唯一信息。
- 键盘：Tab 能到所有可点对象；左侧清单用上下方向键移动、Enter 选择；焦点明显（2px 蓝色外框）。
- 窄屏（约 900px 以下）：左侧收进「目录」抽屉，右侧三段竖向排列；**不能隐藏缺环和"未执行"的说明**。

**任务**：给导出功能加上失败重试 ｜ **当前阶段**：写代码

**四条原始需求**

| # | 原话 | 来源 | 状态 |
| --- | --- | --- | --- |
| 要求 1 | 「导出失败要自动重试三次」 | 用户 10 月 12 日的对话 | 已实现 |

| 工作包 | 来自哪些要求 | 一句话 |

| P2 · 界面与取消 | 重试状态面板 | 尚未开始 |
| P2 · 界面与取消 | 补测试 | 声称完成（无对应改动） |
| P2 · 界面与取消 | 整体验收 | 未执行 |

**真实改动**

- `src/export/retry.ts` —— 新增重试引擎，对应要求 1、4
