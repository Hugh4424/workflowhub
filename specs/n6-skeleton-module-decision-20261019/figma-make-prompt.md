# 任务驾驶舱页面 · Figma Make 设计提示词

这是给 Figma Make 的设计输入。**从下面「可以直接粘贴的部分」开始，到文末「交稿前自查」为止，可以整段复制粘贴。**

本文只用日常语言描述要设计的页面：不含项目内部编号、内部术语、本机路径或代码。

**本文已经把所有要显示的文字写好了**（第 13、14 节）：每块区域放什么、标题写什么、折叠时显示哪句短结论、展开后是什么全文、空的时候显示什么、出错时显示什么，都给了确定的内容和大致尺寸。**请照着排版，不要自己改写文案、不要用「任务 A／任务 B」、Lorem ipsum 或空白占位字段代替。**

## 可以直接粘贴的部分

## 1. 要设计什么

设计一个**只读的「任务驾驶舱」页面**。

打开它，我应该能在一个页面里看清：这个任务要做什么、我当初提的每条要求是怎么被决定的、每条要求对应哪些实施任务、实际改了哪些文件、测试结果怎么样、还有哪些地方没做完。

一句话概括这个页面的目标：

> **先看懂这个任务，再顺着每条要求追到它的决定、实现和验证。**

**我提这个需求的原始说法**（大意）：我需要在一个页面里清楚看见所有原始要求的来源、调研、决定、任务、实现、测试等等，这样我既能看见每条要求的详情，也能看见整个任务的设计，还能知道进度；它相当于当前任务的驾驶舱。

**页面必须是只读的**：它只展示事实，不提供「批准」「标为完成」「接受风险」「通过验收」这类按钮。它是给人看的视图，不是进度本身——真正的进度以实际材料为准。

**不属于这个页面的事**：页面不负责自动打开浏览器（那是生成它的程序做的事）。页面只负责一件事：把「本次更新了哪些地方」显示清楚并高亮出来。

## 2. 谁在看，他要立刻回答什么

读者是这个任务的负责人。他不是来管工时、也不是来看运营数据的。他打开页面想立刻回答五件事：

1. 这件事到底要做成什么？
2. 我当初提的要求有没有被漏掉？
3. 为什么这么设计？
4. 每个实施任务实际改了什么？
5. 测试和验收能不能支撑「做完了」这个说法？

主角是**这个任务和它的真实内容**。不要做成营销页、数据大屏或通用后台模板。

## 3. 页面结构与尺寸

桌面参考尺寸 **1440 × 960**（窄屏收纳见第 12 节）。从上到下五层：

| 层 | 高度（参考） | 内容 |
| --- | --- | --- |
| 1. 页头 | 56px | 产品名、任务短标题、当前阶段 |
| 2. 状态带 | 40px | 「只读视图」声明、当前阶段、来源摘要（可展开） |
| 3. 更新带 | 36px | 「本次更新 N 项」＋变更节点按钮＋「我看过了」 |
| 4. 主工作区 | 剩余高度 | 左侧结构树 292px ＋ 1px 分隔线 ＋ 右侧详情 |
| 5. 底栏 | 32px | 生成时间、来源检查入口 |

- **页头**：低矮、安静。不要大 logo、头像墙、通知中心、全局项目菜单。
- **主工作区**：右侧详情**正文最大宽度 920px**（别让文字横跨整屏），左右各留 32px 内边距。
- **滚动**：只有右侧详情滚动；页头、状态带、更新带、底栏固定。左树内容超高时自己滚动。

**默认状态很重要**：首次打开时选中「任务总览」，左侧所有分支折叠，右侧所有折叠区也折叠。

> **折叠的是细节，不是任务说明。**

首屏必须直接读到：任务标题、一句任务描述、当前阶段、最重要的缺项，以及任务结构。不要让人先展开三层才知道这是什么。

## 4. 左侧结构树

- 行高 **36px**，每层缩进 **18px**，字号 13px。
- **箭头只负责展开／收起，点名字才切换右侧对象**——两个动作分开，不要点箭头顺带切换。
- 选中一个节点时，不要顺手展开其它无关分支。
- 选中态：浅蓝底 `#EEF3FF` ＋ 左侧 2px 蓝线；悬停：浅灰底。
- 层级要分明（顶层分组／中层条目／底层细项），不要混成一大堆同级事项。
- 四个顶层分支：

```text
任务总览
要求与决定
  任务说明
  原始要求
  调研
  决定
  要求变更记录
  未决项
  风险
计划与验收
  方案要点          （这个任务打算改成什么）
  实施任务          （谁去做、做到哪了）
  验收标准
改动与证据
  真实改动          （实际动过的文件）
  测试结果
  独立审查
```

- 树里的标签要短（≤8 字）；**完整标题放在右侧详情里**，不要为了短标签截掉真实内容。
- 展开后的完整节点内容见 **14.3**。

## 5. 右侧详情骨架

选中任意对象后，顶部顺序固定（自上而下）：

| 位置 | 内容 | 说明 |
| --- | --- | --- |
| 1 | 面包屑 | 形如 `要求与决定 / 原始要求 / 要求 1`，最后一段是当前对象 |
| 2 | 完整标题 | 22/30px，最多两行 |
| 3 | 一句结论 | 14/22px 次文字色，一行到两行 |
| 4 | 具名状态 | 2–4 个状态标签，每个带来源说明（悬停或紧跟小字） |
| 5 | 追溯链 | 见第 6 节 |
| 6 | 九个可折叠区块 | 见下 |

九个可折叠区块，**固定顺序**：

**原始要求 · 调研 · 决定 · 验收标准 · 状态 · 未决项 · 风险 · 涉及文件 · 来源**

- 每个折叠标题行：左侧标题（16/24px）＋右侧**一句短结论**（13px 次文字色）＋展开箭头。整行可点。
- **不要求每个区块都有内容**：确实没有的说明原因；还没发生的写「尚未产生＋到时这里填什么」；读取失败的写具体失败原因。
- 点关联对象（要求 ↔ 实施任务）就在同一右侧切换，并更新左侧选中；保留面包屑和「返回上一对象」。返回时恢复原来的滚动位置和展开状态——**这只是浏览状态，不是任务进度**。
- 每个区块的完整文案见 **14.4 / 14.5 / 14.6 / 14.7**。

## 6. 追溯链（这个页面最重要的部分）

每条要求都要能横向走完这条链：

> **要求 → 实施任务 → 真实改动的文件 → 测试结果**

布局：横向四个环，每个环之间用箭头（→）连接；每环宽度约 200px，内容两行：

- 第一行：对象名（可点击，蓝色）
- 第二行：一句短结论（12px 次文字色）
- 环下方一个小字来源入口

- 四个环节**都要能点**；不能只画四个装饰图标。
- **缺环要显眼**：写「**缺**」＋缺的是什么，用失败色 `#B53D42`，并说清什么时候会有。
- **只显示真实改动**：计划要改的文件属于「计划」，**不能填进「真实改动」栏**。
- **矛盾要并排显示**：两边事实都保留，写：

  > 不一致：任务声明完成，但改动清单里没有对应文件。

  页面**不能自动改状态，也不能替人挑一边**。
- 窄屏时这条链改成**竖向四行**，关系不能因为换布局就丢掉。

四种状态的完整文案见 **14.9**。

## 7. 状态怎么表达

状态至少分三组，第一眼靠**分组标题**就能区分，不能只靠颜色：

| 组 | 标签文字 | 含义 |
| --- | --- | --- |
| 来源里的事实 | 尚未开始／进行中／已完成／失败／未验证 | 来自实际记录；没取到就写「未取得事实」，不能猜 |
| 验证与证据 | 未执行／先写的测试（还没实现）／测试通过／测试失败／不可用／不完整 | 说的是某个具名检查及其范围，**不等于用户接受或整体完成** |
| 页面自己的判断 | 已谈定／还在改／还没谈 | 必须紧挨着注明「**页面判断**」，不能冒充任务事实 |

- 未知显示「未知」；不可用显示「不可用＋原因」；不完整显示「不完整＋缺哪一项」；未执行显示「未执行」。
- **不要假进度**：不出现完成百分比、圆环进度、进度条。没有数据就说没有。
- **颜色旁边必须有文字或图标**，红绿不能是唯一信息。
- 具体通过项可以标绿，但整页**不出现「全部验收成功」**这种话。
- 标签样式：圆角 4px，高 22px，内边距 6px 10px，12px 字；底色用第 11 节的浅底，文字用对应主色。完整清单见 **14.10**。

## 8. 空状态与错误状态

这些区块要**保留位置**：不能整块隐藏、不能画成空表格、不能用「暂无」盖住所有含义。样式：浅灰底 `#F0F2F5`、虚线边、14px 次文字色、内边距 16px。

| 情形 | 文案 |
| --- | --- |
| 真实改动还没发生 | 尚未产生。实施后，这里显示实际改动过的文件及其对应要求。 |
| 实施验收还没做 | 尚未产生。任务验收后，这里显示逐条结果、命令与原始输出位置。 |
| 页面／模板还没生成 | 尚未产生。设计确认后才会写入。 |
| 浏览器视觉验收没做 | 尚未执行。到时显示实际浏览器、页面状态与证据范围。 |
| 测试没跑 | 未执行。尚无本次命令与结果。（**不要画成「0 项失败」**） |
| 事实取不到 | 未取得任务事实，当前无法判断实施状态。 |
| 指针找不到目标 | 指针失效：原件中未找到目标标题或编号。（其余内容继续显示） |
| 预览打不开本地文件 | 当前预览无法直接打开本地原件。请按下方路径查阅。（**不能说成文件不存在**） |
| 文件读不了 | 来源不可读：权限不足。（保留路径和具体错误） |
| 没有上一版可比 | 首次生成，暂无上版可比 |
| 有比对但没变化 | 本次没有内容变化 |
| 没给比对结果 | 未提供变更比较结果 |

最后三条**不要混用**。每条放在哪个区块见 **14.12**。

## 9. 本次更新、逐节点高亮、「我看过了」

- **更新带**（36px，主工作区上方，不遮住任务标题）：
  - 左侧文字：`本次更新 2 项`
  - 中间：每个变更节点一个可点的小标签，形如 `[重试状态面板]`
  - 右侧：`我看过了` 文字按钮
- 点更新项时：左侧树自动展开到那个节点并选中它，右侧打开对应位置；**只有真正变化的节点**有克制的暖色高亮（左侧 2px 暖色线 ＋ 浅暖底 `#FFF4D9`）；父节点给轻提示（小圆点），**不要把没变的子项全点亮**。
- 高亮**保留到下一次更新**。
- 点「我看过了」清除高亮并显示 `本次高亮已清除`——它**不确认计划、不接受风险、不改任何状态或验收**。
- 跳转后**焦点落到目标标题**上，键盘和屏幕阅读器也能知道去了哪里。
- 不要持续闪烁；动效 150–200ms；系统设了「减少动效」就关掉展开动画和滚动过渡。
- 更新带三种状态（首次／无变化／没给比对）见 **14.9** 末尾。

## 10. 来源指针

每个来源显示三样：**人能读懂的名字 + 稳定编号或标题 + 位置**。示例：

```text
原始要求 · 用户 10 月 12 日的对话
当前决定 · 决定记录第 1 条
实施任务 · 实现重试引擎
原始输出 · 实施后测试
```

- 行样式：14px，左侧名称加粗，中间用 `·` 分隔，位置用等宽字体 12px 次文字色。
- 用**稳定编号或标题**定位，**页面里不出现行号**（不要 `:123`、`L123`，也不要跳到某一行）。
- **不要把整份代码、报告或决定记录复制进页面**；页面只放短摘录和理解所需的摘要，完整内容仍以原件为准。
- 本地文件打不开时，**就地**显示限制说明和完整可复制的路径：不要静默失败、不要假装成功、不要申请文件系统权限。
- 来源检查入口固定解释一句：**检查只能机械比对编号和标题，不能保证文字没有被改写**；还没拿到检查结果时写 `来源检查：未提供结果`，**不能画成「校验通过」**。

## 11. 视觉方向

**温暖、清晰、安静的工程工作台**：靠排版、留白和少量色块表达层级。

**避免**：装饰性霓虹、玻璃模糊背景、发光连线、渐变 KPI 卡、圆环完成率、满屏表格线。

| 用途 | 颜色 |
| --- | --- |
| 页面底色 | `#F5F6F8` |
| 内容表面 | `#FFFFFF` |
| 主文字 | `#18212F` |
| 次文字 | `#596577` |
| 弱分隔 | `#E3E7ED` |
| 强调蓝（选中／可点） | `#315CCB`，浅底 `#EEF3FF` |
| 变化暖色（本次有更新） | `#9A6508`，浅底 `#FFF4D9` |
| 失败／缺环／不一致 | `#B53D42`，浅底 `#FFF0F0` |
| 未知／未执行 | `#687486`，浅底 `#F0F2F5` |
| 已有结果 | `#277353`，浅底 `#EDF7F1` |

- 用**系统字体栈**（中文优先系统无衬线），不加载远端字体。任务标题 26/34px，详情标题 22/30px，区块标题 16/24px，正文 14/22px，辅助信息 12/18px；编号和路径用系统等宽字体。
- 间距以 4/8px 为步长，区块间 24px，区块内 12–16px。圆角 6–8px。阴影只用在临时浮层。
- 树里短标签 ≤8 字，卡片短标签 ≤6 字；**完整标题、要求原文、错误原因、路径都在详情里完整展示**。
- 长路径可换行；错误文案不要省略成没有意义的「…」。

## 12. 交互与可达性

把下面九条流程做进**同一套组件和状态**里——不是把流程文字印在页面上，也不是做九个导航菜单。

1. **第一次进入**：看到任务总览；分支和细节都折叠，但仍能直接读懂一句任务说明、四个阶段的用途、当前阶段和主要实施任务。没有假百分比。
2. **找一个方案要点**：展开左侧分支，点一个要点，右侧显示完整标题、结论和来源关系；其它分支保持收起。
3. **追一条要求**：点一条要求，看到九个区块和追溯链；展开「原始要求」知道原话出自哪；点实施任务跳过去；点缺失的环知道还没实现；点测试环知道「先写的测试」和「实施验收」是两件事。
4. **看一个实施任务**：读它要交付什么、依赖什么；展开「涉及文件」只看计划路径，再看「真实改动」的未产生说明——**两种文件列表不能混在一起**。
5. **读一次先写的测试**：看到用例数、通过数、失败数、退出码和原始输出入口；返回后仍在原来的滚动位置。
6. **定位更新**：点更新项，树自动展开到目标，高亮只落真正变化的节点；点「我看过了」，状态和验收都不变。
7. **来源打不开**：点一个没有可访问地址的来源，原地出现限制说明和完整路径；页面不丢当前选择和阅读位置。另外单独给出「指针失效」的状态，**文案和原因与前者不同**。
8. **键盘操作**：Tab 能访问所有可点控件，焦点明显（2px 蓝色外框）；树用方向键遍历和展开收起、Enter 选择；折叠区按钮支持 Enter／Space。不要只画焦点样式而不实现导航语义。
9. **窄屏（约 960px 以下）**：左树收进「目录」抽屉，右侧保留面包屑；追溯链变竖向；任务行字段上下排；来源路径可换行。**不能隐藏缺环、状态来源或「未执行」的说明**；关闭抽屉后焦点回到「目录」按钮。

四个阶段的流程带（放在任务总览里）：`定方向 → 做计划 → 写代码 → 验收`，每段下面最多一句用途说明，**当前阶段**有浅底色和「当前」文字，后面的阶段不要画成已完成。

## 13. 示例任务（下面所有屏幕都用它）

**不要**用「任务 A／任务 B」、Lorem ipsum 或空占位字段代替它。

| 项 | 内容 |
| --- | --- |
| 产品名 | `示例产品`（页头左侧，低强调） |
| 页面名 | 任务驾驶舱 |
| 任务标题 | `给导出功能加上失败重试` |
| 短标题 | `导出加重试`（页头用） |
| 一句话描述 | 导出失败时自动重试，让用户看得见每次失败的原因，并且能取消。 |
| 当前阶段 | `写代码`（定方向、做计划已完成） |

**四条要求**

| # | 原话 | 来源 | 现状 |
| --- | --- | --- | --- |
| 要求 1 | 「导出失败要自动重试三次」 | 用户 10 月 12 日的对话 | 已实现 |
| 要求 2 | 「重试的时候我要看得见每次为什么失败」 | 用户 10 月 12 日的对话 | 进行中 |
| 要求 3 | 「我不想等的时候要能取消」 | 用户 10 月 14 日的对话 | **缺环：还没有实施任务承接** |
| 要求 4 | 「只有网络类的错误才重试，别把格式错误也重试」 | 用户 10 月 15 日的对话 | 已实现 |

**两条决定**

- **决定 1**：重试采用指数退避（1 秒／3 秒／9 秒），不用固定间隔。理由：避免同时重试把服务打满。
- **决定 2**：重试状态放在导出面板里，不新建页面。理由：用户是在导出的上下文里关心它。

## 15. 交付形态

- 目标是一份**可复用的单文件 HTML 骨架**：结构、样式、双栏、折叠、选择、跳转、高亮和必要脚本**都在同一个文件里**，之后只替换内容。
- **离线可用**：零 CDN、零远端字体、零外部资源；图标用内联 SVG 或 CSS。
- **不要**：图表库、React／Vite 工程、构建链、后台服务、主题市场、每日查网。
- 如果当前设计环境只能给交互预览或工程格式，**如实说明还没拿到单文件 HTML**，并给出可供后续重建的设计与交互内容——**不要把工程预览说成已经离线可用的交付**。
- 「可复用」靠**结构稳定**体现：任务名、要求、来源和结果可以替换，**视觉骨架和交互语义保持稳定**；不要做成一个无限可配置的搭建平台。

## 16. 交稿前自查

拿第 13、14 节的示例内容手走一遍：初次进入、展开一个方案要点、选一条要求、追到一个实施任务、读一次先写的测试、看缺环、点更新项、点打不开的来源、键盘走一遍、缩到窄屏。

**逐项说明做到了什么、没做到什么**——不要用「现代、简洁、专业」这三个词代替结果。

完成的设计应该能看见：完整任务描述；要求／决定／实施任务／改动／测试的不同层级；九区完整的要求详情；实施任务详情和两张测试卡；追溯链的四种状态；任务级进度；默认折叠；只读声明与来源说明；更新带与逐节点高亮；完整空状态与错误反馈；离线单文件目标。

**不要**用文字声称「浏览器已验证」「视觉已验收」「用户已确认」——效果由真实页面和人来判断。
