## 这一 Phase 交出什么？

复杂与普通逐包路线使用新版卡和审查，小改保留一张卡与一次冷读。

- **本 Phase 结果**：真实 brief、角色回传、完成判据和公开退出使用同一版规则。
- **非目标**：不新增步骤、审查轮次、公共命令或历史回写。
- **改动前**：旧十格／五问和换人路径仍可能让当前包假绿。
- **改动后**：完整路线用十一格／六问／九问，同人首审加复读最多两轮。
- **与相邻 Phase 的边界**：消费 Phase 2 实发审查，向 Phase 4 交回新版检查器。
- **主要风险**：正文切换但普通路线或公开退出漏改；发现后整组回退本 Phase。
- **下一步**：Phase 4 在同版检查器上接写集与声明，方法 owner 处理技能登记未决。
- **动手前必读**：`quality/evidence/decision-maker/p04/card.md:5-15`。
  再读同目录 `design.md:43-109` 与 `build-plan/light-research.md:11-15`。
- **未决事实**：三角色方法技能的去向由 make-decision owner 在本 Phase 定版后决定。
  未决不授权新增步骤；无真实消费者前不得保留虚假登记。

## 这一 Phase 怎么验收？

本 Phase 只承接 spec 的验收3；完整判据以 AC-CONV-001 为唯一权威。
非 UI：不适用——本 Phase 只改方法、路线与检查器，没有页面改动。

- **成本账**：引用 AC-CONV-001；验收活动为25活动分钟，属未校准估算。
  `acceptance_cost_total=25 active_min`；`phase_budget=unknown — 无已校准基线`。
- **资源账**：复用当前包卡、既有旧件、路线和公开检查；负控在隔离夹具就地构造。
- **范围账**：只证新版默认、两轮上限和小改冷读；后续声明类型与退役是供件。

**验收3：新版默认与轻量边界同时成立**

目标是三条路线取得与各自边界一致的真实 brief 和回传。
操作时先跑五份合同测试，再读复杂、普通真实入口与小改卡／冷读。
条件是现有路线、模板、包卡、旧五列样本和两个公开检查可用。
删第十一格、修订卡摘要但无同人复读、追加第三轮或换读者，两个公开检查必须失败。
真跑命令见任务3；独立测试者与路线读者在实现和审查修复后判定。
失败回包4原开发；合法同人复读或小改被误报也须修复，不得改测试求绿。

## 怎么验证？

测试面是命令行合同与真实任务消费，主技能预判为 backend-testing。
目标 RED 来自新版卡、问题、轮次或小改边界的具名断言。

任务3命令：
`npx --no-install vitest run tests/contract/convergence-defaults.test.mjs tests/contract/convergence-card-contract.test.mjs tests/contract/module-convergence-card.test.mjs tests/contract/check-stage-steps.test.mjs tests/contract/decision-evidence-consumption.test.mjs`

RED 期望目标断言非零；GREEN 用同一命令期望0。
手工 oracle 是独立写下完整路线十一格／六问／九问和同人两轮，小改一卡一次冷读。
真实 brief 与回传另证路线消费；旧五列只读样本证明历史未改。
证据经认证捕获保存；隔离负控同进程创建、消费和 `finally` 清理。
目标测试以现有 createTask 建立真实隔离任务，再用 openTask 按同一身份打开。
storageRoot 固定为任务库 `quality/scratch/convergence-defaults/storage`，不得使用 symlink。
真实 manifest 使用 `project_name=fixture`、`task_id=convergence-defaults`、
`activation_cohort=post`、`record_model=vnext-single-write`、当前工作区与真实 HEAD；
其余身份字段沿用现有 createTask 合同，setup 失败不算目标 RED。
createTask 返回的任务根必须是
`quality/scratch/convergence-defaults/storage/Projects/fixture/tasks/convergence-defaults`。
材料目录是该 scratch 根下的真实 `material/` 目录，不用链接代替；证据只写 `quality/tests/`。
两个公开 CLI 的完整调用分别为：
`node tools/cli/check-stage-steps.mjs --stage=make-decision --step=9 --phase=P3 --task-path=/Users/Hugh/Hugh/Knowledge/Projects/workflowhub/tasks/delivery-quality-foundation-20261122/quality/scratch/convergence-defaults/storage/Projects/fixture/tasks/convergence-defaults --material-root=/Users/Hugh/Hugh/Knowledge/Projects/workflowhub/tasks/delivery-quality-foundation-20261122/quality/scratch/convergence-defaults/material`
`node tools/cli/run-checks.mjs --task-path /Users/Hugh/Hugh/Knowledge/Projects/workflowhub/tasks/delivery-quality-foundation-20261122/quality/scratch/convergence-defaults/storage/Projects/fixture/tasks/convergence-defaults`
两命令在删第十一格及修订无同人复读时均期望非零，合法对照期望0。
调用证据分别写 `quality/tests/convergence-check-stage-steps.output` 与
`quality/tests/convergence-run-checks.output`。

覆盖上限：不证后续声明类型、发布安装或全任务对象收口。
显式不覆盖长期审查质量、历史任务重新判绿或新增规划路线义务。

失败时回包4原开发，恢复原生产文件与冻结测试 hunk，保留新原件及失败。
公开退出未非零、普通路线漏接或合法小改被挡都是停止信号。

## 每张任务卡怎么写？

### 任务 3：统一新版默认并保留小改一次冷读

为什么做：执行者需要同一版卡与职责，对应需求5、8与验收3。
交付什么：完整路线新版、小改一卡一次冷读、同人两轮和公开失败传播。
不做什么：不新增步骤或轮次，不改历史原判，不接后续写集或退役逻辑。
前置：Phase 2 已交回同版步骤；包4卡、路线、模板和旧件可读。
怎么做：先改根与普通／小改路线，再改模板和检查器，最后同步批准的测试断言。
怎么验收：运行下方同一命令，另读复杂、普通真实 brief 和小改冷读。
证据：五份测试、真实 brief／回传、两个公开 CLI 负控与旧件哈希各留单份原件。
下游（含何时停）：交 Phase 4 检查器；漏问非零缺失或合法路线被挡即停回包4 owner。
