## 这一 Phase 交出什么？

计划作者从正常入口读到同包、同批次、同卡版的五件原件，并能写出首卡。

- **本 Phase 结果**：五件材料可逐件回读，缺件能定位到包和类别。
- **非目标**：不新增清单、读取回执、材料投影或计划拆解规则。
- **改动前**：部分材料存在，但计划入口未具名消费，方向缺件未必非零。
- **改动后**：方向缺件明确失败；计划作者拿到五件或停受影响包。
- **与相邻 Phase 的边界**：向 Phase 2、3、4 交回共享步骤与检查器已核状态。
- **主要风险**：把路径存在误当真读过；若首卡仍错包，撤回本次接线并由包1 owner 修复。
- **下一步**：独立计划作者写首卡，Phase 2 在已核共享文件上继续。
- **动手前必读**：`quality/evidence/decision-maker/p01/card.md:5-15`。
  再读同目录 `design.md:35-79` 与 `build-plan/light-research.md:5-15`。
- **未决事实**：真实验收需要合法收敛清单；缺失由方向 owner 补齐，不用夹具冒充。

## 这一 Phase 怎么验收？

本 Phase 只承接 spec 的验收1；完整判据以 AC-MAT-001 为唯一权威。
非 UI：不适用——本 Phase 只改命令行、方法和材料读取，没有页面改动。

- **成本账**：引用 AC-MAT-001；验收活动为25活动分钟，属未校准估算。
  `acceptance_cost_total=25 active_min`；`phase_budget=unknown — 无已校准基线`。
- **资源账**：使用真实方向任务、五件原件、Node 与认证捕获链。
  缺合法清单由方向 owner 在真实流程补齐，不能就地造一份假清单代效果。
- **范围账**：只证同包材料进入计划；后续审查角度、默认版本和声明读取是供件。

**验收1：同包材料成为计划输入**

目标是计划作者取得五件并写出内容正确的首卡。
操作时先跑目标测试，再由独立作者从正常计划入口逐件回读。
条件是真实任务、当前卡节及哈希、讨论批次、五件与认证捕获均可用。
故意删除当前卡、移除质询、移除对抗或用总确认代卡，方向检查都必须非零。
计划侧对每个负控均不得写首卡；五件齐全后才由独立作者验收。
真跑命令见任务1；环境失败与目标断言失败分开记录。
未参与写作的独立计划作者在实现与审查修复后判定，证据落任务1所列原件。
失败回包1原开发；修复后只重跑本卡命令和受影响首卡阅读，缺真实输入则停该效果判定。

## 为什么现在做，依据是什么？

后续包都消费同包卡与审查原件，必须先让计划入口取得可信输入。

- **结果**：计划作者能用同包材料写出首卡，坏身份不能接包。
- **非目标**：不改默认卡版本，那是 Phase 3 的独立交付。
- **与其它 Phase 的区别**：本 Phase 证材料消费，不证审查字段或机器默认。
- **依据**：`decision-log.md` 包1与决定1；用户答复 U-021。
  归档 PRD 的同包接卡要求见 `specs/archive/delivery-quality-reform-20261121/prd.md:293-298`。

### 任务 1：让计划作者读到同包五件并写出首卡

为什么做：计划作者需要用户实际讨论的同包材料，对应需求2、8、9与验收1。
交付什么：正常入口可回读五件，独立作者能写首卡；缺件会点名且方向检查非零。
不做什么：不新建清单、不增读取回执、不改 Phase 3 默认版本或历史材料。

怎么做：先流式枚举并逐对象分配 Phase/Task/AC，再接方向声明、检查和计划消费。

证据：开工枚举、逐对象分配、RED/GREEN、五件与首卡各留单份原件。
下游（含何时停）：后续 Phase 和 P7 消费分配；缺对象分配或首卡错包就停回包1 owner。
