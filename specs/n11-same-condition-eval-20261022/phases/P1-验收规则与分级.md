## L0 — 结果与变更

本 Phase 只改「怎么验收」：把会逼出全量重跑的规则换成默认最小范围加一次可说明的例外，并要求验收资产开工前齐备、跳过项留痕、新增文件有登记。P2–P9 的验收口径都从这里取，所以它必须最先落地。

- **结果**：任一 Phase 的验收默认只跑本任务范围内与本次改动相关的测试；判断不了影响面时用最小可证伪集合并记录未知影响面；全局重跑只在改动对象是流程本身且局部无法证明时执行一次并事先说明；跳过项记 `unverified` 加原因与影响面并留在分母；四项禁止各有受控负例；本任务新增的实现脚本在 `docs/architecture/move-map.json` 有登记行。
- **非目标**：不放宽任何真实测试范围，不新增分级档位、stage、门或第二进度权威，不新建技能、标准或模板，不替 P2–P9 写它们的测试。
- **与其它 Phase 的区别**：P1 只交规则文本、模板清单与登记行；P2–P9 各自承担其主题的实施与验收，并把本 Phase 的口径作为固定开工输入。

### 覆盖边界

- **覆盖上限**：证明六处规则正文与两个模板清单在场、15 条登记行在位、两类受控负例能把旧口径与未登记脚本报出；不证明真实会话按此执行，不证明质量因此不下降。
- **显式不覆盖**：真实会话里的分级选择与全局重跑决定（需真实执行记录）、P2–P9 的实施与验收实践、`docs/architecture/move-map.json` 其它既有登记行的正确性、四项禁止在真实执行中的合规性。

### 停止

- 正文锚点与实读不一致：停在原文件，回本 Phase 执行者按 `spec.md#实现设计（全局权威）` 的「代码锚点」重读，材料疑点交 build-plan 作者。
- 测试无法在本次改动后通过，或只能靠删断言、删负例、改 oracle 通过：停在该用例，回本 Task 执行者定位；判据改动需用户真实答复，不得自行放宽。
- `docs/architecture/move-map.json` 同期出现其它持笔者：停登记，回登记作者按真实前后 writer 定序。
- 三项任一发生时不继续下一张卡，缺口按实记录，其余安全工作继续。

### 完成

- 六条承接 AC 各有一条可重放命令与一份原始输出；`npx vitest run tests/contract/n11-acceptance-rules.test.mjs` 退出 0 只证明本文件两个 oracle 的断言通过，不证明 AC 全绿。

- 缺任一项时对应 AC 记 incomplete 并写所需条件与 owner，不写 pass。

- **风险**：规则改小被读成放宽质量（对应 `spec.md#12-风险未决与交接` 的 RISK-01）。
- **影响**：验收变松，问题被漏过，后续 Phase 的质量结论不可信。
- **缓解**：规则与负例同时交付，负例必须能在改坏时报出；跳过项强制三要素并留在分母。
- **回滚**：只回退本 Phase 的六处 hunk 与新增测试文件，保留其它 Phase 与历史原件。
- **触发条件**：负例在改坏时不再失败，或独立审查判定只删规则未补最小可证伪与跳过留痕。
