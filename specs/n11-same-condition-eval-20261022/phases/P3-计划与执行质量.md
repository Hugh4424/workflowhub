## L0 — 结果与变更

本 Phase 交付「计划写下来就能执行、写完还能对账」两条机械事实：build-plan 的方法正文要求每条需求落成动作、命令与期望三件套并给判据加锁；既有校验函数把 Phase 声明写集与真实 diff 逐路径对一遍。它只改方法正文与既有校验路径上新增的只读事实，不新增 stage、公共命令或第二账本。全局目标见 `spec.md#实现设计（全局权威）` 与 §5「计划与执行（PLAN）」。

- **结果**：缺命令或缺期望的 Task 卡在同一份 Phase 材料的机械合同与契约测试里被点名；Phase 声明写集与真实 `changed_paths` 的越界项与「列了没改」项被逐路径报出，缺当前 Phase 的真实 scope 时记 unavailable 而不猜。
- **非目标**：不重写 `spec.md` 的 AC 或 decision-log 的任何决定；不实现「模型是否照做」的自动判定；不改 build-code 的 diff producer、审查裁剪语义、评测链或历史 receipts 字节。
- **与其它 Phase 的区别**：P1 定义验收规则与测试分级，P2 定义讨论质量；本 Phase 只拥有「三件套＋判据锁」的方法正文与「声明写集 vs 真实 diff」的对账事实；P9 消费本 Phase 原件做全 AC 收束，不重做这两件事。
