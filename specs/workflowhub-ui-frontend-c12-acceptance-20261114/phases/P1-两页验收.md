## 这一 Phase 交出什么？

独立验收者可从当前两页字节得到身份、真实调用、辅助浏览器事实和设计对照。
Phase 3 可继续使用同一副本，Phase 4 只读回本段原件。

- **本 Phase 结果**：两页当前稿的逐能力首判均有真实来源，缺证保持未测。
- **非目标**：页面修复、业务验收、发布判断、新原型和性能评级均不交。
- **改动前**：对象和矩阵已锁，但当前运行回执、同页设计预览与八维新审未齐。
- **改动后**：副本可复算、可构建、可驱动，原始事实与缺口可以分别回读。
- **与相邻 Phase 的边界**：本段交未改令牌的副本；Phase 3 才做受控更新。
- **主要风险**：旧图或错误引擎被当成当前页面事实；发生时停用该证据并重新定位来源。
- **下一步**：Phase 3 读取副本与 `.inlineactions` 使用点，Phase 4 读取本段首判。
- **动手前必读**：`spec.md#实现设计全局权威`、decision-log 的能力矩阵与 UI 准备记录。
- **未决事实**：实际选定引擎、端口、视口偏移、交互终态与 reduced-motion 读数待真跑；
  ego-lite 路由已实测（probe 2026-11-14-008），视口偏移与会话标签仍留执行原件。

“RED”指同一目标断言在实现前失败，“GREEN”指同一断言在实现后通过。
“辅助事实”表示可以影响覆盖说明，但不作为两页五类采集的正式通过条件。

### 验收 1：两页能力调用有真实回执

目标：两页适用能力各有调用点、输入、输出、消费者和当前运行回执。
操作：逐行核已锁矩阵，再用副本真实 DOM、行为或数据流验证声明可用的行。
条件：副本身份一致、服务可达、隔离会话合法；无调用点行直接记未测。
通过/失败：可用行必须四件套与回执可回指；缺回执仍判可用即失败。
故意弄坏：移除一条真实回执后，独立判定必须拒绝对应“可用”。
真跑命令：先执行 prepare，再执行 collect；两条命令见任务 1 正文。
prepare 预期 0；collect 只在服务可达且会话合法时预期 0，网关拒绝或采集失败保实际非零。
两个退出码都只证执行完成，不替能力判词，也不写成已通过。
独立判定与证据：未参与实施者读 `planned: quality/evidence/2026-11-14-104-two-pages-capability.json`。
证据计划：判什么=四件套与回执；怎么判=逐行回指；证据从哪来=对象原件；
谁提供=任务 1 执行者；何时能拿到=两页运行结束；成本类别=真实运行加人读；
