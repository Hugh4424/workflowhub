> 写作标准：`skills/material-writing/SKILL.md` 的「材料写作标准（唯一）」是本文件唯一标准。

本文件的词先解释。
「阶段」是一个任务里能独立验收的一部分；本任务有四个，本文件是第一个。
「写集」是本 Phase 允许改的精确文件路径，逐条列，不写目录、模块名或通配。
「G-2」是纯文档、无新增运行行为的验证形状：给可重放的客观检查与独立读者，不造目标 RED。
「判定器」是 `ORACLE-…` 编号，指判真假的那一条断言或那一条读数。
「删除证明」是证明旧形状清到零的三项读数：包清单未变、无代码引用、引用者清单为空。
「纯指针索引」是只存指针、不承载正文的 `phases/index.md`。
「单独提交」指删旧与清尾合成一个提交，可单独 `git revert`，不夹带本 Phase 其它改动。

## 这一 Phase 交出什么？

写计划的人按改后的方法与模板，能写出一段能被独立读者照着做的验收。
这一段含六件：目标、怎么操作、什么条件、怎样算通过（含一处故意弄坏必须失败）、
真跑还是替代、谁判与证据；段末再写失败回修与停止。

- **本 Phase 结果**：除本节与本文件外，同一批改动还让流程先出阶段大纲再写规格，
  让拆分数从 3–7 改成 2–7 只作提示，让任务卡先按 8 个问题写正文再放机器字段。
- **非目标**：不改写 PRD 的方法、模板与版本登记（那属于 P2 的写集，本文件不列其路径）。
  不改 PaperBuilder 的规划 PRD（P3）。不新增校验器、stage、门、字段或第二份判据。
  不改 `skills/spec-plan/skill-bundle.json` 的文件清单。
- **改动前**：验收只要求「动作＋命令＋期望」三件套，缺起点、负控、证据与停止条件。
  Phase 模板的验收节是七个槽；拆分数写 3–7；流程里没有「先出阶段大纲」。
  实读基线（认证 worktree，HEAD 17e78a09）：三件套 3 处、七字段 5 处、
  七槽 7 处、3–7 三处、阶段大纲 0 处；读数根与核对方式见「开始前读什么？」。
- **改动后**：验收是一段六件加失败回修与停止，命令与证据各归其位；
  模板按条写验收；流程先出大纲并取得答复；任务卡 8 问在前、17 个字段在后。
- **与相邻 Phase 的边界**：本 Phase 只交方法、流程与两个模板的形状；
  P4 只读核对提交与覆盖，不改本 Phase 材料；本 Phase 先做，不等 P2，
  也不消费 P2 的产出。
- **主要风险**：改模板时按「补几句」而不是整节重写，留下新旧两套写法。
  若因此返工，按 `specs/archive/workflowhub-thin-core-card-03-20260919/design.md:2594`
  的先例整节重写，并对同一份材料重跑定向测试。
- **下一步**：build-code 按任务 1 到任务 4 的顺序实施；每条卡实施完立即留证据。
- **动手前必读**：见「开始前读什么？」表；先读方法与流程，再读模板，最后读测试。
  顺序反过来会把测试当需求。
- **未决事实**：

  写入集与本文件逐字一致；矛盾由主会话按本文件逐字对齐。
  二是 `execution_budget` 四项未在决策日志给出（window_minutes、command_cap、
  wait_cap、retry_reserve）；owner 是 make-decision；本 Phase 验收不依赖它。
  三是定向测试已扩到 8 条，新增三条测试文件并入本 Phase 写集；
  授权来源：`spec.md` 的「全局文件边界」一节，该节把三条 `tests/` 列入 MODIFY；

## 这一 Phase 怎么验收？

先算三笔账，再写验收；三笔账算不出来就不写。

- **成本账**：逐条引用 `spec.md` Appendix A 的成本七字段与资源来源，按下式汇总。
- **资源账**：九条验收要的读者、执行单元、模板与仓内测试都已存在，不新造样张。
- **范围账**：九条都证本 Phase 自己的交付；没有跨 Phase 承接，P4 只消费原件。

### 验收活动预算怎么算？

串行和 145 活动分钟：九条验收 140，三条新增定向测试每轮约 5。
并行最大取 45：读者级由两位独立读者分摊后是 45，命令级由两个执行单元分摊后是 40。
两组并行时取 45；再加共享准备 10、重试预留 15 与附加重跑 5。
合计 45 + 10 + 15 + 5 = 75 活动分钟；145 是不并行的上界。
共享准备指统一样本、路径与 cwd 各一次；重试预留按每条 `retry_cap=1` 记一次；
附加重跑指三条新增定向测试的同一轮，不重复计。
`estimate_min` 与 `hard_cap_min` 只是活动成本估算，不是时间盒，也不以到时触发停止；
停止只由各条验收的失败信号触发。用户等待与审查等待单列，本 Phase 没有用户确认。

- `acceptance_cost_total=75 active_min`：估算，不是实测。
- `phase_budget={soft_min:120,hard_min:240,variance_threshold:1.5,source:provisional}`：
  120／240 分钟与 1.5 未取得 make-decision 的真实确认，按模板示例记 provisional，
  回原 owner 校准；阈值只帮复盘，不是机器退出门。
- `execution_budget=unknown`：四项取不到真实答复，owner 是 make-decision；
  影响只落在 build-code 执行期，本 Phase 验收不消费它。

### 验收 1：一段验收能让没参与的人照着做，六件事齐且不指派角色（AC-BP-001）

**目标**：改写后的验收段六件齐，读者只读这一段就能开工；
并写明验收在实现前冻结、实施中改验收必须取得用户真实答复。
本条按本次审查加严，判据仍归 `spec.md` Appendix A，规格同步由规格作者改。
**怎么操作**：独立读者只读改写后的验收节与 3 段真实样本，回答四问；
再核「实现前冻结」与「改验收须用户真实答复」两句是否在场、是否写了留原件。
四问是第一步做什么、什么算过、什么算不过、证据在哪与跑多久。
**什么条件**：认证 worktree 的方法文件与模板；样本取本文件与模板里的既有段。
**怎样算通过**：四问齐答；六件齐；每个阈值能指到来源或基线；段内无角色指派；
冻结与答复两句在场，且写明答复要留原件、审查同意与推测不算。
故意弄坏一处一：删掉「证据在哪」一句后，读者必须指出缺件；判不出即不合格。
故意弄坏一处二：模拟实施中擅自改一条验收且无用户答复原件，必须判失败；
判成通过说明这条加严没落到判据里。
**真跑还是替代**：真跑，读者读当前字节；不制造 RED，命令只作结构前置。
**谁判与证据**：未参与写作的独立读者，开发与审查改完后判定；
结论与四问原话落 `planned: 任务根/quality/tests/P1-acceptance-readback.md`。
**成本**：executor=独立读者；estimate_min=20；hard_cap_min=40；
resources=改写后的验收段与 3 段样本；observation=四问原答与阈值来源清单；
retry_cap=1；evidence_tier=读者级。
**资源来源**：复用仓内既有模板与本次材料，不新造样张。
**失败回修与停止**：任一问答案不出回本卡作者改同一段；阈值无来源先补来源；
同一原因连续两次失败停手报主会话，不扩写集。

**资源来源**：仓内既有验收节改写稿，不新造样张。

### 验收 3：四问读者测试真做过，记录可复读（AC-BP-003）

**谁判与证据**：未参与写作的独立审查者，核记录与四问原答，不看实现者自述；
