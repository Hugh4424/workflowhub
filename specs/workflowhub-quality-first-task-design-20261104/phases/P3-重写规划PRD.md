# Phase P3 — 在外部新起一份按新形状重写的规划 PRD

本文件写给 P3 的实施者、独立审查者与 P4 终末验收者；读完要能找到
外部写面、每张卡的改法、可重放的判据与失败边界。
全局目标与唯一判据在 `spec.md`，本文件只写 P3 的实现增量，不复制第二份判据。
本文件是草稿：实际执行状态归任务事实库，这里不写「已跑过」。

> 写作标准：`skills/material-writing/SKILL.md` 的「材料写作标准（唯一）」是唯一标准。
> 本文件不复述标准，只说明自己的例外。
> 例外一：外部路径与命令逐处不折行，会超过 80 字；每处都是可直接复制的原件地址。
> 外部绝对路径只在「每个文件由谁改」那三行出现（路径定义与两条变量定义）。
> 新件头部那一行 `Supersedes:` 字面值逐字不折行，保证可原样粘贴。
> 例外二：文件末「机器字段」块与任务卡的 17 个字段名按原词逐字读取，不改名、不翻译。
> 例外三：旧 PRD 的锚点按 `路径:行号` 引用原件，不折行、不改写。
> 例外四：验收段标题后括注规格里的验收编号，供机器追踪；正文其余处只用中文序号。

本文件的词先解释，后文只用这一次解释。
波次：同批可并行、按先后排组的任务分组；W1–W4 是本次新引入的分组名。
外部写面：不在本工作区、写它要另一次人工批准的产物。
新版本另起：新文件写新内容，旧文件一个字节不动，回退靠删或废弃新件。
Supersedes：新件声明它替代哪一份旧件的字段，回退时按它找旧件。
纯指针索引：只存行与指针、不承载正文的 `phases/index.md`。
判定器：判真假的那一条断言，编号前缀 `ORACLE-`。
RED 与 GREEN：先用目标断言判失败，再用同一断言判通过的一对状态。
G-2：纯文档任务的具名替代写法，用客观检查加独立读者，不制造仪式性 RED。

## 这一 Phase 怎么验收？

三笔账先算，算不出来不写验收；六条验收各写一小段，判法与成本都回 spec。
本节的分钟数只是活动成本估算，不是时间盒；到时不停手，也不据此减判据。

### 三笔账

- **成本账**：六条验收的七字段逐个引自 `spec.md` 的 Appendix A，用原值，不改写。
  串行相加 165 活动分钟（25 + 20 + 25 + 25 + 45 + 25）。
  读者级两条并行，取最大值 45 分钟，替下 45 加 25 的 70，减 25。
  共享准备 15 分钟：旧件字节、七张只读卡切片、脏文件哈希、读者口径各一份。
  重试预留 20 分钟，按每条一次重算预留。
  合计 `acceptance_cost_total=175 active_min`。
- **资源账**：旧件只读，新件是本 Phase 的唯一写入；旧哈希与行数由任务 9 现场算出。
  读者记录格式复用仓内 `skills/spec-plan/scripts/check-reader-record.mjs`。
  没有「就地造」的数据：本 Phase 不造样张，全部读真实原件。
- **范围账**：六条都证本 Phase 的同一份交付（那份新件与它的旧件边界）。
  下游 P4 把它们当供件消费，不写「承接」。

### 预算

- `phase_budget` 四项如下，值按原词读：
  `{soft_min:200,hard_min:400,variance_threshold:1.5,source:provisional}`。
  200 与 400 是从 175 活动分钟按 1.14 与 2.29 倍取的待校准值，不是实测。
  这两项只是估算，不设到时停止，也不因为超了就砍判据。
- `execution_budget=unknown`：make-decision 未给执行预算答复。
  owner 是 build-code 的开发；恢复条件是开发在开工 brief 给视窗、命令上限、
  等待上限与重试预留四项，本文件不补默认值。

### 验收 2（AC-PB-002）：七张只读卡的字节一个没变

- 目标：旧件整份未动，且新件里 T01–T05、T10、T16 七张卡的正文与旧件逐字节相同。
- 怎么操作：按 `### Tnn — 标题` 切到下一张卡标题前一行取字节，
  标题行本身也进哈希；同一条命令对旧件与新件各跑一次，逐卡比。
  命令可直接跑，先 export 一次 `P3_PRD` 与 `P3_PRD_V2`：

```
for id in T01 T02 T03 T04 T05 T10 T16; do
  awk -v id="$id" 'f && /^### T/ {exit} $0 ~ "^### " id " " {f=1} f' "$P3_PRD" \
    | shasum -a 256
done
```

对新件把同一个变量换掉再跑一次：`P3_PRD="$P3_PRD_V2"`，两轮结果逐卡比。

- 什么条件：切片按标题定位，不看旧绝对行号；旧行号只用来核对切到的是同一张卡。
  理由：地图与排期收短后行号整体前移，按行号取值会取到错位字节。
- 怎样算通过：旧件整体 sha256 等于任务 9 的基线；七张卡在两个文件上的切片哈希
  逐个相等；两张卡之间多一行、少一行或改一个空格都判不等。
  外部仓库 `git status --porcelain` 只出现新件与既有脏文件 `scripts/serve_f6.py`。
- 故意弄坏：在临时副本里给只读卡加一个空格，比对必须判不等。
- 真跑还是替代：真跑哈希；等价边界是「同字节即同一事实」，不另造等价物。
- 谁判与证据：独立执行单元；`planned: 任务根/quality/tests/P3-readonly.txt`。
- 失败回修与停止：旧件哈希变了即停手，先恢复旧件；新件切片不等回本 Phase 作者。
- 成本：executor=独立执行单元；estimate_min=20；hard_cap_min=40；retry_cap=1；
  resources=两端文件与基线；observation=整体哈希与七对切片哈希；
  evidence_tier=命令级。资源来源=两份文件只读，哈希现场算。
