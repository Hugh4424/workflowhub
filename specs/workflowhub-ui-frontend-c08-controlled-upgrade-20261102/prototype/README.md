# C08 五状态静态原型（v3）

这是一份用于 build-plan 界面审查的静态原型，不是产品页面，也不是实现。
它用真实类名、真实令牌和真实断点，把 C08 的五个界面状态与它们的焦点、溢出、几何做
成可以直接打开、可以切换、可以观察的页面。

v2 按 2026-11-02 独立设计审查的 F01–F14 修订过；v3 又按补遗审查的 N01–N04 与
F04/F11/F12/F13 残余修了一轮。v1、v2 的原型与证据都保留，不覆盖。
当前判读依据是 `2026-11-02-preview-record-v3.md`；逐版本替换关系见 `replacement-map.md`。

入口是同目录的 [index.html](index.html)；样式在 [prototype.css](prototype.css)，
交互与观测在 [prototype.js](prototype.js)。

## 打开方式

双击 `index.html` 即可在浏览器里打开；它只用相对路径，没有 npm、CDN 或外部字体。
本次隔离浏览器只走 localhost HTTP，没有验证 `file://`，见「没测到的部分」。

因为页面脚本用 `?v=7` 这类查询串绕开静态缓存，直接双击不受影响；用服务打开时建议
带一个任意查询串，例如 `http://127.0.0.1:8899/index.html?v=4`。

推荐用静态服务打开，便于截图与复现：

```bash
cd specs/workflowhub-ui-frontend-c08-controlled-upgrade-20261102/prototype
python3 -m http.server 8899 --bind 127.0.0.1
# 浏览器打开 http://127.0.0.1:8899/index.html
```

五个状态用页面顶部的状态按钮切换，也可以用 `#A`…`#E` 直接落到某个状态。
每个状态顶部有一条「原型演示」栏，放的是原型专用按钮（重放、旧/新行为对照），
不是产品控件；产品控件仍在页面里，位置和文案按真实源码。
未接线的产品控件旁边有可见的「未接线」小标记，点了只会写观察日志，不会假装执行。

## 五个状态各看什么

| 状态 | 初始画面 | 要做的动作 | 通过判据 |
| --- | --- | --- | --- |
| A 业务日志 | 列表 1 行 + 详情抽屉打开 | 焦点移到「重置筛选」再按 Enter | 抽屉消失、筛选按重置后的值显示（2 条）、焦点在重置控件（目标态） |
| B 工作台 | 图表占位 + 定位失败块 + 抽屉关闭 | 点图表错误块里的「重试定位」 | 抽屉恢复 1 个、身份 position-2、错误消失、焦点进抽屉 |
| C 浮层 | compact 回测浮层打开 + 长错误 | 切「显示旧行为 / 显示新行为」 | 新行为错误块不溢出，旧行为溢出 |
| D 台账 | 信号流水 3 行 + 信号详情抽屉 | 焦点移到「清除筛选」再按 Enter | 抽屉消失、筛选重置、焦点回时段筛选（spec 的 clear() 契约） |
| E 台账长错误 | `.lg-warning` 长错误 + 基线对照块 | 切「显示旧行为 / 显示新行为」 | 台账内换行无横滚，基线块保持旧行为 |

抽屉打开时遮罩盖住页面，鼠标点不到背后的筛选按钮；真实产品同样如此。
所以 A、D 的演示走键盘：先让焦点落到产品按钮，再按 Enter。
这一步在本次捕获里真实执行过，不是页面自动播放。

每个状态的说明（问题、旧行为、新行为、通过判据；A 另有一条目标态说明）显示在页面
顶部，切换状态时同步更新；同一份文字也留在下面，方便不开浏览器时阅读。

### A 业务日志：重置筛选后清详情

问题是重置筛选后，上一事件的详情仍挂在页面上。
旧行为只换查询，`detailRecord` 不清，抽屉继续显示旧事件。
新行为是在两个重置入口先 `setDetailRecord(null)`，再交回原重置。

v2 按主会话裁决把重置后的筛选值恢复为默认（对象=全部对象、结果=全部结果、关键词空、
事件类型空、动作=全部动作、时间空），并按新条件重算列表：初始 1 条，重置后 2 条。
看点：抽屉节点归零、筛选显示重置后的值、列表与计数同步、焦点落到「重置筛选」。

焦点这一项是目标态：spec 允许 C08 做最小焦点修复，而当前代码沿 `triggerRef` 把焦点
还给触发行。页面演示栏直接标了这句话，日志也照写，不把目标态当现有行为。

### B 工作台：定位失败后重试恢复

问题是定位失败后关掉抽屉再重试，只重算图表，抽屉不回来，目标身份也丢了。
新行为是重试复用持仓导航：同目标直接重焦，否则走统一导航并恢复抽屉。
看点：只出现 1 个抽屉、`.drawer-position-id` 为 position-2、错误块消失、
焦点在抽屉的关闭按钮上。抽屉里的「上一个 / 下一个 / 下一个亏损单」在两条合成记录间
切换，身份、PnL、方向与解释一起更新。
关闭或 Escape 时重试按钮已随错误块隐藏，焦点按真实回退规则落到页面标题（h2），
页内日志照写“回页面标题（触发控件不可用）”。Escape 只关当前状态的抽屉。

### C 工作台浮层：长错误换行

问题是 compact 浮层里的长错误继承外层 `white-space: nowrap`，窄屏撑出浮层。
新行为只加一条规则：`.backtest-top-popover .backtest-top-error` 内
`white-space: normal`、`overflow-wrap: anywhere`、`max-width: 100%`。
看点：浮层宽 300px（窄屏 `min(300px, 100vw - 20px)`），错误块
`scrollWidth ≤ clientWidth`，页面没有横向滚动。旧行为开关复刻继承 nowrap 的样子。
浮层里的「开始回测」与「±10 天」未接线，旁边有可见“未接线”标记；两个时间输入也标了
“时间输入未接线”。点击它们只写日志，不假装执行。

### D 实盘台账：清除筛选后清详情与焦点返回

问题是清除筛选只重置筛选，详情抽屉还开着；焦点可能落回已被移除的行。
新行为是清除时先关闭详情，再把 `triggerRef` 指向仍挂载的「时段筛选」，然后重置筛选。
看点：抽屉消失、五个筛选控件回到默认（时段=今日）、焦点在
`select[aria-label="时段筛选"]`。这条按 spec 的实盘 clear() 契约（当前 spec.md:834）与 P3 卡改动，不是账户角色筛选。

行与详情是一一对应的：三条信号各自有完整记录（状态、账户、方向、防重发判定、判定
时刻）。复制按钮在 id 存在时可用，点击后如实报告“已复制”或“复制失败”。
单个筛选控件不重新过滤，页内标了「筛选未接线」，只演示「清除筛选」。

### E 实盘台账：长错误换行（作用域限定）

问题是 `.lg-warning` 的长错误文本在窄屏撑出容器，而这个类是 10 个文件共享的。
新行为按 spec 的告警样式契约（当前 spec.md:837）只加父级作用域限定的 `.ll-root .lg-warning`，含
`min-width: 0`、`max-width: 100%`、`overflow-wrap: anywhere` 三个声明。
看点：台账内错误块 `scrollWidth ≤ clientWidth`、页面无横向滚动；
页面下方「全站基线」块用同一段文本证明共享类没有被改。

E 的信号行只作展示：计数 1 条、账户带完整 `title`，行没有 tabindex，也不承诺详情。

## 补遗审查的残余修复

补遗审查指出 4 条新问题和 3 条部分修复；v3 的处理如下，证据在 v3 目录。

- N01 跨状态 Escape 关错层：`anyOpenDrawer` 只看当前 state，切换状态时关闭其他状态的抽屉；
  `B-after-escape-close` 的 `drawerStates` 为 A/B/D 全 0/0，日志写“B Escape 关闭”。
- N02 窄窗直载抽屉头被工具条盖住：工具条后加一段内联脚本先写 `--proto-chrome-h`，
  `refresh()` 与 `ResizeObserver` 继续更新；768/320 直载实测变量与工具条高相等，
  `elementFromPoint` 命中 `close-a`。
- N03 文档高度数字：按状态重测分列（见“不可保真”），不再沿用 v1 的 256/375/423。
- N04 ±10 天缺可见标记：按钮组内加“未接线”，时间输入另加“时间输入未接线”。
- F04 B 关闭日志与焦点不符：关闭日志改为写实际焦点（触发行或页面标题）。
- F11 未接线控件复核：A 相关链接、C 开始回测/±10 天/时间输入、D/E 筛选条都有可见标记；
  D 的复制按钮在 id 存在时可用并如实报结果。
- F12 `aria-label`：抽屉 section 改为真实的“业务事件字段”。
- F13 高度说明：数字改为按状态实测，并写清 320 A 只有 36%、375 为 42%。

## 可保真与不可保真

可保真的部分（静态页就能看到、能测到）：

- DOM 结构与类名：`business-log-shell/main`、`business-log-filters`、
  `business-log-table-row`、`pb-ui-drawer-layer`、`pb-ui-drawer`、
  `position-comment-drawer`、`backtest-top-controls-compact`、`lg-warning`。
- 几何：抽屉 480 / 680、窄屏 100vw、浮层 300 与 `min(300px, 100vw - 20px)`。
- 文本：长错误的换行与任意断词；旧行为下的溢出宽度可测。
- 作用域：台账内 `.ll-root .lg-warning` 与页面外基线的对照。
- 焦点落点：由 JS 显式设置并能读出，用于展示目标态。
- 关闭/Escape：原型实现了最小焦点归还与节点移除；facts 分开报 `drawerVisible`、
  `drawerNodesInDom` 与三个状态的 `drawerStates`；关闭日志写实际焦点（触发行或页面标题）。
- 跨状态隔离：切换状态会关闭其他状态的抽屉，Escape 只关当前状态；`drawerStates` 可直接核。
- 工具条高度：载入时先写 `--proto-chrome-h` 再渲染舞台，facts 的 `chrome.heightPx` 与
  `cssVarPx` 相等，抽屉层 top 跟工具条底边一致。
- 页面级横向溢出：`scrollWidth - clientWidth` 实测。

不可保真的部分（必须由 build-code 在真实页面证明）：

- 焦点归还的真实链路：产品走 `useDrawerFocus` + `triggerRef`，A 的触发行与
  「焦点回筛选控件」并不等价；原型按验收文字演示目标态，不声明产品已实现。
- 图表可见比例：产品用 rAF 在挂载后读抽屉宽度，测试口径是 600/1000=0.6；
  原型在 1280 实测 0.681、768 实测 0.093、375 与 320 实测 0.000，
  这是本页视口的实测值，不是产品测试口径的 0.6。
- 抽屉顶部被原型工具条下移：默认帧的工具条高随状态说明行数与日志换行变化，
  1280 各状态都是 180px；768/375/320 为 A 367/467/515px、B 259/375/408px、
  C 259/375/422px、D 259/375/422px、E 259/375/437px。A 的抽屉高 720/657/345/285px，
  分别占视口 80%/64%/42%/36%；动作帧还会因日志多一行再变。这是原型几何偏差，不是产品几何。
- 清除筛选后行被移除的时序：原型能重算 A 的列表，但 D/E 的单个筛选不重新过滤。
- 实盘 store fixture、只读徽章语义、定位入口：需要 `live/store.ts` 与真实 API。
- 字体：真实页用 `/fonts/*.woff2`，静态页取不到，只保留同一回退栈，字形不同。
- 浮层在 ≤680px 的真实锚点是 `fixed`，原型为了不盖住工具条改成 `absolute`；
  宽度、断点与换行规则保持真实值。
- 图表、足迹、解释卡是占位块，不是真实组件。
- 复制走浏览器剪贴板，不是产品命令通道；失败时原型如实报“复制失败”。

- 原型是状态与几何的展示稿，不是产品页面，也不是实现，不能当执行证据。
