## L0 — 结果与变更

材料合同与写作检查当前是「有 validator、无总检查入口，模板占位被当成真缺」的状态：`validatePostPhaseContract` 只被审查流程消费，`run-checks` 六段不跑材料；`check-skill-consistency` 对干净 index 模板永久报「缺失 纯指针边界」。本 Phase 把材料段接到显式材料根，按任务级别分诊，并修模板占位判定，让「合法、缺段、零输入、轻档、伪轻档」在一条命令下可区分。

- **结果**：维护者用显式根跑总检查时，合法材料 0 error、缺段逐条具名、零输入报「没有输入/不适用」、轻档报「这个级别不适用」；干净模板不再误报，真实 index 缺指针仍红；N2 的历史错误只在显式指向时出现。
- **非目标**：不改 validator 自身行为，不默认扫 `specs/`，不对作者产物做机器语义评分，不新增第三套材料发现规则或必填清单。
- **与其它 Phase 的区别**：P1 负责三个 CLI 的报告/退出语义与既有六段基线，P2 负责来源登记 report-only 段；本卡只负责「把材料合同接进显式根」与模板结构判据，P7 才做全 AC 终验。
