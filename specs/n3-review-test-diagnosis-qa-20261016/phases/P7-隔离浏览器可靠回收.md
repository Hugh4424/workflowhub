### 真实票据输入与传递

以下是T007实施契约，现context尚未实现；不新增公共命令、schema或持久授权对象。默认`browser-qa-context.sh URL`仍只输出既有非秘密exports，保留显式`BROWSER_QA_AUTH_MODE`，不连接source。只有既有私有`--run --url URL --evidence-dir DIR -- argv...`消费本节输入。

| caller输入 / owner | context→runner→helper / 校验 | 缺失或失败 |
| --- | --- | --- |
| `BROWSER_QA_AUTH_MODE=read-only-ticket-export`；caller在已取得真实许可后选择 | context保留模式；runner才执行导出。`none`只做无登录隔离QA，不能静默替代所请求的复用 | 非支持模式非零；请求导出但条件不足为unavailable，不能回退none冒成功 |
| `BROWSER_QA_TICKET_SOURCE_WS`；用户或已获准的宿主提供当前正在运行Chrome的browser级CDP WebSocket URI，caller仅放入本次进程环境 | context只将它交runner内存，不输出export；runner消费后从engine/scenario子进程环境剔除。仅接受显式loopback地址、显式端口和`/devtools/browser/<id>`的ws/wss URI；拒绝userinfo/query/fragment及page endpoint；不探测端口、不扫描profile、不默认9222。runner建立source只读transport后传`transferTargetCookies({source, receiver, scope, signal, report})` | 未提供/当前source不可达为unavailable并非零；语法/边界非法非零。均不输出URI或底层含URI的异常；不能换source、启动/关闭用户Chrome来补齐 |
| `--url URL`；用户给真实目标，验证者给受控目标，caller确认它在本次票据许可范围内 | 这是普通cookie的唯一目标scope输入；runner按URL解析一次生成内存`scope`的`targetUrl`、`hostname`、`pathname`和`secure`（协议是否https），targetUrl仅保规范化origin+pathname。拒绝userinfo、query/fragment、非http(s)、空host及白名单不相容；不猜父域、通配域或额外路径。host-only/domain点边界、RFC cookie path边界、secure、有效期均按同一个URL筛选后才交receiver；scope不另写文件 | 非法或超出已许可目标范围时非零，不自动放宽白名单；没有真实目标/范围为unavailable |

source与receiver必须是不同连接及实例；receiver只取本次owned engine的`get cdp-url`并核PID/start-time/data-dir，不接收caller任意receiver。source只能调用`Browser.getVersion`、`Target.getTargets`、`Storage.getCookies`，导出前后比对targets，不能attach/create/navigate/close/write用户页面。全context响应会短暂含非目标cookie，必须明确披露这一读取边界；仅在源适配器内存立刻筛选，未选中值不得跨到receiver/场景/报告。cookie值与原CDP payload永不进入环境变量；source URI是单独的连接能力，只允许caller→context→runner的短期进程环境输入，runner读取后立即从其后engine/scenario继承环境剔除。系统进程环境并非不可见，此通道要求同机可信进程边界，不能宣称对同机其它可读进程保密；边界不成立则source通道unavailable。source URI不能进入argv、输出exports、stdout/stderr、证据或scenario环境；非秘密site也只按必要范围交runner，不默认扩散到子进程。报告只给受控错误码、方法名和安全范围，不序列化CDP request/response。

真实网关首验必须由caller在进程环境预置并export本次已获准的`BROWSER_QA_TICKET_SOURCE_WS`；需要分区cookie时也预置并export已知`BROWSER_QA_TICKET_TOP_LEVEL_SITE`（禁止把实际连接值写入脚本/证据或开启shell trace），再执行以下同一路径；`${…:?}`只检查输入存在，不代表许可已取得。URL须不含秘密，证据目录在owned临时root之外：

```bash
BROWSER_QA_AUTH_MODE=read-only-ticket-export \
  bash skills/isolated-browser-qa/scripts/browser-qa-context.sh \
    --run --url "${BROWSER_QA_TARGET_URL:?}" \
    --evidence-dir "${BROWSER_QA_EVIDENCE_DIR:?}" \
    -- bash "${BROWSER_QA_SCENARIO_SCRIPT:?}"
```

同次调用前检查`BROWSER_QA_TICKET_SOURCE_WS`存在但不打印值；上例由context继承该环境并只交runner。验收记录填写真实非秘密目标及派生scope（例如`https://app.example.test/private/report`对应`hostname=app.example.test`、`pathname=/private/report`、`secure=true`；若caller已知并提供`BROWSER_QA_TICKET_TOP_LEVEL_SITE=https://example.test`，则`topLevelSite=https://example.test`，否则为null），source只记`provided/unavailable`和browser级/只读核对结果。先以受控source及独立receiver经该命令验证成功、页面失败、取消，再由T007在现skill-contract测试面经同一run入口补齐具名受控case：`missing source never connects or falls back to none`、`invalid source endpoint is rejected before connection`、`invalid target scope never widens allowed domains`、`missing top-level site omits partition cookies but keeps eligible unpartitioned cookies`、`invalid top-level site is rejected before ticket transfer`、`scenario environment excludes source capability and ticket payload`；这些case当前均未实现/未观察，保持incomplete，不改冻结oracle。现冻结16用例的GREEN不证明这六条新增入口边界通过。再以真实用户已登录source经同一命令验目标站点登录及当场目视条件。缺真实source/许可时只给受控技术覆盖，不得把它写成真实登录复用通过。
