### 验收 Phase 固定小节

1. **入口准则**：逐条核对 P1–P11 的 `Done` 与实际写集落地；每条写核对结果与证据路径。
2. **两份就绪件**：数据就绪件（各 Phase 证据原件目录清单）与环境就绪件（Node 与 vitest 版本、真实工作树路径）各一份，独立成件放 `quality/evidence/`，各写状态。
3. **授权边界**：本 Phase 只读材料与本地测试；不推送、不删除、不归档；写目标仅限本 Phase 写入集；失败即停该条。
4. **逐条结论**：每条 AC 一行，写 AC 编号、一个档位、一条具名证据路径；档位只引用既有八值词表；非 `pass` 一律不计通过。
5. **五类执行事实**：逐条记命令与参数、cwd 与执行者、退出码与信号、原始输出落点、测试报告；`refs` 逐条标类型。
6. **效果评测**：成本可复算的比较基线、指标与统计量；正例与负例各一；报实际单位与范围，不报百分比代替原始数字。
7. **复验四项**：复验者与修复者的上下文差异、F2P 与 P2P 用例清单与计数、所跑回归范围与为何是最小可证伪集合、未知影响面。
8. **变更批准**：本 Phase 不改 AC 或用例集合；若上游改动过，引用其测试变更请求编号与独立审查原件；没有改动写「无加理由」。
9. **分诊与关闭**：失败先复现；分诊者不是实现者；字段至少含编号、描述、可复现性、版本、严重级、优先级、处置；终值只用既有六值。
10. **回写五项**：场景卡、AC 表、Phase 契约覆盖 AC、`facts.jsonl` 既有字段、本次修复记录；缺一项不算闭环。
11. **六项结论**：评估与局限、与计划的偏差、未充分测试的特性与原因、未解决事件逐条、残留风险、签核对象；每项非空。
12. **防自证五禁令**：不用授权文本验证授权文本；不删到测试变绿；不重跑到绿；黄金清单改动由另一主体批准；不用计数代替逐条；不把 `incomplete`、`unavailable`、`missing`、`unverified` 写成 `pass`。
13. **失败修复复验闭环**：失败 → 分诊 → 根因 → 修复回原 owner Phase 的 Task → 换上下文复验 → 回写五项；降级项写风险承接人署名。
