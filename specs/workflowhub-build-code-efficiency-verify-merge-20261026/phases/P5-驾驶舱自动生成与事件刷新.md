## 速读卡（人读；只写本 Phase 增量，不复制 `spec.md`）

- **本 Phase 结果**：当前任务驾驶舱由真实材料自动派生 15 类节点与十环，六类事件触发刷新，首次与实质变化自动用系统默认浏览器打开，打不开如实报「未自动打开」。
- **非目标**：不做常驻监控、定时重载或文件监听；不写任务状态；不做第二进度；不新增页面权威；不改模板已确认的组件与视觉。
- **改动前**：`renderAnswerPage` 只校验 caller 的 `pageData`、注入模板、写 HTML 与同名侧车；CLI 从不传 `open`，真实运行恒为 `opened:false`，原因是「缺宿主浏览器能力」。全仓没有打开系统默认浏览器的代码，没有监听或定时机制，没有第二个生产调用脚本。

- **与相邻 Phase 的边界**：P4 交来清单与游标；P5 只消费，不重建清单、不推进第二游标；P12 消费本 Phase 的页面、事件记录与两时点证据，不重跑首判。

- **下一步**：P12 用真实页面、事件记录与缺口逐 AC 对账；事件调用点由 build-code 各 Phase 主会话按方法正文执行。

## L0 — 结果与变更

驾驶舱现在是「有人手工拼 pageData 才出页」的离线生成器。本 Phase 让它变成事件驱动的只读派生页。判定它成功只看一件事：不提供手写 `pageData`，只给任务根与真实报告，页面仍完整出现 15 类节点与十环，缺口如实标注。

- **结果**：同一入口在六类真实事件上自动生成、刷新、按首次或实质变化打开；页面与侧车只写调用者指定目录。
- **非目标**：不做监控、不做第二进度、不写任务状态、不新增页面权威、不改已确认视觉。
- **与其它 Phase 的区别**：P4 管清单/游标/成本；P5 管页面派生与事件；P12 管逐 AC 终末对账。

### 风险与回滚

- **风险**：把既有红灯和本 Phase 失败混在一起；第二个生产调用者被忽略；打开命令在用户机器上不可用。
- **影响**：证据失真或页面不可用，P12 对账失去真实输入。
- **缓解**：证据分段记录、开工实读调用链、打开失败如实报并留原因。
- **回滚**：只回退本 Phase 审后提交；旧页、侧车、历史证据保留，不整树回退。
- **触发条件**：页面写 task facts、出现第二进度、或打开被记为成功却无真实动作。

### 交接知识（给下游 Phase 与审查的已核实事实）

- caller `pageData` 路径仍只做三件事：校验、注入模板、写 HTML 与同名侧车；无 `pageData` 时入口先调派生器。`open` 未传时返回 `opened:false`，原因「未自动打开: 缺宿主浏览器能力」。
- 侧车四键固定为 `schema`、`generated_at`、`source_fingerprint`、`nodes`；`nodes[]` 只有 `stable_id` 与 `content_digest`。派生路径可增加 `kind:<kind>` 节点，但不加字段。
- 模板 `DATA.kinds` 的 15 类与 `ANCHOR` 十环映射是输入，不改名、不重排；环名与状态词表来自 `runtime/task/final-chain.mjs`。
- 真实 diff 与十环报告都可从既有入口取得：diff 用 `git diff --name-only -z <baseline_commit>..HEAD`，报告用 `node tools/cli/run-checks.mjs --task-path <任务根>` 的 stdout。

### T006 — 自动生成 15 类节点与十环

- **来源 / FR / AC**：`U-015`、`F6`、`PFACT-006`；`FR-COCK-002`；`AC-COCK-002`。数据必须从当前材料、task facts、真实 diff、测试与审查原件自动生成 15 类节点与主链十环，缺的标「缺」不编造；页面只写调用者指定目录。
- **文件 / 符号**：`skills/answer-as-page/scripts/build-page-data.mjs` 的符号：`buildPageData`、`KIND_SOURCES`、`main`；`skills/answer-as-page/scripts/render-answer-page.mjs` 的符号：`renderAnswerPage`、`buildNodesSidecar`；`skills/answer-as-page/templates/overview-template.html` 的符号：`DATA` 的 `kinds`、`ANCHOR`、`GAP`；`skills/answer-as-page/SKILL.md` 的符号：驾驶舱取数与 15 类指针表；`skills/answer-as-page/skill-bundle.json` 的符号：`files[]`；`docs/architecture/move-map.json` 的符号：`entries[]`；`tests/contract/answer-as-page-skill.test.mjs` 的符号：bundle 可搬运断言；`tests/contract/cockpit-autogen.test.mjs` 的符号：`ORACLE-COCKPIT-GEN` 用例。
- **动作**：1）新增只读派生器 `buildPageData`，输入只有任务根与真实报告，输出 `pageData`、来源指针、缺口与摘要，不接收 caller 手写数据。2）按 15 类各建至少一个节点，节点只放短标题、结论与来源指针，正文留在材料；每类的 `src` 按下方来源表取，不从模板示例抄。3）十环直接抄 `run-checks` 报告的 `rings[]`；环名与状态值不改写，缺环交给模板显示缺口。4）数据缺失时生成状态为「缺」的节点并写清缺的是哪份原件；尚未发生的写「尚未产生＋到时会填什么」。5）`renderAnswerPage` 在无 `pageData` 时调用派生器，核心校验逻辑保持不变；命令行不再强制 `--data`。6）派生路径的侧车 `source_fingerprint` 记录报告与材料摘要，`nodes[]` 追加 `kind:<kind>` 摘要，结构仍为四键。7）模板只补缺口文案，不改 `DATA.kinds`、`ANCHOR`、`lanes` 与组件。8）在 bundle 与 move-map 登记派生器，更新 SKILL 的可执行命令。9）用不给 pageData 也能生成、同一夹具改材料两次、删审查原件三种负例证明不是手拼。
