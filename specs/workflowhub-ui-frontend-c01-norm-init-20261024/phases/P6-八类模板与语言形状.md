# Phase P6 — 八类规范各有一份能直接照抄的模板

读者：本 Phase 实施者、独立审查者与后续项目的规范作者。
读完要能：按类拿到一份含固定节序、必填项、填写指引与反例的模板，并知道它来自哪条标准形状。

> 三问：①一个结果——八份模板可被另一个项目直接照抄；②判定者——独立读者拿任意一份换项目名实写一页；③可独立提交——本 Phase 写完即可验收，不等验收对象。

## L0 — 结果与变更

用户要求每类规范都有可复用的模板、结构、写法与反例，并吸收简明语言标准（R-013、R-014）。前一轮只把标准写成散文规则，实测传播为 0（ADR-055 的教训）；本轮按 U-017 选八份独立模板，按 U-018 不写死字数，把标准落成"形状"。

- **结果**: 八份模板，各含固定节序、必填项、填写指引与反例列；职责表指模板目录。
- **非目标**: 不写散文规则、不做字数检查、不强制八文件。
- **与其它 Phase 的区别**: 本 Phase 只交模板与指针；九份正文归 P5。

- **来源 / FR / AC**: `R-013`／`U-017`（用户 2026-10-24 追加消息；decision-log WP5）——"八类规范各一份独立模板，含固定节序、必填项、填写指引、反例"；FR-NORM-006；AC-C01-1。
- **输入**: `skills/ui-project-init/SKILL.md:12-23` 的八类默认路径；九份正文现状。执行 owner 为本 Phase 实施者。
- **文件 / 符号**: `skills/ui-project-init/templates/domain-semantics.md`、`skills/ui-project-init/templates/visual-design-system.md`、`skills/ui-project-init/templates/components.md`、`skills/ui-project-init/templates/layouts.md`、`skills/ui-project-init/templates/interaction.md`、`skills/ui-project-init/templates/frontend-engineering.md`、`skills/ui-project-init/templates/craft.md`、`skills/ui-project-init/templates/quality.md`；符号：N/A — 纯文档模板。
- **动作**: ①每份写契约头（类名、默认路径、真实源、owner、consumer）、固定节序、必填项表、填写指引、反例列；②模板的「负责正文／真实来源／消费边界」三段结构与阶段分责取自仓内副本 `skills/external/spec-driven-production/references/design-spec.md` 与 `skills/external/material-agent-readiness-eval-markdown/SKILL.md` 的 GUIDE/AUDIT，并在模板首节写明来源，使 C01-F4 的"实际采用"可回读；③统一"照抄形状、勿照抄文字"的首行声明；④类专属节与其它七份不重复；⑤不写 PB 专有值，用占位字段与获取指引。
- **输出 / 失败**: 八份可照抄；失败信号是缺节、含 PB 值、或同类写法冲突。
- **边界 / 禁止改动**: 不改九份正文、不改职责表（T016 写）。

- **RED 目标失败**: ORACLE-P6-TEMPLATE；八份模板的节序与必填项可复放核对的断言（非新目标 RED）。
- **RED 证据**: N/A — 理由：纯文档流程无新增运行行为；风险为作者误把九份现有骨架当成模板已具备；客观替代为逐份读取与独立文档审查，八份可复放核对。
