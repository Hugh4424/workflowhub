**是否违反「母 PRD 只读」边界**
- **完全不违反**。这是唯一与母 PRD 卡边界零摩擦的方案。

### 9.2 「修改 CARD-07 卡面」是否是必需动作？

分两种情形：

**(a) 对已有 FR-33..FR-38 / AC-33..AC-38 覆盖的 8 类能力 → 不是必需动作。**
母 PRD 已经把这些要求写全了。遗漏之所以发生，是因为**时序**：CARD-02 属 Group 0（母 PRD L124，先开工），CARD-07 属 Group 1（L125，未开工）。也就是说，**card-02 在 CARD-07 的保真机制尚未就位时执行了自己的 make-decision**，于是重演了机制诊断 #1/#3/#4/#6 的病灶。这不是 CARD-07 卡面缺内容，而是**卡面内容尚未生效**。

**(b) 对「覆盖核对须校验强度」（诊断 #6）→ 是必需动作。**
理由（可验证的因果链）：
1. 该要求**无 FR/AC 锚点**（SD-09 L62 无、FR/AC L431-443 无），只出现在来源行（L450 引「机制诊断 L798-807」）与 OI-010 的 `source` 字段（L381，泛指「U-001 第1/2/4点的原缺口」）。
2. CARD-07 的 **oracle（L444）** 只列四项：发散产物存在、全文到达、双层保真+三档可查、无固定轮次锁、追加发散按未知问题触发 —— **不含强度校验**。
3. CARD-10 的核对口径（母 PRD L513）是「各卡 AC 验收事实作为**输入引用**（存在性核对）」，即 **只核对 AC**。无 AC 锚点的要求**不在 CARD-10 的核对范围内**。
4. 结论：若不在 CARD-07 卡面（FR 或 AC）加锚点，「强度校验」在**任何卡的验收中都不可见** —— 正是它的病灶（诊断 #6 后果栏：「弱化在检查里不可见」）以新形式复现。

### 9.3 「母 PRD final + 不得回写」与「彻底解决」之间是否存在不可调和冲突？

**判定：不存在不可调和的冲突。** 三条依据：

1. **「只读」的对象是实施 task，不是母 PRD 权威自身。**
   全部 5 处「母/兄弟材料只读」措辞均出自**各卡的五阶段开工说明**（母 PRD L262 / L291 / L423 / L454 / L535），主语都是「以本卡创建的独立实施 task」。L646「本 PRD(prd.md)与 decision-log.md(只读)可用」是**交付说明中给后续 task 的可用性声明**。没有任何一处说「母 PRD 权威不可修改」。

2. **母 PRD 自带合法修改通道（L652-659）。**
   - L656：**小修**（窄范围的 typo、链接、**澄清**）→ 保留依据与影响于变更说明节即可，**无需重新确认**。
   - L657：**实质变化**（方向、权限、范围、设计行为、**验收**）→ 先展示前后承诺 + 获得真实确认 + 记录来源 revision、受影响条款/卡片与在途影响。
   - L658 锁的是「**历史**决定、确认、审查、测试与物理事实」，不锁当前 PRD 正文。
   - L659：「**既有在途任务保留自己的材料,不自动覆盖**」—— 明确 card-02 不会因母 PRD 变更而报废。
   母 PRD 自己的历史就是这样演进的：变更说明里已有两条条目（L663-667 加固修订、L669-673 第二轮），且第二轮明确写了「decision-log 本体 append-only 未改」「Status 不变」「在途影响：无」。

3. **最彻底的修复不需要动母 PRD。**
   8/9 类能力已在 FR/AC 内 → 只需 CARD-07 执行（母 PRD 已有的「五阶段开工说明」L454 就是它的执行授权）。第 9 类（强度校验）可沿 **card-02 已有用户裁决先例 T-003（L534-539）** 处置：用户已在「母 PRD 边界冲突」这一完全相同的问题上选择了「**不回写母 PRD，在本卡显式登记承接关系**，由 CARD-10 集成验收时核对」。把同一处置套用到 CARD-07 即可。

### 9.4 唯一真正的摩擦点（不是不可调和，但必须显式处理）

**摩擦点**：T-003 的处置路径（登记型）在 card-02 上有效，是因为 card-02 的 AC 会把承接事实带进 CARD-10 的存在性核对。但「强度校验」没有 FR/AC 锚点，**登记型路径会漏过 CARD-10 的核对**（§9.2 因果链第 3 步）。因此：

- **对 O1（decision-log 结构双归属）**：走澄清型小修即可（L656），冲突可完全消除。
- **对 W-1（强度校验）**：登记型路径可让 CARD-07 执行它，但**无法让它进入 CARD-10 的存在性核对**，除非在母 PRD 内加锚点。这是**唯一的「彻底」与「final 只读」之间的形式化缺口** —— 是**局部、单条、可枚举**的，不是不可调和冲突。

## 10. 结论摘要

1. **CARD-07 的能力是 9 类**（C1–C9），其中 8 类已有完整 FR/AC 锚点（FR-33..FR-38 / AC-33..AC-38，母 PRD L431-443），**第 9 类「覆盖核对须校验强度」（机制诊断 #6，L884）无任何 FR/AC/SD 锚点**。
2. **重叠面 8 条**（O1–O8），其中 **O1（decision-log 结构双归属）** —— 母 PRD L21/L175 判给 CARD-07，card-02 U-001 E-1 并入 CARD-02 —— 是**两份权威文件的书面不一致**，不是措辞问题。
3. **遗漏的真实成因不是 CARD-07 卡面缺内容，而是时序**：CARD-02 属 Group 0 先开工，CARD-07 的保真机制（FR-35）尚未生效，于是 card-02 的 make-decision 重演了诊断 #1/#3/#4/#6 的病灶。
4. **母 PRD 是否需要修改**：对 8/9 类**不需要**（只需 CARD-07 执行）；对「强度校验」**需要**（否则它在任何卡的验收中永久不可见）；对 O1 归属冲突**需要一次澄清**。
5. **是否存在不可调和冲突**：**不存在**。母 PRD L652-659 自带小修/实质变化通道，L659 明确在途任务不被覆盖；「母 PRD 只读」是实施 task 纪律，不是权威自身的禁令。
6. **唯一摩擦点**：登记型路径（T-003 先例）让 CARD-07 能执行强度校验，但无法让它进入 CARD-10 的「AC 验收事实存在性核对」（L513），除非在母 PRD 内加锚点。这是局部、单条、可枚举的缺口，六条出路见 §9.5。
