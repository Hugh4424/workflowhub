本段给唯一文档writer、未参与写作的独立读者和最终安装验证者。

## 哪些节必须写，哪些可以省？

本文件written的结果、验收、依据、读源、写主、验证、任务卡和机器字段承载本段增量。

## 这一 Phase 交出什么？

陌生维护者只凭README完成接入并说出下一步和缺项恢复。

- **本 Phase 结果**：一份README交代拿到文件夹、宿主放置、配置、外部引导、更新卸载与排障。
- **非目标**：教程/首任务走查/插件市场按原决定不做；不承诺自动代装外部工具。
- **改动前**：此前README没有当前接入/配置/版本闭环；本段必须使用P4已交真实命令。
- **改动后**：下一读者不需作者补路径或猜provider，未验证命令和能力限制能辨认。
- **与相邻 Phase 的边界**：只写README，P2/P4接口和发布方法不改，P6只重建最终字节。
- **主要风险**：冷读者已受提示；返工时保原答作定位，最终判定用未受提示者。
- **下一步**：P6按成稿从最终包加载。
- **动手前必读**：README现字节、P2命令/配置原件、P4完整包与矩阵、历史D-015至018。
- **未决事实**：独立读者与真实宿主当时可用性由执行owner核，缺失不假装冷读完成。

非UI：读取Markdown和CLI，不观察浏览器页面。

1. 验收标准：唯一判据在Appendix A验收4。
2. 场景：首次冷读成功；缺包/错路径/坏配置；外部项缺来源；未验证命令提示；删链及更新后位置。
3. 环境与数据：P4固定包和独立目标；读者未参与文稿，原始五问/命令输出由capture保存。
4. 用例：下文具名锚点检查与独立逐步冷读；缺任一输入时说清owner和恢复，不把停住当通过。
5. 谁判与承接：独立读者终读；受过修复提示者只定位问题，不自称首次读者；P6消费成稿。
6. 失败回修与重验：读者需要作者补提示、命令和原件不符、外部安装来源缺失或环境不可达时，保原答；文案回P5，接口回P2/P4，环境回真实提供者；

