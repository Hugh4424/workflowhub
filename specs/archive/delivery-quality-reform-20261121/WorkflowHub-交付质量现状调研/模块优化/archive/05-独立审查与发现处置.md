# 模块 05｜独立审查与发现处置

> 覆盖原则：P21–P23（见 `00-原则总纲.md`）
> 状态：改造候选，待逐包收敛。
> 主责边界：本模块**主责**「三类判断、四态、三职责、审查力度、发现闭环」；证据格式归 04，收口声明归 07。

## 1. 任务目标

让「审查过」变成可核的事实：谁审的、有没有独立上下文、读了什么、能判断什么、发现了什么、每条发现最后去了哪。

**做完后要同时看到这些现象（每条都有观察者）**：

1. 每份审查记录都能标出四态之一：不可用 / 无法判断 / 没有发现 / 通过；混写即失败。观察者：收口者。
2. 记录里写明读了什么、能判断什么、没读到什么；缺覆盖不能用空发现列表签通过。观察者：最终验收者。
3. 低风险 + 自称独立 + 无派发身份的记录被运行时拒绝；缺分级事实的记录写入但标 `tier: unavailable`，不阻断。观察者：审查派发者。
4. 高风险（第 4、5 层可逆性）改动落到独立或外部审查；降级必须被拒或有具名理由。观察者：派发者。
5. 收口时发现 id 并集减去处置 id 为 0，或每条差值有具名接受/未完成。观察者：收口脚本。
6. 回放 T05 的 108 条发现，必须报出 61 条未处置；报 0 条即失败。观察者：收口者。
7. 审查结论与验收结论不脱钩：审查停在「需修改」时，验收不能判通过。观察者：最终验收者。
8. 能修的缺陷直接回原实施者，不退给用户分拣；严重风险由人明确承担。观察者：用户。
9. provider 全失败时，结论是「不可用」并带失败原件，不是空发现的通过。观察者：派发者。
10. 报告作者、独立裁决者、关闭执行者是三个可指认的身份，不是同一个人。观察者：独立审查者。

## 2. 范围与不做什么

**做**：四态；三类判断；三职责；独立性的运行时核对；发现集合差；审查力度按可逆性五层；provider 不可用口径；审查与验收不脱钩。
**不做**：不删终末独立审查，也不加第四层审查；不改三审查点的数量与位置；不要求审查回答「事实是否成立」；不新增第五态。

## 5. 方向与取舍

- **候选 A（先集合差，再分级接线）**：先拿低成本回放抓 61/108，再动运行时。代价：分两步。

## 7. 验收标准（带反例）

1. **四态可分**：抽三份审查记录，每份能标出四态之一；标不出或混写即失败。
2. **覆盖可读**：每份记录写明读了什么、能判断什么、没读到什么；缺即失败。
3. **集合差为零**：回放 T05 原件。方向审查实测原件是 **20 份 JSON / 250 findings / 0 disposition**，不是报告里的 108/61；以原件为准，检查器必须报出 250 条未处置。原件在 `/Users/Hugh/Hugh/Knowledge/Projects/PaperBuilder/tasks/strategy-iteration-t05-metrics-20261118/quality/reviews/`（只读；取不到记「不可比」）。**集合差只作一次性只读审计，不复活退役控制面；要复活需新 ADR。**
4. **独立性可核**：声称独立审查的记录必须能指出执行者身份与上下文隔离来源；指不出即失败。
5. **力度匹配**：按运行时五个风险面判；共享状态并发、公共契约关键路径、数据迁移不可逆、权限安全、真实外部依赖至少一个为 present 时，必须有独立或外部审查；provider 不可用时记 unavailable，修复继续。
6. **不脱钩**：审查停在「需修改」时，验收不能判通过。
7. **三职责与可修缺陷**：报告作者/独立裁决/关闭执行三个身份可指认；可修缺陷的派发记录里没有「退回用户」。
8. **反例**：删掉一条发现处置但仍记通过，验收 3 必须报出；把同源审查写成独立，验收 4 必须报出（接线后）；把可修缺陷退回用户，验收 7 必须显示违规。

## 8. 风险与未知

- 分级接线影响所有审查记录写入；历史记录无分级事实会触发异常，必须先写「不可用放行」分支与测试。
- provider 不可用是常态，四态里的「不可用」必须有稳定口径，不能变成「没审也算过」。
- 集合差的 id 稳定性未核：历史发现 id 是否跨轮唯一、处置记录用什么字段承载，需要实测。
- 三职责分离可能只是记录字段；不改变实际权力时，仍是自判。
