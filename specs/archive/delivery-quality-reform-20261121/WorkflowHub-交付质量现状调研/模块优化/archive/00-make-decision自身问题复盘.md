# make-decision 自身问题复盘：为什么会走偏，违反了哪条原则，该归哪个包

- 用途：用我们自己定的 38 条原则，复盘这次规划过程中真实发生的问题。原则如果连自己的过程都诊断不了，就不配拿去改工作流。
- 证据：本次会话的真实操作与用户反馈；引用用户原话；不编未发生的事。
- 读法：先看「问题清单」，再看「根因归纳」和「该归哪个包」。每条都给改法，不做情绪检讨。

## 一、问题清单

### 问题 1｜方向审查审成了文档校对

- **现象**：方向审查的输出是「T05 是 250 还是 108」「T08 三种结果在原件里找不到」「写集验收要变更请求号」这类文件级问题；没有回答「这套改造能不能解决最初的七个问题」「哪个模块是必要的」「有没有更小的路」。用户原话：`你的所有问题、审查的所有结果，对整个workflowhub改造方案几乎没有任何帮助，全是文件写的对不对之类的细节问题！整个方向审查完全无效！`
- **根本原因**：审查问题设计只问「验收能不能跑」，没问「这条改造改变哪个用户可见结果」；审查输入里没有「原始需求 → 机制 → 可观察指标」的追溯表，审查者只能沿着材料本身找错。
- **违反原则**：P1（只问会改变行为的问题）、P4（方向收敛的判据是下游能开工，不是字段齐）、P21（三类判断分开，方向审要回答方向）、P38（原则自身可证伪）。
- **该归哪个包**：包 05（审查问题设计与四态）+ 包 00（溯源矩阵：需求→原则→模块→指标）。
- **改法**：方向审查的第一段固定为「R1–R9 逐条追溯 + 因果链 + 替代方向」，文件级问题降为附录；没有追溯表就不派方向审查。

### 问题 2｜模块文件被另一个来源整体重写，14:19 改写、14:44 才发现

- **现象**：`模块优化/01`–`08` 在我写完后被另一来源改成问答式结构；我发现时模块 01 已经是混合体。
- **根本原因**：共享目录没有唯一写主，也没有写前读、锁或独占；我默认「只有我在写」。多个 writer 同时改同一批文件，谁都不知道对方存在。
- **违反原则**：P27（耦合工作只有一个写主，并行只在资源真独立时成立）、P14（先给合法入口，再限制旧写法）、P24（派发只给指针与结论）。
- **该归哪个包**：包 06（派发、共享资源与唯一写主）+ 包 08（机制登记：谁写、谁读、何时删）。
- **改法**：动 `模块优化/` 前先声明写主与写集；发现第二个 writer 时停手、问用户、再决定接管或合并；不覆盖别人正在写的文件。

### 问题 3｜原则里三处反例是错的，还当成硬证据用了

- **现象**：「失效清单没有消费者」——其实有解析与报错；「契约五问、实际四问」——两边都是四问；「1987 行直连存储」——来自另一个项目，本仓不可核。
- **根本原因**：二手转述当一手用；合并三份原则设计时没有回原文核；没有给证据标「一手/二手/外部类比」。
- **违反原则**：P17（证据只支持它实际看到的对象、版本、范围）、P23（证据只看实际）、P36（知识消费：读到的结论要改变什么）、P34（一条规则一个权威）。
- **该归哪个包**：包 04（证据绑定）+ 包 08（知识消费与来源分级）。
- **改法**：原则与模块里的每条关键反例标来源等级；二手证据不得单独支撑一条原则；外部项目案例只能写「类比」，不能写「本仓证据」。

### 问题 4｜第一版模块漏了 12 类整改项，还有 7 组重复认领

- **现象**：规划子代理存在条件、深模块检验、唯一写主、持久状态恢复、知识消费、观察时点、并发边界等没有家；证据绑定被四个模块同时认领。
- **根本原因**：先写模块、后做覆盖审查；没有「症状 → 原则 → 模块」的溯源矩阵，也没有主责边界。
- **违反原则**：P4（下游能开工）、P7（依赖写成可追的供件）、P38（原则自身可证伪：漏项信号）。
- **该归哪个包**：包 00（溯源矩阵）+ 包 08（原则证伪与覆盖核对）。
- **改法**：模块定稿前先做一次「13 份报告症状 → 原则 → 模块」的回填，找不到落点的即漏项；每个模块写死主责边界，防重复认领。

### 问题 5｜「新技能 0 个」第一版依据不足

- **现象**：第一版说全部落在 7 个现有技能的一节，实际有 4 处塞错节、5 处根本没有节；用户质疑「你是否真的仔细检查了外部调研」。
- **根本原因**：用「有这个技能」代替「这一节真的接得住」；没有逐条做「复用/扩展/新技能/不采用」四选一。
- **违反原则**：P35（控制面要有真实消费者与删除条件）、P36（知识消费）、P33（规则落点按真实成本收益选）。
- **该归哪个包**：包 08（落点与知识消费）+ 包 03/05（具体落点）。
- **改法**：外部机制逐条四选一，写清节选与产物是否匹配；「新技能 0 个」必须附逐条依据与两张否决卡，不能只给结论。

### 问题 6｜验收锚点先写后核，三处对不上原件

- **现象**：T08「三种结果」原件里没有；T05 报告 108/61、原件 250/0；T13 报告 71 条、实测 12 unverified/0 missing。
- **根本原因**：把任务报告的转述当原件；验收写完后没有先跑一次或先打开原件核。
- **违反原则**：P8（判据冻结前实跑坏例）、P17（证据绑定）、P23（证据只看实际）。
- **该归哪个包**：包 04（证据与观察）+ 包 01（答复原件形态）。
- **改法**：任何以历史材料为输入的验收，先写「原件路径 + 实际读数」，再写期望；读数与报告不一致时以原件为准，差值本身就是 finding。

### 问题 7｜方向审查拿复杂路线的期待审规划路线

- **现象**：审查报「计划没有落成 spec/phases/AC id/写集」，但本任务走的是规划路线，按合同不产这些材料。
- **根本原因**：审查输入没有带「级别与路线」；审查者没有先读路线事实，就按复杂路线判。
- **违反原则**：P4（下游能开工）、P21（三类判断）、P24（派发要给对的指针）。
- **该归哪个包**：包 01（级别与路线的消费）+ 包 05（审查输入合同）。
- **改法**：方向审查包必带「级别与路线」原 ref；审查者先读路线，再判材料形态；规划路线不按复杂路线的材料清单扣分。

### 问题 8｜反复拿文件级问题问用户

- **现象**：T05 计数、试点用哪个任务、T08 锚点怎么改——这些是代理能查或能定的事实，却拿去问用户；用户回「你到底在审查些什么东西」。
- **根本原因**：没有区分「用户该定的方向」与「代理能查的事实」；把验收可执行性当成方向问题。
- **违反原则**：P1（只问会改变用户行为的问题，事实归代理查）、P4、P24（派发与回传）。
- **该归哪个包**：包 01（问什么）+ 包 06（分诊与停机）。
- **改法**：提问前先分四类——仓库能答 / 只有用户能定 / 跑一下才能分 / 外部供件；仓库能答的自己查，跑一下能分的先跑，只有方向、范围、验收、风险才问用户。

### 问题 9｜原则编号反复重排（29 → 33 → 38），模块头跟着改

- **现象**：每次补原则就重编号，模块的「覆盖原则」范围跟着改；旧引用失效。
- **根本原因**：没有稳定 ID 与变更记录；把「编号连续」看得比「引用稳定」重要。
- **违反原则**：P2（承诺与失效清单）、P34（一条规则一个权威）、P23（发现闭环）。
- **该归哪个包**：包 01（承诺与失效）+ 包 08（权威与编号规则）。
- **改法**：原则用稳定 ID（P1..Pn 只追加不重排）；新增用 Pn+1，废弃标「已废，由 Px 接」；模块只引 ID，不引序号区间。

### 问题 10｜等待用重复轮询，主会话空转

- **现象**：同一参数的 `wait_agent` 反复调用，被系统提示「你在重复同一个调用」。
- **根本原因**：没有用事件通知；把等待当成需要主动轮询的事。
- **违反原则**：P24（等待用事件，不轮询）。
- **该归哪个包**：包 06（等待与派发）。
- **改法**：子代理完成会自动通知；等待期间做独立工作，不重复同参数轮询。

### 问题 11｜决定权威与展示件双轨，没写清谁是权威

- **现象**：决定写在 worktree 的 `decision-log.md`，用户看的模块文件在 Downloads；两边都像「正式材料」，没有一句话说清谁是权威。
- **根本原因**：展示件与决定材料没有单一权威声明；交接也没有把两者关系写清。
- **违反原则**：P34（一条规则一个权威）、P7（供件）、P31（交接是指针）。
- **该归哪个包**：包 07（交付与交接）+ 包 08（权威）。
- **改法**：在 decision-log 与模块文件头部各写一句「决定以 decision-log 为准，模块文件是展示件」；交接只引 decision-log 的原件与模块文件的路径，不复制结论。

### 问题 12｜范围一路漂移，没有中途重判

- **现象**：从「分析问题」扩到「原则 + 8 模块 + 逐包收敛 + 多轮审计 + 战略评审」，每次都是用户追加要求后直接做，没有一次明确的范围变更记录与代价说明。
- **根本原因**：没有把追加要求转成范围变更；没有对照「新增范围会不会改变交付时间与验收」。
- **违反原则**：P2（承诺与失效）、P9（规划稿只在有跨任务取舍时存在）、P38（试点与准入）。
- **该归哪个包**：包 01（范围与承诺）+ 包 08（改造自验）。
- **改法**：每次用户追加要求，先写「新增什么、影响哪个包、多花多少、原承诺是否失效」，再执行；不把追加当默认。

### 问题 13｜引入用户完全不认得的外部概念

- **现象**：模块 01 出现「双原型」「同时做两个原型让用户挑」，用户回 `我怎么完全没有印象？你直接问我这种东西，我完全不知道怎么回答`。
- **根本原因**：从原则设计和《分析汇总》里搬运概念，没有先问「这是不是现有流程的一部分、用户认不认得、解决哪个真实问题」；把外部建议当成了本仓做法。
- **违反原则**：P1（用户可见语言不出现未解释术语）、P36（知识消费要落到具体改变）、P38（准入判据：先还原成一次实际决定）。
- **该归哪个包**：包 01（问什么与写什么）+ 包 08（知识消费与准入）。
- **改法**：从模块 01 删除；外部做法先说明来源、问题、现状，用户不认可就不进方案；「用户不认得」本身就是不采纳的理由。

## 二、根因归纳

0. **把外部概念当成本仓做法**（问题 13）。用户不认得的概念被写进方案，说明「知识消费」没有落到「解决哪个真实问题」。
1. **审查问题设计围绕「文档正确」，不围绕「结果改变」**（问题 1、7、8）。这是最贵的根因：审查越认真，越容易在错误的层面上认真。
2. **二手证据当一手用，不回原件**（问题 3、6）。报告的转述、原则设计的转述、外部项目的案例，都被当成了本仓事实。
3. **没有溯源矩阵与主责边界**（问题 4、5）。模块先写、覆盖后补，必然漏项和抢位。
4. **共享写主与并发控制缺失**（问题 2）。多 writer 同改一个目录，发现时已经混合。
5. **验收先写后跑**（问题 6、7）。验收不是从原件长出来的，是从报告叙述长出来的。
6. **编号与权威不稳定**（问题 9、11）。重编号、双轨材料，让引用和历史失效。
7. **提问与等待的纪律**（问题 8、10）。该自己查的问了用户，该等事件的在轮询。
8. **范围变更没有重判**（问题 12）。追加要求直接做，没有代价与失效说明。

## 三、对原则的修订（这次复盘倒逼出来的）

- **P1 补一句**：提问前先分四类；仓库能答的自己查，跑一下能分的先跑，只有方向、范围、验收、风险才问用户。
- **P8 补一句**：以历史材料为输入的验收，先写原件路径与实际读数，再写期望；读数与报告不一致时以原件为准。
- **P21 补一句**：方向审查必须先答「原始需求逐条追溯 + 机制因果链 + 替代方向」，文件级问题只作附录；没有追溯表不派方向审查。
- **P27 补一句**：动共享目录前声明写主与写集；发现第二个 writer 时停手、问用户，不覆盖。
- **P34 补一句**：原则与规则用稳定 ID，只追加不重排；新增用新号，废弃标「由谁接」。
- **P36 补一句**：二手转述不得单独支撑一条原则；外部案例只能写「类比」，不能写「本仓证据」。
- **P38 补一句**：每次用户追加要求，先写「新增什么、影响哪个包、多花多少、原承诺是否失效」，再执行。

## 四、对模块的修订（归包结论）

| 包 | 要补什么 |
| --- | --- |
| 00 原则总纲 | 溯源矩阵升级为「原始需求 R1–R9 → 原则 → 模块 → 可观察指标」；原则改稳定 ID |
| 01 定方向 | 提问四分类；范围变更记录；答复原件；稳定 ID 的承诺引用 |
| 02 定计划 | 验收先写原件与实际读数，再写期望（与 04 共用） |
| 03 实施 | 共享目录写主声明（与 06 共用） |
| 04 验收与证据 | 历史材料先跑一次再写验收；来源分级；读数不一致即 finding |
| 05 审查 | 方向审查固定「需求追溯 + 因果链 + 替代方向」三段；文件级问题降附录；审查包必带级别与路线 |
| 06 路由成本停机 | 共享资源与唯一写主；等待用事件；提问四分类的分诊 |
| 07 交接 | 决定权威与展示件的关系；交接只引原件 |
| 08 规范自身 | 稳定 ID；来源分级；改造前写范围变更与失效；覆盖核对 |

## 五、这次复盘能证明什么、不能证明什么

- 能证明：38 条原则能诊断我们自己刚发生的过程问题；问题不是「执行者不努力」，而是「审查问题设计、证据来源、写主、提问纪律」这几处结构没落。
- 不能证明：补了这些细则之后，真实任务的交付质量一定会变好。那要等模块 01/02/04 的试点，用同一批历史坏例回放，看同类问题是否更早被拦住。
- 下一步：先按这份复盘修原则与模块，再做战略方向评审的结论整合；不在文件细节上继续打转。
