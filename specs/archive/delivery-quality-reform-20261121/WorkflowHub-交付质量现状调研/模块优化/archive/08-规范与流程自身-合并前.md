# 模块 08｜规范与流程自身：防止「设计很久、最后没效果」

> 覆盖原则：P33–P38（见 `00-原则总纲.md`）
> 状态：**先行收敛**。其他包等这个模块的基础方案定稿后再收敛。
> 主责边界：本模块**主责**「功能生效台账、最后一公里规则、接线与退役、复杂度只观察」；其他模块只按这套规则执行。

## 1. 任务目标

防止「设计很清楚、开发很久、最后没效果」再次发生。每个质量功能都要能证明三件事：真的被触发、产出真的被读、同一个坏例在改造前后结论不同。做不到，就接线或删除，不算完成。

**做完后要看到这些现象（每条都有观察者）**：

1. 每个质量功能有一张台账，三行齐全：触发（命令/参数/原件）、读者（谁读/回执）、可观察差别（同一坏例前后结论）。观察者：维护者与独立审查者。
2. 第 9 步「已收敛」必须绑定逐包卡、冷读、讨论原件、包级答复；缺一即失败，缺指针也失败。观察者：收口者。
3. 方案卡和三角色回传有真实下游：build-plan 第 1 步或细节审逐包读，并与日志每包十项对账；没有下游就删卡。观察者：build-plan 作者。
4. 一条规则只下发一个权威版本：第⑤问进 `steps.json` 与 provider prompt，不再「正文五问、prompt 四问」。观察者：方向审查者。
5. 缺指针/缺证据时退出码非零，不再「报告 unavailable 但 exit 0」。观察者：任何跑检查的人。
6. 十格卡/五问与十一格卡/六问九问二选一，不能两套并存、默认弱的那套。观察者：维护者。
7. 整体确认不能顶替逐包证据：一次「全部确认」不能让多行变已收敛。观察者：收口者。
8. 每个 required 技能有可归因的产出（哪只镜头产了哪条发现）；没有字段就加字段，没有产出就退役。观察者：审查记录读者。

## 2. 范围与不做什么

**做**：
- 功能生效台账：17 个质量功能逐行三行记录。
- 最后一公里规则：八条，写进现有阶段与检查器。
- 第 9 步完成证据与退出码修正。
- 方案卡/三角色回传的下游消费者。
- 第⑤问进 `steps.json` 与 prompt。
- 两套设计二选一。
- 无消费者功能的退役。

**不做**：
- 不新增合同、不新增阶段、不新增审查轮次、不新增扫描器。
- 不设复杂度上限；只记录阶段/步骤/技能/检查器数量，供判断。
- 不要求 agent「更仔细」「加强审查」。
- 不动宪法、七类公共命令、三审查点。

## 3. 调查结论（为什么设计很久却没效果）

### 3.1 断点不在设计，也不在实现

- **触发段**：第 9 步的完成证据只有「日志节 + talk 目录」，不含卡/冷读/清单；轻档三套只要清单；缺清单指针实测 exit 0（requirements-design 任务 `source=null`、`gaps=["收敛清单指针未取得"]`、exit 0）。
- **消费者段**：卡/冷读/三角色回传 0 下游——build-plan 第 1 步与 build-code 对 checklist/index/coverage 引用均为 0；检查器只核卡 sha、五问齐、8 字段非空；细节审只读日志十项与 `proposal_projection`；第⑤问不在 provider prompt。
- **产出退化**：52 个包行中 34 行精确「已收敛」、51/52 以某种写法声称收敛；真正走完三角色的只有 1 个包；有一个任务 9/10 包无卡无冷读，依据是一次「全部确认」转录。

### 3.2 任务库计数（240 个任务）

- 规范的收敛清单 6 个（2.5%），任意清单 8 个。
- 有方案卡的任务 3 个（共 13 张卡）。
- 有冷读的任务 7 个（107 份）。
- 真正走完三角色的 1 个任务 / 1 个包。
- 52 个包行：34 行精确「已收敛」，18 行未收敛；execution-quality 任务 9/10 包卡与冷读「未取得」。

### 3.3 五个通用模式

1. **规则多副本，执行只用一份**：第⑤问在 SKILL/契约是五问，`steps.json` 与真实 prompt 是四问，从未问过。
2. **机检只判形状**：8 字段可用「决定 N」/AC 编号填满；冷读只数①②③④⑤；卡只比 sha。
3. **产出无下游**：decision-maker 只在 catalog 与一个测试里出现；`proposal_projection` 无代码校验。
4. **整体确认/自证闭环顶替逐项证据**：U-021 一次确认让 10 行全标已收敛；状态列自填；「只报告不阻断」使其永不变红。
5. **时序错位**：就绪表定义晚于使用（0/10 卡）、grill 排在收敛后（2/240）、审查落盘缺失。

## 4. 模块 08 要记录的三样（功能生效台账）

每个质量功能一行，三行缺一不可：

| 列 | 写什么 | 缺了怎么记 |
| --- | --- | --- |
| 触发 | 哪条命令/哪个参数/在哪个步骤；真实触发了吗；原件 ref | 没触发 → 记「未触发」，不得写成通过 |
| 读者 | 谁读这个产出；读的回执/引用 ref | 没有回执 → 只能记「无消费者」 |
| 可观察差别 | 同一个坏例，改造前结论、改造后结论；本次是否出现 | 给不出 → 记「无效」 |

台账覆盖至少 17 个功能：逐包收敛卡、冷读、decision-maker 三角色、五段、写集对账、审查分级、发现处置、证据路径、AC 覆盖、成本账、execution_budget、交接、四类事实、方向审查五问、阶段入口检查、required 镜头、drift 门。

## 5. 最后一公里规则（八条）

1. **完成证据必须包含产出**：步骤的 `completion_evidence` 只列目录/日志不算完成；必须列卡、冷读、讨论原件、包级答复等真实产出。
2. **产出必须有具名消费者**：写清哪个阶段、哪一步、哪个角色读它；没有消费者的产出不许进完成条件。
3. **形状检查不算内容检查**：sha、字段非空、问数齐，只能证明「填了」，不能证明「填对」；内容必须由消费者读，不能只由检查器数。
4. **一条规则只下发一个权威版本**：正文、`steps.json`、prompt、检查器四处必须同版；不一致时以「实际下发的那份」为准，并立即对齐其余三处。
5. **缺指针/缺证据必须 exit 1**：不能「报告 unavailable 但 exit 0」；跳过要留痕，不能静默通过。
6. **整体确认不能顶替逐包证据**：一次「全部确认」只能证明用户确认了整体，不能证明每个包都有卡、冷读、讨论、答复。
7. **两套设计二选一**：十格卡/五问与十一格卡/六问九问不能并存；选一套，另一套删或归档，不能默认弱的那套。
8. **功能完成的四件**：触发 + 产出 + 被读 + 可观察差别；缺一件就是「已写但无效」，接线或删除。

## 7. 依赖与顺序

- **先行**：本模块先定，其他 7 包按它收敛。
- 顺序：第 9 步完成证据与 exit 1 → 卡/角色下游消费者 → 第⑤问同版 → 无消费者功能退役/接线 → required 镜头归因 → 两套设计二选一。
- 与 01–07 的关系：01–07 只提供「本包的功能要写哪三行」，不另立机制。

## 8. 验收标准（带反例）

1. **缺指针必失败**：拿 requirements-design 任务（`source=null`、`gaps=["收敛清单指针未取得"]`）回放，必须 exit 1；现在 exit 0 即失败。
2. **卡被下游读**：抽一个包，build-plan 第 1 步必须引用它的卡/冷读/包级答复；引用 0 次即失败。
3. **第⑤问真下发**：查 provider prompt，必须出现第⑤问；只有正文有即失败。
4. **整体确认不算逐包**：拿 execution-quality 任务回放，9/10 包无卡无冷读，不能因一次「全部确认」记已收敛；记了即失败。
5. **形状不等于内容**：拿一个用「决定 N」填满 8 字段的包，检查器不能只凭字段非空判已收敛；判了即失败。
6. **无消费者功能退役**：decision-maker、预算三字段、五段独立表、`--report` 逐项有退役或接线结论；没有即失败。
7. **镜头可归因**：抽三条审查发现，每条能说出哪只镜头产的；说不出即失败。
8. **反例**：故意删掉一个包的冷读但保留「已收敛」，验收 1 与 4 必须报出；故意把第⑤问从 prompt 删掉，验收 3 必须报出。

## 9. 风险与未知

- 第 9 步加严会让历史任务变红；只对新任务生效，旧任务只读。
- 卡/冷读的下游消费者需要 build-plan 改读法；如果 build-plan 不读，卡就该删，不能两边都留。
- required 镜头归因要改 schema；先确认历史记录兼容，不能回改旧记录。
- 两套设计二选一会丢一套历史；旧材料只读，新任务只用选中的那套。
- 本模块不设复杂度上限，只记录数量；如果只加不减的惯性还在，用「无消费者退役」和「功能完成四件」两条挡。

- 消费者：后续所有改造任务、维护者、审查者、收口者。
