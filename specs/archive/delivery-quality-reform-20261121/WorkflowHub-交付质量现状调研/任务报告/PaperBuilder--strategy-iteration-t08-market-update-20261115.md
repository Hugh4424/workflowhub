# strategy-iteration-t08-market-update-20261115（PaperBuilder）

## 最硬的七个发现

**结论：这次不是“做得糙”，是“证据系统自己不可信”。**
功能与真实数据成立，但决定、计划、代码、验收四层的证据互相打架，
而收口用最后一篇散文把冲突抹平。

1. **自动补数路径缺逐日门。**
   `market_update_weekly._build_weekly_stack` 构造 `SharedDataHubApplication` 时
   没有传 `month_sessions_reader`，只有 `serve_f6.py:8898` 传了。
   结果是 HTTP 路径会拦每日不合格的月，周更自动路径不会。
   而验收十签的正是“自动发起”的通过。
2. **决定层 42 条里，3 条从未被实现或测试消费，2 条只有报告，4 条被推翻仍生效。**
   规格钉死的 10 条证据路径只有 2 条真的存在。
3. **计划把真实检查整段让给最后一段。**
   首现在 P1 第 60 行，被 P2 至 P6 逐字复制；P7 装置落地后仍有 18 个修复提交。
4. **同一不变式最多十处实现。**
   就绪判定十处、0.95 四个来源、映射 hash 两套互斥算法、幂等键四份、deadline 五处丢。
5. **代码里 26 处静默失败、42 处退默认值、40 个公共函数无直接测试。**
   其中三处能让坏数据看起来可用（快照校验、损坏月片覆盖、周更组合漏门）。
6. **验收原件自己互相矛盾。**
   同一夜 `ac0809` 证 AC-008 通过、AC-009 浏览器真实 POST 成功；
   40 分钟后 gate7b 却是 AC-008 FAIL、AC-009 SKIP；
   收口材料又写“浏览器写面未跑”，而证据目录里截图与回执齐全——
   准确说：最终验收没重跑，先前独立环境已跑过，两份记录没有对齐。
7. **最终唯一门禁不是绿的。**
   gate7b 为 60 例、3 failed、5 skipped、exit≠0；
   收口引用的是另一个只有 `.out`、没有 junit 的 55 passed 版本。

## 第三层：验收变成交付，为什么未完成能签通过

**结论：档位是散文，证据是最后一篇写入，冲突靠人眼消。**

验收十的三条子条件——逐格三类记录、自动发起、任务九页面调度实际消费——
在收口时被压成“正式库只读腿通过”一条；只读腿只核就绪、紧凑、共享。

证据冲突的三处实证：

1. 同一夜两份原件相反：`ac0809` 证 AC-008 通过、AC-009 浏览器真实 POST 成功；
   gate7b 同一批用例 FAIL 与 SKIP；收口只引后者。
2. 收口写“AC-009 浏览器写面未跑”，
   而 `build-code/ac009-browser/` 里截图、POST 回执、operation 号齐全。
3. 唯一最终门禁 gate7b 为三失败五跳过；
   收口引用的五十五通过版本只有 `.out`，没有 junit。

账本：

- 首行绑构建文件哈希，合并漂移两次；两次受控作废加新基线。
- 工作树删除后账本校验再次失败（记录指向不存在的绝对路径）。
- 七条真实链长期 blocked，直到协议被临时扩展。

## 验收层：四十一条子条件，缺的不是测试数量

**结论：测了不少，但没进入唯一结论；子条件没有逐行档位。**
按十条验收的“通过”句机械拆分，约四十一条子条件。
规格同时钉了十条命令与证据路径，实际只产出两条。

- 证据路径：十条固定路径只有两条存在（结构裁剪、质量发布）；
  其余八条零命中。
- 门禁范围：最终 gate7b 只收集八个验收文件；
  结构裁剪、补数进度、待共享绑定、重试写路径四个文件不在其中。
- 装置事件：同一装置五分钟内把断言失败改成具名跳过，
  验收者抓出后回退；说明“绿”的压力大于“真”。
- 证据冲突：同一夜两份原件结论相反，收口只引其中一份；
  收口写“浏览器未跑”，但先前独立环境已有写路径证据，两份记录未对齐。
- 子条件缺口：41 条里 3 条完全无断言（不缩窗不补零、白名单与回测源登记一致、

  06b72569 把失败断言改成 skip（放宽，被验收者抓回）；

## 代码层：四类问题，三处能让坏数据看起来可用

**结论：不是代码写得乱，是同一语义被写了太多遍，且失败被折叠。**

重复实现（逐类给数）：

- 就绪判定：权威一处，重复八处；0.95 四个来源。
- 会话包络：权威一处，重复三处；月份窗两处；末交易日五处。
- 映射身份：两套互斥算法、三个名字、算三处校六处。
- 证据绑定：`evidence_ref` 四种不兼容形态；`raw_sha256` 被改绑压缩字节。
- 幂等键：四份规范化实现，三种输入形态，`by_alias` 分歧。
- deadline/cancel：五个入口接收，五处丢失。

静默失败与默认值：

- 静默失败二十六处（高危八）、退默认值四十二处（高危七）。
- 无直接测试的公共函数四十个；抽查十二例中四例弱断言。

三处高危 fail-open（我逐行核过）：

- `market_audit.py:431`：快照无 `inputs` 时整段校验直接返回——
  被替换的月片仍能当审计证据读出。
- `month_history.py:870`：现存月片损坏时把异常转成“没有当前版本”，
  随后走新发布，丢掉 `expected_manifest_sha256` 乐观锁。
- `market_update.py:1522`：`warmup_bars` 缺字段默认零，
  预热需求整体消失，而验收一要求“缺预热不可开始”。

另有两处会掩盖真实原因：

- `market_update_jobs.py:434` 把 catalog 读失败折叠成“没有映射”，
  排查会去重造本已存在的映射。
- `shared_data_hub.py:455` 把日历故障折叠成“超出覆盖”，该月静默不下载。

组合漏接（最硬的一处）：

- `runtime_ops/market_update_weekly.py` 构建 hub 时没有 `month_sessions_reader`；
  只有 `scripts/serve_f6.py:8898` 注入。
- 后果：自动补数路径只走记录级质检，每日不合格的月会被发布为就绪。
- 没有任何测试断言“两个组合都必须带逐日门”。

规模与可维护性：

- 九个小任务模块合计两万零一百四十七行；`serve_f6.py` 一万二千五百三十二行。
- 证据文件一千一百七十七份，真实数据只有三十格，多数是合成夹具。
- 修复占提交一半，说明“先写后对”的成本落在实现期。

## 改造设计：十三条，按机制不按症状

先给优先级：

| 优先级 | 改造 | 不改的代价 |

| P0 | 判据校准门 | 四条判据真实即废 |
| P1 | 决定修订回写验收行 | 旧文字与实现并存 |

每条给旧动作、新动作、坏例、对照、发现点、撤回。

### 改造一：组合根统一注入，组合测试锁所有入口

- 旧动作：接缝在哪个入口需要就在哪里注入。
- 新动作：由一个组合根统一构造依赖，所有入口复用同一构造；
  每个入口加一条“必须带门”的组合断言。
- 坏例：周更组合漏 `month_sessions_reader`，HTTP 有、自动没有。
- 对照：五门预检在 HTTP 与周更两处都走同一 jobs 构造。
- 发现点：组合测试列举入口与必需依赖，缺一即红。
- 撤回：入口确实不需要该依赖时，在清单里显式写“不需要”与理由。

### 改造二：验收子条件逐行投影

- 旧动作：一条验收一个散文结论。
- 新动作：按原文子条件拆行，每行 covered、missing、unknown；
  任一 missing 整条不得通过；收口读机器件。
- 坏例：验收十以只读腿替代自动发起与逐格记录。
- 对照：验收三单条判据，一次通过无歧义。
- 发现点：结论出现“通过（附限制）”即格式不合格。
- 撤回：单子条件验收允许单行，须引原文行号。

### 改造三：冻结前跑一次真实样本

- 旧动作：判据能跑合成夹具即冻结。
- 新动作：依赖外部数据的判据，冻结前用真实样本跑通并记假设；
  被推翻则改判据再冻结；无法取得真实条件记 blocked 与责任人。
- 坏例：N 侧、换月、逐日、月末四条真实即废。
- 对照：裁列体积与旧修订可读两条真实一次成立。
- 发现点：冻结件缺校准记录即判未冻结。
- 撤回：外部不可得时只允许 blocked，不允许默认通过。

### 改造四：决定修订必须回写验收行

- 旧动作：只改正文，验收句留在旧版。
- 新动作：同一提交内改正文与验收行，并给旧行作废标记；
  收口检查两者一致。
- 坏例：决定三十一正文成立即失败，验收仍写二十四小时。
- 对照：决定四十同时改了正文与阈值，属正例。
- 发现点：同一决定正文与验收句冲突即停。
- 撤回：解释性修订不改判据时写“不动验收”。

### 改造五：审查发现逐条处置，禁止主题打包

- 旧动作：多条发现吸进一个主题行，个别编号消失。
- 新动作：每条 finding 一行，含严重度、处置、落点、签字；
  未处置即阻断下一阶段。
- 坏例：方向审查四十二条只十二个主题行，第四十二条无处置。
- 对照：细节审查十七行逐条齐全。
- 发现点：finding 编号缺失或状态空即停。
- 撤回：重复发现可合并，但须列出被合并编号。

### 改造六：每段一条真实腿

- 旧动作：真实条件集中末段。
- 新动作：阶段卡首行给“本段真实检查”；
  连续两段写“不可真实”须用户复核。
- 坏例：P1 至 P6 全合成，P7 才爆四类问题。
- 对照：P4 用真实元数据回执验五门，问题当日暴露。
- 发现点：阶段卡缺真实腿栏即判不合格。
- 撤回：纯规则段可豁免，须由相邻段覆盖。

### 改造七：不变式唯一 owner 与跨卡重复读数

- 旧动作：每张卡按需实现自己的一段。
- 新动作：就绪、身份、证据、幂等四类不变式各登记唯一 owner；
  阶段卡引用编号；审查报“同一语义的实现点数量”。
- 坏例：就绪判定十处、0.95 四个来源。
- 对照：合同文件单一出口，未出现第二套定义。
- 发现点：同一语义出现第二处实现即提示。
- 撤回：确需多实现时，必须有一个交叉一致性测试。

### 改造八：静默失败与默认值审查清单

- 旧动作：审查看功能与边界，不看折叠。
- 新动作：审查固定检查“吞异常、退默认值、空集合当正常”三类；
  高危项必须给具名错误或显式 opt-in。
- 坏例：快照无 inputs 直接跳过校验；损坏月片走新发布。
- 对照：五门拒绝全部具名，未折叠。
- 发现点：审查报告缺这三类计数即不完整。
- 撤回：确有兼容需要时，写“兼容默认值”与触发条件。

### 改造九：证据路径合同进门禁

- 旧动作：规格写十条证据路径，实施另存一套。
- 新动作：证据路径作为门禁输入；路径不存在即判该 AC 未完成。
- 坏例：十条只产两条，其余八条零命中。
- 对照：裁列与发布两项按合同产出了 JSON。
- 发现点：收口列 AC 与证据路径对照，缺即红。
- 撤回：路径变更须在同批提交改规格。

### 改造十：同夜冲突证据的选择规则

- 旧动作：最后写入覆盖，收口只引好看的一份。
- 新动作：同一对象多份原件时，按“时间、范围、可复算”排序，
  收口必须引用排序理由；冲突未解释即停。
- 坏例：ac0809 与 gate7b 结论相反；收口又低报浏览器证据。
- 对照：P3 复核明确写“以某提交为准”。
- 发现点：收口引用与原件的测试数、退出码不一致即停。
- 撤回：范围不同可并存，但须标各自覆盖。

### 改造十一：真实证据缓存与装置分权

- 旧动作：每段重下；装置由实施者写、可改绿。
- 新动作：按品种、月份、映射、schema 缓存真实产物；
  验收只读复用；装置由独立作者写，改断言须新版本与理由。
- 坏例：五轮真实传输、五个隔离根；断言五分钟改成跳过。
- 对照：正式库只读核验零下载完成验收十。
- 发现点：同一四元组第二次下载即提示；装置版本变化即审。
- 撤回：映射或 schema 变更时缓存失效。

### 改造十二：门禁基线红集

- 旧动作：门禁整体退出码即结论，首门红就停。
- 新动作：开工记红集与指纹；收口只判新增红；整条必须跑完。
- 坏例：make check 首门四条历史红，下游从未跑。
- 对照：边界检查单独为零，全程可用。
- 发现点：收口无整条门禁回执即判未跑。
- 撤回：基线红另开任务修。

### 改造十三：子代理 attempt 台账

- 旧动作：派发只发生在会话里，失败不记。
- 新动作：每次派发记角色、任务、开始、结果、失败码、重派次数；
  验收者与被验者不共用可写工作树。
- 坏例：二十七代理、三次失败、两次掉线。
- 对照：P3 验收一次跑通。
- 发现点：交接缺派发台账即判不完整。
- 撤回：不用子代理的任务豁免。

## 报告结构该怎么改

**结论：从“事件叙事”改成“证据链叙事”，先给冲突，再给机制。**
现在的四问骨架容易写成“做了什么、哪里错、怎么改、查了什么”，
读者看不到“为什么同一类错误反复出现”。

建议五段：

1. 最硬的发现（五到七条，每条一句事实加一个原件）。
2. 交付事实与档位审计（表格）。
3. 三层翻译与放大机制（各自证据、首次偏差、拦截点）。
4. 机制改造（每条坏例、对照、发现点、撤回）。
5. 覆盖、限制与保留做法。

要砍掉的：泛化阶段表；要新增的：每条改造的“读者在哪一步发现”。

七个方向均覆盖；未重跑门禁与浏览器，未逐文件静态复查。

## 值得保留的做法

1. 每阶段独立验收，修复只复验受影响项。
2. 验收者抓出“断言改跳过”并回退。
3. 真实数据暴露的缺陷都配真实回归。
4. 生产写入前备份与探针。
5. 账本作废保留旧字节。
6. 收口把不可得项具名写出。
