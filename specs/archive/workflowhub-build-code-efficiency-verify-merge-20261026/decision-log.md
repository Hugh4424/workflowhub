### WP1 — 复杂任务按风险挑 Phase 审查

### WP2 — build-code 自动恢复

- **目标**：同一失败反复或没有新事实时，先停重复动作，自动深研、换假设/方法/独立上下文、修正 Phase 内任务并继续；只有改 AC/方向、缺真实权限凭证外部服务、必须有人承担严重风险三种才停。
- **边界**：可自动改 Phase 内任务拆分/顺序/依赖、实现与测试路线、修复方案、证据补齐；不可自动改 AC/FR/oracle/DO NOT TOUCH/授权写集/方向/验收对象；不设次数/时长上限；不弹三选项。

- **验收信号**：受控故障注入，证明会换路径继续、保留原失败、不弹选项；不跑长任务。
- **未做/未取得**：未实现；未做故障注入；真实权限/外部服务停点未演练。

### WP3 — 验收前移与每 Phase 验收成本化

- **目标**：make-decision 定哪些验收要真实资源、用户到场、当前有没有；build-plan 写逐条证据计划；每个 Phase 只判自己的验收，最后 Phase 一次对账；不设计超大验收。
- **边界**：不默认拆任务；外部验收留在当前任务；不设数字上限、不拿测试数量当质量；准备检查用 spec/Phase 合同加独立审查，不新增检查器。
- **已定做法**：证据计划写判什么、怎么判、证据从哪来、谁给、何时能拿到、成本类别、拿不到怎么办；验收太贵先提更便宜替代并讲代价风险，用户批准后才改标准；客观无法满足当前 Phase 验收时记 incomplete（写清试过什么、卡在哪、谁提供什么、何条件能补），build-code 结束统一提醒；可带 incomplete 结束，但最终报告逐条列缺口，不能宣称完成；代理记 incomplete 必须有真实尝试证据。

- **未做/未取得**：未在真实 Phase 执行；未产出逐条证据计划模板；未跑验收；真实缺口清单未形成。

- **边界**：页面只读派生，不写任务状态、不做第二进度；只放短标题、结论、来源指针，正文留材料；不做核心节点简化版。

- **验收信号**：用当前任务真实材料生成一页、刷新一次、浏览器真实打开并对照模板；不跑长任务。
- **未做/未取得**：未生成/打开任何页面；自动数据源与 15 类节点映射未实现；页面现状已由 `quality/evidence/research/page-audit-20261026.md` 审计：两会话未调用渲染器、两任务无 overview HTML、CLI 不自动打开、pageData 靠手拼；仍缺真实页面视觉对照。

### WP5 — verify-code 并入 build-code（仅复杂任务）

- **目标**：复杂任务三阶段；verify-code 内容搬进 build-code 最后 Phase，删掉其阶段身份；新增终末审查身份；原质量不丢；最终关闭留在外面 `stage-close`。
- **边界**：只复杂任务；小改动/普通/规划不动；旧任务、旧审查行、旧标签只读；关闭确认只一次；不新增检查器。
- **已定做法**：新终末审查可在 verify-code 原审查合同、提示词和质量判据上修改；审查独立执行、审整份交付 diff；验证、全局/架构师审查、修复、测试充分性、验收对象、AC 对账、UI/浏览器、norm-sync、reflection、成本、页面、spec-analyze 全部进最后 Phase；AC 首判仍在各承接 Phase，最后 Phase 只对账；最后 Phase 顺序为冻结实现→spec-analyze→AC/证据对账表→终末独立审查→修 finding 并定向复验→测试充分性/验收对象→UI/浏览器终验→最终 AC 对账和报告→norm-sync/reflection/成本/页面；第一件交付物是职责/质量保全表（原判据、并入位置、执行者、证据、验收），缺一项不算合并完成；`stage-closeout` 完整改名 `stage-close`（目录、技能名、引用、测试一起改，旧名只留历史）；关闭范围确认一次，范围变化或新未知才再问。

- **未做/未取得**：职责/质量保全表未产出；未实现、未改任何技能或 runtime；未跑定向测试；spec-analyze 检查点与最后 Phase 顺序都只有方向，未验证不重复工/不返工。

### WP6 — 证据、游标、上下文与成本

- **目标**：每 Phase 一份执行清单＋失败/差异原件，不再每个命令存一件；Phase 收口更新唯一游标；上下文只带当前 Phase 需要的材料；成本 stage 结束记一次。
- **边界**：不新建第二账本或第二进度；证据保留真实原件；不改历史证据；Phase 卡只列当前材料与审查。
- **已定做法**：每 Phase 一份执行清单放 `quality/evidence`，列命令、cwd、退出码、失败、真实 diff、证据指针；原始输出只在失败、差异、外部返回体等必要处留，同字节复用，不再每命令一件；Phase 收口更新唯一 `phase_progress` 游标，不存历史序列；Phase 卡列本 Phase 只读文件，独立审查核对没有多读整仓；成本在 stage 结束记一次；十环报告在最后 Phase 消费。
- **验收信号**：受控 Phase 夹具证明：多命令只产出一份清单；失败/差异原件保留，重复成功输出复用；游标推进；Phase 卡上下文清单与审查回读一致；成本行出现；十环报告被消费；不跑长任务。
- **未做/未取得**：未实现、未跑夹具；执行清单的具体 schema 与落点由 build-plan 设计；不新增第二账本或第二进度。

### WP7 — 每 Phase 子代理分工

- **目标**：复杂任务每个 Phase 配 1 个开发子代理、1 个审查子代理、1 个测试子代理，其他子代理按需；开发是唯一 writer，审查/测试不改文件；普通 finding 直接回开发；主会话只协调、用户决定、风险处置和最终汇总。
- **边界**：只复杂任务的 build-code Phase；小改动/普通任务仍在 make-decision 内完成，不套三子代理；审查子代理独立上下文、不改代码；测试子代理只跑测试、抓回执、核对 oracle，不改任何文件；主会话不写代码、不跑测试、不查细节 bug。
- **已定做法（Phase 内七步顺序）**：①主会话准备 Phase packet（spec、Phase 卡、AC、写集、测试命令、上下文指针、基线）交给开发子代理；②开发子代理实施、写测试、跑目标测试到通过，确认没有待修项后通知主会话；③主会话再派审查子代理和测试子代理，两者可并行，但不得在开发完成前启动；④普通 finding 直接回开发子代理，开发修完并跑受影响测试，审查/测试只复验受影响文件和用例；⑤开发子代理确认最后一个问题修完、没有待改项后，再次通知主会话；⑥主会话只核对“无 open finding、无未解释测试失败、Phase Done/AC 齐”，然后推进，不自己写代码、不跑测试；⑦出现改 AC/方向/严重风险/缺外部资源，才回主会话按 WP2 处理，其余不打断开发。同一 Phase 内保持同一开发上下文；审查子代理即 WP1 的独立子代理审查，高风险再叠加外部 OCR。
- **验收信号**：受控 Phase 夹具证明顺序（开发完成前不启动审查/测试）、唯一 writer、审查/测试不改文件、开发最后确认、主会话只推进；另证普通 finding 直回开发、同一失败不回主会话循环。
- **未做/未取得**：未实现、未做夹具；子代理数量/并发上限未取得；U-018/U-019 为要点非逐字；七步顺序的时序冲突未实测。

### F4 — WP7 Phase 收口与提交

- 七步顺序补提交点：开发完成、审查/测试回报无进一步 finding、目标测试与证据齐后，由开发子代理在本 Phase 提交一次；最终 Phase 的最终提交在终末审查与修复完成后进行；push/merge/PR/归档/清理归 stage-close。
