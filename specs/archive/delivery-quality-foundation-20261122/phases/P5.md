## 这一 Phase 交出什么？

安装者能运行真实检查，终末读者能拒绝坏证据，收口能读取有效风险接受。
旧 `validateSchema` 实现退出，结果 schema 保留且可读。
既有 record-route 在唯一写盘前用保留 schema 守卫合法与坏记录。

- **本 Phase 结果**：发布闭包、验收证据、风险接受和旧实现退役各有真实消费证据。
- **非目标**：不接旧 schema 校验器，不接 reviewTier，不新增公共命令或行为语义。
- **改动前**：安装缺检查器与依赖，验收证据零生产调用，风险接受无收口读者。
- **改动后**：安装逐项报告，坏证据不冒通过，有效接受绑定当前审查和发现。
- **与相邻 Phase 的边界**：消费 Phase 4 运行时与终末链，向 Phase 6 交回活链状态。
- **主要风险**：用投影或单测冒真实安装／生产接线；出现时对应任务不通过。
- **下一步**：Phase 6 只退已证死对象，Phase 7 复核真实安装和终末证据。
- **动手前必读**：`quality/evidence/decision-maker/p07/design.md:45-147`。
  再读 `build-plan/light-research.md:17-28` 与当前 spec 验收6至8。
- **未决事实**：安装具名未跑边界由发布 owner 开工前确认。
  历史审查兼容范围由审查 owner 核真实样本；真实答复未产生时风险效果未完成。

## 这一 Phase 怎么验收？

本 Phase 承接验收6、7、8，判据分别以 AC-DIST-001、AC-EVID-001、AC-SCHEMA-001 为权威。
非 UI：不适用——本 Phase 只改发布、CLI、证据与合同，没有页面改动。

- **成本账**：三项验收分别估算40、25、20活动分钟。
  串行合计 `acceptance_cost_total=85 active_min`，均为未校准估算。
  等待分账：external_blocked/incomplete/延期沿原字段单列，不计 active_min、不设硬 cap。
  `phase_budget=unknown — 无已校准基线`。
- **资源账**：真实安装需发布器、锁文件和 npm 环境；终末需真实任务和当前审查。
  风险接受需真实答复；缺任一外部条件就具名记不可用，不用合成文本替代。
- **范围账**：任务6证安装，任务7证终末消费，任务8证旧实现退出；互不冒领效果。

**验收6：干净安装能运行声明的检查与命令**

目标是安装者在真实安装根运行自检和四个文档命令。
操作时先构建并真实安装，再跑正常例，删除必需检查器后复跑并恢复。
条件是真实 npm 安装、realpath 后运行器路径和已确认的未跑边界。
故意删 `check-anti-host` 必须非零并点名；advisory 与具名未跑不得冒充门禁。
真跑命令见任务6；独立发布测试者在实现后判定。
失败回包7发布 owner；隐藏依赖缺失逐个补，补不齐保持具名未跑和覆盖缺口。

**验收7：终末证据与风险接受被真实读取**

目标是坏验收证据在真实终末链暴露，有效风险接受被收口读取。
操作时驱动合法与坏证据，并以去掉校验调用的变异证明负控有效。
条件是真实任务、当前审查与发现、有效答复和现有终末链可用。
未答、错发现或无效答复不得被视为接受；坏证据进入既有未完成语义。
真跑命令见任务7；独立测试者与收口读者在实现后判定。
失败回包7运行时 owner；真实答复未产生时只停该效果条件，其它安全工作继续。

**验收8：旧结构校验实现退出而合同保留**

目标是旧模块与符号不能继续调用，保留的结果 schema 仍可读取与发布。
操作时按旧路径导入，再在真实 record-route 写合法与坏记录。
去掉写前结果 schema 守卫后，坏记录在变异中可写，以证明守卫确实生效。
条件是旧路径、保留 schema、真实记录入口和样本可读；历史未核范围单列。
旧入口仍可用、schema 被删、坏记录被拒缺失或变异无效均为失败。
真跑命令见任务8；独立测试者与审查合同读者在实现后判定。
失败回包7合同 owner；不得把旧实现重新接到 `review-record-route`。
