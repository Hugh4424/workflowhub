# 质询书 · 丙队（杠精）——针对甲/乙/丁最薄弱论点

## 对甲队（辩护方）

**质询甲-1**：甲自述②承认"轮次下降"不可证，却把组F 轻放为"接受验证"：无基线、无度量的"省"只是安慰剂；且导航节内嵌=材料永久增重，若实测省额<增重，方向卡即为负收益背书。甲应先把"省多少"说清，而非把不可证问题转嫁 build-spec。

**质询甲-2**："锁语义不锁形态"恰与甲自述①互证：守卫形态、索引载体、负向 oracle 分类三大关键规范全部归"build-spec 定义/验证"，方向期实际零锁定。锁死之名已被三方证伪后，甲只剩"用户已确认"挡箭牌——用户确认的是问题与目标，不是"锁死即可行"这一结论。

## 对乙队（审查发现方）

**质询乙-1**：乙组D 处方"字符数/重读/派发定基线阈值"正面撞方向卡非目标"不做 token 度量机制（Q2）"——要基线就须观测，乙要么自认处方违非目标，要么承认"成本下降"仍不可证。乙批评甲"不可证"的洞，乙原样复制，未补反扩。

**质询乙-2**：乙组A 以"语法规则或机器标签"判负例——负例有效性是语义（"身份不符必须拒绝"），文法只能查"有无否定表达"，判"存在"≠"可证伪"。乙用形式化替换语义，与乙批评甲"提前拍死"同构；乙自述已承认"同样放大方向卡"，乙的锁比甲更细更僵。

## 对丁队（搅局方）

**质询丁-1**：丁②概率误用：40-75% 是单通道成功率，案卷 L5 红蓝配对 6/6 completed 证明多通道下"至少一个异源可用"为常态；六通道全灭概率≈0.25^6≈0.02%。丁把"单通道可能失败"夸成"≈半数 overall 不可用"，其"两向皆坏"恐吓建立在错误算术上。

**质询丁-2**：丁自述承认"未跑校验器用例、矩阵为下界"，却把改动面最小部分（模板只影响新 spec、首个消费者）定性"改错即自卡"；下界数据配上限定性——丁的影响评估证据偏保守、结论偏激进，供裁决价值存疑。
