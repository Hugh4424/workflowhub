## 速读卡（30 秒）

- **一句话需求**：用户发起一个以产出 PRD 为目标的规划任务时，只被问方向层问题，产物精简到可以逐任务执行，并在结束时得到一次复盘和一次不带归档的收口。
- **核心改动点**：
  - 任务类型成为可读的显式声明，规划任务与普通任务使用不同的提问强度。
  - 规划任务的决策记录与 PRD 只保留方向层内容，PRD 必须带可逐条执行的任务清单。
  - 规划任务收口不产生归档；归档改由用户在清单完成时明确下令。
  - 阶段结束时按声明清单逐条核对，并把「交付物是否存在」与「完成判据是否齐备」分开报告。
- **最大影响面**：所有以产出 PRD 为目标的规划任务。普通实现任务的提问强度与产物粒度保持不变。
- **验收信号**：规划任务的提问记录里不再出现实现细节类问题；PRD 明显精简且带任务清单；规划任务结束时没有被移入归档区；阶段末报告能逐条说出哪一步做了什么、哪一步没做、为什么。

## 1. 问题与紧迫性

用户上一个规划任务走完后暴露三个真实缺陷，且各自根因不同。

第一，规划任务的提问跑偏。任务类型这个概念在系统里根本不存在，规划任务与实现任务共用同一套提问强度，结果是规划任务被问了大量实现机制层面的问题。用户当时的原话是「我考虑的也不清楚」——把方向问题和实现问题混在一轮里问，用户既难以回答，也拿不到自己想要的方向结论。

第二，产物膨胀且不可执行。规划任务的内容边界没有任何纪律：约束模板里没有长度或深度条款，也没有「只写到方向层」的明文要求，于是决策记录与 PRD 一路堆到七十余万字节，PRD 读起来不像一份可以逐条派活的清单。

第三，结束动作缺失。规划工作流跑完既没有复盘，也没有收口入口：它既不在正式阶段的清单里，也没有任何步骤在结束时产出复盘事实。用户明确要求规划任务结束时要像实现任务一样复盘，并且这次的收口不包含归档。

这三件事现在必须处理，因为它们互相咬合：提问边界错了，产物必然膨胀；产物不能逐任务执行，子任务就得回头重读母材料；结束动作缺失，用户无法判断这批任务到底做完了没有。

## 2. 背景、目标与范围

### 背景

系统用五个正式阶段串起实现类工作：做决策、写规格、排计划、写代码、验代码。规划任务是一条旁支：它的产出不是代码，而是一份 PRD，PRD 里列出若干个后续要独立立项的子任务。

现状里，任务类型不是任何一处可读的属性。规划任务与普通任务在任务登记信息上逐字段同形，没有任何可区分的标记；系统内也没有任何地方按类型分流。规划任务所用的 PRD 模板规定了必备章节与每张任务卡的字段，但没有规定内容的深度，也没有规定不允许出现哪些内容。

规划工作流共有六个步骤，全部与「读母决策、起草任务地图、确认、展开 PRD、确认最终稿、报告事实」有关，没有任何一步产出复盘事实，也没有任何收口入口。既有的规划收口模式存在且动作集合固定包含归档，本任务不改变它。

### 目标

- 规划任务的提问记录中，实现细节类问题的数量为零。
- 规划任务的决策记录与 PRD 明显精简，PRD 能直接逐条派给子任务。
- 规划任务结束时产出真实的复盘事实，并完成一次不产生归档的收口。
- 规划任务在清单内子任务全部完成、且用户明确下令之前，不会被归档。
- 阶段结束时能逐条说明每个声明步骤的实际状态。

### 范围内

- 任务类型的识别与唯一来源；其他类型只预留位置，行为不变。
- 规划任务下提问的边界与产物纪律。
- 规划任务决策记录与 PRD 的内容边界。
- 规划工作流的阶段末复盘与步骤契约。
- 规划任务的不归档收口与可归档判定。
- 子任务接手时的边界差异留痕，以及子任务不写母任务材料、不写兄弟记录、不搬运文件的只读边界（机器可读的差额检查已由上游降级为不实现）。
- 任务类型与规划任务提问边界的最小术语和架构文档同步。
- 阶段末按清单逐条核对，并分开报告交付物与完成判据。
- 链字段校验必须真正校验到决定条目。

## 3. 用户场景与状态覆盖

### SCN-001：发起一个规划任务并只被问方向层问题

- **角色**：发起规划任务的用户
- **Given**：用户提出一个以产出 PRD 为目标的需求，任务已建立
- **When**：任务进入决策阶段并开始提问
- **Then**：用户只被问到会改变方向的问题；实现机制类问题不出现；每题的选项都写明含义、直接后果和主要风险

### SCN-002：规划任务产出精简且可执行的 PRD

- **角色**：发起规划任务的用户
- **Given**：规划任务的方向已经确认
- **When**：规划工作流展开 PRD
- **Then**：PRD 只写到方向层，不含实现细节，并且带一份任务清单，清单里每一条都有目标、边界、验收与依赖

### SCN-003：规划任务结束时复盘并且不归档

- **角色**：发起规划任务的用户
- **Given**：规划工作流已经跑完全部步骤
- **When**：阶段收口被执行
- **Then**：用户拿到一份复盘事实——产出成功时内容非空并绑定当前任务与规划工作流（不绑定正式 stage），产出失败时如实记为不可用而不是记为完成；决策记录保留在主仓同相对路径，没有被移入归档区；系统没有写下收口完成记录

### SCN-004：清单已全部完成时用户下令归档

- **角色**：发起规划任务的用户
- **Given**：用户已对 PRD 清单的完成情况作出声明
- **When**：初次四动作已结束且专属 worktree 已正常清理，用户在声明之后明确下令归档母任务，并分别授权本次归档、归档提交及所需推送
- **Then**：现有 close 从主仓 `specs/<task-id>/` 的当前材料完成后续归档和归档提交；推送独立授权，不重建旧 worktree、不重复初次四动作。声明为「还有若干项未做」、或用户尚未声明时归档都不发生；被标记为「不做了」的条目不阻挡声明；用户放弃归档时任务保持未归档且不留收口完成记录。缺授权或部分失败保持真实未完成，重试只补未完成动作

### SCN-005：阶段末发现某一步没有真正执行

- **角色**：执行阶段的用户或接手的会话
- **Given**：某个阶段的声明清单中存在未执行的步骤
- **When**：阶段末核对被执行
- **Then**：报告逐条列出该步骤的实际状态，并把「交付物不存在」与「完成判据不齐备」作为两件不同的事分别说明，而不是合并成一个笼统的失败原因

### SCN-006：清单里有被标记为「不做了」的条目

- **角色**：发起规划任务的用户
- **Given**：PRD 清单中有一条被用户标记为「不做了」
- **When**：用户声明其余条目已经完成
- **Then**：被标记的条目不阻挡可归档结论；用户的声明被如实记录且可回查

### SCN-007：按硬约束发起任务

- **角色**：发起规划任务的用户
- **Given**：用户要求按标准流程执行
- **When**：任务被创建并进入决策阶段
- **Then**：先建立独立工作区，再从决策阶段开始，不跳过中间阶段，也不依赖规格阶段补齐需求；违反时下游阶段缺少当前材料，完成事实保持不完整

### 状态覆盖清单

- [ ] **默认态**：SCN-001
- [ ] **空态**：SCN-002，规划任务尚未产出 PRD 内容时清单为空
- [ ] **错误态**：SCN-005，步骤未执行或被静默跳过
- [ ] **加载态**：N/A — 本规格不涉及等待中的界面状态
- [ ] **取消态**：SCN-004，用户在归档前放弃归档，任务保持未归档且不留收口完成记录
- [ ] **边界态**：SCN-006，清单里存在被标记为「不做了」的条目
- [ ] **权限态**：SCN-004，归档只能由用户下令，系统不得自行执行
- [ ] **竞态**：N/A — 本规格不涉及并发写入同一份材料的时序竞争

## 4. 产品事实与假设（PFACT）

- **PFACT-01**：任务类型在现状系统中不是任何一处可读的属性，任务清单文件对规划任务与普通任务逐字段同形。
  - **status**：`verified`
  - **证据或来源**：decision-log 的事实核查章节与 R-07 实测结论；源验收标准 AC-03
  - **关联**：FR-TYPE-001、AC-TYPE-001

- **PFACT-02**：规划任务所用的 PRD 模板没有任何长度或深度纪律，也没有内容禁列。
  - **status**：`verified`
  - **证据或来源**：对规划技能与规划工作流的检索未发现方向层级、篇幅上限或字数约束条款；源验收标准 AC-04

  - **status**：`verified`

  - **status**：`verified`
  - **证据或来源**：R-07 实测；D-027 据此把可归档判定改为人工声明

- **PFACT-06**：现状的阶段末校验只覆盖清单的形状、步骤数量与身份，不存在把某一步声明的交付物与实际产物对照的检查。

- **PFACT-07**：链字段校验器此前只识别三级标题，而被校验材料的决定条目全部使用四级标题，因此它实际上一条都没有校验到。

## 5. 功能需求

### 任务类型（TYPE）

任务是方向决策还是实现落地，决定它被问什么、产出什么。类型必须先确定再提问，并且在改变时把旧类型的产物重新处置。

- **FR-TYPE-001**：每个任务在既有决策材料中以一条显式声明记录自己的任务类型；规划与普通两类都可从该声明唯一读出，且缺声明时按未声明处理并如实报告。
  - **范围边界**：包含声明的存在性、唯一可读性与书写契约——声明写在既有决策材料的任务身份段，使用固定标签「任务类型」，取值只能是「规划任务」或「普通任务」两个受控字符串之一；不包含新增任何字段、结构或控制面
  - **依据**：D-008、D-026
  - **场景**：SCN-001
  - **验收**：AC-TYPE-001

- **FR-TYPE-002**：任务类型可以在中途改变；改变之后，按旧类型产生的提问与产物必须按新类型重新处置，未重新处置的不得继续被消费。
  - **范围边界**：包含触发（类型声明被改写）、失效范围（按旧类型产生的提问记录与产物）、重新进入的阶段（按新类型从提问边界重新处置）与完成事实（新类型下的产物已产出且旧的未被继续消费）；不包含自动改写历史记录
  - **依据**：D-009、D-026
  - **场景**：SCN-001
  - **验收**：AC-TYPE-001

### 提问边界（ASK）

提问强度由任务类型决定。规划任务只问会改变方向的问题，并且每题的选项都要让用户看得懂代价。

- **FR-ASK-001**：规划任务的提问中，属于 D-004 唯一权威清单所禁的实现机制类问题数量为零；提问只覆盖会改变方向的问题。
  - **范围边界**：包含提问内容的类别判定；不包含提问轮次数量、题量上下限或具体措辞
  - **依据**：D-002、D-003、D-004
  - **场景**：SCN-001
  - **验收**：AC-ASK-001

- **FR-ASK-002**：普通实现任务的提问强度与产物粒度与改动之前保持一致，可以继续追问实现细节。
  - **范围边界**：包含行为一致性；不包含对普通任务做任何新增要求
  - **依据**：D-001、D-004
  - **场景**：SCN-001
  - **验收**：AC-ASK-002

- **FR-ASK-003**：每一道面向用户的问答题，其选项都必须用大白话写明含义、直接后果和主要风险，不得只给编号或术语。该条只约束表述方式，不改变任何任务类型的提问强度与题量——普通任务照旧提问，只是选项同样写清后果与风险。
  - **范围边界**：包含选项表述；不包含题的交付形态
  - **依据**：D-004
  - **场景**：SCN-001
  - **验收**：AC-ASK-003

### 产物纪律（DOC、PRD）

规划任务的产物只写到方向层，并且 PRD 必须能直接派活。

- **FR-DOC-001**：规划任务的决策记录保留 D-005 要求的方向层内容——原始需求、已确认的选择与理由、风险、非目标与延期方向——并且不写入属于 D-004 唯一权威清单所禁的实现细节类内容。
  - **范围边界**：包含内容边界；不包含篇幅数字上限
  - **依据**：D-005
  - **场景**：SCN-002
  - **验收**：AC-PRD-001

- **FR-PRD-001**：规划任务的 PRD 只写到方向层，不新增模板未定义的章节，也不写属于 D-004 唯一权威清单所禁的实现细节。
  - **范围边界**：包含章节边界与深度边界；不包含模板字段的增删
  - **依据**：D-006
  - **场景**：SCN-002
  - **验收**：AC-PRD-001

- **FR-PRD-003**：规划任务的 PRD 必须包含完整旅程与需求覆盖两部分内容——这是上游决策要求保留的内容，而不是当前模板已有的章节；精简不得以删掉这两部分为代价。
  - **范围边界**：包含这两部分内容的存在性；落地时优先放进既有章节，若既有章节无法承载则由下游决定承载方式，但内容必须存在；不包含为它们新增模板章节或字段
  - **依据**：D-006
  - **场景**：SCN-002
  - **验收**：AC-PRD-001

- **FR-PRD-002**：规划任务的 PRD 必须带一份任务清单，清单中每一条都写明目标、边界、验收与依赖。
  - **范围边界**：包含清单与四项字段的存在性；不包含清单的载体形式
  - **依据**：D-007
  - **场景**：SCN-002
  - **验收**：AC-PRD-002

### 阶段末复盘（REFLECT）

规划工作流结束时必须留下真实的复盘事实。

- **FR-REFLECT-001**：规划工作流在结束时产出一份复盘事实，内容非空并绑定当前任务与规划工作流；产出失败时如实记为不可用，而不是记为完成。该事实不绑定正式阶段身份，也不接入正式阶段的强闭环。
  - **范围边界**：包含复盘事实的生产、触发与消费——它由规划工作流的最后一步触发，在报告事实之前产出；最小载荷包含结论条目与它引用的步骤；消费方是规划工作流自身的收尾报告与后续接手者。写入规划工作流既有的可选复盘事实位（该位置此前已被声明，但既无生产者也无消费者，本任务补齐两端）；不包含把它接入正式阶段的强闭环，也不包含新建通道
  - **依据**：D-010
  - **场景**：SCN-003
  - **验收**：AC-REFLECT-001

### 收口与归档（CLOSE）

收口不归档；归档由人在清单完成时下令。

- **FR-CLOSE-001**：规划任务收口时执行提交、合并、推送、清理四个动作，并且**不产生归档**、不写下收口完成记录。为做到这一点，规划收口允许从既有物理交付动作集中裁剪掉归档动作；普通任务与既有规划收口模式的动作集不受影响。
  - **范围边界**：包含收口产生与不产生的物理事实，以及「允许为规划收口裁剪动作集」这一授权；不包含具体执行方式，也不包含新增公共命令或控制面
  - **依据**：D-011、D-016、D-031、D-032
  - **材料位置**：提交、合并及推送后，材料可从主仓目标分支的 `specs/<task-id>/` 读回，且不进入 `archive`；随后正常清理专属任务 worktree 与任务分支。cleanup 前主仓材料不可读或未完成推送时，不删除唯一材料副本，不报 cleanup 完成。
  - **场景**：SCN-003
  - **验收**：AC-CLOSE-001

- **FR-CLOSE-004**：收口过程中任一步骤失败时，已完成的动作保持已完成且可读，未完成的动作保持未完成，且不产生收口完成记录；重试或恢复不得重复已完成的动作。
  - **范围边界**：包含部分失败、重试与恢复的可观察结果——每个动作各自的授权与结果事实即为其持久状态，收口完成记录不写；重试只补做未完成的动作。不包含具体重试机制
  - **依据**：D-011
  - **场景**：SCN-003
  - **验收**：AC-CLOSE-003

- **FR-CLOSE-002**：归档只有在用户明确下令时才执行，系统不得自动归档；其他物理交付动作仍遵守 D-011/D-031 的各自独立授权，不因本条免除。
  - **范围边界**：包含授权来源及 D-033 授权的现有 close 窄扩展：正常 cleanup 后从主仓同相对路径准备并执行后续归档、归档提交及独立授权的推送；不新增公共命令、模式、schema、store 或独立收口完成记录；普通任务及显式 legacy --mode=planning 行为不变
  - **依据**：D-012、D-033
  - **场景**：SCN-004
  - **验收**：AC-CLOSE-002

- **FR-CLOSE-003**：母任务是否可以归档，以用户的人工声明为准；声明被如实记录且可回查，未声明完成时不得宣告可归档。用户可以标记某条任务「不做了」，被标记的条目不计入未完成。
  - **范围边界**：包含通过现有记录链保存声明原话并读回；声明自身不等于 close plan 批准或物理操作授权。保留后续原话与撤回事实，不新增完成枚举、撤回链或机器清单差额
  - **依据**：D-013、D-027、D-033
  - **场景**：SCN-004
  - **验收**：AC-CLOSE-002

### 子任务接手（CHILD）

子任务应当能在有限上下文里接手，并且不得越权写母任务。

- **FR-CHILD-001**：子任务从 PRD 接手时不需要重读母任务的实现细节，也不需要重做母任务的方向决策；子任务仍按标准流程做自己的实现设计。接手所需的信息全部来自 PRD 中属于该子任务的条目与子任务自身的材料。
  - **范围边界**：包含接手所需的最小输入集——PRD 中属于该子任务的条目与子任务自身材料；不包含母任务的其他材料，也不包含子任务内部的设计粒度
  - **依据**：D-007、D-021
  - **场景**：SCN-002
  - **验收**：AC-CHILD-001

- **FR-CHILD-002**：子任务的实现做法与母任务给出的边界不同时，差异必须被记录且可追溯。
  - **范围边界**：包含差异留痕的三项内容——母任务原本给出的边界、实际偏离成什么、为什么偏离；不包含差异的批准流程
  - **依据**：D-015
  - **场景**：SCN-002
  - **验收**：AC-CHILD-001

- **FR-CHILD-003**：子任务不得写母任务材料、不得写兄弟任务记录、不得触发母任务收口、不得搬运文件。子任务收尾的机器可读差额检查已被上游降级为不实现。
  - **范围边界**：包含只读边界本身；不包含要求实现机器可读的差额检查或差额计算
  - **依据**：D-014、D-021、D-027
  - **场景**：SCN-004
  - **验收**：AC-CHILD-002

### 阶段末核对（CHECK）

阶段结束时必须逐条说清每个声明步骤的实际状态。

- **FR-CHECK-001**：阶段结束时按声明清单逐条核对每个步骤的完成、跳过、未完成或不可用，并把「交付物是否存在」与「完成判据是否齐备」分开报告；执行者缺失这一类通用原因不得一律当作正常降级。
  - **范围边界**：包含逐条核对与分开报告；不包含新增阶段末控制面
  - **依据**：D-023
  - **场景**：SCN-005
  - **验收**：AC-CHECK-001

### 既有契约保持（CONTRACT）

改动技能文件与模板时，既有的 token、字段名与哈希登记必须继续成立。

- **FR-CONTRACT-001**：规划产物模板的既有必备 token 与字段名保持存在，技能文件的哈希与登记保持一致，既有契约测试继续通过。
  - **范围边界**：包含既有 token 与哈希一致性；不包含新增 token 或改变既有字段语义
  - **依据**：D-017
  - **场景**：SCN-002
  - **验收**：AC-CONTRACT-001

### 链字段校验（CHAIN）

校验器必须真的校验到它声称校验的对象。

- **FR-CHAIN-001**：链字段校验器必须识别材料中实际使用的决定条目标题层级；识别不到任何条目时不得报告为零告警。
  - **范围边界**：包含标题层级的识别，以及识别不到任何条目时如实说明「未识别到条目」而不是报告零告警；不包含为既有决定补写缺失字段
  - **依据**：D-030
  - **场景**：SCN-005
  - **验收**：AC-CHAIN-001

## 6. 模块划分

### 任务类型判定

- **负责什么**：在提问开始之前确定当前任务是规划任务还是普通任务，并让这个判断可被后续步骤读取
- **对外提供什么**：一个唯一的类型结论，供提问编排、产物纪律与收口判断消费
- **依赖谁**：决策材料本身
- **测试边界**：从材料能唯一读出类型；缺声明时返回未知而不是猜测

### 提问编排

- **负责什么**：按任务类型选择提问强度，组织题面与选项
- **对外提供什么**：符合当前类型边界的提问记录
- **依赖谁**：任务类型判定
- **测试边界**：规划任务的提问记录中实现细节类问题为零；普通任务记录与改动前一致

### 产物纪律

- **负责什么**：约束规划任务决策记录与 PRD 能写什么、不能写什么
- **对外提供什么**：只到方向层、且带可执行任务清单的产物
- **依赖谁**：任务类型判定
- **测试边界**：产物结构检查逐类通过

### 阶段收口

- **负责什么**：在规划任务结束时产出复盘事实、执行不带归档的收口、记录人工的可归档声明
- **对外提供什么**：真实的复盘事实、未归档的物理状态、可回查的声明
- **依赖谁**：阶段末核对
- **测试边界**：归档未发生；无收口完成记录；声明可回查

## 7. 关键实体

- **任务类型声明**：
  - **定义**：一条写在既有决策材料里的显式声明，说明当前任务是规划任务还是普通任务
  - **字段和约束**：固定标签「任务类型」，取值只能是「规划任务」或「普通任务」；写在既有决策材料的任务身份段，同一份材料里至多一条；不新增字段或结构；缺声明时视为未知，不得推断
  - **关系**：被提问编排、产物纪律与收口判断共同读取

- **任务清单条目**：
  - **定义**：PRD 中描述一个后续要独立立项的子任务的最小单元
  - **字段和约束**：必须写明目标、边界、验收与依赖；可以被用户标记为「不做了」
  - **关系**：母任务的可归档声明以它为依据；子任务从它接手

- **复盘事实**：
  - **定义**：规划任务结束时产出的一份结构化回顾
  - **字段和约束**：必须非空，并绑定当前任务与阶段；产出失败时状态为不可用
  - **关系**：属于规划任务自身，不进入正式阶段的强闭环

- **可归档声明**：
  - **定义**：用户对母任务清单完成情况的明确声明
  - **字段和约束**：保存用户原话；「已全部完成」「还有若干项未做」「撤回声明」是人读语义例子，不是新增机器受控取值。后续原话与撤回事实保留可回查，旧声明不可冒充本次归档的有效答复；由用户在归档前明确给出，沿既有记录链保存，不写入已封存材料、不新增持久结构。声明不等于批准 close plan；被标记为「不做了」的条目不计入未完成；未声明不得推断。来源 D-027/D-033
  - **关系**：是可归档判定的唯一依据；归档动作另行由用户下令

- **收口事实**：
  - **定义**：规划任务结束时实际发生的物理动作记录
  - **字段和约束**：提交、合并、推送、清理四个动作各自的授权与结果；不包含归档动作；不产生收口完成记录
  - **关系**：与归档动作互斥

## 8. 数据和生命周期

- **数据粒度**：一条任务类型声明对应一个任务；一条任务清单条目对应一个后续子任务；一份复盘事实对应一次规划任务结束
- **数据时效**：类型声明在提问开始前就必须存在，并随类型改变而更新；清单条目随 PRD 修订更新；复盘事实在规划工作流结束时一次性产出
- **缺失或迟到**：类型声明缺失时按未知处理并如实报告，不推断、不默认；复盘事实产出失败时记为不可用，不补写
- **预览与正式**：本规格不区分预览态与正式态，材料即为正式态
- **当前与历史**：原位置保留当前材料；归档发生时才把材料整体移入归档区，且归档不可逆
- **归属与清理**：任务材料由任务自身持有；按 D-032，收口经 merge/push 在主仓保留 `specs/<task-id>/` 同相对路径，随后 cleanup 删除任务 worktree 与任务分支。主仓材料不得被移入归档区或删除；旧 worktree 绝对路径不再承诺保留。被标记为「不做了」的清单条目保留标记而不删除

## 9. 兼容性预留

- **既有消费方**：普通实现任务的提问强度与产物粒度保持不变；正式阶段的收口模式与动作集合保持不变
- **命名预留**：除规划与普通之外的其他任务类型只预留位置，本期不定义其提问与产物规则
- **容器预留**：任务类型的声明写在既有决策材料内，不占用新的字段或结构，后续类型扩展沿用同一处
- **状态预留**：复盘事实保留不可用状态；可归档声明保留「未声明」状态
- **扩展边界**：本期预留其他任务类型的位置与无人值守归档的位置，但不承诺实现，也不为它们改变既有控制面

## 10. 明确不做与默认必须成立

### 明确不做

- 不改变五阶段的拓扑，不新增第六个阶段。来源：D-001 与范围内边界。
- 不新增公共命令、新结构或新控制面；只允许使用既有消费者与扩展点。来源：D-016。
- 不重写或重做已归档的历史材料。来源：D-018。
- 不改变普通实现任务的提问强度与产物粒度。来源：D-004。
- 不把规划收口模式改成不归档；既有模式保持不动。来源：D-011。
- 不实现无人值守的自动归档。来源：D-012，延期项。
- 不重写旧的两份臃肿材料。来源：延期项，永久保持只读。
- 不为调研、可行性测试、设计三类任务定义规则。来源：延期项，待第一个此类任务出现。
- 不新增一份独立的「已收口未归档」记录文件。来源：延期项，用户已接受该代价。
- 不为已探明的验收缺口补写验收标准。来源：D-029。

### 默认必须成立

- 归档之前，规划任务的材料始终留在原位置。关联 FR-CLOSE-001、AC-CLOSE-001。
- 未经用户明确下令，任何任务都不会被归档。关联 FR-CLOSE-002、AC-CLOSE-002。
- 阶段的实际状态以事实为准，缺失的质量事实不会被表述为通过。关联 FR-CHECK-001、AC-CHECK-001。

## 11. 验收标准

> 本节全部验收按 D-019 的口径执行：以结构校验与单元测试为准，**不真跑规划任务**。凡取证对象写成「提问记录」「新产出的 PRD」「类型改变记录」「子任务接手过程」的，其事实由测试夹具或既有已归档产物提供，不要求由一次真实运行产生。

## 12. 风险、未决与交接

- **RISK-01**：收口要求不归档，而现状收口的动作集合固定包含归档且拒绝偏离，两者可能无法在既有路径内同时满足。
  - **受影响 ID**：FR-CLOSE-001、AC-CLOSE-001
  - **触发条件**：实现时发现执行四个动作必然带动归档动作
  - **后果**：规划任务会被提前归档，材料被移入归档区且不可逆
  - **缓解或 STOP**：**已由 D-031 处置**——上游授权为规划收口裁剪既有物理交付动作集（去掉归档）。仅限规划收口；不得新增公共命令或控制面
  - **处理 Stage**：`build-plan`
  - **验证**：AC-CLOSE-001 通过

- **RISK-02**：本任务不真跑一个规划任务，因此「少问、变短」的收益没有运行证据。
  - **受影响 ID**：AC-ASK-001、AC-PRD-001
  - **触发条件**：任何试图用实测数据支撑收益主张的场合
  - **后果**：收益主张只能停留在结构校验与单元测试层面
  - **缓解或 STOP**：如实标注为未知，不以结构校验冒充运行证据
  - **处理 Stage**：`verify-code`
  - **验证**：相关结论保持未知状态，未被表述为已验证

- **RISK-03**：内容边界没有数字阈值，规划产物仍可能膨胀。
  - **受影响 ID**：FR-PRD-001、AC-PRD-001
  - **触发条件**：方向层内容本身篇幅很大
  - **后果**：产物变短的效果不达预期
  - **缓解或 STOP**：靠决策记录 D-004 的类别清单约束，靠结构校验兜底
  - **处理 Stage**：`verify-code`

  - **后果**：用户被问了不该问的问题，需要重新处置
  - **缓解或 STOP**：允许中途改变类型并按新类型重新处置
  - **处理 Stage**：`build-spec`
  - **验证**：AC-TYPE-001 覆盖重新处置

- **OPEN-02**：链字段校验器修复后，同一份材料暴露出一百一十六条真实告警，说明该材料从未建立过这些字段。

  - **处理 Stage**：`verify-code`（收口时如实报告，不转派给下游实现阶段）

## 13. 业务影响与回归范围

### 规划任务的决策与产物

- **既有行为**：规划任务与普通任务共用同一套提问强度；决策记录与 PRD 没有内容纪律；产物可以任意膨胀
- **本需求影响**：规划任务只被问方向层问题，产物只到方向层并带可执行任务清单
- **回归路径**：对既有规划产物做结构与契约检查，不真跑一个新的规划任务（验收口径见 D-019）
- **验收**：AC-ASK-001、AC-PRD-001、AC-PRD-002

### 规划任务的结束动作

- **既有行为**：规划工作流结束时没有复盘，也没有收口入口
- **本需求影响**：结束时产出复盘事实，并执行一次不产生归档的收口
- **回归路径**：对复盘事实与材料位置做结构检查，不真跑一个新的规划工作流（验收口径见 D-019）
- **验收**：AC-REFLECT-001、AC-CLOSE-001

### 普通实现任务

- **既有行为**：可以追问实现细节，产物粒度保持原样
- **本需求影响**：无变化
