## 这是什么，给谁用？

让任务主持人、实施者和验收者能证明准备是否齐全、结果是否成立、交付是否真的发生。

范围以当前 `decision-log.md` 和任务库的需求索引为准。
本任务没有独立的产品需求文档（PRD）。
用户已确认十段大纲，当前文件仍是产品规格草稿。

## 一页看懂：谁要什么结果，怎么算通过？

任务开工前就能发现可验证的准备错误，实施中能及时改换调查方式。
发布前，验收者能用同一批原件核对工作状态、质量结论和交付声明。

- 任务主持人从已记录的需求、取舍、证据和验法排计划。
- 实施者拿到可复跑的数据、清楚的写入范围和已冻结的验收。
- 用户能在原有驾驶舱看到当前阶段、验收和材料来源。
- 独立验收者先核质量，再读回获授权的实际归档、推送和图更新结果。

各阶段先判本阶段交付。
最终验收按附录 A 消费沿途原件，并补只有整条链才能判断的结果。

## 为什么做，给谁用？

前期讨论顺利，仍可能把准备缺口、反复修复和错误的完成声明留到实施才发现。

T13 的历史调查记录了重复返工和子代理开销。
T8 的耗时、用量和返工线索见任务库调研原件第 19–29、68–72 行。
`quality/evidence/research/raw/t8-build.md`
调研负责人在末段签字前回核原执行事件与费账，或可比的工作量及原始量测。
按同一窗口和单位能独立重算时才关闭相应量化缺口。取不到时仍为未知。
当前机制验收只证 WorkflowHub 行为。T8 历史调查保持只读，真实业务仍在范围外。
根因和限制见决策日志需求 2、各包调研原件及附录 B 的事实对照。

### 哪些工作在本任务范围内？

同一个 WorkflowHub 任务完成十个工作包及其验收。
原始请求要求承接上一轮遗漏。每条按决策日志第五节的既有处置回读。
延期、缺证、退役和跨项目事项仍保留原责任人及恢复条件。

边界详见决策日志第一节和第五节的退役清单。
其它项目的业务、真实交易或产品数据库、历史证据重写均在任务边界外。
测试环境准备纳入现有阶段，不增设准备阶段或第二个测试数据负责人。
宿主集成限安装、发现与当次读取留证。
页面沿用现有模板，以已确认缺陷和根因为限。
每个包的设计保留调用方调整、旧输入迁移、退出路径和受影响读者。
逐包四项落在决策日志第 4 节每包的「配套与影响」节，以及各 Phase「这一 Phase 交出什么？」下的配套与影响行；两处指向同一文件与消费者。

## 做成什么样？

读者能在各自工作时点发现失败，找到谁能处理，并拿到独立判定所需原件。

### 开工与交接时会看到什么？

**场景 1。** 新会话从已配置的宿主根发现技能。
步骤检查比对本次读取的实际文件、材料和检查结果。
只有旧读数、缺子技能记录或读取来源不明时，主持人看到具体缺口。
宿主发行件的可见性与步骤完成分别留原件。

**场景 2。** 交出材料的人提供不可变来源、实际确认和开放问题。
规划者从同一版本读回原始字节，并把实际消费回执交给验收者。
来源恢复件明确标补录。
原件不一致时，原提供者补可读指针并保留旧版本。

**场景 3。** 包内只传必要的调研、方案和独立审查供件。
主持人用简洁中文向用户说明选项、后果和风险，实际提问用提问工具。
诊断进展有实质变化时及时汇报。
角色源、用户答复和卡片版本能由下一位读者核回原件。

### 开工失败或返工时会怎样？

**场景 4。** 实施者从计划取得隔离数据的来源、上限依据、复跑命令和清理安排。
配置缺失或数据版本落后时，失败指向当前数据准备。
测试人员可复跑同一命令，并判断实际连接和清理结果。

**场景 5。** 主持人在派发开发前运行现有检查和真实只读探测。
程序拦可复现的声明、版本、依赖、写入范围及探测错误。
可代表性、权限充分性、回退效果、验收语义和风险承担交人判断。
缺人判证据显示未核实。
当前答复见任务库原件。
`quality/evidence/build-plan/2026-11-19-003-clarify-readiness-answer.md`

**场景 6。** 实施者遇到重复失败时保留真实错误并提出新假设。
分诊人检查严重程度和实际新增事实。
发现同一失败仍在重复或冻结判据发生偏离时，回原实施人查因。
资格不明的测试、写入或裁决由独立审查者读回。

### 页面、收口和下一次计划分别会看到什么？

**场景 7。** 用户在原有驾驶舱查看工作包、级别、当前阶段、验收和实际来源。
初次生成、材料更新与失败保留旧件有可见差别。
浏览器仍显示旧输出时，用户能识别过期。
页面来源检查失败时，先修该来源或发布输入。

**场景 8。** 收口负责人读回交付质量和物理范围，按授权归档、提交、
推送任务分支并推送目标分支。
图的文档更新和代码更新各在适用时点留下结果。
图的操作失败时保留原件，收口继续按自身条件判断。

**场景 9。** 独立验收者从冻结的材料和原件判已实施、已验证、已接受。
声明写入者用实际产物、命令或签收原件佐证各自状态。
签后材料变化、取消或环境不可比时，界面和交接保留相应缺口。
T6/T16 原件已失。样本结果限于其受控输入。

**场景 10。** 下一位规划作者只读当前决策日志和可回读原件就能编排工作。
方向审查看得到最初方案、谁否决、为什么。
细节审查逐包看设计记录，规划审查核实际消费是否一致。
需求对照能定位遗漏和仍未关闭的审查发现。

默认正常、缺输入、进行中、占用冲突、权限不足和错误均按上述场景处理。
取消保留已完成动作与原错误。
页面等待仅指生成或读取现有页面时的行为。
异步服务及新交互不属于本任务，受影响页面的状态组合在对应阶段确认。

## 打算怎么做？

沿现有生产、读取和记录入口修复断链。
产品行为按原包从技能加载走到完整验收，实施锚点由本文件后续实现设计交代。

- **功能需求 1｜真实加载。** 宿主发现已安装技能，步骤检查读取当次事件。
  迁移时旧任务无事件显式未知，退出单凭文件存在或跳过步骤判完成的做法。
- **功能需求 2｜原件交接。** 确认和消费绑定同一版本、行位和字节指纹。
  指纹是用来比对同一内容的哈希。
  旧摘要迁到有源引用，既有确认与证据 owner 承接，补录身份保留。
- **功能需求 3｜逐包决策。** 在现有决策流程接入独立的调研、设计、审查。
  同包最多三个子代理，主持人唯一写日志。
  调研交事实和备选，设计写取舍，审查做冷读及挑战反例。
  卡按现有复杂度规则说明复用取舍和适用预算，实际超限按原角色规则暂停并报告。
  先交当前 v2 日志模板供件，再实跑一个完整包。
  旧多角色重复调研和主持人自审退出。轻量任务沿现行分支。
- **功能需求 4｜开工前检查。** 全局与增量材料注明命令、预期、证据、判定者和负责人。
  现有入口消费真实只读探测，不重复调用或靠游标代表探测。
  自动失败时停止相关派发，人判字段保持其真实待核状态。
- **功能需求 5｜修复分诊。** 分诊记录轮次、新假设、严重程度、结论与处理。
  每两轮修复与验收汇合做一次判断，阻塞或高风险要处理。
  同一失败连续两轮没有新证据时转查因。
  实施期间保持准入时冻结的验收与写入范围。
  既有独立裁决处理有效变更，旧原件和成本读数保留。
  固定轮数上限、试点段和独立修复日志检查器退出。
- **功能需求 6｜可追溯页面。** 结构化模型给出工作包、级别、验收和来源。
  当前阶段由任务事实提供。发布前查结构与契约、来源、计数与指纹的一致性。
  级别依据决策日志已定标记。标记缺失或冲突时显示未知。
  旧页重渲染，保留失败前可读版本并标过期。
  逐种自由文本猜测和仅按修改时间判陈旧的路径退出。
- **功能需求 7｜声明对证据。** 独立签字和结果绑定材料指纹。
  失败回放有冻结输入及环境标记。不可比得出明确结果。
  现有终末及收口读回消费原件，旧审查原件继续可读。
  重复手工列举和独立签字检查入口退出。
- **功能需求 8｜隔离测试数据。** 测试标准负责人负责数据来源、任务上限、
  可重跑命令、版本判定和清理。
  准备项纳入现有计划，迁移测试约定。真实库及当前历史备份不纳入测试输入。
- **功能需求 9｜先归档及分阶段更新图。** 授权范围内整目录归档，
  同一提交记录移动和实际交付内容。
  两路推送回执各自可核，图更新按文档交接和代码关闭分段做。
  停止全量抽图、每个工作树复制图以及以永久例外掩盖漏归档。
- **功能需求 10｜日志供规划和审查直接使用。** 新模板保留设计历程和配套影响。
  旧模板和旧原件继续可读，退出旧编号占位与旧包口径。
  三类审查分别消费各自原件。
  外部调研沿现调研台账逐项对照材料问题、适用性和处置，缺证留负责人。
  对账分为原需求、阶段粗核、审后细核，见附录 A 的相应判据。

先交各段功能和受控证据，再完成一次全链核对与实际收口。

移动前后以同一材料字节对账。
各段首判归原承接人，最后一段聚合原结论及必要的未闭环复核。

### 接口与失败语义

入口继续按当前副作用、归属和授权判断。
认证任务 handle 留原始输出及引用。`facts.jsonl` 保当前任务类别和原有进度责任。
记录用现 `captureCommand`、`appendRecord` 及既有 facts 引用。
用 `withRecordLock` 或关闭入口已有锁保护相同状态。
实际多文件发布和 Git 独立读回分别核对。

1. 宿主按配置根安装并读回。
