# Phase P9 — 让材料为读者写：读不懂在写入时就被拦住

材料作者按本卡把完整交付写成下一位读者能接手、能执行、能判断失败的材料。
原七项技术任务与后续全部人读改写分开留来源，独立读者据各自原件判断效果。

> 写作依据：`skills/material-writing/SKILL.md` 的「材料写作标准（唯一）」。
> 二级标题都是读者问题，第一句直接回答；命令与表格行不受行宽限制。
> 命令、路径、退出码与编号逐字保留，不因改写而改。


阶段（Phase）：一次可独立验收的工作包，本任务分十二个，编号阶段1到阶段12。
材料：本任务的人读文件，指决策日志、规格、阶段正文与索引四类。
这里的读者拿材料干活，但不参与写作；
判断看他能否照着执行。
校验器：只读材料形状的脚本；它判不出好坏，只判字段、正文与模式。
读者记录：一次读者检查留下的七段文字，缺段或空答会被脚本退回。
诊断模式：只记缺口、不报硬错的校验模式；另一个模式叫必填（required）。

## 这一 Phase 交出什么？

交出写材料这件工作本身的可执行规则与检查，让新读者能拿材料干活。

原校验器改造分三步交付：先记诊断，再检查当前正文，最后将当前默认设为必填。
留痕指只记缺口、不报错；收紧指缺正文就报硬错。
当前材料的既有检查读取同一正文事实，只有字段或示例仍会报缺正文。
材料行宽与表达由作者按现标准达成，统计脚本只报告。
三份模板改成先叙述、后字段；同一编号一份材料只出现一次。
构建计划第11步接独立读者检查，按验收对象读取必要原文并保原答。
脚本只核记录形态，不能把限读包、形状或计数当成真实效果。
一页作者开工前读的写作契约，含十九条可检查规则与一好一坏对照。
七张任务卡的结果、判定器与覆盖上限，见下面「七张任务卡各做什么？」。
工作包声明：本 Phase 不在 11 个工作包里；它按本轮方法要求改材料写法。

它不做页面采集，也不改页面审计的七条验收。
合进别的 Phase 会被页面判据盖住，所以单独成 Phase。
来源是用户 2026-10-29 的直接指示，不在四十三条原始需求里，卡片如实写来源。
把S类断言迁出这件事已移到阶段11，因为要改阶段1的冻结测试。

### 用例怎么编号，怎么判？

用例一核来源：原话、理由、否定边界和后续选择在实际新稿中得到完整承接。
用例二核范围：读者无需自裁旧失败、后到确认、当前功能与未验证能力的关系。
用例三核动作：读者解释首步和恢复，保真实无生产副作用消费的输入与观察。
用例四保反例：模板齐、记录齐、投递成功或检查零退出，仍不能替代前三项效果。
每例保输入、动作、观察和独立预期；未执行如实记未执行，不补答或改预期求绿。

### 谁判，什么时候判？

沿原审查和测试职责回读受影响新稿，作者不判自己写出的效果。
本轮参与作者准备的只读助手不能替正式角色签新的独立质量或冷读原答。
作者明确实现就绪并停写后，由父会话按现有职责安排接手。
材料修复回原角色做受影响复核，不把旧版本判断反绑新稿，不重开普通角色。

### 失败了怎么回修，怎么重验？

缺原义、否定或必须由读者自裁时，问题回本材料作者同一会话。
作者在实际正文修好，原受影响角色按同一预期复读和消费，旧失败继续保留。
命令或接口字面受损先按既存原件恢复受损片段，不改代码、降低判据或整份覆盖。
需要改变验收或方向时才交原负责人；已授权的安全修订继续。

### 任务 1：读者检查进第 11 步，且有固定记录形态

build-plan 的执行者要一条能照着记录、缺段就退回的读者检查。
它放在方法第 11 步之后，交付三件：只判形态的脚本、方法正文的第七类、一条契约测试。
它不判断读者说得对不对，只拦缺段与空答；记录本身也不证明材料有效。

为什么要固定形态：口头说读过，事后没有可回读的痕迹。
为什么只判形态：判断归读者，脚本只做缺段与空答的门。
为什么缺段退 2 而不是退 1：2 是内容缺，1 是文件读不到，两类要分开。
为什么要独立子代理做读者：同一个人写、同一个人读，等于自证。
为什么记录要落固定目录：下一位读者要能按路径找到它。
读者按验收对象读取必要完整原文，保实际读到与未读范围。
原先只给索引和一张卡只能观察受限启动，不是本轮全部材料效果的验法。
为什么不改既有六类文字：第七类是增量，动旧文会让别的阶段跟着变。
为什么样例要一好一坏：只跑好样例，看不出脚本会不会漏拦。

### 任务 4：结构读数，一条命令报四个数，只报不拦

阶段读者要一条只报不拦的读数命令，一次报出四个数。
四个数是编号重复、单行最长、常量字段与每千字编号，外加几条来自写作规范的观察项。
它不进持续集成、不设门，只用来找该删哪里；算不出的项去掉并记缺口。

为什么只报不拦：读数用来找位置，一设门就会有人改数字不改材料。
为什么四个数就够：再多没人看，四个覆盖重复、超长、空字段与密度。
为什么超预算也退零：退非零等于设门，设门就要定阈值。
为什么算不出就去掉：硬凑一个数比缺一项更糟。
为什么不引依赖：引了依赖，别人就跑不起来。
为什么读数是事实不是结论：数字好看不等于材料好用。
为什么每千字编号要算：绝对数随篇幅变，密度才可比。
为什么单行最长要报：一行太长，读者读着就断。
为什么常量字段要数：字段成片出现，说明正文被挤掉了。
为什么读数要单行 JSON：下一位读者要能直接读，不要人肉解析。

为什么读数不进持续集成：一进就变成门，门会逼着人改数字。
为什么键集合要固定：键一变，下游读法全要跟着改。
它证明不了观察项有用：观察项只作提示，不作结论。
它证明不了两例之外的材料读数合理：样本只取两例。

| 单行最长 | 按字符数取最大 | 编码不同就记未知 | 本卡写主 |
| 常量字段 | 数成片的字段行 | 形态变了就记缺口 | 本卡写主 |
| 每千字编号 | 编号数除字数乘千 | 字数算不出就去掉 | 本卡写主 |
