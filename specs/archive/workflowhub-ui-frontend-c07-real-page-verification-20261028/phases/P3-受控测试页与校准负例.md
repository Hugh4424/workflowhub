# Phase P3 — 受控页装九个可定位缺陷，四条校准页让重要与阻断两档可被区分

本卡把故意设置的页面缺陷和校准页交给末验收执行者。
执行者据清单定位、注入和复验，不用静态结构检查代替真实页面结论。

> 写作依据：`skills/material-writing/SKILL.md` 的「材料写作标准（唯一）」。
> 二级标题都是读者问题，第一句直接回答；命令与表格行不受行宽限制。
> 命令、路径、退出码、编号、哈希逐字保留，不因改写而改。


夹具：本 Phase 交付的七个文件总称，供末验收注入与复测，不替代真实页面。
受控页：一个故意埋了缺陷的测试页，缺陷位置固定、可被选择器找到。
校准页：一对基线与观测值（应有的量与实测的量）的页面，用来验证同一把标尺（同一套定级规则）能分出正确档位。
档位：一条缺陷的严重度，全文只用三档词 `BLOCKER`（阻断）、`IMPORTANT`（重要）、`MINOR`（次要）。
清单：一份机读文件，写每条缺陷的 id、选择器、维度、档位与检测方法。
契约测试：只读文件与字符串的测试，证明页面、清单与校准页互相引用得上。
注入：把清单里的缺陷按 id 放进目标页面，看判据能不能检出。
判据正文：阶段1写的那份页面判据文本，本Phase只读档位词，不复制。
契约决定：`build-plan` 原件里逐条编号的取舍，正文写「契约决定 n」。

## 这一 Phase 交出什么？

交给末验收一套可注入的夹具，含一个受控页、一份清单、四条校准页和一条契约测试。
这套夹具按名可读：每个region（页面里可单独定位的区块）有固定id。
清单与校准页都按同一id引用。

一个受控页装九个region，每个对应一类已知缺陷。
页面单文件、内联样式与脚本，无外链。
一份清单写九条 region 与四条校准条目（三重要加一阻断），每条五个必填字段。
四条校准页各带一组基线与观测值：字体 20 到 17px、间距 16 到 8px、颜色 `#1A73E8` 到 `#3A83E8`。
其中三条还原偏差是重要档，一条主操作被遮罩接管是阻断档（按钮还在，但点不到）。
阻断档不靠像素百分比，靠可操作性事实：`document.elementFromPoint` 落在遮罩上，主操作点不动。
缺陷是结构性的，不是白屏。
一份自洽契约测试证明四者互相引用、档位不越界，只做字符串与结构断言，不启浏览器。
原规划不注入、不运行采集器，也不首判真实页面；后续执行按本卡实际原件回读。
（2026-10-31 按用户指令补跑了真实注入、检出、200% 缩放、键盘与两次定级；读数与档位见附录 B，上面这句保留为计划时的不做范围。）
工作包声明：本 Phase 对应 decision-log 的工作包 3、5，即九项标准与定级校准负例。

## 这一 Phase 怎么验收？

先答这一问：假设本 Phase 全部实现、所有已设计测试也都通过，还会不会漏掉原始需求？
答不出「不会」之前，任何测试通过都不算达成验收。
这组受控页真能暴露预期缺陷，负例真被判红，两档真能分开。
契约测试绿只证文件与字面互相指得上，不证缺陷在浏览器里触发。
一个 Phase 只有在验收标准真的被满足后才能说开发完成；代码审查通过、测试全绿、结构检查通过，都不是完成条件。
RED/GREEN 表、覆盖上限与命令细节留在「怎么验证？」，本节只指向它。

1. **验收标准**：逐条列本 Phase 承接的两条验收，各写判据、成功与失败三句。
   - 验收 3：判据是九类缺陷各自在真浏览器里被检出，档位与清单一致。
     成功长这样：九条各指到元素与观察量，200% 缩放与键盘焦点有实测结果。
     失败长这样：注入后检不出、region 只是装饰，或拿受控页结果冒真实页面。
   - 验收 4：判据是同一数值差异用同一标尺跑两次得同级，阻断靠可操作性事实。
     成功长这样：字体、间距、颜色三条各得重要档，遮罩那条得阻断档且两次同级。
     失败长这样：两次不同级、把「任务还能点」降档、用像素百分比当阻断依据。

2. **场景**：正常两例、反向两例、负控一例，每个写输入、动作与预期。
   - 正常：输入是受控页在真浏览器里打开，动作是按清单九条 id 逐条观察。
     预期：九条各检出一次并带上观察量，缺一条或多一条都不算。
   - 正常二（校准）：输入是四条校准页，动作是同一标尺各跑两次。
     预期：三条重要、一条阻断，两次档位相同，理由指到刻度与负例。
   - 反向一（档位越界）：输入是把窄屏那条写成表外档位，或把阻断降成重要。
     动作是跑契约测试。
     预期：各被拒收，档位不越出三档。
   - 反向二（结构对不上）：输入是删掉一条 `data-region` 的受控页副本。
     动作是跑契约测试。
     预期：清单与页面 id 对不上，被拒收。
   - 负控（去掉遮罩）：输入是把阻断页的遮罩层删掉的副本。
     动作是跑同一标尺。
     预期：不再判阻断；
     仍判阻断说明只认字段不认事实。

3. **环境与数据**：写环境、数据、谁提供、来源与清理；缺的写 incomplete。
   - 环境：本机真浏览器加静态服务；受控页单文件、内联样式与脚本、无外链。
   - 数据：九条 region 的预置缺陷，加四条校准页六个读数：20 对 17、16 对 8、两色值。
     阻断页不靠数值，只靠主操作点不动这一件事实。
   - 数据真实性：64 位哈希用 `9efb7e57` 重复八次，不引真实数据，也不冒业务样本。
   - 来源：九类 region 与六个刻度取自契约决定 6、7，与判据正文同一份口径。
   - 谁提供：夹具由本Phase实施者交；
     真浏览器执行者归末验收，修源归阶段4。
   - 视口：基准 1440，窄屏 640 与 320 两个断点；三宽矩阵还没存进清单。
     这一格记 incomplete，补法是新加一个数组，不改现有五个字段。
   - 构造与清理：本 Phase 只落文件；注入与跑页归末验收；不写 C05 归档。
   - 规划时的缺口：真实注入、检出、修复与两次定级当时尚未执行，状态记incomplete。
     原因：本Phase只交静态夹具；
     负责方是末验收执行者与阶段4的修源者。

4. **用例**：五条用例，逐条给对应验收、操作、预期与判定方式。
   - 用例一（对应验收 3）：打开受控页，按清单九条 id 逐条观察并记检出与档位。
     判定：看是否指到元素与观察量；契约测试退出 0 不算判定。
   - 用例二（对应验收 3·负控）：删掉固定底栏那条的定位，再观察一次。
     判定：该条不再被判阻断；仍判阻断即说明只认结构、不认事实。
   - 用例三（对应验收 4）：同一标尺跑字体、间距、颜色三页各两次，记两次档位。
     判定：三次都落重要档且两次同级；理由要指到刻度，不是「看着差」。
   - 用例四（对应验收 4·阻断）：打开阻断页，取按钮中心做命中测试再点一次。
     判定：命中落在遮罩、主操作点不动才算阻断；像素百分比不算依据。
   - 用例五（负控·清单）：内存副本写表外档位、降档、校准置空、删 `data-region`。
     判定：四类各被拒；
     门禁命令见「怎么验证？」，它只证互指与档位词。
     它证不了缺陷真触发，也证不了两次同级，因此不是本条的判定器。

5. **谁判**：执行者与判者都换上下文，本 Phase 只交夹具不自判验收。
   - 执行者：末验收 Phase 的独立执行者，另一会话，拿夹具与真浏览器自己跑。
   - 负控判者：独立测试子代理跑契约测试与内存副本四类，不碰真实夹具。
   - 时点：实现就绪后独立审测；有问题回原作者修，再由受影响方复验。
     审查、测试明确回报且验收满足后，原作者才确认开发完成；边写边自判不算。
   - 判者不改清单、不改档位、不补 region，只按原判据读观察量。
   - 自查的绿只说明结构齐，不能当验收结论，也不进 Done 的状态词。

6. **失败回修与重验**：失败信号、分诊、回 owner、重验与结论更新各一句。
   - 失败信号：注入后检不出、档位越界、两次不同级、阻断只靠像素百分比。
     另一类信号是 region 在页面里存在却触发不了，那说明缺陷是装饰性的。
   - 分诊：由独立判者分；
     夹具结构回本Phase，档位与刻度回阶段1。
   - 回owner：结构回本Phase；
     三档词与刻度回阶段1负责人；
     真检出与修源回阶段4。
   - 重验：补完 region 后重跑同一注入，并重验受影响面（同维度其它 region）。
     同刻度受影响时，另外两页也要各跑一次，别只测被改的那一页。
   - 结论更新：清单与状态只按新原件改，原失败保留；不改刻度凑绿。
   - 重报：执行者与独立判者重报，夹具作者不自签检出可用。

7. **承接**：结论落在本文件的状态行与具名原件上，下游照这两处读。

## 失败了怎么办？

结构、档位、刻度、词表与样本钉对不上都会停，每处写清回谁、改哪件。

- **风险**：缺陷写成装饰性 region，检测描述与页面结构对不上。
- **影响**：末验收注入时检不出，九类映射失真。
- **缓解**：检测必须指向可观察量，测试至少核选择器指向的 id 存在。
- **触发条件**：任一 region 的检测描述与结构对不上，或门禁非零。
- **回滚**：只撤对应 region 的页面与清单条目，保留其余八条。
- **无法回滚**：把该 region 的期望档位交回 P1 负责人与末验收。
- **无法回滚时**：本 Phase 只留结构事实，不补签该档位。
- **刻度冲突**：停本卡，回规格与刻度记录核对六个字面值，不改测试放宽。

失败分派：
- region 缺失或 id 对不上：停本卡，按九行表逐条补，不合并 region、不改 id 命名。
- 档位越界：停本卡，回 P1 判据包核三档词，不换第二套词。
- 刻度与判据正文的默认刻度不一致：停本卡，回 P1 负责人与判据正文核对。
- 校准词表变更：停本卡，回那份冻结测试的负责人取新词。
- 回滚后由受影响方复验；复验没回来之前不称完成。
