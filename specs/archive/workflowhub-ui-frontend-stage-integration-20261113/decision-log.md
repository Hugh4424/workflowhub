# 决策日志（decision-log）

这是一份决策记录：任务定方向时定下的做法、边界、验收和风险。
后面的排阶段与写代码照着它走；它不写实现，也不改产品代码。

## 这些词各指什么：UI、阶段、设计源、接线、冷读？

先给十三个高频词各一句解释，后文不再重复；其余术语第一次出现时当场解释。

- UI：用户看得见、能点的界面部分，包括页面、按钮、跳转和样式。
- PRD：产品需求文档，写清产品要做什么、给谁用。
- 阶段：一次任务分四步走，分别是定方向、写需求、排阶段、写代码与验收。
- Phase：排阶段排出来的单个实施阶段，一个 Phase 是一次可独立验收的实施。
- 设计源：照着做界面的原件，可以是设计稿，也可以是已经上线的现有页面。
- 接线：把界面上的数据和按钮接到真后台，而不是假数据、假动作。
- 组件沉淀：把这次写出的可复用界面部件写回组件规范，下次直接复用。
- 冷读：找没参与的人只读材料，看能不能说清改什么、为什么、边界、怎么验、还剩什么。
- 工作包：一块能独立交付、能单独验收的工作。
- 收敛：把一个包讨论到改什么、为什么、怎么做、怎么验、还剩什么没定都清楚。
- 取舍：在几个做法里选定一个，并写清哪些被否、代价是什么。
- 证据：能回读的原件，比如截图、检查记录、命令输出。
- 校验器：自动检查材料格式的程序；它只报读数，不替人判通过。

### 工作包 9：先定“逐包收敛”怎么做

**结果**：每个包写出一张十格方案卡，再由没参与的人冷读；读不出五问就不算收敛。

**对应需求**：需求 14（收敛清楚再做细节审查）、需求 16（现在只会重复需求、满篇黑话）、
需求 12（变更可验证）。

**现状缺口**：定方向第 9 步现在只有十列台账和五类分析，每格只要求“有结论”。
台账是逐项对照的表；十列是包、目标、边界、方案、验收、风险、依赖、消费者、未决、状态。
五类分析是目标、范围、数据状态、验收、约束。
这十列没要求写方案、被否替代、反例和白话复述，执行者容易把原始需求换个说法填进去。
读者最后还是不知道要改什么、为什么、怎么验。

**方案与取舍**：在现有第 9 步里加十格方案卡，不新增步骤，不新增审查轮。
十格是结果、对应需求、现状缺口、方案与取舍、边界、数据与状态、验收、风险与回退、未决、白话复述。
写完由独立助手冷读五问：改什么、为什么、边界、怎么验、还有什么没定。
答不出就改。
被否替代两个：只要求“写详细点”，没法判；新增一轮收敛审查，成本高。

- 改动：定方向技能第 9 步、步骤表第 9 步的可见结果与证据、决策记录模板或收敛原件。

**边界**：不改十列台账与五类分析的机器形状，不新建第二份材料。
卡是第 9 步的正文组织方式，不是另立一份文件；UI 包与非 UI 包同样适用。

**数据与状态**：输入是原始需求、调研、讨论与当前阶段文件；输出是方案卡与冷读记录。
状态分草稿、待冷读、已冷读、未收敛；未决不为空就不算收敛。

**验收**：通过——拿本任务一个包做样例，先用定方向那个 UI 包。
独立读者只读卡能答五问；每条需求有真实落点；至少有一个被否替代；每条验收有反例；
卡里没有未解释的黑话。
失败——读者答不出；卡只是复述需求；没有替代与取舍；验收没有反例；出现未解释黑话。
反例——把旧版“目标：支持 UI；验收：通过”给读者，读者应指出它缺方案、验收和反例。
把卡里的方案删掉，冷读必须失败。
谁判：独立读者加你抽查。

**风险与回退**：卡变长，就每格只写一句结论，细节放表。
冷读主观，就固定五问，并坚持答不出即失败。
卡变成填表负担，就退回十列台账，只保留方案、验收、反例、白话四格。

**未决**：无。
冷读由独立助手做、你抽查；模板放在决策记录模板里。

**白话复述**：以后每个包不能只说“要做 X”，要写清现在为什么做不到、打算怎么改、
不做什么、怎么证明改好了、还有什么没定。
写完找个没参与的人读，读不懂就不算收敛。

### 工作包 1：定方向时认出 UI，并留下设计依据

**结果**：含 UI 的任务在定方向时被认出，决策记录里留下页面范围、设计稿来源与验收基准。
不含 UI 的任务一步也不多。

**对应需求**：需求 3（认出 UI、做调研、问设计稿）、需求 9（能力真接线）、需求 12（可验证）。

**现状缺口**：第 1 步只写一句“按三个来源识别 UI”，什么也没留下；不问设计稿从哪来。
细节审查不查 UI 需求与设计稿有没有收敛。

**方案与取舍**：在现有十五步里只加一条 UI 才走的支路；支路是满足条件才多走的一小段。
十五步里 UI 任务只多这些动作：
第 1 步做三个来源判定，并写一张五行卡；设计稿问题并进第一次提问，不另开一轮。
第 2、3 步调研顺带查现有页面、路由、组件与规范；只有设计源或还原口径不清才加外部调研。
第 4、5 步骨架仍按现有四查落位；设计源四路的选择与无稿风险并进骨架确认，不另开确认。
第 8、9 步只对 UI 包，在“数据与状态”“成功失败验收”两格里补设计源、对照项、通过失败与反例。
第 9 步的验收五问只加一个子问：“设计源和对照基准可用吗”。
第 10 步细节审查加一个设计审查镜头，核对 UI 需求是否收敛、设计源是否确认、验收是否可判。
第 11–15 步：质询只在 UI 术语或争议出现时处理；写稿、核对、最终确认、交接各带一行 UI 引用。
复用现有技能：设计源准备、原型渲染、设计审查、深度调研、知识图、提问、文档质询，不新增技能。
成本边界：非 UI 任务零额外步骤、零额外问题、零额外审查镜头。
UI 任务只多一张五行卡、首次提问里一个设计源问题、逐包收敛里两个格子、细节审查一个镜头。
判定标准是“多出来的每个动作都能被 UI 任务的实际需要解释”，不能变成第二个定方向流程。

#### 决定 1 — 用决策记录的“UI 范围与设计基准”当唯一共享输入。

- 做什么：按十五步表接入，第 1 步产出“UI 范围与设计基准”，后面各步逐步消费它。
  记录细度按页面、路由、组件加设计源加验收基准，不展开到每个状态乘每个视口。
- 不做什么：不新建阶段或检查门，不建第二份 UI 台账或独立状态对象；非 UI 任务不写空壳。
- 风险：字段太多会变成填表；只保留下游真要读的字段，缺项写缺口，不填假值。
- 改动：定方向技能与步骤表、技能依赖表；决策记录模板只加一节，不改机器字段。

#### 决定 2 — UI 识别看三个来源，非 UI 必须写理由。

- 做什么：三个来源是原始页面或交互要求、真实路由与组件与技术栈、已接受计划或实际前端变更。
  任一命中就按 UI 处理；三个来源都没有时，写清非 UI 的理由与依据。
- 不做什么：不靠文件名、调用者标签或旧记录猜；不把“没有页面”直接当非 UI。
- 风险：三个来源都缺时可能误判；缺源记“未知”加负责人，不默认非 UI。
- 改动：同决定 1；方向审查材料与机器读取的字段各加一个可选 UI 字段，只在 UI 任务时非空。

#### 决定 3 — 设计源固定四路，没有稿必须你自己选。

- 做什么：四路逐路写清触发、负责人与证据。
  内部设计稿：设计方在具体页面或区块标“可开发”，并给注解。
  外部设计稿：外部设计方提供，要有来源、版本、可用范围与验收基准。
  沿用现有页面：以现有真实页面为基准，记页面、路由、版本。
  无稿：你在“先做原型或设计稿”与“直接实现并接受风险”之间选，记下选择与后果。
  四路都要记来源、负责人、可用时间、验收基准与缺项；信息不足记“未知”加负责人，不默认通过。
  设计稿能不能开工不做形式化确认，也不加新字段；在聊天里说清并记下你的答复即可。
  没有设计稿直接做，必须你明确接受风险。
- 不做什么：不默认“没有设计稿也能做”；不把技能自述当设计源；不替你接受设计偏差。
- 风险：设计源迟到会卡住整个 UI 阶段；记下可用时间与卡在哪里，不用“以后再说”过关。
- 改动：定方向第 1、3、5、9 步；设计源准备、原型渲染、设计审查三处技能的触发条件。

**边界**：只定识别、调研、设计源与验收依据，不写实现，不选具体设计工具。
不新建阶段或检查门；不把“设计稿可开工”做成形式化确认或新字段。

**数据与状态**：输入是你原始要求、现有页面与组件、你的答复。
输出是决策记录里的五行卡，位置在“原始需求”之后。
状态分 UI、非 UI、不确定，不确定记“未知”加负责人。
消费者是写需求、排阶段、写代码三处作者与独立审查者。

**验收**：通过——UI 样例出现五行卡、设计稿问题，细节审查能查出缺设计源。
非 UI 样例不多任何动作；无稿时记下你接受风险的答复。
失败——UI 任务没有这一节；非 UI 任务被硬塞；设计源缺失却写“已具备”。
无稿没有你的风险接受；细节审查查不出缺设计源。
反例——删掉设计稿那一行，审查必须报；把非 UI 样例标成 UI，必须被识别为误判。
谁判：细节审查的独立审查者先判，可接受偏差由你最终确认；实现者不能自签。

**风险与回退**：卡没人读，就由细节审查固定检查。
支路变重，就只让 UI 触发。
改坏流程，就恢复卡与触发条件的原字节，再跑一遍非 UI 样例。

**未决**：无。
卡片位置、内部必查外部按缺口、独立审查加你确认，三件都已定。

**白话复述**：以后接任务先看有没有页面、按钮、跳转。
有就多问设计稿从哪来、按什么验收并记下来；没有就照原样走。

### 工作包 2：写需求时排出 UI 任务链

**结果**：含 UI 的 PRD 会多出页面清单、设计任务（需要时）、前端底座（跨多页或多任务时）、
逐任务接线、视觉还原验收、组件复用与沉淀、页面数据清单。
不含 UI 的 PRD 不多一段。

**对应需求**：需求 4（阶段里要有 UI 步骤与验收）、需求 7（写需求阶段没有 UI 安排）、需求 9、需求 12。

**现状缺口**：写需求阶段只有一句“涉及 UI 用现有方法展示设计”。
任务地图没有设计任务、前端底座与逐任务接线；验收只写“页面能用”。

**方案与取舍**：只在两个时点加 UI 内容：第一次出任务地图时、写完整 PRD 时。
不新增作者，PRD 只写两遍，先出地图，再写完整版。
出地图时，UI 任务写用户看得见的结果；需要设计就先排设计任务。
跨多页或多任务才排前端底座，就是先用样例数据与统一数据接口把界面撑起来。
写完整 PRD 时，每个 UI 任务补接线、视觉、组件三段；PRD 作者另写一张页面数据清单。
最后仍只审一次，UI 多一个设计角度。
被否替代两个：另写一份 UI PRD，等于第二权威；每个 UI 都排底座，过重。

#### 决定 4 — 写需求阶段必须安排 UI 任务链。

- 做什么：UI 任务地图至少含设计任务（需要时）、前端底座、逐任务接线、页面数据清单。
  还要含视觉还原验收、组件复用与沉淀、设计偏差处置。
  接线是假数据换真数据、假动作换真动作；每个 UI 任务的验收写清改哪些页面区域。
  还要写清哪些数据或按钮变真、后台值变化页面是否跟着变、后台失败是否显示失败态。
- 不做什么：不把“页面做完”当“接线完成”；不让后续任务只做后台；不新增第二份 PRD。
- 风险：任务过多会拖长规划；按真实 UI 范围裁剪，纯后台任务不硬塞。
- 改动：写需求技能与步骤表、技能依赖表；必要时在 PRD 任务卡模板加 UI 字段。

**边界**：只改写需求的规划方法与步骤登记，不写产品 PRD 正文，也不写页面代码。
不新增第二份 PRD，不新增内容作者，纯后台任务不硬塞，不做形式化开工确认。

**数据与状态**：输入是 UI 五行卡、原始需求与现有页面。
输出是页面清单、设计任务、前端底座、逐任务接线、视觉验收、组件沉淀、页面数据清单。
消费者是排阶段、写代码与审查。
前端底座只在跨多页或多任务时排，这一点已定。

**验收**：通过——UI 样例（需要设计且跨多页或多任务）出现清单、设计任务、前端底座与三段验收。
单页且有设计稿的样例，不得被强加设计任务或前端底座。
每个 UI 任务写清页面区域、数据或动作的真假变化、失败态。
失败——只有“做页面”没有接线；设计稿验收缺失；页面数据清单缺失；把后台任务硬塞 UI 验收。
反例——删掉“逐任务接线”，审查必须报；给纯后台任务加 UI 验收，必须被识别为越界；
单页有稿样例被强加底座，必须被识别为过度规划。
谁判：独立审查者按写需求阶段的审查五件事加 UI 面。

**风险与回退**：PRD 变长，就只给 UI 任务加三段。
底座过多，就只在跨多页或多任务时排；设计任务拖慢，就有稿不排。
回退时删掉新增的段。

**未决**：无。
底座何时排、接线验收写多宽、页面数据清单谁写，三件都已定。

**白话复述**：写 PRD 遇到 UI，不能只写“做个页面”。
要写清设不设计、要不要先用假数据搭底座、每个任务怎么接线、怎么对照设计稿、
哪些组件要沉淀；再加一张页面数据表。

### 工作包 3：排阶段时给碰页面的 Phase 六项验收

**结果**：碰页面、路由、组件或样式的 Phase 会多出六项 UI 验收、独立设计审查和组件回写位置。
不碰的不加。

**对应需求**：需求 4（Phase 里写 UI 步骤与验收）、需求 9、需求 12。

**现状缺口**：排阶段第 5 步已有设计稿准备与八维设计审查，但阶段验收只写功能。
第 9 步三项 UI 事实缺一项就不加设计审查；组件没有回写位置。
第 5 步“要不要用户答复”的标记，和“没有答复时怎么走”，都有错。

**方案与取舍**：第 5 步继续用现有设计稿准备、原型与八维设计审查，不做形式确认。
八维是业务任务、信息架构、交互状态、内容数据、视觉规范、响应式、无障碍、真实代码交接。
第 7 步给 UI 阶段在现有六件验收里补六项。
六项是设计源、页面/路由/组件与状态乘视口、视觉对照项、前端质量门、
组件复用与沉淀、独立设计审查与证据。
六件验收是目标、怎么操作、什么条件、怎么算通过（含反例）、真跑还是替代、谁判与证据。
第 9 步：三项 UI 事实是原始要求是不是 UI、项目有没有真实页面与路由与组件、
已接受计划或实际改动是不是 UI。
三项缺一项、但本阶段碰页面或路由或组件或样式时，仍加设计审查。
同时修正第 5 步的用户答复标记与没有答复时的出口，别把要你答的问题当成不需要回复。
组件沉淀要写清回写到哪个位置、谁读。
被否替代两个：每个阶段都加，变成噪音；只写一条视觉检查，无法判定。

#### 决定 5 — 排阶段的 UI Phase 固定六个字段。

- 做什么：六个字段是设计源引用、页面/路由/组件与状态乘视口、视觉还原验收项、
  前端质量门、组件复用与沉淀、设计审查与证据。
  前端质量门含组件质量、浏览器验收、响应式、无障碍、性能预算。
  非 UI Phase 不写这六项，写不适用理由。
- 不做什么：不把 UI 字段做成所有 Phase 的必填噪音；不把设计审查留给实现者自判。
- 风险：字段过多会压垮小改动；按 UI 范围分级，给最小充分验收。
- 历史材料：旧决策记录、规格、Phase 缺新 UI 字段时按“未知”处理并补问。
  不追溯判旧任务失败；历史 UI 与非 UI 样本各留一个，验证不会误判或静默跳过。
- 改动：排阶段技能与步骤表、技能依赖表；阶段模板。
  第 5 步的答复标记改成“该步需要真实答复”，与正文一致；UI 设计稿确认并入这次答复，不另开确认门。

**边界**：不新增阶段、检查门或审查轮；不要求非 UI Phase 写。
不在排阶段写页面代码，也不替代写代码阶段的验收。

**数据与状态**：输入是 PRD、UI 五行卡、设计稿与现有页面。
输出是六项 UI 验收、设计审查、组件回写位置；消费者是写代码、审查与你。

**验收**：通过——UI Phase 出现六项、设计审查、组件回写；非 UI Phase 不多。
缺设计源时仍加设计审查；第 5 步不再吞掉你的答复。
失败——UI Phase 缺视觉验收；非 UI Phase 被硬塞；缺源被免审；用户答复步骤被标成不需要回复。
反例——删掉视觉验收，审查必须拦；把非 UI Phase 加上 UI 字段，必须被识别为噪音。
谁判：独立审查者与 Phase 作者交叉。

**风险与回退**：阶段卡变长，就只给 UI 加。
设计审查过重，就只在碰页面、路由、组件或样式时加。
组件沉淀喊口号，就强制写回写位置和读的人。
回退时恢复六项与触发条件。

**未决**：无。容差已定：不设统一数值，按逐项对照；可接受偏差由你在阶段验收时确认。

**白话复述**：排阶段碰到 UI，不能只写“功能做完”。
要写清对照哪份设计稿、看哪些页面和状态、怎么算还原、前端质量怎么查、
组件怎么沉淀、谁独立看设计；缺设计稿也要审。

### 工作包 4：写代码时出视觉对照与前端质量证据

**结果**：含 UI 的 Phase 会多出设计稿对照证据、前端质量记录、组件复用与沉淀结论。
不含 UI 的 Phase 照原样走。

**对应需求**：需求 5（视觉还原、高保真、设计稿对齐、前端开发、前端质量、组件规范、
组件沉淀、像素级）、需求 9、需求 12。

**现状缺口**：写代码第 6 步有浏览器验收、第 7 步有页面审计。
页面审计是逐页检查结构与可访问性的检查。
可访问性就是无障碍：色弱、只用键盘、用读屏的人也能用。
但页面审计不要求拿设计稿逐项对照；没有截图和差异。
组件不要求写回；代码审查没有设计角度。

**方案与取舍**：第 1 步读设计稿和已批准的原型；第 6 步给 UI 阶段加设计稿对照。
对照固定 1440×900 与 390×844 两个尺寸，固定浏览器与系统默认字体，缩放 100%，固定数据。
截图并排看，逐项写通过、差异、你接受的偏差。
通过条件是指定对照项逐项通过，或只余你明确接受的小偏差。
失败条件是任一对照项有未接受差异、缺证据、或用功能测试代替视觉验收。
不接受“看起来差不多”；关键区域仍可做像素对比，就是把两张截图按点逐个比。

200% 缩放：主操作可达、不裁切、页面不出现横向滚动；

测不到就记不可用，不写通过。

#### 决定 6 — 写代码阶段的视觉还原与前端质量步骤。

- 做什么：UI 阶段实施步骤加读设计源、组件复用与沉淀、实现、视觉对照、响应式与无障碍、
  前端测试、独立设计审查、浏览器验收。
  视觉对照固定比较基准（设计源版本）、环境（浏览器、字体、缩放）、视口与状态、
  数据夹具、截图或差异证据。
- 不做什么：不承诺判不了的“像素完全一致”；不以功能测试通过代替 UI 通过。
  不让实现者给自己的视觉验收签字。
- 风险：截图差异受环境影响；固定环境、固定视口、固定数据，差异逐条归属。
- 改动：写代码技能与步骤表、技能依赖表、页面审计口径；设计审查技能在写代码阶段的范围。

**边界**：不新增步骤或审查轮；不要求非 UI 阶段截图；不承诺像素完全一致。
不让实现者自签，也不改设计稿。

**数据与状态**：输入是 Phase 卡、设计稿、已批准原型、现有页面。
输出是截图与差异、前端质量记录、组件沉淀结论、审查记录。
截图和差异放任务证据区；差异形式是并排加逐项文字，这一点已定。
审查材料要用的七项界面判定字段是：UI 适用性、UI 合同、组件质量图、真实消费者、
状态所有者、类型化视图模型、样式令牌所有者；机器字段名见审查材料清单。

**验收**：通过——UI 阶段出现规定尺寸与状态的截图、逐项差异、你接受的偏差、组件沉淀记录。
失败——只跑功能测试就判 UI 通过；没有截图或差异证据；组件复制不沉淀；实现者自签；
200% 缩放或物理读屏缺证据却写通过。
反例——把按钮移到被遮挡的位置但功能仍可点，视觉或浏览器验收必须发现。
复制组件不沉淀，审查必须报。
谁判：独立设计审查者加浏览器验收，不由实现者自判。

**风险与回退**：截图工作量大，就只对 Phase 卡的对照项和关键状态做。
环境误报，就固定浏览器、字体、缩放、视口与数据，差异逐条归属。
组件沉淀喊口号，就强制写回写位置和读的人。
回退时去掉新增证据与审查角度。

**未决**：无。截图位置、差异形式、回写目标、容差与可接受偏差的判定都已定。

**白话复述**：写 UI 不能只看“功能能点”。
要按规定尺寸和状态截图，和设计稿并排看，逐项说哪里一样、哪里不一样、哪些你接受。

### 工作包 5：审查加 UI 六问

**未决**：无。

### 工作包 8：用真实页面走一遍四个阶段

**结果**：v15 页面和 Downloads/UI 的设计源走完四个阶段，五组故意破坏都被对应阶段或审查拦住。
证据可回读。

**对应需求**：需求 2、需求 6、需求 9、需求 12。

**现状缺口**：前七个包只改方法，没证明真到页面能跑；文档和脚本只能证明“写了”。

**方案与取舍**：用 v15 页面和 /Users/Hugh/Downloads/UI 的设计源，按新方法走四个阶段。
四个阶段是：定方向出五行卡、写需求出页面清单与接线、排阶段出六项验收、
写代码出截图对照与组件沉淀。
正常路径与每组破坏都从真实阶段入口跑，保留调用事实、技能触发、下游读回与失败信号；
不只检查生成材料，手工补写材料不算通过。
本演练不重跑 C09 的双路径与六指标、C10 的发布与接入；
这两项引用原卡验收，若要重跑另开任务。
五组破坏与该拦住它们的位置如下：
①删设计源，定方向第 1 步与细节审查应报“缺设计源”。
②删视觉验收，排阶段第 7、9 步应报“缺六项验收”。
③功能能点但视觉错，写代码第 6 步设计对照应判失败。
④假数据没接线，写需求阶段的接线验收与写代码第 6 步应判失败。
⑤组件复制不沉淀，写代码第 7 步与审查应报“缺组件沉淀结论”。
加一个本地测试数据源：用静态服务加一个可改的数据文件或小接口；
改一个值，页面刷新后显示新值；把数据改坏或停服务，页面显示失败态。
这样第④组“假数据没接线”才能判真假。
再加一组质量破坏：390 宽下键盘到不了主操作，或 LCP 超过 2.5 秒，写代码与审查必须拦住。
固定浏览器、字体、缩放、视口与数据；截图放任务证据区。
被否替代三个：只看文档，证明不了；新做小样例，不真实；用生产页面，有风险。

#### 决定 10 — 端到端演练用真实页面与真实设计源。

- 做什么：默认用 C11 搬入的真实页面与 Downloads/UI 的对应设计源。
  不可用时退到“一个真实小页面加一份可回读的设计稿或原型”，由你在包 8 收敛时确认。
  四个阶段各产出应有材料；再故意破坏设计源、视觉验收、前端质量、组件沉淀、接线。
  逐项写明应由哪个阶段的哪个消费者、以什么信号拦住。
- 不做什么：不在生产数据上演练；不把演练当产品质量结论；不用示意图代替真实设计源。
- 风险：设计源拿不到会拖住演练；备选是现有页面加明确设计基准。
  仍然拿不到就记缺口，不伪造。
- 改动：演练脚本与记录放任务证据区，不新增产品功能。

**边界**：不碰生产数据与真实用户，不做全量回归，不新增阶段或检查门。
不用示意图代替设计源，不把演练当产品质量结论。

**数据与状态**：输入是 v15 页面、Downloads/UI 设计源、一个可改的本地测试数据源、四个阶段的新方法。
输出是四阶段材料、五组破坏记录、截图与差异；读者是你与最终验收者。
没拦住就回对应包修，不改演练判据。

**验收**：通过——四阶段材料齐全；五组破坏逐组被对应阶段或审查拦住并留下信号；
本地数据源改值后页面跟着变，停服务或坏数据时页面显示失败态；质量破坏被拦；
每次运行有真实阶段入口的调用事实与下游读回。
正常路径能走完；证据可回读。
失败——只读文档不真跑；手工补写材料；破坏一处没人拦；用示意图代替设计源；演练污染生产数据。
把 C09/C10 原卡验收写成已重验。
破坏没拦住却改演练。
反例——把设计源删掉仍走完四个阶段，必须判失败；把视觉验收删掉仍判通过，必须判失败。
谁判：你加没参与实现的独立验收者。

**风险与回退**：页面或设计源不可用，就换等价样例或记缺口，不伪造。
环境噪声，就固定环境；演练变成改产品，就只在隔离样例或工作副本里做。
破坏没拦住却改演练，就回对应包修，不改判据。

**未决**：无。页面与设计源定为 v15 加 Downloads/UI，环境是固定浏览器加静态服务；只有不可用时才退等价样例，由你确认。

**白话复述**：选 v15 和 Downloads/UI，按新方法走四个阶段。
故意弄坏五处，看是不是每处都有人拦；没拦住就回去修方法，不是改演练；证据留住。
