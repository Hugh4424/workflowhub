# Phase P4 — 只读终末验收与回退核对

本文件写给 P4 的实施者、独立读者与用户；读完要能只读核完全部判据，
并说清哪一步能单独回退、哪一步不能。
全局目标与唯一判据在 `spec.md`，本文件只写 P4 的实现增量，不复制第二份判据。
本文件是草稿：实际执行状态归任务事实库，这里不写「已跑过」。

> 写作标准：`skills/material-writing/SKILL.md` 的「材料写作标准（唯一）」是唯一标准。
> 本文件不复述标准，只说明自己的例外。
> 例外一：命令与路径逐处不折行，会超过 80 字；每处都是可直接复制的原件地址。
> 例外二：文件末「机器字段」块与任务卡的 17 个字段名按原词逐字读取，不改名、不翻译。
> 例外三：`git show` 一类命令按原词引用，占位符 `<sha>` 与 `<路径>` 不替换成例子。
> 例外四：验收段标题后括注规格里的验收编号，供机器追踪；正文其余处只用中文序号。

本文件的词先解释，后文只用这一次解释。
只读提交核对：只跑 `git show`、`git log` 与 `git status`，不 revert、不建分支、不改工作树。
写集：一个 Phase 允许改的精确文件路径清单；本 Phase 的写集为空，只写自己申报的证据件。
覆盖表：把每条需求、每条验收各自落到某个 Phase 与某条证据的对照表。
档位：验收结论用的一组固定词，本次只用 `pass`、`incomplete`、`unavailable`。
判定器：判真假的那一条断言，编号前缀 `ORACLE-`。
用户独占确认：全任务只有一处要用户本人答复，它只拦最终收口。
纯指针索引：只存行与指针、不承载正文的 `phases/index.md`。
Supersedes：新件声明它替代哪一份旧件的字段，回退时按它找旧件。
合成输入：按真实形状在临时目录造出的小样本，用来做负控，不碰真实提交或真实仓。

## 这一 Phase 交出什么？

交付一份只读的终末结论：每条验收一行、每行一个档位与一条证据路径。

- **本 Phase 结果**：覆盖表齐、提交可回退、静态检查逐条有退出码、用户有一次答复。
- **非目标**：不修 P1 到 P3 的缺陷，也不回写它们的材料。
  理由：修复要回原 Phase 的作者；本 Phase 只写自己申报的证据件。
- **非目标之二**：不做真实 revert 演练。
  理由：演练会改工作树，与「只读终末验收」冲突（`decision-log.md:186`）。
- **改动前**：前三份 Phase 的 Done、证据件与提交散在各自材料里，没有一张总表。
- **改动后**：一张覆盖表、一份提交核对、一份静态检查清单、一份读者记录。
- **与相邻 Phase 的边界**：P1 到 P3 交材料与提交，本 Phase 只读；不回头改它们。
- **主要风险**：把「命令退出 0」当成整体通过。
  若因它返工，替代走法是逐条读证据并写缺口，不用计数代替逐条。
- **下一步**：用户按规格的 Appendix A 给一次真实答复，收口结束。
- **动手前必读**：`spec.md` 的 Appendix A 与 Appendix B、三份 Phase 的 Done、
  `phases/index.md` 的写入集列、本文件的「验收 Phase 才能做的检查」。
- **未决事实**：决策日志第 200 行仍写「细节审查待发起」，与原件不符（规格未决 2），
  本 Phase 按原件读，不改日志。
  验收判据里的 `tools/cli/check-reader-record.mjs` 实际在
  `skills/spec-plan/scripts/` 下，本文件按真实路径写，差异交 spec 作者。
  验收计数按三层口径核：唯一验收编号 219（202 条 `AC-Tnn-n` 加 17 条 T19 的
  A/B/C 形式）、定义行 166（112 条加粗加 54 条不加粗）、文件行号 16 处跨 9 个文件。

## 这一 Phase 怎么验收？

三笔账先算；八条验收各写一小段，判法与成本都回 spec 的 Appendix A。
本节的分钟数只是活动成本估算，不是时间盒；到时不停手，也不据此减判据。

### 三笔账

- **成本账**：八条验收的七字段逐个引自 `spec.md` 的 Appendix A。
  串行相加 190 活动分钟（25 + 25 + 15 + 25 + 30 + 40 + 20 + 10）。
  并行组只有一组：静态检查与终末全绿共用同一批命令，取最大值 30，
  替下 25 加 30 的 55 分钟，减 25。
  共享准备 15 分钟：提交清单、写集清单、读者口径各一份。
  重试预留 20 分钟，按每条一次重放预留。
  合计 `acceptance_cost_total=200 active_min`。
- **资源账**：仓内 git 与既有命令；外部旧件与它的字节证据；
  三条收口命令与十条定向契约测试都在仓内。
  读者记录格式复用 `skills/spec-plan/scripts/check-reader-record.mjs`。
- **范围账**：八条都证「本任务的全部材料与提交能独立复核」这一件事。
  前三个 Phase 的 20 条验收由本 Phase 逐条消费，写成供件，不写承接。

- `phase_budget` 四项如下，值按原词读：
  `{soft_min:220,hard_min:440,variance_threshold:1.5,source:provisional}`。
  220 与 440 是从 200 活动分钟按 1.1 与 2.2 倍取的待校准值，不是实测。
  这两项只是估算，不设到时停止，也不因为超了就砍判据。

### 档位与用户判吗

## 怎么验证？

验证就是只读复核：git 输出、命令退出码、读者复读三样各管一段。

- **验证策略**：逐条跑、逐条记；不用「全绿」代替逐条结论。
- **开工前四要素**：判什么、怎么判、证据从哪来、拿不到怎么办，四条缺一不开工。
- **判定方式**：五条机器可判（验收 1、2、4、5、7），三条只能人读（3、6、8）。
  不制造仪式性 RED：本 Phase 不改东西，RED 只来自断言在材料不全时非零；
  每条红都写归因，setup 失败与目标断言失败分开记。
- **只读承诺**：全程 `git status` 前后一致；不 revert、不建分支、不写工作树。
  真 revert 演练不做，等价边界是旧字节哈希可重算相等，并写进证据件。
- **不做全量重跑**：只跑十条定向契约测试、一条一致性检查与三条收口命令。
- **负控只用合成输入**：改字节、删映射、改测试、造提交都在临时目录的副本里做，
  不碰真实提交、真实测试与外部仓；跑完即删副本。
- **两个根别混**：证据路径一律写成 `planned: 任务根/quality/...`；`任务根` 指任务库
  里的任务目录，不是 worktree 仓根。仓内命令与测试路径（`tools/…`、`skills/…`、
  `tests/…`）才相对 worktree 根。`worktree 根/quality/evidence/` 也真实存在，
  不写前缀会读错。
- **cwd 分两处，别混**：结构检查与契约测试在认证 worktree 根执行，
  `--root "$PWD"` 里的 `$PWD` 就是工作树根，不是主仓；
  读写 `任务根/quality/` 证据件的命令在任务根执行，路径按任务根相对写。
  只有任务根证据与外部文件用绝对路径，其余一律 `$PWD` 或相对路径。

**覆盖上限**：本 Phase 只证材料与提交能独立复核，不证方法在新任务上更快，
也不证 PaperBuilder 的工程质量。
**显式不覆盖**：不证长窗结论；不证外部仓库能运行；不证用户已确认。

失败了怎么办：失败只报不修，路径写在下面六条。

- **风险**：把「命令绿」当整体通过，漏掉语义缺口。

- **缓解**：逐条写档位，非 `pass` 一律不计通过。
- **回滚**：本 Phase 没有仓内写入，回退对象是结论本身；错的结论撤回并重判。
- **补救与交接**：缺陷回原 Phase 作者修，修完重跑受影响的那一条。
- **触发条件**：任一断言非零且无具名原因；工作树被改；用户答复针对旧稿。
