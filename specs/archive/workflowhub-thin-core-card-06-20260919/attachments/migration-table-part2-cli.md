## 主要发现（供聚合与审查）

1. **基线本就是红的，「删后通过标准」必须先定**：调研 03 §1 实测 `run-checks` 唯一 FAIL 就是 `check-task-record-paths`（7 条），`verify-structure` 缺 README 段，`check-skill-closure` 6 条（wh-review 4 条 sha256 mismatch + 2 条 prompt 引用未声明技能），`smoke-local-skill-dispatch` 抛 `bundle sha256 mismatch`——`npm run check` 五段里至少四段红。因此 B1/P2 收敛 scripts 后不能直接拿 `npm run check` 当回归 oracle，须先按 P2/P8 的 oracle 定义通过标准。
2. **G-3 批次列跨片段不一致，聚合时必须归一**：`check-task-record-paths`（本表 B1/P2 vs 片段 6 G3-24 表 B5/P6）、`task-close.mjs`（本表 B4/P5 vs 片段 6 G3-02 表 B5/P6）、`smoke-local-skill-dispatch`（本表 B5/P6 vs 片段 6 G3-22 表 B4/P5）、`stage-runtime.mjs`（本表 B4/P5 vs 片段 6 G3-13 表「B5/P6（CLI）」）。本表一律取片主规则 + 对应 Phase 卡的直接证据（P2 T003/T004、P5 T017~T023、P6 T024、P7）。
3. **跨片顺序风险（悬空 import 窗口）**：片段 1 把 `runtime/stage/stage-agent-outcome-adapter.mjs` 放在 B4/P5 删除，而 `tools/host/workflowhub-stage-agent-bridge.mjs`（其消费者）在本表 B5/P6 才删——B4→B5 之间 bridge 会 import 不存在的模块。P5 的 gate 不含 bridge 测试（bridge 测试调研 05 排在 B5），暂不阻断，但建议把 bridge 三件前移到 B4/P5 同批删除（见 S-7）。
4. **ADR-013 双层 hash 是一条跨 4 个片段的顺序链，任何一处提前删字段都会让 closure 全红**：`package.json` `check:skill-closure`（本表 B1/P2 摘入口）→ `runtime/evidence/check-skill-closure.mjs`（片段 1/4）→ `runtime/adapters/local-skill-resolver.mjs` hash 比对（MT-1-014，B5/P6）→ `skills/catalog.yaml` 43 条 `local_bundle_hash` + 26 个 `skill-bundle.json` 的 `files[].sha256`（skills/schema 面，B5/P6 最后删）→ `tools/cli/smoke-local-skill-dispatch.mjs`（本表 MT-2-020）与 `runtime/schemas/{skill-catalog,skill-bundle,review-bundle}.schema.json`（片段 4）。本面在链上只承担入口摘除（B1）与 smoke 去 hash（B5），顺序不可换。
5. **B5/P6 在本面承载 30/44 行，是第二大风险集中批**：tools/architecture 9 + tools/host 3 + 旧 CLI 16 + 两个 NARROW 改接同批落地，删除前须按 ADR-006 做一次 G-3 扫描；`tools/architecture` 全删后 AC-27 的「零消费者/无换名残留」证明只能依赖 B1/P2 写入的残留扫描测试与 B6/P7 move-map（不得留旧诊断工具当第二证据面）。
6. **本面 G-3 覆盖 9 项**（G3-01、G3-03、G3-06、G3-08、G3-10、G3-11、G3-13、G3-22、G3-24），其中经本面文件命中的是 G3-06（`stage-runtime.mjs` L11 调用 `assertRuntimeAuthority`）、G3-13（`runReviewRecordWithSignalHandling` 保留）、G3-22（smoke 逃逸断言保留）、G3-24（`check-task-record-paths` 删除）；其余为经 `stage-runtime.mjs`/`task-close.mjs`/`task-bootstrap.mjs` 改接的既有 G-3 项登记。G3-17（multica-sync 阻断保留）不经本面文件，但其消费者 `skills/workflowhub-multica-sync/scripts/multica-skill-sync.mjs` 调用本面 `tools/cli/task-bootstrap.mjs`（MT-2-023）——改接本件时不得改变 task 目录原子发布语义，否则会连带打断 G3-17 的同步前置。
