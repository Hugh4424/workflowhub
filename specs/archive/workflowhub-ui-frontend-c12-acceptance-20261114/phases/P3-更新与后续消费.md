## 这一 Phase 交出什么？

独立验收者可判断副本令牌是否同步到两页，并看到 C10 后续读回仍缺真实原件。
Phase 4 只读回这些事实，不把同任务重放写成后续任务消费。

- **本 Phase 结果**：一次受控更新有前后身份、唯一差异、构建与两页计算值。
- **非目标**：原树修改、额外样式调整、C10 执行、业务验收和发布判断均不交。
- **改动前**：Phase 1 副本保持 `--inline-action-gap:12px` 与已核十九件身份。
- **改动后**：副本仅该令牌变为 16px，两页同步按真实计算值给四值。
- **与相邻 Phase 的边界**：消费 Phase 1 未改副本；交 Phase 4 更新原件和读回缺口。
- **主要风险**：构建绿但页面未消费新值；发生时按计算值判，不改回旧值掩盖。
- **下一步**：Phase 4 首读更新原件；C10 以后实际读回才可恢复后续条件。
- **动手前必读**：Phase 1 交接、decision-log D-008/D-015 与 spec 更新条款。
- **未决事实**：实际计算值、构建结果、引擎会话与清理结果待真跑；C10 原件未取得。

“同步”指副本样式变化被两页实际计算样式消费。
“后续读回”指 C10 在另一真实任务中读取新版，不是 C12 再读一次。

### 验收 4：同步事实与 C10 读回分开判

目标：副本从 12px 到 16px 的唯一变化被两页真实消费，后续读回不冒名。
操作：先核改前身份等于 Phase 1，再改单行、构建并读取两页计算间距。
条件：使用 Phase 1 同一副本与已选引擎；workbench 直读，board 先执行显示操作。
通过/失败：两页都变为 16px 是同步可用；仅一页是部分可用；均未变是不可用。
构建或服务失败使同步未测；C10 缺真实原件时整条 AC-C12-004 保持未测。
故意弄坏：额外改另一文件、只变一页、或把 C12 重放写成 C10，均须被拒。
真跑命令：依次执行任务 3 的 prepare、collect、cleanup 三条原命令。
prepare/collect 成功预期 0；同步不可用不借退出码改判，C10 未测也不伪造 0 证据。
cleanup 预期 0；清理失败保留实际非零，不删除证据或其它进程。
独立判定与证据：`planned: quality/evidence/2026-11-14-301-update-result.json`。
证据计划：判什么=真实同步与后续状态；怎么判=身份、差异、构建和计算值；
证据从哪来=Phase 3 原始件；谁提供=任务 3 执行者，C10 件由 C10 提供；
何时能拿到=更新结束，后续件仅在 C10 真跑后；成本类别=真实更新运行；
拿不到怎么办=同步按事实降级，后续保持未测并写 C10 与恢复条件。
失败回修/STOP：脚本或判词回任务 3；实现缺陷只登记交原 owner，不改回旧值求过。
