## 这一 Phase 交出什么？

独立验收者可从 v15 当前七件字节得到稳定格五维、能力回执、交互和设计对照。
Phase 4 只读回本段原件，不把 C11 旧字节审查冒名为当前复验。

- **本 Phase 结果**：v15 当前稿逐能力首判和稳定格五维均有真实来源。
- **非目标**：v15 修复、查询写入、业务验收、发布判断和新原型均不交。
- **改动前**：当前七件身份已锁，完整新鲜矩阵、交互闭包与八维新审未齐。
- **改动后**：只读静态服务可复放，稳定格、瞬时态和缺口可以分别回读。
- **与相邻 Phase 的边界**：本段与 Phase 1 输入和写集互斥，可并行；不交更新副本。
- **主要风险**：旧 C11 字节或 `pending` 伪稳定格冒名；发生时停止对应格判定。
- **下一步**：Phase 4 读取本段首判、旧新字节差异和未测项。
- **动手前必读**：`spec.md#实现设计全局权威`、decision-log 的矩阵与 UI 准备记录。
- **未决事实**：实际选定引擎、端口、视口偏移、交互终态与 reduced-motion 读数待真跑；
  ego-lite 路由已实测（probe 2026-11-14-008）；v15 十态由页内控件进入，
  状态标记已实读存在，实际 match/mismatch 读数待执行原件。

“稳定格”指 URL 状态在采集时保持且 `state_observation=match` 的页面格。
“pending”是 150ms 后离开的瞬时态，只能另做交互观察，不冒稳定格。

### 验收 2：v15 稳定格五维是正式判据

目标：十稳定态乘三视口（共 30 格）逐格取得五维 JSON、八项身份与状态观察。
操作：裸入口打开后，用页面既有控件进入状态，再复用五个单维采集器：
候选列表单选 `input[name="local-sample"]` → `#demo-use-sample`（ready）→
`#demo-scenario` → `#demo-confirm`（success、empty、error、permission、partial、unknown）；
进入 success 后再点一次 `#demo-confirm` 得 duplicate；`#demo-recover` 得 recovered；
`#demo-reset` 得 unselected；每格记控件序列。
条件：console/network 同导航窗口；目标路由唯一；状态声明不能代替观察。
网关只接受无查询串或唯一 `?source=live` 的目标 URL，状态不从查询串设置。
`pending` 是 150ms 过渡态：点击后等定时器结束、`data-state` 离开 `pending` 再读，
`pending` 期间读数不算稳定格观察。
通过/失败（状态观察唯一口径，见 spec AC-C12-002）：
从 `#demo-result` 的 `data-state` 读状态值、从 `#demo-confirm-panel` 的 `aria-busy` 读忙标记。
`data-state` 等于目标状态且稳定态 `aria-busy` 为 `"false"` 记 `match`；
不一致（`data-state` 不同、`aria-busy` 为 `"true"` 或缺失）记 `mismatch` 并写明哪项不符；
只有 `data-state` 缺失、为空或不是合法状态名、状态确实读不出时才记 `unknown` 并写原因。
有可读 `data-state` 却记 `unknown`，或把 `mismatch` 记成 `match`，都属伪造，本条失败。
`stateObservation(declared,observedUrl)` 只比较网址有无状态声明，v15 固定给 unknown；
该值不得写进覆盖件的 `state_observation.result`，也不得当作记 unknown 的理由。
缺格或缺维在本 AC 级记未测并写原因、不判通过；包级缺稳定格由本卡判包不通过。
故意弄坏：删掉 ready 的一个视格，或把 mismatch 写成 match，检查必须失败。
另一反例：标记可读却记 unknown，或拿网址观察值充覆盖件观察，检查必须失败。
真跑命令：任务 2 的 collect 原命令；完成本次声明的采集范围并按上述口径记录观察时为 0，
缺格、采集失败或未到达的格保实际非零。退出码不替 AC 判词。
独立判定与证据：`planned: quality/evidence/2026-11-14-207-v15-coverage.json`。
`pending` 记录义务：三个视口各留一条（390×844、1280×800、1440×900），
每条含 150ms 定时器事实、离开稳定态的证据与未测原因；少于三条记 incomplete。
该三条义务当前由独立读者人读承接并写进覆盖限制；要升级为自动断言须走 TCR。
证据计划：判什么=稳定格五维与身份；怎么判=逐格核 JSON；证据从哪来=采集器；
谁提供=任务 2 执行者；何时能拿到=矩阵采集结束；成本类别=真实浏览器；
拿不到怎么办=对应格未测并写原因；缺格属包级缺稳定格时判包不通过，AC 级记未测。
失败回修/STOP：回任务 2 修采集或判词；浏览器阻断只修所选引擎，不换引擎。

真实页面命令必须经隔离网关，不得显式强制 agent-browser。

### 定向 RED/GREEN 是什么？

| 目标 | Task | 角色 | gate_cmd 与预期退出码 | 判据与证据 |
| --- | --- | --- | --- | --- |
| v15 稳定格、身份与状态观察 | 任务 2 | RED | `node --test tests/acceptance/c12-v15.test.mjs`；非零 | ORACLE-C12-CAPABILITY；actual `quality/tests/2026-11-14-019-c12-tcr2-final-p2-v15-red.json` |
| 同一断言 | 任务 2 | GREEN | 同命令；0 | ORACLE-C12-CAPABILITY；planned `quality/tests/2026-11-14-202-v15-green.json` |

预写测试由独立测试设计作者固定，目标包括稳定格缺失拒绝、状态 mismatch、
八项身份缺项、pending 不得伪稳定，以及实际加载 CSS 必须进入七件身份。
模块缺失、依赖缺失、浏览器启动失败与测试收集失败均不是目标 RED。
若骨架本来已满足目标，如实记“本来就通过”，不得回退实现造红。

目标 URL 必须传裸入口路由：隔离网关只接受无查询串或原样 `?source=live`，
`?state=` 会在导航前得到 `INVALID_TARGET_SCOPE`。
裸入口按 `initialState()` 落默认 `unselected`，因此三视口的默认格可正常采集。
另外九个稳定态不靠 URL，而靠页面既有控件到达（序列见验收 2），
所以十格五维可采、`pending` 仍按 150ms 瞬时态记未测。
`driveUrlState()` 是 app 闭包内函数、没有挂到 `window`，不能直接调用；
但控件路径足以覆盖十个稳定态，不需要拼接查询串。
状态观察按 AC-C12-002 唯一口径读 `#demo-result[data-state]` 与
`#demo-confirm-panel[aria-busy]`：一致记 match、不一致记 mismatch 并写不符项、
只有标记读不出才 unknown 并写原因；有可读标记却记 unknown 属伪造。
不得写“预期 0 必须通过”这类不可达条款，也不得用 `history.replaceState` 伪造 URL 状态。

任务标识由驱动在 collect 前从 `openTask(...).identity.taskId` 导出为 `BROWSER_QA_TASK_ID`，
再交给网关 `--run`，不是外部缺失项。已实测：导出后以裸路由跑
`node -e 'process.exit(0)'` 得 exit 0，ego-lite 依次产生
ego-workspace-created、lifecycle run=succeeded、finished（closed_space=true），
原件为 `quality/tests/2026-11-14-008-browser-gateway-route-probe.json`。
本段按“驱动导出标识 → gateway → ego-lite owned TaskSpace”执行；
只有导出后仍出现 `EGO_NOT_RUNNING` 或其它真实错误才记 unavailable 并保原错误。
引擎体检必须传具体引擎名：`browser-qa-doctor.sh auto` 返回 exit 1（unsupported_engine=auto）。
auto 合法落到 agent-browser 时，由其自启隔离 Chrome 并在收尾清理。
禁止显式强制 agent-browser 绕过 Ego 拒绝；选定后失败不得换引擎。

预期 prepare 为 0；collect 在完成本次声明的采集范围并按事实记录状态观察时为 0，
缺格、采集失败或未到达的格保实际非零；退出码不替 AC 判词。
报告不以截图或 `pending` 交互件补稳定格。

覆盖上限：本段不证明两页、更新同步、后续读回、物理读屏、业务链或发布。
显式不覆盖：pending 稳定格、完整用户满意判断和未取得的性能字段保持未测。

失败了怎么办：保留首次失败、命令、cwd、执行者、exit、signal、timeout 与原输出。
风险是旧字节或瞬时态冒名；影响是正式条款假绿；缓解是逐格身份与状态观察。
回滚只撤本卡错误 hunk，保留其它改动和失败原件；不得改测试或 v15 求绿。
服务由本段在 collect 后停止，隔离会话由网关收尾；清理失败也保留原始事实。
无法恢复时交任务 2 开发者修脚本，页面缺陷交原 owner，环境缺口交宿主。
