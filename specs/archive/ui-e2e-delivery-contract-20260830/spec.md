## 速读卡（30 秒）

- **一句话需求**：作为 WorkflowHub 用户，当任务涉及界面或需要交付验收时，要从 make-decision 就想清楚、build-spec 能看到高保真原型、build-plan 有验收任务、build-code 真实环境真实数据真跑、证据进任务追踪目录、close 拦得住漏网。
- **核心改动点**：
  - make-decision：UI 判定必问（unknown 不许静默）+ 目标/范围/方案/验收四维收敛检查
  - build-spec：UI 需求必须出高保真原型（基于设计规范+现有组件）+ 迭代确认（宪法 F7 修订为第四处限定确认）

  - close：侧车路径进快照结构报错；质量归档缺事实不漂白；自检只列缺口不阻塞
- **最大影响面**：所有走 WorkflowHub 的任务（本次强制范围为 UI/全栈/高风险用户可见任务）；宪法 F7 条文修订
- **验收信号**：本任务用真实本地命令和任务存储完成 S2-S4：证据进任务目录、侧车被 close 拦截、非 UI 任务缺验收 task 被拒、聚焦回归不破；S1 外部 UI dogfood 延后单独执行

## 1. 问题与紧迫性

F19（PaperBuilder 手动 YAML 编辑器，2026-08-29）是一次真实失败：UI 改动需求在 make-decision 没有讨论交互细节，build-spec 没有设计给用户看，build-plan 没有前端实现和验收测试任务，build-code 最后随便做了点样式、没有真实起端口验收、没有测试留痕；执行证据（8 张截图+报告）被提交进项目主分支，任务追踪目录却完全空白。取证显示这不是单次事故：PaperBuilder main 已混入至少 8 个任务的约 214 个产物文件，workflowhub 自己 main 也被人工清理过 164 个根目录产物；历史上三轮"UI 交付契约"任务全部以五阶段未完成+风险承担 close 收场。如果不修，每个 UI 任务都会重演 F19，每个任务都会继续污染主分支。

## 2. 背景、目标与范围

### 背景

WorkflowHub 已有 UI 条件契约（UI 判定三输入、UI 契约字段、设计源盘点技能、浏览器 QA 适配器），但全部是"调用方自报才触发"的条件路径，不传就静默降级——F19 正是这样无声跳过全部 UI 要求。证据的官方归宿（任务存储 quality/*）有完整机制，但缺"工作区截图/报告 → 任务存储"的发布通道，close 对已提交侧车不设防。

### 目标

- UI 型需求：make-decision 必问、build-spec 高保真原型必须给用户确认、build-plan 有前端 task 和端到端验收 task、build-code 真实环境真实数据验收、证据进任务目录、close 拦得住。
- 非 UI 任务：验收测试 task 底线（不豁免），端到端深度按档；全量强制延期到下一轮。
- 所有改动符合宪法：不设推进阻断门、不新增公共命令、不堆自动化基建、质量裁决异源。

### 范围内

- 五阶段契约与校验改造（UID/CONV/DSG/PLN/EXE/VER 六域）
- close 机制与证据发布通道（CLS/EXE 域）
- 宪法 F7 修订 v1.7.0（CST 域）
- 项目仓库 .gitignore 约定模板（CNV 域）
- 本任务自身本地 S2-S4 dogfooding；S1 PaperBuilder UI dogfood 作为独立后续任务

## 3. 用户场景与状态覆盖

### SCN-001：UI 型需求完整交付（用户视角）

- **角色**：WorkflowHub 用户（产品负责人）
- **Given**：提出一个涉及页面改动的需求（如 F19 手动 YAML 编辑器）
- **When**：按五阶段推进
- **Then**：make-decision 阶段被系统主动讨论交互流程/页面范围/数据状态/成败边界/非目标；build-spec 阶段看到基于设计规范和现有组件的高保真原型页并迭代确认；build-plan 里看到前端实现 task 和端到端验收 task；build-code 结束后看到真实端口运行证据与截图在任务追踪目录；close 前缺口清单一目了然。

### SCN-002：判不出是否碰界面（unknown 路径）

- **角色**：执行者（agent）与用户
- **Given**：需求描述模糊，三输入无法判定 UI 或非 UI
- **When**：make-decision 完成判据检查
- **Then**：系统停下来问用户「这需求碰不碰界面」，用户答案写入决策日志；绝不静默按 non_ui 继续。

### SCN-003：没有设计规范的项目

- **角色**：执行者
- **Given**：UI 项目无 Design.md/Experience.md
- **When**：build-spec 设计源盘点
- **Then**：从现有页面/组件反推最小设计基线（token/组件清单/交互要点），用户确认后作为设计权威出原型。

### SCN-004：用户觉得原型难看

- **角色**：用户
- **Given**：build-spec 展示高保真原型
- **When**：用户不满意
- **Then**：用户继续提意见迭代，或明确同意切换为"设计提示词包"自行外部设计；agent 无权自行降级。

### SCN-005：验收证据落位与 close 拦截

- **角色**：执行者
- **Given**：build-code 产生截图/日志
- **When**：发布证据并 close
- **Then**：证据通过官方通道进任务存储；若有人把侧车提交进任务分支，close 前置结构检查报错并指引先发布再 close。

### SCN-006：非 UI 后端任务

- **角色**：执行者
- **Given**：纯后端任务
- **When**：build-plan
- **Then**：plan 必须有验收测试 task（服务级深度）与验收数据来源；缺则校验失败；浏览器级 E2E 不强制（延期项）。

## 5. 功能需求

### UI 判定域（UID）

保证「碰不碰界面」不再靠静默默认值，判不出就必须问用户。

- **FR-UID-001**：make-decision 完成判据必须包含 ui_applicability 事实：三输入合并出 `ui/non_ui/unknown` 并写入决策日志；`unknown` 或证据冲突时必须向用户发起真实问答并记录裁决，不得默认为 non_ui
  - **范围边界**：只改完成判据与记录，不改三输入合并算法本身
  - **依据**：D1, PFACT-01
  - **场景**：SCN-002
  - **验收**：AC-UID-001
- **FR-UID-002**：下游阶段从任务决策日志读取 ui_applicability 事实，而非依赖调用方自报 contract_facts；自报缺失不再静默降级为 non_ui
  - **范围边界**：改读取源，不删除 contract_facts 显式传入能力（传入与日志冲突时以日志为准并报冲突）
  - **依据**：D1, PFACT-01
  - **场景**：SCN-001, SCN-002
  - **验收**：AC-UID-002

### 决策收敛域（CONV）

- **FR-CONV-001**：make-decision 完成判据增加四维收敛检查（目标/范围/方案/验收）：每维要求真实用户答案或明确"无新需求"记录、答案引用具体事实/材料、验收维必须含可执行验收标准（场景+数据来源+过/不过判据）；任一维未收敛→保持进行中并列出缺口，不得宣称完成
  - **范围边界**：收敛检查是完成判据不是推进门；不替代 Talk/Grill 流程本身
  - **依据**：D2（用户 R3-Q8-3 范围修正）
  - **场景**：SCN-001
  - **验收**：AC-CONV-001

### 设计域（DSG，仅 UI 需求）

- **FR-DSG-001**：UI 需求进 build-spec 先做设计源盘点：有 Design.md/Experience.md→作为设计权威；无→从现有页面/组件反推最小设计基线并经用户确认；盘点结果（权威来源+版本）记录进 UI 契约
  - **范围边界**：盘点是只读事实+用户确认，不生成设计内容本身
  - **依据**：D4, PFACT-04
  - **场景**：SCN-003
  - **验收**：AC-DSG-001
- **FR-DSG-002**：UI 需求 build-spec 必须产出高保真原型——真实组件渲染的原型页（基于设计权威+现有组件/设计 token），以浏览器截图+可交互预览向用户展示；用户迭代意见→修改→再展示，直到用户确认或用户明确同意切换提示词包；原型页作为设计材料，不进入产品源码目录；设计确认为宪法第四处限定确认（FR-CST-001）
  - **范围边界**：原型是设计材料非产品代码；确认仅 UI 需求触发；非 UI 任务无此步骤
  - **依据**：D3, D5, PFACT-05, PFACT-06
  - **场景**：SCN-001, SCN-004
  - **验收**：AC-DSG-002
- **FR-DSG-003**：降级路径仅在用户明确同意后可用：产出设计提示词包（页面目标/结构/组件/状态/文案/验收要点文本），用户外部设计后回传设计稿，build-spec 记录设计参考并继续
  - **范围边界**：切换必须用户明确同意事实；提示词包是文本交付，不集成外部工具
  - **依据**：D3
  - **场景**：SCN-004
  - **验收**：AC-DSG-003

### 计划域（PLN）

- **FR-PLN-001**：①UI/全栈/高风险用户可见任务的 plan 必须含至少一个端到端验收测试 task（通常为最后 phase 的最终 task），验收场景引用 make-decision 验收标准与 spec AC；分档判据：UI/全栈=浏览器级、高风险后端=服务级、流程类=命令级；②所有任务（含纯后端/纯材料）的 plan 必须含至少一个验收测试 task（非强制范围按服务级/命令级底线），验收场景引用 make-decision 验收标准；缺验收测试 task→plan 校验失败；③纯后端/纯材料的端到端全量强制为延期项
  - **范围边界**：本期强制范围=UI/全栈/高风险；底线=所有任务有验收测试 task；延期项不进本期验收
  - **依据**：D6, D7, PFACT-07
  - **场景**：SCN-001, SCN-006
  - **验收**：AC-PLN-001
- **FR-PLN-002**：UI 需求 plan 必含独立前端实现 task（与后端 task 分开），其实现引用设计权威与 UI 契约
  - **范围边界**：只要求 task 独立存在并引用设计材料；不规定 task 内部拆分粒度
  - **依据**：D6
  - **场景**：SCN-001
  - **验收**：AC-PLN-002
- **FR-PLN-003**：所有验收测试 task 必须为每个验收场景写明结构化 `acceptance_data[]={source,sample,scenario,tier}`；`tier` 只能是 `browser`、`service` 或 `command`，来源/样本/场景不得为空或占位。来源必须声明项目现有真实数据；build-code 运行时无法解析、定位或使用该来源时必须产出 explicit unavailable 事实，不得伪造
  - **范围边界**：来源声明在 plan/task 卡中；数据准备本身由执行者按声明执行
  - **依据**：D6（Q5-2）
  - **场景**：SCN-001, SCN-006
  - **验收**：AC-PLN-003

### 执行域（EXE）

- **FR-EXE-001**：build-code 对强制范围任务按档执行真实验收：起真实前后端/服务、使用计划声明的真实数据、走真实用户流程/调用链/命令链；结果（跑通事实+截图/日志）作为物理事实记录；环境起不来→如实 unavailable 留痕，不得伪造
  - **范围边界**：执行者只采集物理事实，不作通过/不通过裁决（FR-VER-001）
  - **依据**：D8（Q5）
  - **场景**：SCN-001
  - **验收**：AC-EXE-001
- **FR-EXE-002**：build-spec/build-code 的 UI 相关处理在缺关键事实（判定/契约/组件质量图/适配器）时产出显式缺口项，不得返回 null 或静默 non_ui
  - **范围边界**：消除静默默认，不改正常路径行为
  - **依据**：D8, PFACT-01
  - **场景**：SCN-002
  - **验收**：AC-EXE-002
- **FR-EXE-003**：证据发布通道——把工作区产物（截图/日志/报告/原型页）发布到任务存储 quality/evidence/<域>/，复用现有单写内核机制；登记四问：唯一 consumer=build-code/verify-code 完成判据与 close 归档校验；owner=build-code；替代=取代"写工作区并提交进 main"；删除条件=任务关闭归档策略生效后；发布失败如实报错
  - **范围边界**：只做发布通道，不自动迁移历史产物；不新增公共命令（走阶段运行时内部能力）
  - **依据**：D10, PFACT-02
  - **场景**：SCN-005
  - **验收**：AC-EXE-003

### 验收裁决域（VER）

## 6. 模块划分

### 判定与收敛（make-decision）

- **负责什么**：UI 判定必问、四维收敛检查、验收标准产出
- **对外提供什么**：决策日志中的判定事实+收敛事实+验收标准
- **依赖谁**：现有收敛分析器与 Talk/Grill 流程
- **测试边界**：判定与收敛校验的契约测试

### 设计（build-spec）

- **负责什么**：设计源盘点、高保真原型生成与迭代、设计确认（第四处限定）、降级提示词包
- **对外提供什么**：UI 契约+原型材料+确认事实
- **依赖谁**：设计权威（Design.md/Experience.md 或反推基线）、现有组件、宿主预览能力
- **测试边界**：UI 契约校验、确认事实校验

### 计划（build-plan）

- **负责什么**：E2E 验收 task 强制、前端 task 强制、验收数据来源强制
- **对外提供什么**：plan/tasks 校验结果
- **依赖谁**：make-decision 验收标准、spec AC
- **测试边界**：plan 校验的契约测试

### 执行与证据（build-code + 证据通道）

- **负责什么**：分档真实验收执行、证据发布任务存储、静默消除
- **对外提供什么**：执行事实+证据引用
- **依赖谁**：验收数据来源、宿主环境能力
- **测试边界**：证据发布的 roundtrip 测试

### 收口（verify-code + close）

- **负责什么**：E2E 事实+独立裁决完成判据、侧车拦截、归档完整性、自检清单
- **对外提供什么**：close 缺口清单与结构校验
- **依赖谁**：任务存储事实、快照机制
- **测试边界**：close 校验的契约测试

## 7. 关键实体

- **ui_applicability 事实**：
  - **定义**：任务与界面相关性的判定
  - **字段和约束**：result ∈ {ui, non_ui, unknown} + 三输入引用 + 用户裁决记录（unknown 时必填）
  - **关系**：make-decision 产出；build-spec/build-code/verify-code 消费
- **UI 契约**：
  - **定义**：UI 需求的页面范围/交互流程/文案/状态矩阵/预览引用
  - **字段和约束**：page_or_region、interaction_flow、visible_labels、state_matrix、preview_refs、design_authority（新增：来源+版本）
  - **关系**：build-spec 产出；build-plan/build-code/verify-code 消费
- **验收标准**：
  - **定义**：make-decision 产出的可执行验收判据
  - **字段和约束**：场景+数据来源+过/不过判据+档位（浏览器级/服务级/命令级）
  - **关系**：make-decision 产出；plan E2E task 引用；build-code 执行；verify-code 裁决
- **证据发布记录**：
  - **定义**：工作区产物进入任务存储的事实
  - **字段和约束**：来源路径+任务存储 ref+发布者+时间；同内容不重复记录
  - **关系**：build-code 产出；verify-code/close 消费

## 8. 数据和生命周期

- **数据粒度**：一条验收事实=一次真实验收执行；一条证据=一个已发布产物
- **数据时效**：事实绑定当次材料 revision；修复后新事实按最新终态投影
- **缺失或迟到**：缺失保持 unknown/incomplete 可见，不补假
- **预览与正式**：原型=预览材料（设计确认前）；设计确认后 UI 契约为正式
- **当前与历史**：质量事实追加式保留，不覆盖
- **归属与清理**：任务存储持有证据；工作区侧车由 close 清理；任务关闭后按归档策略

## 9. 兼容性预留

- **既有消费方**：非 UI 任务流程不感知新确认点；contract_facts 显式传入仍可用（以决策日志为准并冲突报错）
- **命名预留**：quality/evidence/<域>/ 域段可扩展（browser-qa/design/e2e 等）
- **容器预留**：档位判据表可增档（如移动端级）

- **扩展边界**：本期预留纯后端/材料任务 E2E 全量强制开关（下一轮），不承诺本期实现

- **既有行为**：UI 契约条件触发、自报缺失静默降级
- **本需求影响**：判定必问、缺口显式、完成判据收紧
- **回归路径**：既有 18 个 UI 契约测试+收敛回归测试+五阶段集成测试必须全绿
- **验收**：AC-UID-001/002, AC-CONV-001, AC-EXE-002, AC-DOG-001（S2-S4；S1 外部后续）

### close 与快照

- **既有行为**：已提交侧车并入快照进 main；manual-risk-close 只记用户请求
- **本需求影响**：侧车结构报错；归档完整性缺口可见不漂白
- **回归路径**：既有 close 测试全绿；正常任务 close 五步不受影响
- **验收**：AC-CLS-001/002/003

### 宪法文本

- **既有行为**：F7 三处确认
- **本需求影响**：F7 v1.7.0 第四处限定确认（仅 UI）
- **回归路径**：宪法引用处（文档/技能/测试）同步检查
- **验收**：AC-CST-001

- **可能受冲击的业务规则**：anti-gate 精神（完成判据≠推进门）、close 三义分离（物理交付≠质量结论）、公共命令七类不变
- **明确无影响**：非 WorkflowHub 任务的项目仓库文件（存量不动）；外部设计工具生态；哈希校验机制
