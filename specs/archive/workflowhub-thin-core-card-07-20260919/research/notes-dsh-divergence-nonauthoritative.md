### 轴外新方向（去重）

| # | 名称 | 解决什么 | 机制要点 | 提出者 |
|---|---|---|---|---|
| N1 | 交互预算熔断 | 用户注意力耗尽导致讨论流产 | 设硬预算（总轮数/总提问数），每轮开头显示已用/剩余；超预算未收敛则强制输出「分歧清单 + 带风险的默认收敛」让用户选 | muse |
| N2 | 需求压缩探针 | 无声弱化原始需求且不告知 | 落盘前跑压缩检测器：未绑定原子的派生块占比 + 原话/派生长度比；超阈值在顶部插告警横幅 | muse |
| N3 | 异源盲度保证 | 异源只是同模型换 prompt，塌缩依旧 | 调用时禁止传入主会话的大纲结论与候选排序，只给原子 + 调研全文；要求返回「未见主结论」声明 | muse |
| N4 | 发散废弃物回收 | 被拒候选丢失，下次重复发散 | 未选中候选统一落盘，带拒绝原因 + 证伪条件，作为负样本召回 | muse |
| N5 | 决策可逆性分级 | 所有决策被同等对待 | 收敛时标 `可逆性：高/中/低`，只有低可逆需用户显式确认 | muse |
| N6 | 沉默语义化 | 「嗯、可以、你定」被当成确认 | 定义沉默三态：明确接受（需复述关键约束）/ 默认接受（2 轮未反驳，标待复核）/ 沉默（不计入三档，校验器不认） | muse |
| N7 | 异步人机会话模型 | 用户注意力是比 token 更稀缺的资源 | 显式分「在席确认点」与「离席工作区」；回席先读 ≤5 行简报再进入选择题模式；批次问题 ≤3 个 | deepseek-v4-flash |
| N8 | 隐含需求抽取与来源标注 | 需求不只被压缩，也会被 agent 悄悄补全 | 启动时从仓库现状抽约束，产候选池；每条强制 `origin`：user-verbatim / agent-inferred / repo-derived；后两类必须过用户显式确认 | deepseek-v4-flash |
| N9 | 低参与信号与降载路径 | 疲劳产出「假确认」 | 可检测信号清单（连续 N 轮 <20 字、连续同意 3 次、把问题抛回）；命中后强制降载并记录触发次数 | deepseek-v4-flash |
| N10 | 附带想法队列（parking lot） | 跑题想法丢失 | 与当前问题不同主题的发言自动入队（原文 + 轮次 + 上下文），到自然断点**强制回访** | deepseek-v4-flash |
| N11 | 机制触发台账 | 「写了没实现/死代码」×6 | 每新机制挂触发计数器；连续 N 次会话触发为 0 进「死机制预警」；台账是事实记录不是 gate | deepseek-v4-flash |
| N12 | 显式发散预算 | 预算烧穿后被砍成便宜模型，质量伪装成模型问题 | token / 轮次 / 异源调用数三栏配额，对用户可见可调；配额耗尽 = 强制收敛兜底判据 | deepseek-v4-flash |
| N13 | 反需求作为一等原子 | 压缩常违反用户没说出口的「不要什么」 | 澄清阶段强制问一轮「绝不要的形态/交互/复杂度」；每条发散过反需求违反检查 | kimi-zhipeng |
| N14 | 用户自身需求漂移的逐轮 diff 报警 | 只防了 agent 弱化，没防用户自己改口 | 每轮把新表述与逐字原子库 diff，追加不覆盖，显式问「这是替换还是补充」 | kimi-zhipeng |
| N15 | 静默阅读备忘制（write-then-talk） | 顺序锚定/节奏乱/聊过即忘部分源于「对话」载体本身 | 每模块开场先写一页备忘落盘，用户异步按编号批注，对话只处理批注 | kimi-zhipeng |
| N16 | 便宜模型批量独立采样发散，贵模型只做对抗批判 | 多样性瓶颈是独立采样数而非单点智力 | 发散子任务派便宜模型跑 N 个互不可见上下文；高智力模型只做去重、对抗质疑与后果评估 | kimi-zhipeng |
| N17 | 淘汰单与收敛前强制清扫 | 淘汰无声发生 | 任何方向退出候选池必须生成淘汰单（逐字 + 理由 + 依据引文）；收敛前置条件 = 所有淘汰单已被用户逐条见过 | kimi-zhipeng |

### 「只保留一条改动」的选择（三家不一致，如实并列）

| 提出者 | 保留哪条 | 理由要点 |
|---|---|---|
| muse | **AX19 的 atom 级 Source 绑定**（生成时强制带 ID，校验只做 ID 存在性） | 唯一能同时堵住三类历史失败；编译期可阻断，不会成为死代码 |
| kimi-zhipeng | **FR-35 逐字双层保真 + 其机器半边（逐字原子入参、独立上下文逐条核对）不可拆分地一起落地** | 三痛点与两类历史死因的公约数是「压缩不可见、验证不可信」；砍掉独立核对那一半就是自我认证的保真 |
| deepseek-v4-flash | **需求/方向/结论行强制三字段（origin + disposition + anchor）落库 + 带生产调用点的双向差集校验器（配负向测试）** | 同时压住 FR-33/35/37；直接对抗「不可证伪」与「死代码」两大历史失败模式；且自足 |

**汇合点（三家独立指向同一处）**：三家的答案都落在**「原子级绑定 + 独立上下文的可核对处置」**上，且都明确反对把它做成自评。这与外部调研 R1 的「过度澄清/自评校准」证据、R2 的「生成与判定分离」证据、以及 I2 的「粒度 + 接线双主因」结论**方向一致**。
