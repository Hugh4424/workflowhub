复用 temp-dir 现 owner，在原 spec-plan/Phase 模板补完整生命周期消费。
依据 R-027、研究004:24–39、70–76；这是 P1/P2 最小路径选择。
可删 scratch、交付包、正式原始证据、provider packet TTL 分开处理。
创建、使用与 dispose 同一进程，正常/异常/可捕获取消都保原退出语义。
SIGKILL 后可能残留；下次仅在本任务精确根和用途前缀内核 marker/PID/年龄。
活 PID、PID 权限不明、符号链接、换 inode、其它任务及未知目录均保留。
不新增 manager、scheduler、状态对象、公共清理命令，也不扫历史 /tmp。

### ADR-003 — 怎样让终末真正调用完整收尾？

补 build-code 终末 caller、依赖、末步与 catalog 接线，复用 stage-close。
依据 R-028、研究004:18–22、41–68；不是新关闭系统。
代码图、语义图分别读回；新增/变化文档及当前 prompt/mode 缓存 miss 均核。
免费缓存先用，新增收费抽取仍沿原方法核精确范围与费用许可。
图文件进实际最终 commit/PR/merge/push。
归档或规范同步再产新字节时只补相应图核查与提交，不递归图自身或重复合并。
Git 必要动作复用持续授权，动作前 record/consume 当前目标及 HEAD。
PR/直接 merge 按实际路线执行；精确最终归档/删除范围确认仍只取一次。
未执行、拒绝、失败与部分成功逐项保真，不把自动触发当无条件推送删除。

### ADR-004 — 新版怎样拆分和验收？

按六个真实结果重组旧九包，保原需求来源与已选范围。
依据 U-003、最新 phase-template 拆并全集与研究005:124–183。
接入与配置同给新维护者，按共同消费者合并。
发布树、清单与版本同判完整发布物，按共同判据合并。
临时资源、自动收尾、README 冷读各有独立效果，分开首判。
末段只对最终安装对象首次跑真实链，并读回其余首判与必要补验。
旧九包不是九阶段配额；预算与 S/M/L 选择未获本轮确认。
