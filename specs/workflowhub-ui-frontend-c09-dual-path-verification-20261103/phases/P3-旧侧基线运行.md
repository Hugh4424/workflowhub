## 这一 Phase 交出什么？

旧侧用固定提交与同输入，在旧侧副本上把两页真正做出来，并逐事件记下经过。
构建与启动有回执，两条路由可读回，事件字段与另一侧完全一致，且没读新侧产物。

- **本 Phase 结果**：旧侧实施段可被独立读者重跑，并通过独立、只读的当前标准验收；
  事件可被 P5 直接计数，且执行者未拿到含比较目的的全文。
  事件流指按冻结字段逐条追加的记录；基线指旧侧在同输入下跑出的结果。
- **非目标**：不做旧侧的决策、规格、验证三段；
  不用当前仓的新方法或新脚本代替旧方法；
  不读新侧产物；不做比较、不算六项指标；不要求视觉达标；
  不做旧侧真实业务 E2E，是否加做待用户决定，本 Phase 不加后端、不造业务链。
- **改动前**：旧侧副本只是三行占位的空壳，没有旧侧产物；
  旧版本只能按提交重建，不能沿用被清理的安装；
  旧侧两页的截图、几何与视觉数据全无；旧侧没有依赖安装与验收件。
- **改动后**：依赖已装、两页在旧侧副本内实现，构建与启动有退出码；
  两页可访问并留有 1440×900 与 1280×900 四张默认态截图；事件流逐条追加；
  盲化派发记录可核；独立验收有目标行为测试、代码审查、运行质量与定向复验；
  禁读核对写明没有读新侧；上层环节如实记未覆盖。
- **与相邻 Phase 的边界**：P1 交出旧版工作区、副本、任务文字、事件定义、矩阵、
  共享数据与 238 行清单；本 Phase 只写旧侧副本与自己的证据；
  P4 在本 Phase 收口后才开工，保证旧先新后；

- **主要风险**：旧版本依赖源不可用或两页构建失败，会让旧侧拿不到可运行产物。
  若因它返工，替代走法是：停在该路径并保原错误，记 `unavailable` 与 owner，
  P6 报告写单侧限制；不用新版本或历史记录冒充旧侧。
  若盲化派发被破坏，该轮判污染，停止并把原件交独立验收者。
- **下一步**：P4 开工；P5 用本 Phase 的事件与截图合成指标。
- **动手前必读**：`spec.md` Appendix A 的验收 8、`spec.md` 的「方案 3」、`decision-log.md` 的工作包 8、
  `decision-log.md` 的 AC-P08、`decision-log.md` 的 D-008、`decision-log.md` 的 D-018、
  `build-plan/2026-11-03-002-...md` 的「2. 旧侧基线的真实边界」、`$TASK_ROOT/quality/evidence/research/2026-11-03-001-c09-preparation-inventory.md` 的「2.1 问题 1：旧 WorkflowHub 基线」表「『启动』语义」行、

### 七个槽

1. **验收标准**：验收 8（AC-P08）只有一条：旧侧用固定版本与同输入跑完实施段，
   事件可记且无新能力混入。
   判据是构建、启动退出码、事件字段与独立验收；成功是两条路由可访问、事件同字段、
   盲化派发可核、独立验收四项齐、禁读无违规、上层环节记未覆盖。
   失败是用历史记录代替旧侧、混入新侧产物、把实施段说成完整流程、
   执行者拿到含比较目的的全文。
2. **场景**：正常场景按任务 10 从读输入到构建、启动、截图、记录、清理。
   反向场景一：把 `NEW_COPY` 的文件或 P4 材料带进旧侧，禁读核对必须报违规，
   该轮事件判污染，不得重跑洗白。
   反向场景二：构建非零仍启动，启动检查必须非零并保构建错误。
   反向场景三：把旧侧做成完整流程或补上层材料，范围核对必须判超出，
   只保留实施段结论。
   反向场景四：把 P3 全文、AC 或比较目的交给执行者，或简报含侧别词，
   派发记录必须判违规并停该轮。
3. **环境与数据**：环境是旧版工作区、旧侧副本、本机 Node 与 npm、浏览器引擎；
   数据是冻结任务文字、设计源只读引用、矩阵选定的状态与视口、共享数据与 238 行清单。
   不造新数据、不另造夹具；端口用冻结的 3100，先探测再占用；旧版安装与本次运行的原件保留。
4. **用例**：`CASE-P3-1` 对应任务 10 的实现与构建，
   `CASE-P3-2` 对应安装、构建、启动与两页访问，`CASE-P3-3` 对应事件字段，
   `CASE-P3-4` 对应禁读核对，`CASE-P3-5` 对应独立读者重跑，
   `CASE-P3-6` 对应独立验收四项：行为测试、代码审查、运行质量、定向复验。
   判定方式：安装、构建、启动与访问用同一命令退出码；事件、禁读与验收只能人读，
   由独立读者与验收者按清单核；命令退出 0 不证明旧方法有效。
5. **谁判**：由未参与旧侧执行的独立读者与独立验收者判定，与执行者不同上下文；
   验收者另跑行为测试、代码审查与运行质量，审查者与实现者不同人。
   执行时点：任务 10 实现完成并清理后；首判一次，P6 末验只读回放。
   判定者拿到旧版本回执、副本哈希、任务文字、事件流、四张截图、盲化派发记录、
   独立验收四项与旧版本文档；不改验收标准、不改实现。
6. **失败回修与重验**：失败信号是安装构建启动非零、事件缺字段、禁读违规、
   盲化泄露、独立验收有 finding 或上层环节被写成已覆盖。
   先由主会话分诊：实现问题回旧侧执行者，环境问题回环境与端口 owner，
   事件定义问题回任务 5 的作者，盲化问题回协调者。
   修后只重验受影响面；旧侧已产生的学习效应不重跑洗白，如实写进报告。
7. **承接**：结论写在 `quality/evidence/P3/AC-P08-first-judgment.md`、
   任务 10 的「完成」字段与阶段三证据根；
   P4 读边界与先后，P5 读事件与四张截图，P6 读未覆盖与业务 E2E 待定说明。

**效果类判据（语义判定）。**

- **判什么**：独立读者只按旧版本文档与本次回执，能重跑同一实施段，
  并说出哪两页、用哪些命令、事件字段是什么，且能指出简报不含比较词。
- **谁判**：未参与旧侧执行的独立读者；不需要用户本人到场。
- **怎么观察**：按旧版本文档从构建到访问复跑，不看执行者自述；
  重跑成功且能指出事件字段算过，只能靠执行者提示算没过。
- **证据落点**：`quality/evidence/P3/AC-P08-first-judgment.md`，
  记读者身份、命令、退出与原话；通过记 `pass`，未执行记 `incomplete`。

## 为什么现在做，依据是什么？

旧侧若在新侧之后做，执行者会带着新侧经验，学习效应方向就说不清。
所以顺序固定旧先新后，旧侧只用旧版本、旧方法与同输入，只做实施段。

- **结果**：旧侧两页可运行、事件可记、无新能力混入。
- **非目标**：不做上层三段，不做比较，不出指标数值。
- **与其它 Phase 的区别**：P1 固定输入，P2 修入口，P4 跑新侧；
  本 Phase 是唯一在旧侧副本上做实现的 Phase。
- **依据**：D-002（两侧各两页）；D-008（旧侧只做实施段）；
  D-018（旧侧用当前标准、不告知实验，故走盲化派发）；D-009（固定旧版本与同输入）；
  风险 5（两侧不可比）。

## 怎么验证？

用旧版工作区与旧侧副本的真实字节跑构建、启动与访问；旧侧不新写目标测试。
本 Phase 属基线运行段，不宣称 RED/GREEN（`spec.md` 的「全局验证策略」）。
红绿指先让目标测试非零、再让同一测试退出 0 的两份回执。

开工前四要素：

- **验证层**：真实构建、真实启动、HTTP 访问、事件字段检查与人读禁读核对。
- **命令或数据**：`OLD_COPY` 的四个文件、旧版本脚本、冻结任务文字与矩阵。
- **预期结果**：构建 0、启动 0、两条路由 200、事件字段齐、无新侧读取。
- **失败条件**：构建非零、路由非 200、事件缺字段、禁读违规或范围超出。

失败了怎么办：

- **风险**：旧版依赖源不可用、构建失败或端口被占。

- **回滚**：只撤回本卡受影响文件到初始十件哈希状态并重做；
  证据与失败原件保留，不删除。
- **补救与交接**：依赖源交主会话；实现问题回旧侧执行者；
  端口被占即停并报偏差，不擅自换；P6 写单侧限制。
- **触发条件**：构建非零、启动非零、路由非 200、事件缺字段或禁读违规即执行。
