## 这一 Phase 交出什么？

六项指标逐行有值、单位、原件与缺失原因，四格可比；
无稿在仓库外隔离实例上完成一次真实的策略快照闭环，含权限拒绝与重复恢复；
取消语义如实记未覆盖。

- **本 Phase 结果**：指标表与四格比较可被 P6 直接引用，
  无稿闭环有六段请求响应、真实 403、重复恢复与服务端证据，
  或每一项未完成都有 owner 与恢复条件。
- **非目标**：不改两侧源码与测试；不重新采集造数；
  不改 P1 的分母、阈值与六项定义；不合成总分或加权；
  不把无稿收益混入有稿比较；不做无稿取消语义（D-020 记偏差）；
  无稿资产链按用户决定不纳入，只保留策略快照链，报告记未覆盖；
  不写生产库、不改 PaperBuilder 源码；不生成报告（归 P6）。
- **改动前**：六项指标只有口径没有数值；四格没有同源截图与事件；
  无稿需求文档未写；隔离实例未建；六段请求与 403/409 未取。
- **改动后**：六行指标各有值或 `unknown` 与原因，分母与 P1 冻结件一致；
  四格按矩阵逐维对齐，偏差与学习效应方向逐条登记；
  无稿需求文档、可操作页、隔离实例、六段请求响应、403 与恢复齐备；
  页面源码在证据区，阶段材料只留指针；
  无稿资产链未纳入，只保留策略快照链，报告记未覆盖；
  取消语义具名未覆盖，并按 D-020 记偏差。
- **与相邻 Phase 的边界**：本 Phase 只消费 P1～P4 的适用事件、截图与
  提取产物，不重新采集；只向 P6 交指标、比较与无稿结论。
- **主要风险**：无稿隔离授权或仓外路径缺失、QA 服务起不来、
  事件流字段不齐，会让指标全记 `unknown` 或整段记 `unavailable`。
  若因它返工，替代走法是：停该面，记真实尝试、卡点、owner 与恢复条件，
  不拿 mock、录制回放或生产库顶替；其余面照常交。
- **下一步**：P6 逐条消费六项指标、四格比较与无稿闭环；
  报告把有效性与达标分列，不把 `unknown` 读成通过。
- **动手前必读**：`spec.md` 的「Appendix A — 验收判据（唯一权威）」
  AC-P09、AC-P10；「六项指标怎么算，比较矩阵是什么？」及其
  「比较矩阵：两页 × 状态 × 视口 × 数据」；
  「实现设计（全局权威）」的「全局验证策略」；
  「测试计划是什么？」；
  `decision-log.md:522`、`decision-log.md:539`、`decision-log.md:288`；
  `research/2026-11-03-006-paperbuilder-runtime.md:135` 与 `:377`。
- **未决事实**：无稿隔离路径与授权未取得（owner 用户，恢复条件为
  路径报备、授权原件、对象与接口可回读）；QA 服务在当前 HEAD
  能否起未实测（任务 19 现场核 `/openapi.json`）；
  六项数值未产生（本 Phase 现场计数）；视口与数据取值以 P1 冻结件为准；
  用户 2026-11-03 已决定补有稿业务 E2E（D-024），归 P4 T018A；

### 七个槽

1. **验收标准**：本 Phase 承接验收 9、10，逐条写成能判真假的话。
   验收 9：六行各有值、单位、原件与缺失原因，或按定义记不适用；
   分母与开跑前一致；无稿与旧侧的提取覆盖记 N/A 并写理由，
   不计入达标分母，不写成未覆盖或 `unknown`；
   四格齐全；缺任一格必须非零并记未覆盖，不写影响当通过；
   视觉只在同源、同状态、同视口、同数据下
   逐项比；缺任一格或缺少同条件视觉证据时，AC-P09 不得 pass，
   只记未覆盖并判相应指标未达到；偏差逐条登记，学习效应方向写清；
   独立读者能复算其中一项。
   验收 10：先有从页面翻译的完整需求文档，再有能开能操作的页面；
   六段各有请求与响应原件；权限拒绝走真实 403；重复恢复有原件；
   隔离根在仓库外且未碰生产库；服务端证据来自被测系统之外；
   无 mock、无录制回放；取消语义记未覆盖并写原因。
   失败信号分别是：换分母、总分吞 `unknown`、混算无稿数据、
   缺格仍 pass、把不适用写成未覆盖或 `unknown`、
   用 200/toast/story 充数、用生产库、缺授权仍跑。
2. **场景**：正常场景是隔离实例上从列表走到读回与 409，再补 403。
   反向场景一：把 `QA_ROOT` 指到 PaperBuilder 仓内或生产根，
   造库或启动必须非零并拒绝，不得继续。
   反向场景二：用旧凭据建快照，必须返回 409
   `selection_credential_stale`，不得被当成 201。
   反向场景三：事件流缺一段却填数值，指标脚本必须判失败并记 `unknown`。
3. **环境与数据**：环境是仓库外 QA 存储、隔离 API 18844、
   隔离前端 18843、无稿页代理 18845、本机浏览器引擎；
   数据是 PaperBuilder 自带 QA 夹具（`bollinger_pullback:v1..v5`、
   固定回测与模拟卡）、真实请求响应、服务端日志；
   不写生产库、不碰真实业务数据。
   真实外部环境产生判据时，由任务 20 的脚本自动取回请求响应、
   代理日志与服务端证据，原件落 `TASK_ROOT/quality/evidence/P5/`，
   全部保留，不用完删；浏览器会话按技能清理并记残留。
4. **用例**：CASE-P5-1 到 CASE-P5-4 与任务 19～22 一一对应，
   命令见各卡门禁字段与「怎么验证」的测试面表。
   判定方式是命令退出码加独立读者复读；命令退出 0 只证明结构可读，
   不证明语义；语义由第 5 槽的判定者按观察协议判。
5. **谁判**：验收 9 由未参与计量的独立读者判，按表复算一项并核对分母；
   验收 10 由未参与业务执行的独立验证者判，能在隔离实例上复跑同一条链路；
   两者都与实现者不同上下文，不需要用户本人到场。

**效果类判据（语义判定，不是命令退出）。**

- **怎么观察**：干净 shell，按本文件命令复算一项指标；
  只读原件，不看执行者说明；能指出缺格与未覆盖并判 AC-P09 不
  pass 算过，
  只能复述「都跑了」算没过。
- **证据落点**：`quality/evidence/P5/AC-P09-P10-first-judgments.md`，

## 为什么现在做，依据是什么？

两侧都跑完才有同口径事件；无稿也只在此时才有一份可对照的真实闭环。
本 Phase 是整轮验证里唯一把事件变成指标、把文字需求变成业务闭环的位置。

- **结果**：六项指标逐行可复算，四格可比，无稿闭环有真实请求与恢复。
- **非目标**：不重采、不改分母、不合成总分、不做取消语义、不写报告。
- **与其它 Phase 的区别**：P4 只产事件与页面事实，P6 只消费结论；
  本 Phase 不判整体收益，只按冻结口径计数与比较。
- **依据**：D-003（无稿用翻译需求加真实后端）、D-020（只跑策略快照）、
  D-004（单案例报告）、D-005（四格比较）、D-006（事件与指标先定）、
