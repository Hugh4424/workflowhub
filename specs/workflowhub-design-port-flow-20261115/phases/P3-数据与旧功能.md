## 这一 Phase 交出什么？

实施者能把样本接到本地真实数据源和旧接口，并证明失败、写回执与恢复没有假象。

- **本 Phase 结果**：数据状态、样例边界、写回执、旧功能三链和旧行为恢复均可重放。
- **非目标**：不做四类机器校验，不做最终目视，不新增业务接口或公共运行时能力。
- **改动前**：阶段 2 只有判断、移植和合成样本，真实状态与旧功能尚未接回。
- **改动后**：有源失败不填样例，写结果只认真实回执，旧接口和旧钩子可定向恢复。
- **与相邻 Phase 的边界**：阶段 2 交样本与登记；本阶段交真实对象，阶段 4 消费它校验。
- **主要风险**：样例外观掩盖数据或旧功能缺失；发生时保留失败，不以页面看似完成收口。
- **下一步**：阶段 4 对同一对象执行机器与独立目视检查。
- **动手前必读**：spec.md 的实现设计、Appendix A 验收 3 与 5，以及下方读表。
- **未决事实**：真实外部业务服务不在范围；本地真实源只证明其声明边界。

本地真实源指本任务启动并控制的实际数据服务，不是硬编码页面值。
写回执指写入端真实返回的结果证据；没有回执不能报告写入成功。
UI 指页面、路由、组件或样式；本阶段驱动并观察这些状态，因此适用 UI 验收。
ViewModel 指供页面显示的数据视图形状。
SHA256 是内容摘要，用于核对字节是否一致。
Swiss 指本原型采用的白色网格与左对齐视觉方向。
JSON 指机器可读的结构化文本。
Node 是执行本阶段脚本与测试的本地运行环境。
PID 是自建服务进程标识；URL 是实际页面或服务地址。
GET/POST 分别是 HTTP 读取与写入方法；DOM 指浏览器读到的页面结构。

### 验收 3：数据与状态区分真实和样例

目标：页面消费者能辨认加载、成功、空、错误、超时和写回执，且不会把样例当真实值。

怎么操作：先启动本地受控服务，再用真实源与合成源分别重放各状态。
随后运行数据脚本、纯函数与状态合同测试，并观察当前对象的固定视口页面。

什么条件：阶段 2 对象、八份数据文件、本地服务、Node 和隔离浏览器可用。
数据实施者提供来源与状态；独立测试者在实现和审查问题修完后判定。
实际服务由 check-data-discipline.mjs 的 --mode=serve 启动，页面 URL 为 http://127.0.0.1:8768/index.html。
服务读取 P2-port-output.json 的 output_root，不直接服务设计源目录；GET /identity 返回实际 URL、进程与配置身份。
页面客户端已由阶段 2 写在 app.js 并原样生成；阶段 3 只提供它消费的同源路由和输入。
真实模式用 /index.html?mode=real 打开；声明状态输入由当前服务夹具提供，页面从单一状态口消费响应。
适配缺失回阶段 2 原写者修复、重新生成和采摘要，阶段 3 不私自注入页面字节。
写入口为 POST http://127.0.0.1:8768/records，请求值来自 data/write-receipt.json。
服务把真实记录与回执写入命令给定的临时 store 文件，页面回显不是存储真相。
定向测试或浏览器场景以子进程拥有服务，等待 GET /identity 就绪并保存 PID、URL、store；finally 只停止该自建服务。
stage 4 复用同一 8768 动态对象，不另起静态源或 8769 服务。
data/timeout.json 必须写 timeout_ms=25 与服务 delay_ms=100；这是夹具时序，不是性能预算。

怎样算通过：通过、失败和证据以 spec.md Appendix A 验收 3 为唯一权威。
反例是有源错误被样例掩盖、未知错误误分档、样例模式允许写入或无回执报成功。

真跑还是替代：真跑本地服务与真实页面，不用静态 JSON 存在代替状态行为。
数据检查命令为 node skills/design-source-extraction/scripts/check-data-discipline.mjs --fixture tests/fixtures/design-port-sample/data。
实际服务命令为 SERVICE_STORE="$(mktemp -d)/store.json"; node skills/design-source-extraction/scripts/check-data-discipline.mjs --mode=serve --fixture tests/fixtures/design-port-sample/data --listen=127.0.0.1 --port=8768 --port-output-record "$P2_PORT_OUTPUT_REF" --store "$SERVICE_STORE"。
服务同时提供页面、固定读取路由和 POST /records；检查模式从夹具读取服务 URL、写入口与超时。
合同命令为 npx --no-install vitest run tests/contract/design-port-data-discipline.test.mjs。
预期恢复后退出 0，受控反例退出非零。

谁判与证据：未参与数据实现的独立测试者读状态输出、回执、冲突裁定和页面证据。
命令由 captureCommand 保存；语义裁定与新截图由 appendRecord 保存。

失败回修与停止：数据问题回任务 4 开发，服务问题交本地环境 owner。
修后只重跑失败状态和受影响页面；不得用样例填充或改判定器消除失败。

### 验收 5：旧功能接回且旧行为可恢复

目标：旧接口仍收到预期参数，页面消费真实回执，旧钩子与回退后的旧行为保持。

怎么操作：读取三链清单，用旧接口间谍记录真实调用并核页面回执。
随后断开处理器、接错接口，再在临时副本撤回本任务改动块并重放旧行为。

什么条件：阶段 2 对象、阶段 3 接线映射、旧接口夹具、真实回执和定向测试可读。
接线实施者提供三链与尝试记录；独立测试者判定，具名缺口由独立审查者确认。
真实旧接口来自 P2 样本 app.js 的 LegacySampleGateway。
readRecord({recordId:"sample-01"}) 经 GET /records/sample-01 读取；writeRecord({recordId:"sample-01",value:"legacy-write",requestId:"req-01"}) 经 POST /records 写入。
真实回执来自 POST 响应与服务侧 store 的同一记录；命令回执不能代替业务回执。
旧入口是样本 #next-sample，旧钩子是 #result-panel[data-legacy-hook="sample-result"]。
回退对象是临时副本内本任务适配器改动块；恢复后重放上述旧参数、入口和钩子。

怎样算通过：通过、失败和证据以 spec.md Appendix A 验收 5 为唯一权威。
反例是静默放弃旧功能、断开未被识别、缺口无尝试记录或回退后旧接口仍受损。

真跑还是替代：真跑受控旧接口与恢复用例；间谍只观察边界，不替代关键页面接缝。
接线命令为 node skills/design-source-extraction/scripts/check-wiring.mjs --map tests/fixtures/design-port-sample/wiring/wiring.md。
合同命令为 npx --no-install vitest run tests/contract/design-port-wiring.test.mjs。
预期恢复后退出 0，目标反例退出非零。

谁判与证据：未参与接线的独立测试者核参数、回执、钩子、反例和恢复。
证据由 captureCommand 保存；缺口审查保留独立身份与原件指针。

失败回修与停止：接线问题回任务 5 开发，旧功能本身问题回原旧功能 owner。
修后只重跑受影响三链和恢复用例；严重范围或验收变化交原决定 owner。

## 每张任务卡怎么写？

### 任务 4：让真实数据、样例和写回执可辨

为什么做：消费者需要知道页面值来自哪里，以及读取或写入是否真实成功。
交付什么：数据方法、八份状态输入、检查脚本、本地服务和可观察页面状态。
不做什么：不用样例填有源失败，不自造提示替代控件，不改组件样式或旧接口。
前置：阶段 2 样本与登记交回，本地服务和独立测试输入可构造。
怎么做：先写数据档案、默认源和失败分档纯函数，再接加载至写回执状态。
随后实现样例写入拒绝、真实模式样例清理和冲突裁定记录。
怎么验收：运行数据脚本、定向测试和本阶段浏览器场景，逐状态核反例。
证据：状态原输出、真实回执、冲突记录、页面截图和命令回执。
下游（含何时停）：任务 5 取真实回执；缺源或环境不可用时保原错误，不填样例。
