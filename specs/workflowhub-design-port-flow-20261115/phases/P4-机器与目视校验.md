## 这一 Phase 交出什么？

独立审查者取得能识别受控破坏的四类机器校验，以及实际实施对象的独立目视结论。

- **本 Phase 结果**：四类检查绑定当前实际内容；实施对象在固定视口完成独立目视。
- **非目标**：不内置目标项目探针，不改页面组件，不验收其它视口或真实外部项目。
- **改动前**：已有移植、数据和接线方法，但没有本阶段四类脚本与实施目视检查。
- **改动后**：每类校验有正反证据；视觉差异逐项修复或由独立审查者附理由接受。
- **与相邻 Phase 的边界**：阶段 2/3 交同一实施对象；本阶段只新增校验与目视资产。
- **主要风险**：报告只绑提交号会漏掉未提交内容；替代走法是绑定文件、配置和探针内容。
- **下一步**：阶段 5 读取已核报告与共享文件状态；阶段 6 读回本阶段首次判定。
- **动手前必读**：`spec.md#实现设计全局权威`、Appendix A 的 AC-004/AC-006。
- **未决事实**：实际预览入口、探针输出与实施证据尚未产生；由任务 1/2 在执行时取得。

“脏工作树”是含未提交改动的当前工作树。
“探针”是从实际页面读取计算样式或结构的受控脚本。
“设备像素比”是 CSS 像素与设备像素的缩放比例，本任务固定为 1。

- **范围账**：AC-004 只证声明配置和当前样本；AC-006 只证实际对象的固定视口。
  阶段 2/3 产物是供件，不在本阶段重新首判其验收。
- **阶段预算**：`phase_budget={soft_min:unknown,hard_min:unknown,variance_threshold:unknown,source:spec未给阶段值}`。

### 验收 1：四类校验能识别破坏并绑定当前内容

目标：独立测试者能分别判几何、结构、来源与生成物覆盖、功能保留的真假结果。
操作：先读四份配置和 `ORACLE-PORT-VERIFICATION`，再运行任务 1 的定向合同测试。
条件：Node、固定样本、实际探针、当前提交号、脏状态和后端身份均可读取。
内容摘要覆盖被比较文件、配置与探针输出；报告不只记录提交号。
任务 1 先取得 P2-port-output.json 的实际绝对路径为 `P2_PORT_OUTPUT_REF`。
该原件由 P2 生成后 appendRecord，记录 output_root、source_root、逐文件 hash 和生成回执。
任务 1 在取身份前启动阶段 3 同一 `--mode=serve` 动态对象，唯一服务地址为 8768。
服务 owner 用受管后台任务保存 job/PID、实际 URL、绝对 store 路径和进程回执。
ready 条件是 8768 页面与 identity 均可读；未 ready 不执行四类检查。
后端身份来自 `GET http://127.0.0.1:8768/identity` 的真实响应、进程回执和
`data/real-mode.json` 配置摘要，不接受报告自写身份字符串。
测试用 `crypto` 独立重算文件、配置和探针摘要，并保存响应与进程原件。
不另起 8769，不把动态对象换成静态源码服务。
通过：每类对具名破坏给出目标失败，恢复后同一判定器通过，内容或后端变化会失效。
反例：在提交后只改移植件而不改提交号，报告必须因内容摘要不符而失败。
真跑：四类私有命令逐条执行，并由同一合同测试自动完成改坏与恢复。
命令和输入见任务 1；目标断言失败退出非零，合法恢复退出 0。
缺配置记 `unverified`，环境客观不可用记 `unavailable`，二者整体退出可为 0。
它们不得称全部通过；只有另一独立审查者书面接受缺口后，才允许进入目视。
脚本错误、断言红或内容身份错配均为失败，不能改写为跳过。
判定者与证据：未参与实现的独立测试者在审查修复后判，读四组原输出与缺口审查。
证据计划落 `quality/evidence/build-code/P4/T006-verification.md`，命令回执留 `quality/tests/`。
失败回修：目标失败回任务 1 原写主；环境失败由环境提供者恢复。
修后只重跑受影响类别和身份检查；未接受缺口、身份不符或反例仍绿时停止目视。

### 验收 2：实际实施对象完成固定视口独立目视

目标：独立设计审查者对实际实施对象的声明状态逐项给出视觉结论。
操作：任务 1 已使 8768 动态对象 ready 后，任务 2 复用同一 URL、进程、store 和字节。
实际页面为 `http://127.0.0.1:8768/index.html`，由阶段 3 serve 模式提供页面、数据和身份。
任务 2 不启动第二服务；服务 owner 在本阶段结束时 finally 只停自建 8768 服务。
条件：真实浏览器、1440×1000、设备像素比 1、设计对和机器缺口结论齐备。
设计侧为阶段 2 源 `prototype/index.html`、`styles.css`、`app.js`。
实施侧固定读取 P2-port-output.json 的 `output_root`，经阶段 3 同一 serve 对象交回。
P2 的真实生成命令为 `OUT="$(mktemp -d)"; node skills/design-source-extraction/scripts/check-port-manifest.mjs --mode=generate --manifest tests/fixtures/design-port-sample/port/manifest.json --design-root tests/fixtures/design-port-sample/prototype --output "$OUT"`。
P2 开发在生成后 appendRecord 输出原件并采集逐文件 hash；P4 在实施验收时使用这些实际 hash。
当前未生成的 hash 为 unknown 是正常事实，不是规划缺口；不得提前实施或伪造。
每对记录设计源路径/hash、移植输出路径/hash、实施 URL、状态和读取时点。
路径相同且内容来自同一源目录时以 `SELF_COMPARISON` 失败；实施字节改变也必须失效。
状态为加载、成功、空、错误、超时、写回执、错误恢复和样例模式写拒绝。
通过：声明状态均被观察；每条差异为无差异、已修复或独立接受及理由。
反例：拿旧原型图、设计源目录自比或机器全绿代替实施目视，均失败。
真跑：合同测试只用 `tests/fixtures/design-port-sample/visual/review.json` 做正负形状夹具。
实际报告、设计对和差异结论由独立审查者经 appendRecord 保存到任务证据目录。
实际验收命令对该返回目录执行 `check-visual-review --dir`，不得检查开发夹具冒结论。
合同命令 `npx --no-install vitest run tests/contract/design-port-visual-review.test.mjs` 预期 0。
完整浏览器命令见「怎么验证？」；缺截图、服务或语义结论分别保留真实缺口。
判定者与证据：未参与实现的独立设计审查者实际看图并判，记录浏览器、字体和 DPR。
证据计划落 `quality/evidence/build-code/P4/T007-visual-review.md`，实际报告用 appendRecord 新件。
失败回修：视觉问题回实现 owner；服务/浏览器问题回环境 owner；记录问题回独立审查者。
修后只复验受影响状态和维度；未解决差异、自比、对象不符或自判时停止本项收口。

### 碰页面的六项验收是什么？

1. **设计源引用**：对照 `prototype/README.md` 的任务局部 Swiss 方向和已确认状态。
   该说明实读 SHA256 为 `883175229b2046b42a847cf91c76c336c557cfda115876018e6270e2cfe29f86`。
   实时复核 046 的 SHA256 为 `8d82f32cf27aaf33a7fecf834e64c6478377ad9229f98dfa19a7d36435d1c026`。
   用户答复原件为 047，读取时点为 2026-11-15。
   实际设计对分别记录 P2 设计源与实际移植输出的不同路径和 hash。
   输出身份固定来自 P2-port-output.json；生成后采实际 hash，缺项或同源自比时停止。
2. **页面／组件与状态乘视口**：实施样本页、结果区、状态序列和唯一按钮。
   加载、成功、空、错误、超时、写回执、恢复和样例写拒绝均只看 1440×1000、DPR1。
   键盘焦点、可访问名和主操作随这些状态观察。
   390 像素、其它视口、缩放与压力内容未覆盖，不作通过条件。
3. **视觉对照项**：对照局部网格、层级、大序号、字体、颜色和三层样例标识。
   同页像素还原因无合法同页稿而不适用；差异与接受理由由独立审查者分开记录。
4. **前端质量门**：组件质量只回读既有地图，本阶段不改组件。
   浏览器须真实打开并无观察期控制台错误；插桩前未覆盖处如实披露。
   1440 下无横向文档溢出且主操作可达；其它宽度不外推。
   键盘可达、焦点可见、可访问名和状态语义须实际观察；真人读屏未覆盖。
   性能未测量且不是本次通过条件，不套用通用性能数值。
5. **组件复用与沉淀**：不适用——本阶段只新增校验与审查资产，不改组件或样式。
   既有组件地图和真实消费者只读回读，不新增沉淀位置。
6. **独立设计审查与证据**：由未参与实施的新上下文执行八维审查并保存实际输入、观察和限制。
   计划落点为 `quality/evidence/build-code/P4/T007-independent-design-review.md`。
   build-plan 的 030/046 只作输入，不冒本阶段审查原件。
