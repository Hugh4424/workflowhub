- **来源 / FR / AC**：R-029「提交/合并/归档/推送/清理/PR/图谱更新」整组收尾共用一个技能、R-030 指定两 caller 人工确认后使用；ADR-018、M7；FR-KG-010、FR-KG-006、FR-KG-011；AC-011 的独立调用、AC-012 的授权保全、AC-006 的更新委派子条件。

- **文件 / 符号**：owner=stage-closeout 方法作者；`skills/stage-closeout/SKILL.md`；`skills/stage-closeout/skill-bundle.json`；`skills/catalog.yaml`；N/A — 非代码方法/登记。bundle 复用现有 schema_version=1、skill=stage-closeout、files 仅列 SKILL.md 的形状；catalog 依赖闭包包含自身和真实调用的 knowledge-graph，不新增第二图 owner。
- **动作**：
  1. 从 verify-code 现有收口原文逐项做保全映射：任务身份、质量限制、真实授权、当前 HEAD、PR、归档、push、工作区/分支清理和结果读回分别归到新方法对应步骤。确认/审查/正式阶段 facts 与 stage-handoff 的作者仍留 caller；不把质量裁决搬给收尾作者。
  2. 新方法先核调用者传入的真实 task/worktree/材料/分支/remote/写集。build-prd 内容确认只证明稿件被同意，Git 动作须有真实范围授权；verify-code 必要 commit/push/merge 沿任务持续授权。实际 Git 动作前仍用现 git-authorize record/consume；普通非 scoped 记录在 HEAD 改变时重新核对记录，旧 HEAD 授权消费必须失败。build-code scoped commit 沿现实现保留同 task/分支/阶段的跨 HEAD 复用及每次真实 HEAD 消费记录，不由共享方法缩减其既有授权。
  3. 在任务分支 worktree、提交前调用 P2 更新方法：代码图读真实 exit 与无事可做含义；文档仅按 M1 本次改动集合及预计份数询问后处理；分开报告。图不可用或文档未批准保真实原因，继续其它安全工作；图变动单列非源码写集。图忽略项清理由 P2 给出本次具名创建事实，未知/唯一字节保留为明确例外，禁止整目录丢弃。
  4. 用现窄工具与普通 Git 完成有授权的 commit、push-task、PR 与 merge。需要 PR 时将真实 URL 立即交给人，`until=pr` 仅表示该次调用停在真实 PR 的效果；同次执行流以实际 PR/head/base/分支读回继续剩余动作，不等待新答复，不创建/消费旧 close plan 或新增状态账本。PR 能力不可用时如实保原因，普通五步收尾沿已授权范围执行。
  5. 最终 archive/删除/cleanup 前统一展示当前结果、质量限制、归档路径、task-owned worktree、本地/实际存在的同名远端分支和具名例外，取得一次真实范围确认。父规划材料仍被子任务消费时保留这些具体路径和用途；内容确认不冒归档授权。复用 inspectWorktreeCleanup 与 createTaskWorktreeRemoval probe/execute/verify，普通 branch -d，实际已交付才删同名远端分支；main/existing workspace 保留。
  6. 实施、质量、图更新、PR、commit/merge/push、归档、worktree/本地与远端分支清理逐项读回，回 caller 供唯一正式事实与 stage-handoff 消费。独立调用者能只凭当前方法、真实输入与来源执行，不绑定当前账号/绝对路径/特定宿主。
