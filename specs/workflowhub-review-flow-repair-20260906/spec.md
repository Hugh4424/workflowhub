## 速读卡（30 秒）

- **一句话需求**：用户发起审查时，只维护一份 provider 定义；确定无法执行的问题立即解释原因，每次调用都能找到真实结果或失败记录。
- **核心改动点**：去掉重复 profiles/priority；静态预检在派发前完成；任务记录、复用引用和裸跑诊断各有明确语义。
- **最大影响面**：所有 wh-review 阶段路由、任务审查记录与 E2E 选择；历史记录仍可读，但旧 policy 结果一次性停止复用。
- **验收信号**：静态必败在 1 秒内返回且没有派发；已返回的审查可凭引用找到记录；重复拦截或复用不制造新 attempt。

## 1. 问题与紧迫性

同一 provider 在 WorkflowHub 和 3rd-review 重复声明，用户修改一处后可能被另一处的一致性检查阻塞。静态错误延迟到 provider 执行后才显露，浪费等待和调用成本。结果依赖调用方自觉保存，失败时尤其难以追溯。

本期直接解决上述三类故障。审查内容质量和外部 provider 响应时间不由本期承诺改善；静态问题的等待时间、记录可查性和兼容行为必须可验证。

## 3. 用户场景与状态覆盖

### SCN-001：维护 provider 定义

- **角色**：配置维护者。
- **Given**：3rd-review 有有效 provider 定义，WorkflowHub 路由引用它。
- **When**：只修改该 provider 的 model/effort/thinking 等定义，再发起审查。
- **Then**：直接消费这份定义，不要求另一份 profiles 声明与之匹配。

### SCN-002：调整路由先后

- **角色**：配置维护者。
- **Given**：initial/closure 含多个合法 provider。
- **When**：用户调整列表顺序。
- **Then**：列表顺序就是选择顺序，不被独立 priority 重排；原有异源和数量约束继续适用。

### SCN-003：静态输入不能执行

- **角色**：审查调用者。
- **Given**：缺配置、配置结构错误、引用不存在/禁用 provider、身份不可用、附件越界或必需材料为空。
- **When**：发起审查。
- **Then**：进入打包、锁等待和 broker 前终止，1 秒内返回 blocked_before_dispatch 诊断及实际记录引用。

### SCN-004：探测结果未知

- **角色**：审查调用者。
- **Given**：本地静态条件均合法，仅 broker 版本或能力探测为 unknown。
- **When**：发起审查。
- **Then**：unknown 不被当作必败，不阻止正常派发；后续运行失败保留实际原因。

### SCN-005：完成、部分成功或运行失败

- **角色**：审查调用者与结果阅读者。
- **Given**：静态预检通过。
- **When**：provider 返回有效 findings，或发生超时、取消、坏输出、部分成员失败。
- **Then**：保存实际 provider、状态、可用 usage、结果或失败原因；一个有效异源成员可形成 available-with-failures，空 findings 和失败均不被包装成验收通过。

### SCN-006：重复静态拦截

- **角色**：修复配置或材料的用户。
- **Given**：同任务、同阶段和审查对象、同材料指纹与同拦截原因已有记录。
- **When**：相同请求再次被同一原因拦截，包括并发重复请求。
- **Then**：引用已有记录，不增加 attempt、不改旧报告；改变原因或材料不会错误引用不相干记录。

### SCN-007：没有任务上下文的裸跑

- **角色**：直接使用审查 CLI 的用户。
- **Given**：调用只有审查材料，没有认证任务上下文。
- **When**：审查成功、失败或被预检拦截。
- **Then**：返回本地诊断 sink 的记录位置和非权威标记，用户可追溯，但它不能充当任务正式质量事实。

### SCN-008：引用已存在的审查

- **角色**：审查调用者与阶段结果消费方。
- **Given**：有满足当前 policy、异源和既有身份/等价规则的可复用结果。
- **When**：重复调用命中它。
- **Then**：返回 reused 和原始引用，不派发、不新增 attempt；源记录身份保持原样。若仅内容一致但当前认证不成立，只能作为历史参考，当前质量缺口明确可见。

### SCN-009：记录写入失败

- **角色**：调用者。
- **Given**：记录目录不可写、磁盘写入失败或存在异字节冲突。
- **When**：保存调用结果。
- **Then**：明确报告保存失败与可执行修复动作，不声称记录已保存，不把非权威诊断冒充权威记录；已存在记录保持原样。

### SCN-010：迁移配置与历史结果

- **角色**：配置维护者和历史记录阅读者。
- **Given**：旧配置含 profiles/priority，旧结果含旧 policy 形状。
- **When**：备份并迁移 WorkflowHub 配置，再读取历史或发起新的审查。
- **Then**：路由顺序和 provider 定义保留；历史可读而旧结果不可复用；下次需要审查时按当前路由与原有预算规则处理，不批量重写历史或主动触发重审。

### SCN-011：E2E 使用首个 provider

- **角色**：E2E 调用者。
- **Given**：initial 包含零项、一项或多项。
- **When**：发起 E2E 审查。
- **Then**：固定选择 initial 第一项；initial 为空（无首项）按路由不可用拦截、落盘 blocked_before_dispatch 记录、不派发；首项同源、禁用或不存在时失败并记录，不自动换到后项；多项本身不再导致失败。

### SCN-012：实施后真实验证

- **角色**：当前任务执行者与验收者。
- **Given**：本期实现已可执行，配置已备份并迁移。
- **When**：执行静态失败、正常/运行失败、复用与重复拦截的真实流程。
- **Then**：实际记录、时间和调用事实可互相核对；未执行场景、环境失败和外部依赖缺口仍标记未验证。

- **FR-CONFIG-001**：WorkflowHub 不再要求或接受 wh_review.profiles/priority；provider 定义直接来自 3rd-review 的已配置值，不进行两份声明一致性校验。
  - **依据**：R-001/R-002、D-001、PFACT-001；**场景**：SCN-001；**验收**：AC-CONFIG-001。
- **FR-CONFIG-002**：initial/closure 列表顺序是唯一显式路由顺序；保留既有异源、最低人数与 legacy tiers 无显式路由时的行为。

- **FR-CONFIG-003**：迁移先保留可恢复备份，仅移除 WorkflowHub 重复定义，保留路由顺序、无关配置和原 provider 定义；旧格式被明确拒绝并给出迁移动作。
  - **依据**：R-001/R-002、D-001、PFACT-001；**场景**：SCN-010；**验收**：AC-CONFIG-003。

### 静态预检（PREFLIGHT）

预检只判断本地已经确定不能执行的条件，避免把未知外部状态变成假阻塞。

- **FR-PREFLIGHT-001**：缺失或无效配置、路由引用不存在/禁用 provider、路由列表为空（无可派发项）、host 身份格式或同源约束失败、附件越界、必需材料缺失/空值，在打包、锁等待和派发前处理。材料检查沿用当前阶段必需材料列表，不新增第二套深校验规则。
  - **依据**：R-002/R-003、D-002、PFACT-002；**场景**：SCN-003；**验收**：AC-PREFLIGHT-001。
- **FR-PREFLIGHT-002**：从本次审查进入静态预检到返回拦截诊断和记录引用，耗时不超过 1 秒；unknown 不构成拦截条件。超限真实记为验收失败，不扣除锁等待或写盘时间掩盖。
  - **依据**：R-003、D-002、PFACT-002；**场景**：SCN-003/004；**验收**：AC-PREFLIGHT-002。
- **FR-PREFLIGHT-003**：拦截显示 blocked_before_dispatch，诊断含 field、expected、actual、next_action，并复用 MATERIAL_INCOMPLETE / MATERIAL_FORBIDDEN / ROUTE_UNAVAILABLE。运行时失败保留原错误码；敏感值不进入公开诊断。
  - **依据**：R-002/R-003、D-002/D-008、PFACT-002；**场景**：SCN-003/005；**验收**：AC-PREFLIGHT-003。

### 记录（RECORD）

每个返回结果都能说明调用发生了什么、记录在哪里、记录能否用于当前任务。没有语义结果时不伪造 result。预检拦截的落盘复用既有未派发记录能力（材料预检与路由缺失两类已存在、带幂等去重），对齐同一去重口径，不建第二套落盘路径。

- **FR-RECORD-001**：任务调用保存实际 attempt、可产生的 result 和 report。有效语义结果保留 findings 与成员失败；无有效语义结果保存失败 attempt/report、resultRef=null，保留错误与恢复说明。
  - **依据**：R-004、D-003、PFACT-003；**场景**：SCN-005；**验收**：AC-RECORD-001。
- **FR-RECORD-002**：预检拦截保存 unavailable attempt 和 report，不生成 result、不生成虚构 provider attempt；阶段事实只在记录成功后发布，明确未派发。
  - **依据**：R-004、D-002/D-003、PFACT-003；**场景**：SCN-003/006；**验收**：AC-RECORD-002。
- **FR-RECORD-003**：复用和重复同原因拦截返回已有不可变引用，不新增 attempt、不修改源记录。去重限制在同任务/阶段/审查对象、相同材料指纹和原因；不同身份不得互用。引用呈现原始身份和当前匹配结果，不能单凭内容一致冒充当前认证；重审原因只记录，是否重审继续服从既有规则。
  - **依据**：R-004/R-005、D-003/D-007/D-008、PFACT-003/PFACT-006；**场景**：SCN-006/008；**验收**：AC-RECORD-003。
- **FR-RECORD-004**：裸跑将本次诊断写至 ~/.workflowhub/review-sink/ 并返回可定位引用，显式非权威。sink 不枚举或写入 task 正式记录，不参与 canonical 复用或阶段质量认证；重复拦截按裸跑去重键（材料指纹+拦截原因+调用参数指纹；调用参数指纹只取归一化后的结构性字段，剔除时间戳、随机标识、临时路径等易变字段）幂等去重，仅 sink 内局部、不构成跨任务身份。
  - **依据**：R-004、D-003、PFACT-003；**场景**：SCN-007；**验收**：AC-RECORD-004。
- **FR-RECORD-005**：写入失败、并发冲突、取消与材料漂移必须保留真实失败；相同字节重复写幂等，异字节不得覆盖。调用不能在实际保存失败时报告“已保存”；部分记录可见时明确缺失项，恢复不得修改旧证据。
  - **依据**：R-004、D-003/D-008、PFACT-003；**场景**：SCN-005/006/008/009；**验收**：AC-RECORD-005。

## 6. 模块划分

- 配置与路由：从唯一 provider 定义和有序列表产生可解释选择；边界为 SCN-001/002/011。
- 审查执行：静态预检、既有 broker 派发与真实结果返回；边界为 SCN-003～005。
- 追溯：任务权威记录、裸跑诊断、历史引用及保存失败说明；边界为 SCN-006～010。
- 阶段消费：继续由现有 owner 判断预算、finding 处置和质量；本规格只约束其输入事实不丢失。

## 7. 关键实体

- Provider 定义：3rd-review 的单一记录；路由只按 provider 标识引用，不复制 model/effort/thinking。
- 路由：按阶段/track 区分的 initial/closure 有序列表，保留现有最低人数规则。
- Attempt：一次实际审查尝试或首次静态拦截的不可变事实；具有 task、stage、材料身份、实际 provider 成员及错误。复用引用不是新 attempt。
- Result：有有效语义产出时的审查结果；关联原始 attempt；没有语义产出时不存在。
- Report：面向用户的可读记录，展示状态、实际来源、失败原因、恢复动作和引用。
- 复用引用：在现有返回结构中指向原始记录，明确 reused；不新建永久对象、不修改原始身份。
- 裸跑诊断：本地、非权威的调用记录，不能替代 task 记录。

## 8. 数据和生命周期

静态检查 → 首次拦截并保存，或进入既有派发 → 收集真实语义/失败 → 保存 → 返回引用。命中复用或相同拦截时直接返回已有引用。保存出错进入明确失败，不报告完整交付。

新记录区分派发事实和语义结果。blocked_before_dispatch 对阶段仍是 unavailable；reused 描述本次引用，不能把历史源 attempt 改为 reused。schema 对扩展状态的支持不授予新的阶段完成状态。

task 记录归当前 task owner 持有；原始来源、报告和历史 hash 不覆盖。裸跑 sink 归本机调用者持有，保留/清理由 build-plan 细化（OPEN-002），本期没有自动删除承诺。结构损坏的记录不作为复用候选，暴露诊断而不重新解释成成功。

配置或材料在检查后变化时继续由既有绑定规则检测；旧引用保留原身份。符合既有等价规则才可供当前认证，不发明新的跨 snapshot 等价规则。缺记录/身份不可绑定时当前质量 incomplete，可继续同任务修复。

进程被硬杀或存储完全不可用时，无法承诺完整终态文件一定存在；AC-RECORD-005 要求可观察失败不被伪装成功。build-plan 必须设计开始记录和可捕获终止路径的最小写入时机，并明确不可捕获中断的证据限制，不能将“每次调用”悄悄缩成“只有成功调用”。

## 9. 兼容性预留
保留旧记录可读、新写严格、policy 一次性失效、现有阶段结果形状和原始 usage。字段扩展只服务 FR-COMPAT-001，不预建通用版本平台。

已知上游 usage 消费不匹配登记 RISK-001；原始 usage 保留的验收与上游统计正确性分开。上游预算观察发生在阶段事实收集时（消费后检查，不阻断派发），其类型映射存在已知失真（部分审查类别永不产生、个别状态分支永不命中）；本任务不重写预算规则，未派发记录按原预算规则被如何计数不得在本任务修改；若导致用户仍不能调用，记录真实缺陷交给相邻 owner。

失败：只用示例或摘要、实现前声称新机制已生效、漏报未执行场景。
证据：实际调用输出、记录引用、针对性测试和逐AC观察清单。

## 12. 风险、未决与交接

- **RISK-001**：上游消费者与新/旧记录不匹配（已被代码核实：usage 读取路径与状态词汇和写入不一致，预算观察输入无状态字段，现行链路上恒读不到真值，且预算为消费后检查）。受影响：PFACT-006、FR-SAFETY-002/FR-COMPAT-001/FR-RECORD-003 及其 AC；触发：新字段或历史引用进入旧读取器；后果：原始记录存在但统计/认证 incomplete；缓解：保留原始事实，优先维持现有公开形状；处理 Stage：build-plan；owner：本任务规划主会话；验证：真实producer→consumer合同及明确失败；需改排除域或改变预算规则时 STOP 对应修改，回方向 owner，不能静默扩范围。
