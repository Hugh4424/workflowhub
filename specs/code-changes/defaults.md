# 代码改动域 · 错误与默认值

定位：本组只回答「失败怎么露出、默认值谁定、兜底放哪」。读者：写错误处理的实现者、审该分支的审查者。
边界：宪法 F8/F9 的正文在 CONSTITUTION.md；API 错误码与字段归 specs/api/contract.md；页面失败态归 specs/frontend/frontend.md。

## 规则

1. 每条失败路径必须有可观察结果；空 catch、静默 return、用默认值吞掉失败都算未完成（强制：审查问句；锚：[F9 可证伪、不假绿](../../CONSTITUTION.md#f9-可证伪不假绿)）
2. 每个默认值只有一个具名 owner；没有 owner 时写未决并留缺口，不许自己填一个（强制：审查问句；锚：[F8 简单优先](../../CONSTITUTION.md#f8-简单优先)）
3. 兜底只允许放在边缘适配层，且必须写明触发条件与可观察后果；核心路径不兜底（强制：审查问句；锚：[当前治理边界](../../AGENTS.md#当前治理边界)）
4. 错误向上传播保持原因与位置；要改写成更具体的说法时，原文与出处一起留（强制：审查问句；锚：[build-code 测试与质量](../../docs/standard-workflow.md#build-code-测试与质量)）
5. 新增默认值或兜底时同批写下反例：什么输入必须仍然失败（强制：审查问句；锚：[行为测试与证伪](../../skills/backend-testing/SKILL.md#行为测试与证伪)）

## 边界与不承接

宪法条款正文不在此复制；检查器不判「兜底是否合理」，只由审查问句判。
