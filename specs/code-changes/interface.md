# 代码改动域 · 接口变更处置

定位：本组只回答「这次改接口怎么处置」，不回答「字段叫什么」。读者：改 public/CLI 调用前的人与审查者。
边界：字段、状态、协议归 specs/api/contract.md；模块、依赖、接缝归 specs/backend/architecture.md；本文件不复制字段、不定义 schema。

## 规则

1. 动接口前先写四个处置答案：真实 caller 是谁、输入是否跨模块边界、能否作一次纯函数判断、公共面是否暴露内部表示（强制：审查问句；锚：[当前治理边界](../../AGENTS.md#当前治理边界)）
2. 只有跨模块边界的输入才做校验；模块内不重复校验同一输入（强制：审查问句；锚：[专业规则与失败边界](../../specs/api/contract.md#专业规则与失败边界)）
3. 公共面不暴露 storage/transport/framework 内部表示；需要时先在边缘转换，再进公共面（强制：审查问句；锚：[当前治理边界](../../AGENTS.md#当前治理边界)）
4. 字段、状态、协议一律不在此定义；要改先回接口合同，处置结论只写「怎么改」不写「字段是什么」（强制：结构——本文件不得出现字段表；锚：[专业规则与失败边界](../../specs/api/contract.md#专业规则与失败边界)）
5. 处置结论落在本次 Phase 卡或 spec 的接口与数据流段，不另建登记表（强制：仅文档；锚：[step-spec-plan](../../workflows/build-plan/SKILL.md#step-spec-plan)）

## 边界与不承接

本文件对字段与协议没有权威；与接口合同冲突时以合同为准，并把冲突写回原 owner。
