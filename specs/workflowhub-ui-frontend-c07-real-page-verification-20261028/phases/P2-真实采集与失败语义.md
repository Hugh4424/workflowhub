把已有的浏览器网关接成一条能跑的采集链。
ego 在跑就用；装了没开回退 agent-browser，并把回退四子字段写进 stdout。

- 一条可回放的回退分支：假 PATH 下 marker 只出现一次，输出带四子字段。

采集链是编排与真实验证的入口，没有它后面两个 Phase 无从下手。
它依赖 P1 的判据与形状校验器，所以排在 P1 之后。

**采集器的身份输入（与 P5「编排器到采集器的身份传递」逐字对齐）。**
五个采集器的命令行仍只有 `--cdp-url`、`--out` 与可选 `--viewport`、`--state` 四项；五个身份值从 P5 的命令行接收：P5 解析 `--workspace`、`--service`、`--route`、`--object-version`、`--engine-session` 后，逐次注入每个采集器子进程的五个环境变量。采集器自己不新增身份命令行参数。

| P5 命令行参数 | 采集器环境变量 | `object` 键 |
| --- | --- | --- |
| `--workspace` | `PAGE_AUDIT_WORKSPACE` | `workspace` |
| `--service` | `PAGE_AUDIT_SERVICE` | `service` |
| `--route` | `PAGE_AUDIT_ROUTE` | `route` |
| `--object-version` | `PAGE_AUDIT_OBJECT_VERSION` | `object_version` |
| `--engine-session` | `PAGE_AUDIT_ENGINE_SESSION` | `engine_session` |

一、采集器启动先读这五个变量，只当声明值填进 `object`，不猜、不派生、不填默认值。
二、缺任一个或为空串：不连接 CDP、不写 `--out`，stderr 出一行 JSON `{"ok":false,"outcome":"unavailable","errors":[{"code":"E_IDENTITY_INCOMPLETE","path":"<缺的键>","message":"..."}]}`，退出 2。`path` 只写 `workspace`、`service`、`route`、`object_version`、`engine_session` 之一。
三、不把缺项写成 `null` 继续，也不记 `failures[].class:"IDENTITY_MISMATCH"`；后者只留给 receiver 实际观察到的身份与声明值不符，按 ADR-0031 不降级为 warn。
四、五个值齐：`object` 五键逐字等于注入值；`state`、`viewport`、`engine` 三键仍按原规则填，八键齐。

身份判据两条：
- 正向：五个变量齐备跑任一采集器，`object` 五键逐字等于注入值，`failures` 不含 `IDENTITY_MISMATCH`，退出 0，`--out` 存在。
- 反向：删掉 `PAGE_AUDIT_WORKSPACE`（或置空）重跑，退出 2、stderr 的 `errors[0].code` 为 `E_IDENTITY_INCOMPLETE`、`path` 为 `workspace`、`--out` 不存在、CDP 桩连接计数 0。

**共享导航窗口（只用于 console 与 network）。**
这两维是事件流，P5 调用它们时不再各跑一次；一次导航只开一个窗口：

一、角色：`collect-console` 与 `collect-network` 都只订阅；导航由 P5 的编排器唯一触发，采集器不导航、不重试。
二、开始：P5 先并发拉起两个采集器，各带同一组窗口环境变量 `PAGE_AUDIT_WINDOW_DIR`、`PAGE_AUDIT_TARGET_ID`、`PAGE_AUDIT_WINDOW_ID`。采集器连同一端点、attach 到同一 `targetId`，完成 `Page.enable` 与各自域（`Runtime.enable` / `Network.enable`）后，原子写 `<dir>/console.ready` 或 `<dir>/network.ready`；写不出按 `TOOL_ERROR` 收尾。
三、动作：P5 等两个 ready 文件都出现后，才对同一页面目标发唯一一次导航（`Page.reload`，等价于 `Page.navigate` 到当前 URL），等 `Page.loadEventFired`，再等 500 ms 静默窗；任一采集器未就绪，P5 不发导航。
四、结束：P5 写 `<dir>/finish`；两个采集器看到 finish 后把已收事件刷进 `--out`，`items[]` 带 `window_id` 与主帧 `loader_id`，退出 0；收不到 finish 超过 30 秒（测试用 `PAGE_AUDIT_WINDOW_TIMEOUT_MS` 压到 50 ms）按 `TOOL_ERROR` 收尾。
五、同一次导航的证明：两份输出的 `window_id` 逐字相等、`loader_id` 逐字相等且等于 P5 记录的 `loaderId`；动作注入的一条 console 错误与一条失败请求分别落在两份输出里。出现第二个 `loaderId` 或只一方命中判红。
六、无 `PAGE_AUDIT_WINDOW_DIR` 时保持原单跑行为、不自导航，供契约测试与独立使用；窗口模式不改变五键输出与四类失败。

窗口判据两条：
- 正向：两个采集器并发启动、两个 ready 都出现后才有导航，两份输出的 `window_id` 与 `loader_id` 相等，且 console 错误与 network 失败各在对应输出里。
- 反向：只启动一个采集器、不写 `finish`，超时（测试压到 50 ms）后 `failures[0].class` 为 `TOOL_ERROR`、`items` 保留已收事件、退出 0；期间不得自行导航（桩收不到 `Page.reload`）。

五维各取什么：
- console：`Runtime.enable` 加 `consoleAPICalled` 与 `exceptionThrown`；窗口模式另 `Page.enable`，记主帧 `loaderId`。
- network：`Network.enable` 加 `requestWillBeSent`、`responseReceived`、`loadingFailed`；窗口模式同样 `Page.enable`，记主帧 `loaderId`。
- overflow：`Runtime.evaluate` 只读 `scrollWidth` 与 `clientWidth`。
- perf：三段分开采，`Performance.enable` 只用来打开域，数值一律取原始值或 `unknown`，不出 score、总分或阈值判定。
  一、导航三计时：`ttfb`、`domContentLoadedEventEnd`、`loadEventEnd` 各跑三次（次数写死，不加 CLI 参数），每轮是一次独立导航（`Page.navigate` 到同一 URL，等 `load` 后再读），三次原始值进 `runs[]`，中位数进 `median`。三次不是同一次加载读三遍。
  二、交互测量：页面任务脚本执行前打 `performance.mark('c07:act-start')`、结束后打 `performance.mark('c07:act-end')` 并 `performance.measure`，只取本次 `measure` 返回 entry 的 `name` 与 `duration` 进 `measures[]`；无提供任务时 `status:"unknown"`，`measures:[]`，不以页面预置同名条目冒本次任务。
  三、长任务：用页面内 `PerformanceObserver` 的 `observe({type:'longtask',buffered:false})` 覆盖任务动作，动作结束后读回条目，只统计 `> 50 ms` 的次数 `count` 与最长值 `max_ms`。无提供任务时先读原文档 buffered 长任务；取不到观察能力保持 unknown。
  三段字段：`nav.{ttfb,domContentLoadedEventEnd,loadEventEnd}.{runs[],median}`、`interaction.{measures[],status}`、`long_tasks.{count,max_ms}`，全落在 `items[]` 的 perf 条目里，另带 `object.状态` 与 `object.视口` 两个坐标。
