# Phase P2 — 真实采集接成一条可执行链：ego 优先、回退留痕、五脚本统一四类失败语义

## L0 — 结果与变更

### 这个 Phase 做什么

把已有的浏览器网关接成一条能跑的采集链。
ego 在跑就用；装了没开回退 agent-browser，并把回退四子字段写进 stdout。
选定引擎后失败不切换。
身份顺序的 bug 按「先取 cdp-url、再重解析 pid 与 profile」修掉。
五个薄采集器只产事实，共用一套命令行、输出形状与四类失败。
这个 Phase 不启动 ego、不建第二个选择器、也不碰真实页面。

### 交付什么

交四件东西：
- 一条可回放的回退分支：假 PATH 下 marker 只出现一次，输出带四子字段。
- 一个身份修复：身份解析挪到取 cdp-url 之后，ps 快照只取一次。
- 五个采集脚本与一份契约测试：五键输出、对象八键、四类失败各有具名出口。
- 一次保守简化：网关技能与清理脚本去掉 browser-use 残留，便携包 13 项减到 11 项。

### 为什么现在做

采集链是编排与真实验证的入口，没有它后面两个 Phase 无从下手。
它依赖 P1 的判据与形状校验器，所以排在 P1 之后。
它自己不起浏览器，失败面小：回退分支、身份顺序与五个脚本的桩用例成立就算完成。

### T005 — 任务 2：五个薄采集脚本，统一输出与四类失败语义

五个脚本各采一维，只产事实，不判通过。
命令行、输出形状、失败分类三处必须一致。
四类失败都是数据而不是抛错：未启动、失联、工具异常、身份不符各有出口。
参数非法时退 2 且不写件；写件失败退 1。

| 对象八键 | 工作区、服务、路由、对象版本、会话、状态、视口、引擎 | 契约决定 5 |
| 四类失败分类 | `NOT_STARTED`、`UNREACHABLE`、`TOOL_ERROR`、`IDENTITY_MISMATCH` | 契约决定 3 |
| 退出码 | 数据类 0、参数非法 2、写件失败 1 | 契约决定 3 |
| 便携包 | 追加五个脚本路径后可解析 | 003 §8.2 |

步骤：
1. 统一形状：`failure` 造错、`collect` 纯函数、`runCli` 返回数字。

4. `--out` 原子写：先写临时文件再 rename。
5. 五维只读采集：console、network、overflow、perf、a11y 各一个脚本。

8. 视口记 `WxH@<dpr>`，dpr 缺省 1；引擎只从环境变量映射，不猜。
9. 四类分流：连接被拒归 `NOT_STARTED`，失联归 `UNREACHABLE` 且保留 `items`。
10. 五条路径追加进前端测试便携包。

五维各取什么：
- console：`Runtime.enable` 加 `consoleAPICalled` 与 `exceptionThrown`。
- network：`Network.enable` 加 `requestWillBeSent`、`responseReceived`、`loadingFailed`。
- overflow：`Runtime.evaluate` 只读 `scrollWidth` 与 `clientWidth`。
- perf：`Performance.enable` 加 `getMetrics`，只报原始值。
- a11y：`Accessibility.enable` 加 `getFullAXTree` 的 role、name、focusable。
