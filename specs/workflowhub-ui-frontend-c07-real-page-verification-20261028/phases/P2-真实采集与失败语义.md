# Phase P2 — 真实采集接成一条可执行链：ego 优先、回退留痕、五脚本统一四类失败语义

读者：本 Phase 的实施者、独立审查者，以及 Phase 5 与 Phase 8 的消费方。
读完要能：找到三张任务卡各改什么、用哪条命令验证、失败怎么恢复，以及交出去的事实与缺口。

本文用 Phase 指一个可独立验收的阶段；用任务指一张可独立演示的改动卡。
ego 是本机已装的 ego-lite 浏览器引擎；agent-browser 是已装的命令行回退引擎。
浏览器网关（下文称网关）是统一管引擎选择、会话与输出的入口。
cdp-url 是浏览器调试协议（CDP）给出的调试地址。

## 这一 Phase 交出什么？

本节交代谁得到什么结果，边界在哪。

执行者得到一条能跑的采集链：引擎选择与回退有据可查，身份不再误报。
五个采集器各读页面的一面，只产事实；失败有四类出口。
Phase 5 拿这条链接编排，Phase 8 拿它做真实页面验收的采集面。
工作包声明：本 Phase 对应 decision-log 的工作包 4，即用哪个浏览器、怎么算采到了。

- **本 Phase 结果**：四件东西。
  - 一条可回放的回退分支：假 PATH 下 marker 只出现一次，输出带回退四字段。
    假 PATH 指只放一个假 `agent-browser` 的临时目录；marker 是它写下的标记文件。
    回退四字段是 `from`、`to`、`reason`、`probe`。
  - 一个身份修复：身份解析挪到取 cdp-url 之后，ps 快照只取一次。
    ps 快照是用 ps 命令读到的进程状态；pid 是进程号，profile 是浏览器配置目录。
  - 五个采集脚本与一份契约测试：五键输出、身份八键、四类失败各有具名出口。
    五键输出是 `engine`、`observed_at`、`object`、`items`、`failures`。
    身份八键是工作区、服务、路由、对象版本、会话、状态、视口、引擎。
    四类失败是未启动、失联、工具异常、身份不符。
  - 一次保守简化：网关技能与清理脚本去掉 browser-use 残留。
    便携包 13 项减到 12 项，只退旧教学引用，保留私有 Python 附件。
    便携包是 `skill-bundle.json` 里的文件清单；browser-use 是旧的可选浏览器入口。
- **非目标**：不启动 ego，不建第二个引擎选择器，不碰真实页面。
  也不写报告解析、不改编排脚本。
- **改动前**：装了 ego 但没开时，网关抛旧错误码，采集直接失败。
  身份在取 cdp-url 之前抓取，与重启后的进程必然对不上。
  五个采集面没有统一的命令行、输出形状与失败分类。
- **改动后**：装了没开就回退 agent-browser，并把回退四字段写进 stdout。
  身份在取 cdp-url 之后，用同一次进程快照重解析；还不同才明确失败。
  五个采集器共用命令行、五键输出、身份八键与四类失败。
- **与相邻 Phase 的边界**：Phase 1 给判据与形状校验器。
  本 Phase 把采集链交给 Phase 5 编排、交给 Phase 8 做真实页面验收。
- **主要风险**：身份仍变或回退事实没留全，采集读数无法复核。
  回网关 owner（负责网关的人）查原因，不静默重试。
- **若因风险返工，替代走法**：保留两次进程快照，回网关 owner 定是否允许一次重试。
- **下一步**：Phase 5 的 owner 接手采集器做编排；Phase 8 在真实目标上做验收。
- **动手前必读**：见「开始前读什么？」。
- **未决事实**：本机 agent-browser 行为与 0.36.0 是否一致未核。
  它影响回退分支的真机验证，交给 Phase 8 真跑时确认。

## 这一 Phase 怎么验收？

先答这一问：假设本 Phase 全部实现、所有已设计测试也都通过，还会不会漏掉原始需求？
答不出「不会」之前，任何测试通过都不算达成验收。
真机隔离环境里跑一次真采集，拿到真输出与身份块，再造出一种失败。
校验脚本对字段、桩按预期应答，都只算机制，不算这一节的通过。
一个 Phase 只有在验收标准真的被满足后才能说开发完成；代码审查通过、测试全绿、结构检查通过，都不是完成条件。
RED/GREEN 表、四组断言与命令细节留在「怎么验证？」，本节只指向它。

1. **验收标准**：逐条列本 Phase 承接的三条验收，各写判据、成功与失败三句。
   - 验收 1：判据是一次真采集在真页面上出真读数，且身份块能让人复跑。
     成功长这样：别人照身份块的引擎、会话、视口、状态与工作区复跑，拿到同维读数。
     失败长这样：结果里没有身份块、两个引擎混在一份结果，或用桩数据冒真页面。
   - 验收 2：判据是错工作区、服务未启动或路由不符时，具名报出并停在该对象。
     成功长这样：具体不一致项或未启动原因被写出，且没有出正常报告。
     失败长这样：报空结果、报通过，或换引擎后还按原引擎口径给结论。
   - 验收 6：判据是未知、空值、失联采集与证据错配不聚合成通过。
     成功长这样：四态保留、失联不出正常报告、空值不当 0。
     失败长这样：未知被吞成通过、失联出正常报告，或没采用的工具写成已修。

2. **场景**：正常三例、反向两例，每个写输入、动作与预期。
   - 正常：输入是样本 A 的默认态，动作是选定引擎后跑五个采集面。
     预期：五份输出带引擎、观察时间、对象、条目、失败五个键，四类读数各就位。
   - 正常二（回退·没装）：输入是只有假 `agent-browser` 的临时 PATH，也没有 ego-browser。
     动作是跑一次网关启动，看 marker 与 stdout。预期：marker 只出现一次。
     预期还有：stdout 带从哪来、到哪去、为什么、探针四个字段，退出 1。
     这一路不是绿：它证回退发生且留痕，不证采集成功，也不证页面可用。
   - 正常三（回退·装了没开）：输入是临时 PATH 有假 `ego-browser` 可执行件，
     但它没有运行中的调试端点。动作是同一网关启动。
     预期：仍回退 agent-browser，reason 逐字取
     `ego-lite not running before launch`；不按「只有没安装才回退」判失败，
     marker 仍只一次，退出 1。
   - 反向一（身份不符）：输入删掉工作区变量或把路由改成别的。
     动作是跑一次采集。预期：退出 2、具名身份码、零连接、不写件。
   - 反向二（服务未启动）：输入是关掉的静态服务，动作是跑一次采集。
     预期：记未启动一类、不出正常报告；失联那条先收条目再记失败。

3. **环境与数据**：写环境、数据、谁提供、来源与清理；缺的写 unavailable。
   - 环境：本机装了 ego-lite 与 agent-browser，网关统一选引擎与开会话。
   - 版本：agent-browser 的行为与 0.36.0 是否一致未核，这一格记 incomplete。
     负责方是网关 owner；核不到就不把版本写进结论，也不按版本号推行为。
   - 数据：对象是 C05 样本页的 C07 自有副本 A、B，数据是 mock，结论只到 mock。
   - 替身：最小 CDP 桩只按被调方法应答，只用于契约测试，不作真机证据。
   - 谁提供：引擎由用户在本机授权使用；样本随材料落盘；真机执行者归末验收。
   - 构造与清理：临时静态服务起在本机，假二进制放进临时目录，退出 7 写 marker。
     收尾用 `finally` 关服务、删临时目录，不碰别人的浏览器配置与 profile。
   - 拿不到：本 Phase 原先没跑真实页面那一轮；2026-10-31 已由本 Phase 执行者补跑一次。
     原件见附录 B，缺的记 incomplete，不记通过。
     末验收那一轮仍归 P8 执行者，原件在它名下，本 Phase 不复用桩。

4. **用例**：五条用例，逐条给对应验收、操作、预期与判定方式。
   - 用例一（对应验收 1）：在样本默认态跑五个采集面，落五份 JSON 与身份块。
     判定：独立执行者按身份块复跑同维并比对读数，命令退出 0 不算判定。
   - 用例二（对应验收 2·身份不符）：删一个身份变量再跑同一面。
     判定：看退出 2、具名身份码、零连接、没写件四件事同时成立。
   - 用例三（对应验收 2·未启动）：关掉服务再跑，判定看是否记未启动且无正常报告。
   - 用例四（对应验收 2·回退）：临时 PATH 放假 `agent-browser`，
     分别布「没装 ego」与「装了没开」两种输入，看四字段、reason 与 marker。
     判定：两例都发生回退；marker 一次、四字段逐字在场、退出 1 且带启动失败码；
     四缺一即不通过。
   - 用例五（对应验收 6）：跑性能三个负例（缺一采样、耗时 null、无长任务）。
     判定：三条各记 unknown 不记 0；失联那条必须先有条目再记失败。
   - 门禁命令只证契约与桩面，不判上面任何一条；命令见「怎么验证？」。
     五个脚本的命令行与参数逐字记在 `quality/evidence/build-code/P2-collect.json`。
   - 退出 0 只说明脚本按桩应答，不说明采到了真实页面，因此不是本条的判定器。

5. **谁判**：执行者与复验者都换上下文，真机那一轮归末验收。

## 为什么现在做，依据是什么？

本节说明这条链为什么必须排在判据之后、真实页面之前。

采集链是编排与真实验证的入口；没有它，Phase 5 的编排与 Phase 8 的页面验收都无从下手。
它依赖 Phase 1 的判据与形状校验器，所以排在 Phase 1 之后。
它自己不起浏览器，失败面小：回退分支、身份顺序与五个脚本的桩用例成立就算完成。

- **结果**：五个采集器与网关按同一套输出和失败语义工作，引擎回退可复核。
- **非目标**：不证明真实 ego、agent-browser 或任何页面读数可用。
- **与其它 Phase 的区别**：Phase 1 判形状，Phase 5 做编排，Phase 8 做真实页面。
  本 Phase 只接采集链，不做判定，也不做报告。
- **依据**：
  - 决定 24：ego 装了没开也回退 agent-browser，并记回退事实（engine-fallback）。
    回退事实四要素是 `from`、`to`、`reason`、`probe`。
  - 决定 26：把身份解析挪到取 cdp-url 之后，身份与端点来自同一次解析。
  - 决定 27：保守简化，留回退，压长流程，browser-use 降为可选。
  - 契约决定 3、4、5（004 原件里的三条）：统一输出、四类失败、回退判定与身份八字段。

### 任务 1：回退可达，身份在取 cdp-url 之后重解析

本节写清本卡修哪两处、先改什么、失败交给谁。

本卡面向网关脚本的维护者，交付一条可回放的引擎回退分支和一个不再误报的身份检查。
起点是引擎测试 `:74` 那条旧用例：它现在断言「装了没开就抛旧错误码」。
先把它改成回退语义，看它按预期失败，再改网关脚本；旧的两条口径断言保留。

改完后，auto 且 ego 装了没开时不再抛旧错误码。
网关改为回退 agent-browser，并把回退四字段写进 stdout（标准输出）。
身份改成先取 cdp-url，再用同一次 ps 快照重解析 pid 与 profile；还不同才明确失败。

1. 采集器启动先读这五个变量，只当声明值填进 `object`。
   不猜、不派生、不填默认值。
   `object` 八项来源要逐项写清，别把整块当声明或整块当观察：
   `workspace`、`service`、`route`、`object_version`、`engine_session` 来自五个 `PAGE_AUDIT_*`；
   `state` 来自 `--state`，`engine` 由 `BROWSER_QA_ENGINE` 映射，这七项都是声明值。
   `viewport` 先写声明，比对之后、采集之前由页面回报的 `WxH@dpr` 覆盖，
   是唯一带观察值的坐标；保留 dpr 是冻结断言的要求。
   所以 `failures` 为空不等于身份已核：除 `viewport` 外的坐标是否一致只看比对表，
   表里 unknown 既不是 match 也不是通过；消费者不能凭 `failures` 为空推断身份已观察。
   合同边界仍是输出五键、对象八键、四类失败；unknown 不是失败类，也不新增字段。
2. 缺任一个或为空串：不连接 CDP、不写 `--out`。

   三个变量是 `PAGE_AUDIT_WINDOW_DIR`、`PAGE_AUDIT_TARGET_ID`、`PAGE_AUDIT_WINDOW_ID`。

- overflow：`Runtime.evaluate` 只读 `scrollWidth` 与 `clientWidth`。
- a11y：`Accessibility.enable` 加 `getFullAXTree` 的 role、name、focusable。
- perf：三段分开采；`Performance.enable` 只用来打开域。
  数值一律取原始值或 `unknown`，不出 score、总分或阈值判定。

     协议返回新 loader 时等对应根 frame/loader 的 lifecycle load。
     若同文档导航省略 loader，则只对该原 loader 做 `Page.reload`，仍等新文档完整加载。
     新 loader 不得等前一文档或已采文档。
     读值后再核当前 frame/loader 与完整 URL（含 hash），不改验证对象或 window namespace。
     三次原始值进 `runs[]`，中位数进 `median`。
     同文档跳转、旧 load 或同一加载读三遍均不算样本。
  2. 交互测量：页面任务脚本执行前打 `performance.mark('c07:act-start')`。
     结束后打 `performance.mark('c07:act-end')` 并 `performance.measure`。
     只取本次 measure 返回 entry 的 `name` 与 `duration` 进 `measures[]`。
     无提供任务时 `status:"unknown"`，`measures:[]`，不以页面预置同名条目冒本次任务。
  3. 长任务：用页面内 `PerformanceObserver` 覆盖任务动作。
     观察参数是 `observe({type:'longtask',buffered:false})`。
     动作结束后读回条目，只统计 `> 50 ms` 的次数 `count` 与最长值 `max_ms`。
     无提供任务时先读原文档 buffered 长任务；取不到观察能力保持 unknown。
  三段字段：
  `nav.{ttfb,domContentLoadedEventEnd,loadEventEnd}.{runs[],median}`。
  `interaction.{measures[],status}`。
  `long_tasks.{count,max_ms}`。
  全落在 `items[]` 的 perf 条目里。
  另带 `object.状态` 与 `object.视口` 两个坐标。

perf 的三条负例，都不许凑数：
1. 三次采样少一次：该计时 `median:"unknown"`，不拿两次平均顶替，`runs[]` 保留实际条数。
2. `duration` 是空、`false` 或 `null`：该 measure 记 `unknown`。
   不写 0，也不从 `measures[]` 删掉。
3. 没有任何长任务条目：`count:0` 是真实观察，`max_ms:"unknown"`；把 `max_ms` 写 0 判红。

审后补记的技术边界（改法不变，只把当时被审查点出的边界写清）：
- 三次导航会销毁原时间线，所以先在原目标完成任务与长任务观测并保存，再做三次导航。
  后续导航失败仍保先取的任务事实；初稿「三次导航后采任务」的顺序作废。
- 私有模块导出 `collectPerf(config,env,runTask?) -> Promise<五键doc>`。
  config 只用原 `endpoint/viewport/state`，无需 out；env 仍原声明与选定 engine。
  复用 collectWith 的输入验证、连接与收尾；模块不写文件或 stdout。
  `runTask({evaluate})` 只接已验同 target 的薄能力，不拿 transport、session、storage 或 env。
  创建者等待真实可观察终态；resolve 只结束窗口，不证明业务成功。
  回调返回值不作性能事实。
- observer 用远端对象句柄保留，不在 page-global 场景注册。
  启动打点失败、reject、正常路径都尝试 disconnect/release；失联结束等待未决任务。
  35 秒自动断开只沿原生命周期预算；CLI 四参数不变，不从 route、state、judgments、JSON 或 env 猜动作。
- Phase 5 的 owner 回源确认：编排脚本目前只规划、尚无生产 caller。

- console 与 network 共用必要元数据白名单：丢弃 headers、body、任意 RemoteObject 值与描述。
