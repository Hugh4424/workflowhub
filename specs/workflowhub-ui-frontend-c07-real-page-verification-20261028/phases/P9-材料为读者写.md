# Phase P9 — 让材料按读者需要变形，让"读不懂"在写入时就被拦住

## L0 — 结果与变更

### 这个 Phase 做什么

这个 Phase 交付写材料的方法本身：判定对象不是页面事实，而是新读者能不能拿这份材料干活。
它把"材料为读者写"从一句建议，变成写入时就会被拦住的检查。
它只改一处物理来源，不让规则散落到多份文件，也不新建第二份规范。
合进别的 Phase 会被页面判据盖住，所以单独成 Phase。
来源是用户 2026-10-29 的直接指示，不在四十三条原始需求里，卡片如实写来源。
它不做页面采集，也不改页面审计的七条验收。

这张卡不承接页面验收：它改的是 workflowhub 自身，真判据是本卡的门禁命令。

### 交付什么

- 一个能拦住"只有字段没有正文"的校验器改造，加一条扫当前材料的通用门。
- 三份模板改成先叙述、后字段；同一编号一份材料只出现一次。
- build-plan 第 11 步加有预算的读者检查，记录形态固定、可机读。
- 一页作者开工前读的写作契约，含十九条可检查规则与一好一坏对照。
- 只迁 S 类断言这件事已移出到 Phase 11，因为要改 Phase 1 的冻结测试。

### 为什么现在做

现在做，因为读不懂是这次的主要病灶，不修它，后面每份材料都会重犯。
现状数字：89% 的编号没有解释，决策日志 0/28 节有读者提问（`2026-10-29-021`）。
根因是读者不在执行位，写作者手里没有可执行的写作契约（`2026-10-29-024` 第 1 节）。
可行性已实测：三批材料的卡内正文段落都是 0，字段降级只对 17 个字段里的 10 个字面生效
（`2026-10-29-025`、`2026-10-29-027`）。
