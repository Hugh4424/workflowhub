## 这一 Phase 交出什么？

交一个编排入口、一个规范消费脚本、两份契约测试、
一份判定样张和两处追加登记。

执行者得到一条能跑的编排链：一次调用进，一份被形状接受、退出码 0 的报告出。
四类采集失败各有具名出口，任何未测都不被折成通过。
同一批材料还要能回答：判据引用的规范解析得到吗，带版本与负责人吗。
这个 Phase 的测试不启真实浏览器；真执行归 Phase 8，
编排器对页面的唯一一次导航只在桩上验证。
工作包声明：本 Phase 对应 decision-log 的工作包 7、8，即报告接入与复用证明。

- **本 Phase 结果**：五件东西。
  - 一个编排脚本：串身份块、锁引擎、五个采集、合并判定、形状校验、写报告。
  - 一个规范消费脚本：给出被引用、悬挂、从未被引用三份清单。
  - 两份契约测试与一份判定样张。
  - 两处登记：便携包的文件清单与目录映射的条目。
- **非目标**：不采集真实页面，不判页面好坏，不建第二套引擎选择，
  不改形状校验器，不签任何页面验收。
- **改动前**：判据、采集与报告三段各自成立，但没有一个入口把它们接起来。
  判据执行不起来，报告也过不了形状校验。
- **改动后**：一次调用产出报告；四类失败各走具名出口；
  规范缺失落成对应检查项未测，而不是被静默补全。
- **与相邻 Phase 的边界**：P1 给判据与校验器，P2 给五个采集器与身份语义，
  P4 给报告消费措辞。本 Phase 把编排入口交给 P7 与 P8。
- **主要风险**：编排长出第二套判定，脚本自己把某项写成通过。
- **若因它返工，替代走法**：撤回判定那一段，只保留搬运；
  判定语义交回 P1 的负责人，本 Phase 不自己定通过。
- **下一步**：P7 读报告的结论、判据与覆盖上限三段；
  P8 用受控页做终演，并复跑窗口断言。
- **动手前必读**：见「开始前读什么？」。
- **未决事实**：晚到的真实页面依赖仍在 P2 手里，
  它让三条验收保持不完整，见「三条验收现在什么状态？」。

## 这一 Phase 怎么验收？

先答这一问：假设本 Phase 全部实现、所有已设计测试也都通过，还会不会漏掉原始需求？
答不出「不会」之前，任何测试通过都不算达成验收。

验收判的是本 Phase 让下游拿到的那项结果有没有出现，不是脚本写得对不对。
代码正确与完整归独立审查；这里只认下游能观察到的结果。
一个 Phase 只有在验收标准真的被满足后才能说开发完成；代码审查通过、测试全绿、结构检查通过，都不是完成条件。
七槽逐条写实；RED/GREEN 表、覆盖上下限与命令细节留在「怎么验证？」，本节只指向它。

1. **验收标准**：本 Phase 承接三条验收，每条写成一句能判真假的话。
   判据原文取规格 Appendix A 的同号条目；这里补成功与失败两种可观察信号。
   - **验收 1（AC-C07-1）**：判据是一次调用进、一份逐维有据的报告出。
     成功是接手的人按报告能逐维读到原始结果或未测理由，三键引用可解析，没有总分。
     失败是某维自行置通过、缺维无理由，或引用悬挂却判来源齐备。
   - **验收 2（AC-C07-2）**：判据是身份对不上时报出具体哪一项不一致或未取得。
     成功是单行 JSON 带 `E_IDENTITY_INCOMPLETE` 与 `errors[0].path`，
     退出 2，且不写报告文件。
     失败是缺参数仍启动采集、报笼统错误，或照样写出报告。
   - **验收 6（AC-C07-6）**：判据是未知、空、假值、失联与证据错配不聚合成通过。
     成功是对应项落成未测或被拒收，理由指到缺哪一项。
     失败是缺证据仍出通过结论，或把失联写成 0 分。
   已经观察到的：受控页上五个采集经同一入口跑通，报告与 stdout 同值，八项身份齐。
   没有观察到的：真实页面整跑；这一层见第 3 槽与用例 6。
   三条现在的档位见「三条验收现在什么状态？」，本节不另记。

2. **场景**：正常场景要真跑一次，反向场景要让实现错了就失败。
   - **正常（真实页面整跑）**：给一份真实页面与五个身份参数，跑一次编排入口。
     五个采集各出一份原始件；报告四键齐、形状被接受；观察者按报告逐维回读。
   - **正常（受控替代）**：在自有本地 HTTP 与 WS 服务和受控虚拟机上跑同一命令。
     这一层只证接线，不证页面事实；两层不可互相顶替。
   - **反向（缺身份）**：删掉 `--workspace` 再跑，必须退出 2 且不写报告。
     它若仍进入采集或写出了报告，就是这条反向场景失败。
   - **反向（窗口错位）**：让第二次导航发生，必须停在该次采集。
     两份输出的 `loader_id` 不等或出现第二次导航，都算检出。
   - **反向（失联与错配）**：断开采集但报告里有已观察项，必须落成未测。
     证据指向别的对象时，同样不许聚合成通过。

3. **环境与数据**：写清用什么跑、数据谁给、拿不到算哪一档。
   - **环境**：本机；node 与仓库内 vitest；受控本地 HTTP 与 WS 服务。
     真实浏览器、引擎网关与真实页面由 P2 与 P8 的原 owner 提供。
   - **数据**：一份真实页面的 route、视口与状态参数；五个采集的原始输出；

## 为什么现在做，依据是什么？

判据、采集与消费三块零件都到了，
缺的是把它们接起来的那一个入口，所以本 Phase 排在它们之后。

正式实施已取得主会话交棒，按 P1 判据、P2 最终模块与 P4 已交报告接线
把三块零件接起来。
判据、采集、消费分别归这三个前置 Phase；零件存在不等于依赖已经交付。
没有这个入口，判据执行不起来，报告也过不了形状校验。
它必须看到三者的交付原件与当前接口才能实施。
它自己的成功信号是退出码与报告字节，不是判据正文，也不是采集能力。

- **结果**：一次调用得到一份被形状接受、且引用可解析的报告。
- **非目标**：不在真实浏览器里跑，不判页面内容对错。
- **与其它 Phase 的区别**：P1 判形状，P2 采事实，P4 读报告；
  本 Phase 只做接线、合并与拒收。
- **依据**：
  - 契约决定 2、3、4、5、10：拒收、四类失败、引擎选择、身份八字段、消费接口。
  - 决定 19：每个判据必须引它实际读过的规范来源。
  - 主会话交棒：P2 最终模块与 P4 三方法接线源已可读。

## 每张任务卡怎么写？

本节列出三张卡各自交付什么、从哪个输入开始、失败交给谁。

### 任务 1：参数与身份校验、引擎锁定可复放

本节列出本卡把哪三样钉成可重放的形状、从头读哪份输入、失败交给谁。

本卡面向编排脚本的作者，交付一张能对照的参数表、一次身份校验与一次引擎锁定。
起点是引擎网关已有的选择函数：本脚本只调它一次，不写第二套探测。
先落参数与身份两条断言，看它们按预期失败，再写实现。
身份缺项就停，缺哪项要指名到字段，不给默认值。
显式给引擎就交给网关直返；缺省由网关探测，回退只抄网关那一条。
非法参数算自身失败，退出 1，不写报告。

命令行参数分三层：
- 规格的四个：`--cdp-url`、`--state`、`--viewport`、`--out`。
- 身份的五个：`--workspace`、`--service`、`--route`、`--object-version`、
  `--engine-session`。
- 可选的三个：`--engine`、`--collector-root`、`--judgments`；
  `--probe-cmd` 不再有，探测归网关。

`--collector-root` 缺省为本技能 `scripts/`，按脚本位置解析；
显式值从当前目录解析。
它只用于定位四个命令行采集器。
perf 静态复用原模块，不由此目录注入动作，也不替代 producer；
缺脚本按未启动出口。
`--judgments` 显式值从当前目录解析，输入对象见任务 3。
省略时按 P1 八维骨架各保一行未测、空 evidence 与「未提供判定文件」，
并写提供者与恢复条件，整体记不完整。
该缺省只生成未测行，不自动补规范版本、身份或判定。

五个身份参数只解析一次，原样保留给任务 2。
任一参数缺省或为空，在启动采集器之前退出 2，
错误码 `E_IDENTITY_INCOMPLETE`。
`path` 写缺的那个参数名，不写报告，不进入采集。

每项必须出现什么：

| 位置 | 必须出现什么 | 出处 |
| --- | --- | --- |
| 命令行 | 规格四参数名逐字，参数值可空时报用法错 | 规格实现设计一节 |
| 命令行 | 五个身份参数名逐字；可选三参数缺省有确定行为，参数表里没有 `--probe-cmd` | 契约决定 5 |

`engine`、`engine_session`、`object_version`。

`ok:false`、`outcome:"unavailable"`、`errors[0].code:"E_IDENTITY_INCOMPLETE"`。
`errors[0].path` 指向缺的命令行参数，带 `--`，不是报告字段名。
退出码 2，`fs.existsSync(out)` 必须为假。
五个参数的对应关系是：`--workspace` 对 `workspace`、`--service` 对 `service`、

本脚本原码透传、退出 2、不写报告，不改名、不静默回退。
六、可核判据三条同一条断言里：源码里 `selectBrowserEngine` 出现且只有一处调用；

对采集器来说，身份不占自己的命令行，走环境：
编排器把任务 1 解析好的五个身份值逐次交给四个子进程的 env 及 perf 的局部 env，
不改全局环境。名称与报告 `object` 的键一一对应：

| 命令行参数 | 采集器环境变量 | 报告 `object` 键 |
| --- | --- | --- |
| `--workspace` | `PAGE_AUDIT_WORKSPACE` | `workspace` |
| `--service` | `PAGE_AUDIT_SERVICE` | `service` |
| `--route` | `PAGE_AUDIT_ROUTE` | `route` |
| `--object-version` | `PAGE_AUDIT_OBJECT_VERSION` | `object_version` |
| `--engine-session` | `PAGE_AUDIT_ENGINE_SESSION` | `engine_session` |

**身份传递。** 这五个值是 P2 采集器对象八键里不由 CDP 观察得到的那五项。
传之前先按下面的「采集前身份比对」核过；比对不到的字段记 `unknown`，
不把声明值当已核身份。采集器从这五个同名环境变量取值填入 `object`，
命令行仍是四项；加上命令行已有的 `state`、`viewport` 与引擎环境映射，
`object` 八键齐。

P2 的规则：采集器读不到五个变量中的任一个，
就在连接 CDP 之前报 `E_IDENTITY_INCOMPLETE` 退出 2，
不置 `null`、不记 `IDENTITY_MISMATCH`。
编排器的责任是让这种情况不发生：

- 五个声明值只从命令行解析一次；实际值按下面的比对表取得，不派生、不填默认值。
- 缺任一个或为空：在第一次 `spawn` 之前退出 2，
  码 `E_IDENTITY_INCOMPLETE`，`errors[0].path` 写缺的参数名，
  采集器调用 0 次，`--out` 指向的报告文件不存在。
- 五个都齐：五次调用逐次注入五个变量，值与解析值逐字相等；
  报告 `object` 的五个键也逐字相等，不是 `null`，也不是占位串。
- 采集器仍报 `IDENTITY_MISMATCH`，也就是接收端实际身份与声明值不符：
  按四类失败的身份不符出口处理，退出 2、不写报告；
  这与编排器没传是两件事，恢复条件不同。

**采集前身份比对。** 编排器在 `spawn` 之前用已有观察源核声明值，
不再把声明值当已核身份。

| 身份键 | 声明值 | 实际观察源 | 不符时 |
| --- | --- | --- | --- |
| route | `--route` | 选中页目标的 URL 路径与查询 | `E_COLLECT_IDENTITY_MISMATCH`，退出 2，不写报告 |
| service | `--service`（服务 origin） | 目标 URL 的 origin，加一次健康检查 | 同上 |
| viewport | `--viewport` | 会话 `Page.getLayoutMetrics` 的可视区 | 同上 |
| engine、engine_session | 参数与网关返回 | 网关本次返回的引擎与会话 id | 同上 |
| workspace | `--workspace` | 静态服务报告的文档根 | 有源就比；无源记 `observed:null` 与 `unknown` |
| state | `--state` | 页面状态标记 | 同上 |
| object_version | `--object-version` | 服务页文件的钉版哈希 | 同上 |

`errors[0]` 同时保留声明值与观察值，`path` 指身份键；
恢复是重新取得匹配端点与身份后重跑，不自动重建会话。
无源字段不写通过：AC-2 保持未完成，写明缺哪个观察源与谁提供。

比对判据三条：
- 正常路径：桩目标 URL 与 `--route` 一致，五组观察值写入编排证据，结果全为 `match`。
- 反向路径：只把桩目标 URL 换成另一条路径，退出 2、
  码 `E_COLLECT_IDENTITY_MISMATCH`、零采集器调用、报告不存在，
  错误里同时有声明值与观察值。
- 无源字段：`--workspace` 的服务根读不到时，观察值记 `null`、该字段记 `unknown`，
  不写已验证；AC-2 不记通过。

可核判据两条：
- 正常路径：桩采集记录四次 `spawn` 的环境，perf 模块调用记录局部 env；
  五次调用的五个变量每次都在、值逐字相等，报告 `object` 五键无 `null`。
- 反向路径：删掉 `--workspace` 重跑，退出 2、码 `E_IDENTITY_INCOMPLETE`、
  `path` 为 `--workspace`、采集器调用 0 次、报告文件不存在。

**同一次导航的采集窗口。** 这两维是事件流，不能各跑一次；
各跑一次就会各看一次导航，导航期错误只落在其中一份输出里。
改成一次导航会话内完成：

一、谁触发导航：`skills/frontend-testing/scripts/run-page-audit.mjs` 唯一负责。
它先把 `--cdp-url` 解成浏览器级端点：
`ws://` 直用，`http://…/json/version` 先取 `webSocketDebuggerUrl`，
目标形如 `ws://…/devtools/browser/…`。
复用票据脚本的 `connectCdp` 连上，
用 `Target.getTargets` 按 `route` 选出唯一页面目标 `targetId`；
0 个或多于 1 个就停，码 `E_COLLECT_NOT_STARTED`，不猜。
`connectCdp` 只收 `/devtools/browser/...` 浏览器端点；
页面目标用 `Target.attachToTarget` 拿会话。
二、开始：并发 `spawn` `collect-console` 与 `collect-network` 两个子进程，
命令行仍是四项，
另注入 `PAGE_AUDIT_WINDOW_DIR`、`PAGE_AUDIT_TARGET_ID`、`PAGE_AUDIT_WINDOW_ID`
三个环境变量。
采集器 `attach` 同一 `targetId`，完成 `Page.enable` 与各自域后
写 `<dir>/console.ready` 或 `<dir>/network.ready`，然后只订阅。
三、动作：两个 ready 都出现后，才对同一 `targetId` 发唯一一次 `Page.reload`，
等价于 `Page.navigate` 到当前 URL，等 `Page.loadEventFired`，
再等 500 ms 静默窗；任一未就绪不发导航。
四、结束：编排器写 `<dir>/finish`；
两个采集器同时把事件刷进各自 `--out`，
`items[]` 带同一 `window_id` 与主帧 `loader_id`；
收齐两个退出码才跑 overflow、perf、a11y。
就绪前无明确 CDP 失联事实的退出按 `E_COLLECT_NOT_STARTED`；
已连接失联按 `UNREACHABLE` 保原观察；
就绪后工具异常或收尾超时按 `E_COLLECT_TOOL_ERROR`。
五、同一次导航的保证：两份输出的 `window_id` 与 `loader_id` 逐字相等，
且等于编排器记录的 `loaderId`；
动作注入的一条 console 错误与一条失败请求分别落在两份输出里；
出现第二个 `loaderId` 或只一方命中判红。
六、不补第二次导航：窗口失败就停该次采集，按四类出口处理；
未启动、工具异常、身份不符退 2 不写报告，失联写报告并记未测；
不重试、不换目标、不把两次导航拼成一份报告。

窗口判据两条：
- 正常路径：桩记录两次起子进程的时间重叠、两个 ready 文件都出现后才有
  `Page.reload`，两份输出的 `window_id` 与 `loader_id` 相等，
  console 错误与 network 失败各在对应输出里。
- 反向路径：只让 console 就绪、network 不写 ready，编排器不发导航，
  退出 2、码 `E_COLLECT_NOT_STARTED`、报告文件不存在；不得出现第二次导航。

输出不是 JSON、缺统一输出键或失败类不在四类里，
是编排无法解释的协议或执行失败：退出 1，保原 stdout 与 stderr，不写报告，
也不把它伪装成一条合法 `TOOL_ERROR`。
合法输出里的 `failures[].class:"TOOL_ERROR"` 才映射 `E_COLLECT_TOOL_ERROR` 退出 2；
编排器已掌握的窗口就绪后异常与收尾超时也走这个具名出口。
就绪前退出仍按未启动；CDP 失联有明确事实时按 `UNREACHABLE` 保已观察。
例如 `failures:[{class:"TOOL_ERROR",detail:"收尾超时"}]` 退 2；
正文为 `not-json` 或 `class:"OTHER"` 退 1。
二者都不生成正式报告；恢复是核原输出与 P2 统一输出合同，
在同任务修复后重跑，不切引擎。

具名拒收的单行 JSON 沿
`{ok:false,outcome:"unavailable",errors:[{code,path,message}]}`。
身份不符的 `message` 必含声明身份、实际不一致项、原采集输出位置，
以及「按原 QA 网关重新取得匹配端点和身份后重跑」，不自动重建会话。
`path` 指对应身份键；本段不新增错误字段或码值。

四类失败各自怎么落：
- 未启动：不写报告，退出 2，码 `E_COLLECT_NOT_STARTED`。
- 工具异常：不写报告，退出 2，码 `E_COLLECT_TOOL_ERROR`，不写成未测。
- 身份不符：不写报告，退出 2，码 `E_COLLECT_IDENTITY_MISMATCH`，带修复指引。
- 失联：写报告，相关结果记未测，`untested_reason` 具名，
  保留已观察的 `items[]`，追加 `coverage_limits`。
  首次失联后停止后续采集，不以重连后的未启动覆盖原失联，
  不伪造未执行维度的五键正常结果。
  窗口驱动原连接失联另留具名原始事实，正常回路仍只一次窗口导航。

最后两道：
- 把 `--judgments` 并进 `criteria[]`；无本项观察却声明通过就拒收，退出 2；
  没有明确采集映射时不借其它维任一非空 `items[]`。
- 交互未知只影响实际主依赖 perf 且声明交互（或未分组整体性能）的项，
  显式导航不继承无关交互未知；导航未知只影响声明导航的项。
  已观察失败保原状态、理由与原证据，未覆盖另列 `coverage_limits`，
  不设新性能阈值。
- 写完调形状校验器：退出 2 就删报告并把 `errors[]` 原样带出。

### 任务 3：规范引用可解析，三处指针指向同一节

本节写清判据引用的规范真存在、带不带版本与负责人、缺失怎么落进报告。

本卡面向判据与报告的维护者，交付一个只产事实的扫描器，
以及把这三类缺失落成未测的那一步。
扫描器仍只产事实、退出码只表工具状态：能扫完就 0，哪怕有悬挂引用。
但事实要被报告吃掉，不能只交读者：
缺规范、过期、缺版本三类各把对应检查项记未测，写进报告。
三处指针要指同一个节：判据正文、编排的默认路径、报告消费段。
对不上就记成悬挂引用，由报告的判定消费写成未测，不让脚本冒充通过。

每项必须出现什么：

| 位置 | 必须出现什么 | 出处 |
| --- | --- | --- |
| 输出 | 三键 `cited_norms`、`unresolved_refs`、`never_cited_norms` | 002 原件 §3.1 方案 A（165 行） |
| 输出 | 每个引用带 `path#section` 与版本、负责人、使用者三字段 | 002 原件 §3.1（165、173 行），P1 判据「规范来源」 |
| 退出码 | 能扫完就 0（即使有悬挂）；参数非法或读不了就 1 | 本卡预写测试 |
| 三处指针 | `page-audit.md` 的节锚、编排默认锚、报告行 `cited_norms[].ref` 同节 | 本卡消费设计；冻结判据包测试 104 到 106 行只证文件名 |
| 反向样张 | 故意写 `page-audit.md#no-such-section`，三键仍齐且仍退出 0 | 本卡预写测试 |
| 报告消费 | 三类缺失各把对应检查项写成未测，带 `untested_reason` 与 `norms_missing[]` | 规格 4.1 节最小读取集；需求 42 |

三个输出键：被引用的规范、悬挂引用、从未被引用的规范。
退出码只表达工具状态：能扫完就 0，参数非法或读不了就 1。
反向样张里故意写一个不存在的节锚，三个键仍要齐、仍要退出 0。

**扫描器输入与解析。** 这是本次 P5 内部的最小设计选型，
不冒称已有决定或已实现接口。
002 的 §3.1 只规定静态引用事实，当前 spec 与 P1 判据要求逐项来源；
没有现成扫描输入协议。
复用唯一的 `--judgments` JSON 作本次引用载体，
不增规范登记表、公共命令、schema 或依赖。

- 调用：当前目录为认证仓库根，命令与两个参数见下节命令块。
  两参数必填且只接文件；相对文件路径及引用的仓库相对路径都从当前目录解析，
  拒绝绝对 ref 与越出仓库的 ref；不递归扫整仓。
- 输入对象用 `criteria[]` 承载现有判定，每项沿报告原字段，

  `ref` 为 `path#section`；`consumer` 写本项 `id` 与实际用法，非空字符串。

  扫描器不声称懂任意自然语言表格。
- 同一输入的 `norm_candidates:["path#section",…]` 必须是数组，
  是调用者给本次对象选定的候选全集，可显式为空；
  按当前判据「规范来源」表及实际任务四类最小读取集选择，未核到的不补全。

  引用不在候选中仍须解析，不能被过滤掉。
- 缺 `version`、`owner`、`consumer` 或 `cited_norms` 不算输入语法错，
  必须进入缺失事实。
  引用缺 `ref`、空 ref、载体不是对象或数组、缺候选数组、JSON 损坏
  属输入非法，退 1。
  缺整类读取来源时，该相关项保空 `cited_norms`；

  `skills/frontend-testing/references/page-audit.md#规范来源`

  去 heading 标记、转小写、空白变 `-`、去标点、保留中文；
  重名按出现次序加 `-1` 等后缀；围栏代码中的标题不算节。
  扫描事实保完整原 ref；本卡调用统一 `path#section`，
  不把未实现的 `file:line` 当已支持。
- 元数据只认正文第一个标题后首段（至下一标题前）的
  `版本：<值>` 或 `version: <值>`、`owner：<值>` 或 `负责人：<值>`、
  `consumer：<值>` 或 `使用者：<值>`，
  或文件开头 YAML 的同名标量 `version`、`owner`、`consumer`。
  值以换行或 `。；;` 分隔，去首尾空白，版本逐字比较。
  例如 P1 的
  `版本：1.0.0。owner：frontend-testing 方法维护者；consumer：…`
  可直接解析。
  没有该载体则保缺失，不拿 catalog、HEAD、文件日期或「当前可读版」猜版本，
  也不改原规范补齐。
- 输出恰好三键，数组均保 `ref`：
  `cited_norms` 保引用的 `version`、`owner`、`consumer` 与检查项 `id`；
  `unresolved_refs` 保同项身份与具名原因，原因是文件或节不存在、
  版本不一致、缺元数据之一；
  `never_cited_norms` 为候选 ref 减实际被引 ref。
  扫描可完成即 stdout 一行该 JSON，并把相同字节写 `--out`，exit 0。
  有引用缺陷仍是 0。
  `--input` 不可读、存在的原件无权读取、写出失败或自身异常为 exit 1
  并保 stderr，不冒空事实成功；引用目标 ENOENT 则是可记录的缺规范事实。
- 原 caller 是任务 2 的 `mergeJudgments`：从 `--judgments` 读同一对象的
  `criteria[]`，在写报告前调用扫描函数，命令行与函数共用同一逻辑；
  按 `id` 与完整 `ref` 关联缺项，仅将受影响的 `criteria[]` 行降为未测，
  保存原 evidence 与观察；`norm_candidates` 不写成报告判据。
  扫描自身 exit 1 则整次编排 exit 1、不写正式报告，不能当来源齐备。

一段可直接当输入的样张，可放在唯一那份判定样张里；
失败变体在测试临时目录生成，不另落长期登记件：

```json
{"criteria":[{"id":"layout","dimension":"layout","state":"未测","evidence":[],"untested_reason":"待观察","cited_norms":[{"ref":"skills/frontend-testing/references/page-audit.md#规范来源","version":"1.0.0","owner":"frontend-testing 方法维护者","consumer":"layout：核读取清单"}]}],"norm_candidates":["skills/frontend-testing/references/page-audit.md#规范来源"]}
```

三处同节的目标是
`skills/frontend-testing/references/page-audit.md#规范来源`：
P1 标题存在、编排默认规范来源 ref、判定样张及报告对应行的
`cited_norms[].ref` 都指向它。
冻结的文档测试 104 到 106 行只核文件名；
同节事实由本卡新增的消费测试核，不扩大其既有证明范围，也不改冻结测试。

扫描器到报告的消费，三类各一条。生产者仍是扫描器，
消费者是编排脚本写报告前那一步：

一、缺规范：引用指的文件或节不存在。
该规范被哪个检查项的 `cited_norms` 引到，该检查项就记未测，
`untested_reason` 写「缺规范：<ref>」，`norms_missing[]` 带这条 `path#section`。
二、过期：引用带的 `version` 与原件头部登记的版本不一致。
同上，理由写「规范过期：<引用版本>≠<原件版本>」。
三、缺版本：引用没带 `version`、`owner`、`consumer`，

同上，理由保「规范缺版本」，并具名所缺元数据、提供者与恢复条件；
`norms_missing[]` 只带 `path#section`，不猜版本或负责人。

## 失败了怎么办？

五处会停，每处写清回谁、改哪件、怎么恢复，不重试到绿。

最大的风险是编排长出第二套判定：脚本自己把某项写成通过。
触发条件是任何测试出现「脚本依据采集输出自行置通过」。
缓解是让通过只来自判定文件，脚本只做两道拒收：无观察的通过、形状非法。
回滚只撤判定那一段，保留采集调用与失败传播，条件是两份测试仍过。
无法回滚时把判定语义交回 Phase 1 的负责人，本 Phase 只保留搬运。

窗口错位是另一种风险：两份输出的 `loader_id` 不等或出现第二次导航，
导航期错误就只落一份。
缓解是两 ready 后才导航、`finish` 同时收尾、两份输出比 `loader_id`；
回滚只撤窗口那一段，保留五采集调用与四类出口。

停点五条：
- 身份块缺项：码 `E_IDENTITY_INCOMPLETE`，停该次运行，补参数后重跑。
- 形状驳回：校验器退出 2 就停写报告，回 Phase 1 的负责人核判据包。
- 规范引用悬挂：只记事实，脚本仍退出 0，但不据此判来源齐备。
- 编排自身异常：退出 1，保标准错误原样，同任务内修，不重试到绿。
- 窗口错位：两份输出 `loader_id` 不等或出现第二次导航，停该次采集，
  保留两份输出与桩日志，回本卡查 ready 与 finish 顺序；不补第二次导航。

回滚的写法：只撤本卡受影响的 hunk，保留其它改动、原输入与失败原件。
修好后由受影响方复验；复验没回来之前不称完成。
