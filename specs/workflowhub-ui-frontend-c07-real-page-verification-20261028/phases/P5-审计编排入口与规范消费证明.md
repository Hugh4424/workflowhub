# Phase P5 — 一次调用把采集编成合法报告，并证明规范被真实引用

## L0 — 结果与变更

### 这个 Phase 做什么

接一个编排入口：一次调用进，一份被形状校验器接受的报告出。
四类采集失败各有具名出口，任何「未测」都不被折成「通过」。
同一批材料还要能回答：判据引用的规范解析得到吗，带版本与负责人吗。
这个 Phase 的测试不启真实浏览器，真执行归 Phase 8；编排器对页面的唯一一次导航只在桩上验证。

### 交付什么

- 一个编排脚本：串身份块、锁引擎、五个采集、合并判定、形状校验、写报告。
- 一个规范消费脚本：给出被引用、悬挂、从未被引用三份清单。
- 两份契约测试与一份判定样张。
- 两处登记：便携包的文件清单与目录映射的条目。

### 为什么现在做

现在做是因为三块零件都到齐了，只差把它们接起来。
判据、采集、消费已由前三个 Phase 各自独立交付，却没有任何入口串起来。
没有这个入口，判据执行不起来，报告也过不了形状校验。
它必须看到前三者的产出才能判，所以排在他们之后。
它自己的成功信号是退出码与报告字节，不是判据正文，也不是采集能力。

### T013 — 任务 2：五个采集调用、四类失败传播与未知不聚合

这张卡让一次调用先在同一个导航窗口里并发跑 console 与 network，再依次跑 overflow、perf、a11y，并把失败分成四类。
通过不由脚本自己给：通过只来自判定文件，脚本只做两道拒收。
有未测项时总体必须是「不完整」，不许聚合成「通过」。
写盘之前先过形状校验器，被驳回就把报告删掉。

每项必须出现什么：

| 位置 | 必须出现什么 | 出处 |
| --- | --- | --- |
| 采集调用 | console 与 network 同窗口并发、同时收尾；overflow、perf、a11y 依次各一次 | 契约决定 3、本卡「同一次导航的采集窗口」 |
| 采集调用 | 每次参数含端点、输出、视口、状态四项 | 契约决定 3 |
| 身份传递 | 五个身份值逐次注入五个采集器子进程的五个 `PAGE_AUDIT_*` 变量，值逐字相等且无空值；缺项在 spawn 前退 2 | 契约决定 5、本卡「编排器到采集器的身份传递」 |
| 窗口交接 | console 与 network 两 ready 后唯一一次导航；两份输出同 `window_id` 与 `loader_id` | 本卡「同一次导航的采集窗口」 |
| 失败分流 | 码 `E_COLLECT_NOT_STARTED`、`E_COLLECT_TOOL_ERROR`、`E_COLLECT_IDENTITY_MISMATCH`，三类都不写报告 | 契约决定 3 |
| 失败分流 | 失联写报告，结果记未测并具名原因，追加覆盖上限 | 契约决定 3 |
| 拒收 | 无观察却声明通过 → `E_PASS_WITHOUT_OBSERVATION`，退出 2 | 契约决定 2 |
| 收尾 | 调 `check-page-audit.mjs --input`：0 接受、2 删报告带出错误、其它非零退出 1 | 形状测试第 5 行、第 44-76 行 |

五个采集器各 spawn 一次，命令行参数仍是端点、输出、视口、状态名；console 与 network 的并发窗口见下节。
对采集器来说，身份不占自己的命令行，走环境：编排器把任务 1 从自己命令行解析好的五个身份值逐次注入每个采集器子进程，
名称与报告 `object` 的键一一对应：

| 命令行参数 | 采集器环境变量 | 报告 `object` 键 |
| --- | --- | --- |
| `--workspace` | `PAGE_AUDIT_WORKSPACE` | `workspace` |
| `--service` | `PAGE_AUDIT_SERVICE` | `service` |
| `--route` | `PAGE_AUDIT_ROUTE` | `route` |
| `--object-version` | `PAGE_AUDIT_OBJECT_VERSION` | `object_version` |
| `--engine-session` | `PAGE_AUDIT_ENGINE_SESSION` | `engine_session` |

**编排器到采集器的身份传递。** 这五个值是 P2 采集器对象八键里不由 CDP 观察得到的那五项；
采集器从这五个同名环境变量取值填入 `object`，命令行仍是四项；加上命令行已有的 `state`、`viewport`
与引擎环境映射，`object` 八键齐。P2 的规则：采集器读不到五个变量中的任一个，
就在连接 CDP 之前报 `E_IDENTITY_INCOMPLETE` 退出 2，不置 `null`、不记 `IDENTITY_MISMATCH`；
编排器的责任是让这种情况不发生：

- 五个值只从命令行解析一次，不猜、不派生、不填默认值。
- 缺任一个或为空：在第一次 `spawn` 之前退出 2，码 `E_IDENTITY_INCOMPLETE`，
  `errors[0].path` 写缺的参数名，采集器调用 0 次，`--out` 指向的报告文件不存在。
- 五个都齐：五次调用逐次注入五个变量，值与解析值逐字相等；报告 `object` 的五个键
  也逐字相等，不是 `null`，也不是占位串。
- 采集器仍报 `IDENTITY_MISMATCH`（receiver 实际身份与声明值不符）：按四类失败的身份不符
  出口处理，退出 2、不写报告；这与「编排器没传」是两件事，恢复条件不同。

可核判据两条：
- 正常路径：桩采集记录五次 `spawn` 的环境，五个变量每次都在、值逐字相等，报告 `object` 五键无 `null`。
- 反向路径：删掉 `--workspace` 重跑，退出 2、码 `E_IDENTITY_INCOMPLETE`、`path` 为 `--workspace`、
  采集器调用 0 次、报告文件不存在。

**同一次导航的采集窗口（console 与 network）。** 这两维是事件流，不能各跑一次；各跑一次就会各看一次导航，导航期错误只落在其中一份输出里。改成一次导航会话内完成：

一、谁触发导航：`run-page-audit.mjs` 唯一负责。它先把 `--cdp-url` 解成浏览器级 `ws://…/devtools/browser/…`（`ws://` 直用，`http://…/json/version` 先取 `webSocketDebuggerUrl`），复用票据脚本的 `connectCdp` 连上，用 `Target.getTargets` 按 `route` 选出唯一页面目标 `targetId`；0 个或多于 1 个就停，码 `E_COLLECT_NOT_STARTED`，不猜。
二、开始：P5 并发 spawn `collect-console` 与 `collect-network`，两者命令行仍是四项，另注入 `PAGE_AUDIT_WINDOW_DIR`、`PAGE_AUDIT_TARGET_ID`、`PAGE_AUDIT_WINDOW_ID` 三个环境变量；采集器 attach 同一 `targetId`，完成 `Page.enable` 与各自域后写 `<dir>/console.ready` 或 `<dir>/network.ready`，然后只订阅。
三、动作：两个 ready 都出现后，P5 才对同一 `targetId` 发唯一一次 `Page.reload`（等价 `Page.navigate` 到当前 URL），等 `Page.loadEventFired`，再等 500 ms 静默窗；任一未就绪不发导航。
四、结束：P5 写 `<dir>/finish`；两个采集器同时把事件刷进各自 `--out`，`items[]` 带同一 `window_id` 与主帧 `loader_id`；P5 收齐两个退出码才跑 overflow、perf、a11y。就绪前退出按 `E_COLLECT_NOT_STARTED`，就绪后异常或收尾超时按 `E_COLLECT_TOOL_ERROR`。
五、同一次导航的保证：两份输出的 `window_id` 与 `loader_id` 逐字相等且等于 P5 记录的 `loaderId`；动作注入的一条 console 错误与一条失败请求分别落在两份输出里；出现第二个 `loaderId` 或只一方命中判红。
六、不补第二次导航：窗口失败就停该次采集，按四类出口处理——未启动、工具异常、身份不符退 2 不写报告，失联写报告并记未测；不重试、不换目标、不把两次导航拼成一份报告。

窗口判据两条：
- 正常路径：桩记录两次 `spawn` 的时间重叠、两个 ready 文件都出现后才有 `Page.reload`，两份输出的 `window_id` 与 `loader_id` 相等，console 错误与 network 失败各在对应输出里。
- 反向路径：只让 console 就绪、network 不写 ready，P5 不发导航，退出 2、码 `E_COLLECT_NOT_STARTED`、报告文件不存在；不得出现第二次导航。

输出不是 JSON，或失败类不在四类里，算工具异常，退出 1。

四类失败各自怎么落：
- 未启动：不写报告，退出 2，码 `E_COLLECT_NOT_STARTED`。
- 工具异常：不写报告，退出 2，码 `E_COLLECT_TOOL_ERROR`，不写成未测。
- 身份不符：不写报告，退出 2，码 `E_COLLECT_IDENTITY_MISMATCH`，带修复指引。
- 失联：写报告，相关结果 `state:"未测"`，`untested_reason` 具名，
  保留已观察的 `items[]`，追加 `coverage_limits`。

最后两道：

- 写完调形状校验器：退出 2 就删报告并把 `errors[]` 原样带出。

### T014 — 任务 3：规范引用可解析，三处指针指向同一节

这张卡回答一件事：判据引用的规范是不是真存在，带不带版本与负责人。
扫描器仍只产事实、退出码只表工具状态：能扫完就 0，哪怕有悬挂引用。
但事实要被报告吃掉，不能只交读者：缺规范、过期、缺版本三类各把对应检查项记「未测」，写进报告。
三处指针要指同一个节：判据正文、编排的默认路径、报告消费段。
对不上就记成悬挂引用，由报告的判定消费写成未测，不让脚本冒充通过。

三个输出键：被引用的规范、悬挂引用、从未被引用的规范。
退出码只表达工具状态：能扫完就 0，参数非法或读不了就 1。
反向样张里故意写一个不存在的节锚，三个键仍要齐、仍要退出 0。

扫描器到报告的消费，三类各一条（生产者仍是扫描器，消费者是 `run-page-audit.mjs` 写报告前那一步）：
一、缺规范：引用指的文件或节不存在 → 该规范被哪个检查项的 `cited_norms` 引到，该检查项 `state:"未测"`、`untested_reason` 写「缺规范：<ref>」、`norms_missing[]` 带这条 `path#section`。
二、过期：引用带的 `version` 与原件头部登记的版本不一致 → 同上，理由写「规范过期：<引用版本>≠<原件版本>」。

三类都不改判据、不改退出码：报告照写、扫描器仍退出 0；变的是那几行检查项的 `state`，与 `criteria[]` 的原始结果并列保留。

### 风险、回滚、停点

最大的风险是编排长出第二套判定：脚本自己把某项写成通过。

缓解是让通过只来自判定文件，脚本只做两道拒收：无观察的通过、形状非法。
回滚只撤判定那一段，保留采集调用与失败传播，条件是两份测试仍过。
无法回滚时把判定语义交回 Phase 1 的负责人，本 Phase 只保留搬运。
窗口错位是另一种风险：两份输出的 `loader_id` 不等或出现第二次导航，导航期错误就只落一份。
缓解是两 ready 后才导航、`finish` 同时收尾、两份输出比 `loader_id`；回滚只撤窗口那一段，保留五采集调用与四类出口。
