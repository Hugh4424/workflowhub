# Phase P11 — 去掉断言里的字面匹配，换成行为观察，并自证仍红

读者：本 Phase 的实施者、独立审查者，以及后续所有 Phase 的门禁消费者。
读完要能：找到哪几行断言要迁、换成什么观察、凭什么说迁移等价、失败了停在哪。

写作标准是 `skills/spec-specify/SKILL.md` 的「十条材料写作标准」。
每个二级标题是一个读者问题，第一句直接回答。
正文用中文编号；机器编号只出现在卡末与文末机器字段。
表只放对照，不承载步骤；命令与表行不受 80 字行宽限制。

先说明十四个会反复出现的词。

- S 类断言：只把「出现某句话或某个旧标签」的检查，换成对同一行为的观察。
- M 类方法语义：断言背后的方法短语含义；本卡不迁。
- 断言：测试里那句判对错的话，失败时让测试变红。
- 迁移：换一种观察写法，判据语义不变。
- 等价迁移：换写法后，同一条单点坏输入仍被对应断言拒绝。
- 坏输入：把某条断言保护的职责弄坏的一处改动；一次只改一处。
- 命中：坏输入让哪条断言报错，以及报在哪一行。
- 判红／判绿：退出非零且点名目标断言／退出 0 且通过数在场。
- 冻结断言：本轮不改字节、继续运行的既有断言。
- TCR（测试变更请求）：逐条写原断言、拟新观察、仍要拒的坏输入与保留边界。
- 门禁：一条能直接执行、用退出码判红绿的命令。
- 判据：判断结果对错的依据。
- 档位：available 或 incomplete；按逐条红绿是否在场定。
- 真实 reader：真正读材料并报缺项的入口，不是测试自造的检查器。

### 谁判，什么时候判？

执行者造坏输入并留原件；判据由任何人在同一仓重跑得出。

- 时点：卡改完即跑；正式审测仍由主会话在开发完成通知后派发。
- 上下文：判的人拿 runbook 与原件重跑，不看实施者口述。
- 分工：执行者交原件；正式 OCR 与独立测试由主会话派。
- 自判边界：本卡只记观察事实，档位可复算；最终质量仍由独立审测签。
- 判的顺序：先核副本在仓外，再核红在目标行，最后看真实交付。

为什么字面断言必须换：写死 label 等于把措辞当契约，改一句话就假绿。
为什么换成职责承载键：材料还在，缺哪个职责仍能指名，语义没放宽。
为什么用真实 reader：自造检查器会照抄假设，真实 reader 的缺项才是观测。
为什么等价要按单点坏输入判：整体非零可能来自别的错误，不能当等价证据。
为什么每条负控只删一个键：同时删两处，分不清是哪一处被拒。
为什么先红后绿再恢复：先证明断得住，再证明改完不误伤原例。
为什么 M 类不迁：M 是结构化断言，迁了只会把能红的降成无观测。
为什么四文件要一次跑：分次跑，某处变红时说不清在哪一步引入。
为什么变更请求要先独立核：自己写的目的自己判，等于自证。
为什么历史坏输入保同字节：换了输入，迁移前后的比较就不成立。
为什么复验要重跑同一输入：不重跑，只能证明当时那一份字节。
为什么坏输入放仓外：改仓内测试求红，等于把契约改成能过。
