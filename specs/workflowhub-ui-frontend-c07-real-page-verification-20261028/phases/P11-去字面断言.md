# Phase P11 — 把"断言散文里出现某句话"的测试改成行为断言

## L0 — 结果与变更

### 这个 Phase 做什么

改四份契约测试，把"检查文档里有没有某句话"的断言，换成"检查文档是否承担某个职责"。
只改 S 类：模板、表格、错误码这类有明确结构的东西。
M 类不迁，因为它们迁完就再也红不了，等于把门拆了。

这件事为什么要单独一个 Phase：它要改 P1 冻结的测试，必须等 P1 的测试落地之后才能做。
它也改的是测试强度，不是产品行为，和页面审计的七个验收无关。

交付两件东西：
- 四份改过断言的测试文件。
- 一份迁移清单：每条旧断言、新断言、旧红证据、独立审查意见。

### 为什么现在做

现在的契约测试里有大量"文档里必须出现某句话"的断言。
这直接导致写材料的人为了过测试而堆句子，是"写给校验器"的主要来源之一。
用户已明确允许改这些断言（答复原件在 `quality/evidence/human-confirmations/2026-10-29-001-allow-frozen-assertion-change.md`）。

### T036 — 任务 1：迁 S 类断言并自证仍红

改四份测试，只迁 S 类。
每条迁移都要留下四件东西：旧断言、新断言、旧红证据、独立审查意见。

2. 只迁 S 类；M 类写清不迁的理由。
3. 迁移后跑同一份坏材料，确认仍红且失败项是行为断言。
4. 附一份独立审查意见。

### 改完重跑早先门禁并重签证据

改断言会让早先几个 Phase 的绿当场过期：P1 的门禁读 `page-audit-doc-contract.test.mjs`，
P4 的门禁同时读它与 `page-audit-report-consumption.test.mjs`。
迁移落地就按下面六步做，不留到下一轮，也不许拿上一轮的绿顶现行结论。

一、重跑 P1 门禁（逐字同 P1 机器头）：`node node_modules/vitest/vitest.mjs run tests/contract/page-audit-shape.test.mjs tests/contract/prototype-design-review.test.mjs tests/contract/page-audit-wiring.test.mjs && node node_modules/vitest/vitest.mjs run tests/contract/page-audit-doc-contract.test.mjs -t "page-audit.md judgment pack"`。

三、重跑 P9 门禁（逐字同 P9 机器头）：`node node_modules/vitest/vitest.mjs run tests/contract/reader-record.test.mjs tests/contract/phase-contract-prose.test.mjs tests/contract/authoring-shape.test.mjs tests/contract/authoring-budget.test.mjs tests/contract/phase-prose.test.mjs tests/contract/authoring-contract.test.mjs tests/contract/spec-analyze-classes.test.mjs`。
