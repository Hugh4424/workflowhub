# Phase P7 — 引用越界与版本绑定各一条薄脚本，校准负例能判红

读者：本 Phase 的实施者、独立审查者，以及下游做收口验收的那一步。
读完要能：找到两条薄脚本改哪、凭什么判红判绿、红了交给谁、本 Phase 不签什么。

> 写作标准：`skills/spec-specify/SKILL.md` 的「十条材料写作标准」。
> 二级标题都是读者问题，第一句直接回答；命令与表格行不受行宽限制。
> 命令、路径、退出码、编号、哈希逐字保留，不因改写而改。

先说明六个会反复出现的词。

薄脚本：一条只做一件事的命令行脚本，用单行 JSON 加退出码回答。
阻断：脚本判「这次不许放行」，退出 2；它只裁决当次运行，不是阶段门。
校准负例：故意造出来的坏输入，证明脚本真会判红，不只会说允许。
白名单：只许出现的字段名单，多一个少一个都算越界。
自哈希：算出判据文件自己的摘要，再与期望值比，防止判据被悄悄改。
改名等价：只换路径、摘要与字节都没变，算同一份材料，不记差异。

## 这一 Phase 怎么验收？

先答这一问：假设本 Phase 全部实现、所有已设计测试也都通过，还会不会漏掉原始需求？
答不出「不会」之前，任何测试通过都不算达成验收。

验收判的是这两条脚本能不能真挡住坏输入、放过好输入，不是白名单写没写。
判法是拿一份坏输入去骗它、再拿一份好输入看它误不误报。
一个 Phase 只有在验收标准真的被满足后才能说开发完成；代码审查通过、测试全绿、结构检查通过，都不是完成条件。
七槽逐条写实；RED/GREEN 表、覆盖上下限与命令细节留在「怎么验证？」，本节只指向它。

1. **验收标准**：本 Phase 承接两条验收，各自写成一句能判真假的话。
   - **验收 1（AC-C07-6）**：判据是越界引用与材料错配能被判红，并说出越界在哪一类。
     成功是真实报告原件上删掉「未测」，脚本判阻断且理由带词类；
     同一原件完整转述时判允许；真实材料清单能算出身份与判据摘要。
     失败是坏输入仍判允许，或干净输入被误报阻断。
     全范围首判仍由 P8 补具名原件，本 Phase 记部分。
   - **验收 2（AC-C07-3）**：判据是真实页面注入反例、修复后复验，200% 与键盘焦点必测。
     本 Phase 只交离线切片，没有跑这部分。
     成功是注入被检出、修复后同一对象复验通过。
     失败是只注入不修复，或未测就记通过。
     现在记 `unavailable`；恢复由 P8 的原执行者取真实注入与复验原件。
   已经观察到的：真实判定原件上完整引用判允许、删限定判阻断，材料字节与判据摘要算得出。
   没有观察到的：真实页面注入与修复复验；它见第 3 槽与用例 6。
   页面首判不由本 Phase 签，见「这一 Phase 不签什么？」。

2. **场景**：正常场景证明不误报，反向场景证明真会拦。
   - **正常（干净引用）**：给一段完整转述原件的引用句。
     观察：退出 0、命中项为空、不产生理由。
   - **正常（干净材料）**：给一份五字段齐全、字节与摘要一致的材料清单。
     观察：退出 0，三类差异都为空。
   - **反向（删掉未测）**：原件有未执行或不能证明，引用句删掉它。
     预期：退出 2，理由指到缺的那一类。
   - **反向（覆盖缺签名人）**：覆盖记录五个字段任一为空。
     预期：退出 2，不许只看 ref 与 quote 就放行。
   - **反向（白名单多字段）**：材料多一个或少一个字段。
     预期：退出 2 并报越界码；只改路径不算换材料，记改名不记差异。
   - **反向（判据被改）**：判据字节改了、期望哈希不变。
     预期：退出 2，报哈希不符。
   - **反向（骗它一轮）**：把词类判断置空、暂禁字节比较。
     预期：各 8 项与目标断言失败；恢复后同一门禁全过。

3. **环境与数据**：写清用什么跑、数据谁给、拿不到算哪一档。
   - **环境**：本机 macOS；node 与仓库内 vitest；子进程驱动，不读网络。

非目标：不判页面好坏，不判质量通过，不以退出 0 代替任何验收。

### 任务 1：引用越界检测，五类词与覆盖记录

这张卡判一句话能不能代表原件：原件有否定或限定，引用句丢了就阻断。
输入是原件与引用句，也可以给一份引用句清单批量判。
第一处动作：在原件里按最长公共子串定位来源窗口，取窗口内的五类标记。
工具异常（文件不可读、参数缺项）退出 1，不冒充阻断。

五类词是：否定、限定、未执行、不能证明、待补证。
阻断要给理由，指到命中哪一类、缺的是哪一类，不只给一个布尔。
覆盖要靠记录，不能靠口头：五个字段齐才算有效覆盖。

每项必须出现什么：

| 位置 | 必须出现什么 | 出处 |
| --- | --- | --- |
| 命令行 | `--source`、`--quote`（或 `--quotes`）、`--override`、`--out` 参数名 | 契约决定 8 |
| 词表 | 五类逐字：否定、限定、未执行、不能证明、待补证 | 契约决定 8、9 |
| 判定 | 引用句缺窗口内某一类的全部标记即阻断，理由带 `term_class` | 预写测试 quotes 组第 1 例 |
| 覆盖记录 | 五字段 `ref`、`quote`、`reason`、`signer`、`expires_if` 任一空即阻断 | 契约决定 9、预写测试 quotes 组第 2 例 |
| 输出 | 单行 JSON：`ok`、`verdict`、`reasons[]`、`matched[]` | 形状测试第 68 到 76 行 |
| 退出码 | 允许 0、阻断 2、工具异常 1 | 契约决定 2 |

## 失败了怎么办？

五处会停，每处写清回谁、改哪件，不调阈值求绿，也不改判据。

最大的风险是把引用检测做成关键词删除器：删掉否定词就放行。
触发条件是校准组出现「原件有否定、引用句没有却判允许」。
影响是把一条越界引用判成允许，下游据此当成原件已核。
缓解是阻断依据「原件窗口有、引用句缺」的结构差，缺哪类写进理由。
回滚只撤判定函数那一段，保留命令行与夹具，条件是三例校准仍两红一绿。
无法回滚时把词表与判定交回 Phase 1 的负责人，本 Phase 只保留形状校验。

停点四条：
- 词表被要求加一类或放宽：停，回 Phase 1 的负责人与主会话，不就地扩表。
- 白名单被要求加字段：停，加字段等于改定义，须回定义卡。
- 自哈希被要求当门：停，它只作事实，成门即违反契约决定 8。
- 夹具造不出判红案例：停，记未完成与缺哪类负例，不写「已检出」。

修好后由受影响方复验；复验没回来之前不称完成。
