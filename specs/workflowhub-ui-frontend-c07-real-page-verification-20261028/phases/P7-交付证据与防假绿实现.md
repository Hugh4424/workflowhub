# Phase P7 — 引用越界与版本绑定各一条薄脚本，校准负例能判红

## L0 — 结果与变更

### 这个 Phase 做什么

做两个薄脚本：一个查引用有没有删掉原件的否定与限定，一个查材料版本绑没绑。
两者都用单行 JSON 加退出码表达：0 允许、2 阻断、1 工具异常。
阻断只作当次运行的裁决，不是阶段门，也不写成「防假绿成立」。
校准负例负责证明它们会判红：三例引用句、四类材料负例。

### 交付什么

- 引用越界脚本：五类词、允许与阻断、覆盖记录的形状校验。
- 版本绑定脚本：白名单、改名等价、重签发差异、判据自哈希。
- 一份契约测试与两份夹具：引用用例、材料用例。
- 两处登记：便携包的文件清单与目录映射的条目。

### 为什么现在做

现在做是因为判据、采集、消费、编排都就位了，只差这两问没人答。
这两问最容易被做成「看起来有检查」，所以必须连校准负例一起交。
它只读 Phase 1 的定义与 Phase 5 的报告，不改定义，失败面在脚本与夹具。
判定对象是「报告、引用句、材料清单」三样，与真机执行无关。

### T018 — 任务 1：引用越界检测，五类词与覆盖记录

这张卡判一句话能不能代表原件：原件有否定或限定，引用句丢了就阻断。

阻断要给理由，指到命中哪一类、缺的是哪一类，不只给一个布尔。
覆盖要靠记录，不能靠口头：五个字段齐才算有效覆盖。

### 风险、回滚、停点

最大的风险是把引用检测做成关键词删除器：删掉否定词就放行。
触发条件是校准组出现「原件有否定、引用句没有却判允许」。
缓解是阻断依据「原件窗口有、引用句缺」的结构差，缺哪类要写进理由。
回滚只撤判定函数那一段，保留命令行与夹具，条件是三例校准仍两红一绿。
无法回滚时把词表与判定交回 Phase 1 的负责人，本 Phase 只保留形状校验。

停点四条：
- 词表被要求加一类或放宽：停，回 Phase 1 的负责人与主会话，不就地扩表。
- 白名单被要求加字段：停，加字段等于改定义，须回定义卡。
- 自哈希被要求当门：停，它只作事实，成门即违反契约决定 8。
- 夹具造不出判红案例：停，记未完成与缺哪类负例，不写「已检出」。
