# Phase P4 — 把页面审计接进 build-code 的冻结前与终末，并把报告消费与回修闭环写成可执行契约

## L0 — 结果与变更

### 这个 Phase 做什么

把页面审计从技能里的方法变成 build-code 的固定动作。
冻结前必须正式审一次；终末只复核四项，不重跑全量。
给审查镜头一条消费规则：按四态与覆盖边界读摘要，不新增字段。
把回修闭环写成顺序：定位、路由、最小修复、独立复验、三轮或一轮无新增即停。
这个 Phase 只改两份方法文件与一条静态契约测试，不跑审计。

### 交付什么

交四件东西：
- build-code 三处接线：触发句、冻结前插入块、终末复核半句。
- 触发词扩一处：前端测试条目的适用面加上浏览器可见页审计。
- 审查镜头新增一节「页面审计摘要消费」。
- 一条静态契约测试，把弱断言加强到同句同块。

### 为什么现在做

编排 Phase 要读到「什么时候必须审」的措辞，末验收要按终末四项复核取证。
它只改方法文本，不依赖采集能跑，失败面小。
它依赖 P1 的报告形状，所以排在 P1 之后。

### 回修一步：在自有副本上修一处缺陷
