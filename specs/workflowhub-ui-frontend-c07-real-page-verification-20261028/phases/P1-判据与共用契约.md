# Phase P1 — 判据正文成为唯一权威，校验器只判形状

## L0 — 结果与变更

### 这个 Phase 做什么

做一份判据正文，再配一个只判形状的校验器。
判据正文说清四件事：查什么、结果怎么记、怎么算通过、什么情况拒收。
它是唯一权威：采集器按它写输出，报告解析按它读结果。
这个 Phase 不采集、不消费报告、不驱动浏览器。

交付四件东西：
- 一份判据正文，十一个二级节。
- 一个校验器，按退出码三分，按六类具名码拒收。
- 两处方法正文各一句指针，指向正文与校验器。
- 一条接线测试，证明指针指得到、指得对。

### T001 — 任务 1：写判据正文

写一份判据正文，共十一个二级节。
它回答四件事：查什么、结果怎么记、怎么算通过、什么情况必须拒收。
这份正文是唯一权威，采集器与报告解析都按它写。
这张卡不写采集器，也不写脚本。

十一个二级节，每节必须出现什么：

| 节 | 必须出现 | 出处 |
| --- | --- | --- |
| 八维骨架 | 八个维名逐字，各一句「这一维交付什么」 | 设计审查技能 36-43 行 |
| 九维到八维的映射 | 三列表加分隔行；每维一行，行内带「主」或「副」 | 判据包测试 41-59 行 |
| 四态 | 通过、未测、不适用、失败，各带理由要求 | 判据包测试 16-19 行 |
| 分级刻度 | 三档，加字体、间距、颜色三条还原负例与一条主操作被遮罩的阻断负例 | 契约决定 6 |
| 采集失败四类 | 未启动、失联、工具异常、身份不符，各写落在哪个状态 | 契约决定 7 |
| 必测门 | 200% 缩放与键盘焦点同一句含「必测」；读屏同一句含「不作必测门」 | 判据包测试 104-106 行 |
| 业务任务脚本 | 按页面任务判成败；mock 上写未覆盖 | 契约决定 7 |
| 回修闭环 | 三轮上限；一轮无新增即停；停不等于通过或失败 | 契约决定 8 |
| 不适用与依据 | 同一句写理由与依据 | 判据包测试 16-19 行 |

### T002 — 任务 2：写形状校验器

写一个只判形状的校验器，不判内容对错。
它读一份报告，按结构拒收：缺字段、类型不对、出现总分。
拒收时给六类具名错误码；退出码分三种：通过、拒收、用法错误。

三个入口：
- 读报告并校验结构。
- 收集全部错误，不只报第一个。
- 输出裁决与错误码。

六个错误码，逐字写进脚本：

| 码 | 什么时候报 |
| --- | --- |
| E_TOTAL_SCORE | 报告里出现总分或百分比 |
| E_UNKNOWN_AGGREGATED | 把未测或未知聚合成一个数 |
| E_MISSING_EVIDENCE | 通过但没有证据 |
| E_MISSING_UNTESTED_REASON | 未测但没写理由 |
| E_STATE_OUT_OF_ENUM | 状态不在四态里 |
| E_LIMITED_PASS | 只在限定范围内通过却写成通过 |

用法：node skills/frontend-testing/scripts/check-page-audit.mjs --input <report.json>
