## C2 只改两处（唯一实施项）

C2 的唯一写入面是 `skills/wh-review/scripts/simple-review-runner.mjs` 与新建的 `tests/contract/wh-review-detail-incomplete.test.mjs`。两处改动如下，第三处起一律不做。

**第一处：detail 面的「材料里有任何键」检查（`skills/wh-review/scripts/simple-review-runner.mjs:963` 之后、`:964` 之前）。**

- 条件：`input.stage === "make-decision"`，`(input.review_track ?? input.reviewTrack ?? null) === "detail"`，`input.materials` 是非数组对象；且当前 `materialPreflight` 为假（没有本阶段已知键）。
- 动作：用 `materialAllowlistForRule(rule)` 取 `required`（去掉 `generated`），逐键用 `preflightMaterialPresent`（模块级，`:717-724`）判断；第一个缺失键就返回 `blockedPreflight(input, "MATERIAL_INCOMPLETE", "required material <key> is missing or empty", preflightDiagnostic({field:<key>, expected:"non-empty caller material", actual:有键但空/缺键, nextAction:"supply current material and retry"}), pair, {material_id:null})`。
- 语义：把 detail 面原先「`return hasKnownMaterial`，只认已知键」换成「材料里有任何键」（代码形态是新增 detail-only 分支，不是改 `:892` 的公共 return）；只在 detail 生效，不把公共 `shouldRunMaterialPreflight` 改成全局 any-key（那会打红 30 条 material-only/`verify-code` 用例）。
- 边界：新分支在 `materialResult` 之后、`providerPreflight` 之前，`blockedPreflight` 已给 `status="unavailable"`、`dispatch_state="blocked_before_dispatch"`、`provider_results=[]`、`findings=[]`，不进 `normalizeProviderError`，不改 `:1477` 的 catch。

**第二处：缺键分支去掉「只在收尾阶段才检查」的限制（同一文件 `:792`）。**

```js
// 改前
}), pair, reviewActivationCohort(input) === "post" ? { material_id: null } : {});
// 改后
}), pair, { material_id: null });
```

只改 `if (missing) {` 这一支；`:770` 的 direction 揭示分支不动。

**不动的三件（明确禁止）**

1. **不换 `forbiddenMaterial` 顺序**：`runMaterialAllowlistPreflight` 现在先查 `forbiddenMaterial`、后查 `missing`。换序会让构建阶段 `{junk_material}` 从「禁止」变「不完整」，打红 `simple-review-runner.test.mjs:1742-1790` 两条今天全绿的测试；实测把「缺键优先」放宽到所有面会红 30 条（70/57）。第五例专门锁这个分界。
2. **不改 `:892` 的公共 `return hasKnownMaterial`**：它服务 `verify-code` 的 material-only API 与其它面；全局放宽的代价就是上面的 30 条红。
3. **不改 bundle 层与路由**：`review-materials.mjs`、`ocr-delegation-route.test.mjs` 只读；在 bundle 抛错会同时改 `:1477` 的异常路径和 6 处断言。
