# Phase P3 — 检查记录与就绪

这一阶段只干三件事：让检查记录自证身份、删掉身份即失效、开工真读就绪五列。
读完这张卡的人应当能直接开工、能独立验收，也能把它交给 P4。

## 哪些节必须写，哪些可以省？

模板必填节全部在场；phase-maker 逐 Phase 的调研、设计、任务卡、回读对象各占一节；
写作脚手架不落盘。

| 节 | 本文件怎么处理 |
| --- | --- |

## 这一 Phase 交出什么？

一条记录能自己说清是哪道检查、在哪份材料上跑的；删掉身份就不算有效；
开工前真的读一遍计划声明的就绪条件。

- **本 Phase 结果**：身份判定与剥离共用一处；无身份记录判「未取得」且不回退；
  未收敛包的退出码读 `kind`；就绪输出点名「人判未验证＝N」但不阻断；
  两份定向测试与既有断言同批通过。
- **非目标**：只加诊断不改判定，可做但本次不选，理由是删身份仍会登记为有效
  （决策日志包 3 第 3 项否掉备选 D）。
- **非目标**：按「归档过」或「材料时间」划分旧记录，可做但本次不选，
  理由是可事后翻转、材料时间可改（备选 E、F）。
- **非目标**：就绪侧把人判行改成阻断派发，可做但本次不选，理由是既有测试固定该
  行为，改它等于新增一道门（备选 G）。
- **非目标**：重写历史记录或改原件字节，可做但本次不选，理由是历史只读、零迁移。
- **改动前**：双层包装只剥一层，写读两侧都认不出声明门；最新声明门无身份时回退到
  更早绿件；缺身份与坏件同判失败；退出码读中文字串（`:2781`、`:946`）；
  就绪人判行记了但没点名；close 投影只写不算。
- **改动后**：剥离上限 4 层、写读同源；无身份即「未取得」且不回退；不可读原件报
  原文；退出码读 `kind`、旧 gap 走兜底；就绪输出点名人数、退出码不变。
- **与相邻 Phase 的边界**：上游 P1 交回身份与入口；下游 P4 读本阶段的方法接线口径；
  本阶段不写方法文件、不改阶段模板、不做流程锚。
- **主要风险**：活跃任务的最新声明门没有身份而被拒。若因它返工，替代走法是先把
  规范化与「未取得」落定，再补不回退；判据不动。
- **回退保留**：三处代码可独立还原、零迁移；原始失败原件（回放清单、身份删除前后
  sha256、退出码原件）与无关改动都不动，历史记录不重写、不删除。
- **下一步**：P4 在同一份 `tools/cli/run-checks.mjs` 与 `runtime/` 上继续；先读本阶段
  当前字节。
- **动手前必读**：按读序排在「开始前读什么？」一节。
- **未决事实**：剥离规则唯一家在 `runtime/task/delivery-claims.mjs:267`，

### 首卡纵切

首卡是 T014；这条链让没写卡的人能开工。所有负例都在 `mkdtemp` 副本上做，
真实原件不动。

- **公开入口**：`node tools/cli/task-close.mjs status --project=<项目> --task=<任务>`
  （只读，读验证项与 claim 原因）；close 是否被拒再用
  `node tools/cli/task-close.mjs prepare --project=<项目> --task=<任务>` 复核。
- **装配点**：`tools/cli/stage-runtime.mjs:1162-1165` 把
  `gateIdentityFromCapture` 的结果写进 gate-results 的 `gate_identity`。
- **调用者**：close 投影读 claim 的 `gate_identity`，再交
  `runtime/stage/stage-content-contracts.mjs` 的身份选择裁决。
- **可见结果**：状态里验证项失败、原因写「身份缺失」、证据指针指向被删那一件。
- **失败信号**：证据指针指到更早的件，或 close 退 0；两者任一出现即错。
- **首读符号**：`canonicalCommand`（`runtime/task/delivery-claims.mjs:267`）、
  `gateIdentityFromCapture`（同文件 `:302`）、字段 `gate_identity`。
- **首改路径**：`runtime/stage/stage-content-contracts.mjs` 里「跳到更早带身份的门」
  那段身份选择。
- **判错动作**：在副本删掉最新声明门的 `gate_identity` 后跑 status 与 prepare，
  读原因、证据指针与退出码；再把身份选择改回「跳到更早带身份门」，同一输入必须
  从失败变通过（证明这一段就是裁决处）。

## 这一 Phase 怎么验收？

先算三账，再按一条一小段写九段；判据正文只在附录写一次，本节只引。

- **成本账**：九条判据的成本七字段取自 Appendix A 包 3 每条的成本行。
  估算 20+12+10+10+10+12+10+10+15＝109 活动分钟；硬上限 265 分钟；
  共享准备 5 分钟；重试预留 10 分钟。活动总额 124 分钟，略超软上限 120、
  低于硬上限 240；不拆分，重试预留与共享准备各计一次。
- **资源账**：真实任务事实副本（`mkdtemp` 内改）、真实旧无身份记录、真实就绪材料
  副本、改动前基线输出、本机 Node 与 bash、两份定向测试；每条段内标来源。
- **范围账**：验收 1、2、6 证身份与绑定；验收 3、4、5 证后置绿与不可读；
  验收 7、8 证就绪；验收 9 证退出码；跨阶段只写「供件」。

`acceptance_cost_total=124 active_min`
`phase_budget={soft_min:120,hard_min:240,variance_threshold:1.5,source:provisional}`

阈值是待校准值；起始事件未取得，预算只作观察，不建退出门。

**先答这一问**：假设本阶段全部实现、所有测试都通过，还会不会漏掉原始需求？
不会漏掉包 3 九条；全仓历史回放与整链验收本阶段明确不判（前者只抽样、后者归末验）。
本阶段只证这九行，末验合并判。回退时按「交出什么」的回退保留句执行。

**验收 1：删掉最新声明门身份后，验证项失败、原因身份缺失、证据指向该件、close 拒。**
目标：删一件就失效，且证据不回退到更早件。
怎么操作：把真实任务事实复制到 `mkdtemp`，删最新声明门的 `gate_identity`，
跑 close 投影与收口，读验证项、原因、证据指针与退出码。
什么条件：只读副本、原件前后 sha256 不变、本机 Node。
怎样算通过：验证项失败、原因写身份缺失、指针＝被删那件、close 非 0。
真跑还是替代：真跑，副本内造负例。
谁判与证据：没参与实现的独立执行者，回执 `quality/evidence/p3/identity-delete.json`；
对应包 3 第一条。
**故意弄坏必须失败**：把身份选择改回「跳到更早带身份门」，同输入必须变通过，
此时本段判失败。

**验收 2：无身份记录判「未取得」并拒绝 close，原件字节不变。**
目标：旧记录只被标成没取得，不被写成失败也不被补身份。
怎么操作：同一副本里选一条本就无身份的旧记录，跑 close 投影与收口，
记判定文本、退出码与原件 sha256。
什么条件：真实旧记录副本；前后 sha256 必须相同。
怎样算通过：判定为「未取得」、close 非 0、sha256 与操作前一致。
真跑还是替代：真跑。
谁判与证据：独立执行者，回执 `quality/evidence/p3/identity-absent.json`；
对应包 3 第二条。
