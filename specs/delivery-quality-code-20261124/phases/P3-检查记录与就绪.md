# Phase P3 — 检查记录与就绪

这一阶段让每条检查记录自己说清它是哪道门、在哪份材料上跑的；删掉这个说明就不再算数；
让未收敛包的退出码只看结构化原因；让开工入口把「人判未验证」点出来但仍只诊断。
读完这张卡的人应当能开工、能独立验收，也能把它交给 P4 作者。

“自述身份”指记录原件里的 `gate_identity` 三元组（`phase_id`、`phase_ref`、`gate_cmd_sha256`），
由写侧捕获时写入，读侧只读它、不重算命令（用户裁决 2026-11-24，D 方案）。
“跳过”只有两个条件：`gate_identity === null` 且没有 `gate_unbound`，或身份命中**别的 Phase** 的声明门；
两者都是**已知否定**，不是“不知道”，也不等于回退。
“未取得”是键存在但值为 `null` 且带 `gate_unbound`（`unparsable`／`depth-exceeded`）的捕获，
它与“身份缺失”同一条失败路径，只由原因串与码区分。

## 哪些节必须写，哪些可以省？

模板的必填节全部在场；只属于末验阶段与写作脚手架的节不落盘。
本卡对应 phase-maker 八步：第 1 步在「开始前读什么」；第 2、3 步由 `spec.md` 与决策日志承接；
第 4 步在「本 Phase 调研结论」；第 5 步在「首卡纵切」「首卡开工五列」与「真实供件登记」；
第 6 步在九张任务卡；第 7 步在纯指针索引；第 8 步在「下一消费者拿什么继续」。

## 这一 Phase 交出什么？

P3 交出「记录带自述身份、删身份即失效、未收敛退出码读结构化原因、开工点名但不断路」的可执行版本。

- **本 Phase 结果**：`runtime/task/delivery-claims.mjs` 的 `selectDeclaredGate` 只按记录自述身份裁决，
  读不出、缺身份、身份不符一律具名失败且证据指到那一件；`claims.<名>.code` 与顶层 `claim_codes`
  在失败时给出 `GATE_IDENTITY_MISSING` 等具名码，close 拒绝消息带同一码；
  `tools/cli/check-stage-steps.mjs` 的 `gapFailureCode`／`convergenceExitCode` 由冻结表唯一决定退出码；
  就绪输出点名「人判未验证＝N」而退出码不变。
- **非目标**：在 read 侧保留“重算命令再对撞”的旧做法，可做但本次不选，理由是用户 2026-11-24 裁决
  读侧只核记录自述身份；要求的检出能力由写侧身份与 marker `#sha256=` 字节绑定承担。
- **非目标**：给 `claim.status` 增加第三态 `unobtained`，可做但本次不选，理由是 AC-P3-001 要「验证项失败」、
  AC-P3-002 要「未取得」，二者是同一条代码路径（`gate_identity` 键缺失），第三态会把今天判 `fail` 的
  无效标记／`GATE_ABSENT`／`GATE_NOT_CAPTURED`／原件不可读四类一起吸走，判定者对不上；
  「未取得」由 `code` 与原因文本承载。
- **非目标**：把就绪侧人判行改成阻断派发，可做但本次不选，理由是既有测试固定该行为

### 首卡纵切

首卡是任务 14；沿公开入口、装配点、调用者、可见结果、失败信号写，
让没写卡的人能写出首读符号、首改路径与判错动作。

- **公开入口**：用例入口 `npx vitest run tests/integration/vnext-delivery-close.test.mjs -t "P3-AC-001"`；
  真实读入口 `node tools/cli/check-delivery-claims.mjs --project workflowhub --task delivery-quality-code-20261124`
  （`tools/cli/check-delivery-claims.mjs:42` 打印整个 `result`，含 `claim_codes`）；
  收口入口是 `recordCloseClaimsReadback`（`runtime/task/delivery-claims.mjs:551`）。
- **装配点**：`readDeliveryClaims`（`:400`）→ `gateMarkers`（`:326`，从 build-code stage 行的 `source`
  取 `ref#sha256=` 指针）→ `selectDeclaredGate`（`:330`，本卡整段替换）→ 成功路径 `jsonReference`（`:431`）
  逐字节校 sha256 → `claim()`（`:377`，加第 4 参 `code`）→ `recordCloseClaimsReadback`（`:551`）。
- **调用者**：close 投影 `recordCloseClaimsReadback`（`:552` 读 `requireReadback: false`）与
  `core/task-close.mjs` 的收口入口；独立审查者读 `tools/cli/check-delivery-claims.mjs` 的 JSON；
  build-code 第 7 步审查者读同一份 `claim_codes`。
- **可见结果**：`claims.verified.status === "fail"`；`reasons` 匹配 `/身份缺失|no gate identity/`；
  `claims.verified.evidence` 等于被改写那一件的 `{ref, sha256}`；`claim_codes.verified === "GATE_IDENTITY_MISSING"`；
  close 抛 `DELIVERY_CLAIMS_REJECTED` 且 message 含 `[GATE_IDENTITY_MISSING]`；退出码非 0。
- **失败信号**：`f.gate` 没换成最新件（`claimsFixture` 的 `f.gate` 是 `:369` 的 `gatePointer(f)` 取 `.at(-1)`，
  第二件捕获后它已不是最新件），断言会拿重写前的 sha 比新件，形成假绿；
  证据指到 `markers[0]`；把 `:354` 改回 `identityless += 1; continue` 后同输入仍判失败（说明回退没被真删）。
