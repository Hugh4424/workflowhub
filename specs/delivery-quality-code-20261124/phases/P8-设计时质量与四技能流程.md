# Phase P8 — 设计时质量与四技能流程

这一阶段把「为什么这条能解决、对应哪个原问题、还剩什么没闭环」写进作者正在看的格子，
给四个技能补同一套七步流程，并把四个阶段正文的接线从目录型改成能判完成的具名产物。
读完这张卡的人应当能开工、能独立验收，也能把它交给 P9 作者。

## 哪些节必须写，哪些可以省？

模板的必填节全部在场；只属于末验阶段与写作脚手架的节不落盘。
本卡对应 phase-maker 八步：第 1 步在「开始前读什么」；第 2、3 步由 spec 与决策日志承接；
第 4 步在本节调研表；第 5 步在「契约头与写集」；第 6 步在五张任务卡；
第 7 步在纯指针索引；第 8 步在「下一消费者拿什么继续」。

| 节 | 本文件怎么处理 |
| --- | --- |
| 交出什么 | 写结果、非目标、改动前后、调研表、契约头与写集、首卡纵切、五列、供件、半径、回退 |
| 开工就绪表 | 写五列增量行，含指纹与四份技能在场核对 |
| 怎么验收 | 写三笔账、五段验收、非 UI 声明与预算 |
| 为什么现在做 | 写现状证据与顺序依据 |
| 开始前读什么 | 写九份材料与读序 |
| 每个文件由谁改 | 写十一个写集路径、首动作与共享写者 |
| 每张任务卡怎么写 | 写五张卡，任务 1 至任务 5 对应 T050 至 T054 |
| 怎么验证 | 写命令面与人读面 |
| 下一消费者拿什么继续 | 写交给 P9 的可观察件与回读协议 |
| 机器字段 | 写文件级十个标签 |
| 末验专属检查 | 不写，本阶段不是唯一末验阶段 |
| 写作脚手架与示例 | 不写，它们是模板作者自用的草稿，落盘即删 |

### 首卡纵切

首张任务卡沿「公开入口 → 装配点 → 调用者 → 可见结果 → 失败信号」写，
让没写卡的人能写出首读符号、首改路径与判错动作。

- **公开入口**：`node tools/cli/check-stage-steps.mjs --stage=build-plan --step=6 --card`
  带真实 `--task-path` 与 `--material-root`，读回 `skill.file`、`skill.anchor`
  与 `step_slug`；比对入口用 `node --test tests/contract/four-skill-wiring.test.mjs`。
- **装配点**：`workflows/build-plan/steps.json` 第 6 步的 `skill` 声明与
  `completion_evidence`；模板句落在 `skills/spec-plan/templates/phase-template.md`。
- **调用者**：build-plan 第 6 步的写卡子代理与主会话；下游 P9 作者读同一批句。
- **可见结果**：卡模板与 Phase 模板里能读到「为什么这条能解决」「对应原问题/FR」
  「残余/未闭环」三句；写卡子代理按八步出卡。
- **失败信号**：入口读不到 `skill` 指针或 `step_slug`；三句只写成「见 spec」；
  或读者指不出三句在卡正文的位置。
- **首读符号**：`skills/decision-maker/templates/card.md` 的「方案与取舍」格；
  `skills/spec-plan/templates/phase-template.md` 的「这一 Phase 交出什么？」与
  「下一消费者拿什么继续？」两节；`skills/phase-maker/SKILL.md#八步`。
- **首改路径**：在卡模板「方案与取舍」格加一句；在 Phase 模板两节各加一句；
  在 phase-maker 第 6 步与回读契约各加一句。
- **判错动作**：入口读不到指针、三句缺一或写成「见 spec」时停手，
  保留原输出回计划作者，不新增字段、不改十一格定义。
