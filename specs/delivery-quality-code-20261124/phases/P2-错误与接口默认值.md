# Phase P2 — 错误与接口默认值

本卡交给阶段 2 专属作者、独立审查者、独立回读者与阶段 4 作者。
“假成功”是坏输入被空串、0、false、null 或空 catch 伪装成正常。
“默认值”是缺值时程序替调用方选的值，必须写清谁定、依据哪条。
“绕行”是明知不理想但暂时保留的路径，每处要有唯一删除票。
“删除票”写在施工卡 `非目标` 行，由 build-plan 计划期写，审查只核不写。
“两问”是默认值谁定、坏输入会不会看起来成功；“四问”是接口深度四问。
本卡按 `skills/phase-maker/SKILL.md#八步` 写；精确命令按原字保留。

## 这一 Phase 交出什么？

一句话：审查问得出默认值谁定，检查器抓得住新增行的假成功，删除票只有一家。

- **本 Phase 结果**：简化审查多两问与接口深度四问；新增只扫本次新增行的检查器
  与契约测试；施工卡 `非目标` 行有删除票唯一写法；build-code 第 5 步捕获门命令回执、
  第 7 步读回；检查器与测试在 move-map 登记。
- **非目标**：不做全仓默认值扫描、不做整洁度门、不做通用重复扫描；
  不判理由真假；不追扫历史行；不改三角色、运行时写入或 close。

  `workflows/build-code/SKILL.md` 第 5/7 步没有回执挂点说明；

## 这一 Phase 怎么验收？

六条判据在[规格附录 A](../spec.md#appendix-a--验收判据唯一权威)包 2 写一次；
本段只引编号，不复制正文。

- **成本账**：六条估算 5、15、10、20、15、10，串行相加 75；硬上限合计 165；
  无共享准备；重试预留 10。`acceptance_cost_total=85 active_min`。
- **资源账**：检查器与测试在本段新建；真实 diff 用本 Phase 起点；
  审查件与 build-code 回执用真实原件；缺件按 unavailable/incomplete 记。
- **范围账**：001 证自测；002 证真实新增行零漏报；003 证不碰历史与夹具；
  004 证审查有结论；005 证删除票唯一家；006 证回执挂第 5 步。
  给阶段 4 的是两问四问与类型边界，写成供件。

不适用——本任务无页面、路由、组件或样式改动：写集没有前端应用文件，
仓库没有 `apps/` 或 `.tsx`、`.vue`、`.jsx`。

**验收 1。** 目标：自测退 0，且只含新增行正反例，不含历史行。
怎么操作：跑 `node tools/cli/check-added-failure-masks.mjs --self-test`，读退出码与逐条输出。
什么条件：仓内当前字节、本机 Node；不接真实任务库。
怎样算通过：退出 0，自测列出正例与反例两类，无历史行命中。
反例：往自测塞一条历史行命中仍退 0，必须判失败。
真跑还是替代：真跑并记退出码；不能跑记 `unavailable`。
谁判与证据：独立执行者；`quality/tests/p2-self-test.output`。

**验收 2。** 目标：真实新增行上每条命中都有处置，新增假成功零漏报。
怎么操作：先造一处 `catch { return null }`（RED 捕获），跑
`node tools/cli/check-added-failure-masks.mjs --base <Phase 起点>`，
核对命中文件与行号正是该处；处置后再跑一次。
什么条件：本 Phase 真实差异（含未跟踪，按 `-U0`）、起点 commit；
不得用历史提交差异替代。
怎样算通过：故意造的两类新增行各命中一次并给行号；无漏报。
反例：删掉“出错返回空/假”模式后，同命令对 `return null` 漏报仍判通过。
真跑还是替代：真跑两份并留输出；不能跑记 `unavailable`。
谁判与证据：独立执行者；`quality/tests/p2-real-added-lines.output`。

**验收 3。** 目标：不报历史行，也不报 tests/fixtures/docs；测试同款只进跳过。
怎么操作：同一次运行里抽三条历史命中候选与至少一条 tests/ 内同款，
核对前者未出现在命中、后者出现在跳过计数。
什么条件：仓内当前字节、已知历史行位置清单（只读）。
怎样算通过：命中列表无历史行、无测试/夹具路径；测试同款在跳过计数。
反例：把扫描起点改成无范围全仓，同命令必须报历史行；仍判通过即失败。
真跑还是替代：真跑并读输出；不能跑记 `unavailable`。
谁判与证据：独立执行者；`quality/tests/p2-scope-boundary.output`。

**验收 4。** 目标：审查记录里两问与四问各有结论，并写路径与锚。
怎么操作：独立读者打开 `skills/simplicity-guard/SKILL.md` 与本次 P2 审查件，
逐问找结论，核对写的是路径加锚而不是“已检查”。
什么条件：真实 P2 审查件、simplicity-guard 当前字节；未产生记 `incomplete`。
怎样算通过：两问与四问逐条有结论，每条带 `path#anchor`，无空条。
反例：压成一句“已按规范检查”并删路径与锚，必须判失败。

**验收 5。** 目标：每处绕行在施工卡 `非目标` 行有唯一删除票。

绕行、删除条件、决定人、结束条件；再核审查件只判断不写票。
什么条件：真实 P2 卡、Phase 模板当前字节、P2 审查件。
怎样算通过：每处绕行一条四要素票；审查只判断；无第二处票。
反例：把票改写到 `quality/reviews/`，或 `非目标` 行留空，必须判失败。

什么条件：真实 build-code 事实副本、`workflows/build-code/SKILL.md`；
