# Phase P5 — 单元复盘

这一阶段把「单元做完当场留一条五问复盘记录」落成可执行的结构：五个技能各长出一个固定节，
新建一条合同测试逐文件断言节名，任务根下留出记录目录并写出第一条真实记录，四份步骤表只换一句口径。
读完这张卡的人应当能开工、能独立验收，也能把它交给 P1、P3、P6、P7 作者。

- **交出什么**：`skills/stage-reflection/SKILL.md` 新增「单元模式：单元复盘记录」一节，
  写清触发点只有一个（单元完成时）、单元只有三类（任务分节／一个包／一个 Phase 的设计与执行完成）、
  阶段不是单元、缺记录只让该条判未完成；`skills/task-maker/SKILL.md`、`skills/phase-maker/SKILL.md`、
  `skills/run-phase/SKILL.md`、`skills/decision-maker/SKILL.md` 各加一节「收尾：单元复盘记录」，
  四句职责各不同、都只指向复盘技能、不复述方法；`tests/contract/unit-reflection-wiring.test.mjs`
  逐文件断言这两个节名与五问字段；任务根 `quality/evidence/reflection/` 下第一条 `unit-*.md`
  五问齐、指针可打开；四份 `steps.json` 的关闭步只换一句，步骤数 6／12／12／15 与 `step_slug` 不动。
- **对应原问题/FR**：R-024 每个任务、包、Phase 设计与执行完成后复盘且结构优先、聊天摘要可见；
  R-026 规则按域进 `specs`、不自建独立经验库；R-009 不新增门、不设通用重复扫描；
  承接 FR-CODE-005，落在 AC-P5-001 至 AC-P5-006 与 T029 至 T034。
- **下一消费者**：P1、P3 作者拿五处节名、五问格式与记录位置写自己的单元记录；P6 作者建域规则表时
  只补列、不改记录格式；P7 作者只读记录里的晋升、驳回、未执行三组字段。本阶段不写规则表、
  不写七步流程锚、不做接线断言。

## 哪些节必须写，哪些可以省？

模板的必填节全部在场；只属于末验阶段与写作脚手架的节不落盘。
本卡对应 phase-maker 八步：第 1 步在「开始前读什么」；第 2、3 步由 `spec.md` 与决策日志承接；
第 4 步在本节之后的三张表（调研结论、逐字表、对应原问题/FR）；第 5 步在「首卡纵切」「首卡开工五列」
「开工就绪表」「真实供件登记」「未知半径」「回退保留」「可能冲突的阶段」；第 6 步在六张任务卡；
第 7 步在纯指针索引；第 8 步在「下一消费者拿什么继续」。

| 节 | 本文件怎么处理 |
| --- | --- |
| 交出什么 | 写结果、非目标、改动前后、三句交接、调研结论、逐字表、首卡纵切、五列、就绪表、供件、半径、回退、冲突 |
| 怎么验收 | 写三笔账、六条验收（怎么跑、通过信号、反例）、既有红与保绿清单、非 UI 声明、预算 |

| 每张任务卡怎么写 | 写六张卡，任务 29 至任务 34 对应 T029 至 T034、AC-P5-001 至 AC-P5-006 |

### 单元定义、五问与五处节名（交给下游的逐字表）

五问与节名逐字取自设计原件 `design-p5.md` 的 S1、S2；状态词与摘要上限同源。
本节是下游读的唯一逐字表，卡内其它处只引用，不另抄一份变体。

| 项 | 逐字 |
| --- | --- |
| 触发点 | 只有一个：单元完成时 |
| 单元三类 | 任务分节、一个包、一个 Phase 的设计与执行完成 |
| 阶段不是单元 | 阶段末只汇总，不另记一条 |
| 复盘技能节名 | `## 单元模式：单元复盘记录` |
| 四技能节名 | `## 收尾：单元复盘记录`（四份各自一节，职责句各不相同） |
| 五问一行 | 问题｜以前有没有｜实际改了什么｜为什么不用更高层｜怎么证明 |
| 摘要上限 | 不超过五条，每条一句、结论先行，超出并进已发条目并写明合并理由，末尾给记录路径 |
| 状态词 | 只写「命中」「首次」「待 P6 表」，不自造列名、不写 `specs` 路径 |
| 记录位置 | 任务根 `quality/evidence/reflection/` |
| 记录文件名 | `unit-<YYYY-MM-DD>-<三位序号>-<单元名 slug>.md`，序号作用域是本任务＋本目录＋当日，撞号用 `flag:'wx'` 改写下一个号 |
| 不是门 | 不改阶段与 Phase 的推进条件；缺记录只让该单元这一条判未完成 |
