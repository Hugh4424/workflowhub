本卡交给 P10 实施者、独立审查者与 P11 作者。
「真实使用者动作」是三处载体共用的最小可观察形态：谁（被具名使用者与记录者都具名）、做了什么（对真实对象做的动作）、留下什么（可打开的原件与行位）。
「卡外事实」是卡面没写、且能在原件定位的新事实（真实行号、当前值、邻接符号、命令输出或退出码、卡面未写的差异）；卡面自带的符号与路径不算卡外事实，照抄卡面六件必须判失败。
「真动作五条」是身份、动作、读回、产物、时序同时成立；只复述、只登记、替身、已通知各自死在固定的一条上。

| R3 | 读回 | 至少一项**卡面之外**、能在原件定位的新事实：真实行号、当前值、邻接符号、命令输出或退出码、卡面未写的差异 | 复述或照抄卡面六件、只给 artifact ref 或目录名、只写「读完了」、只写结论不写定位 |
| R4 | 产物 | 留下可读指针：路径＋行位，或命令＋退出码，或时间＋来源 | 「已通知／已说明」本身、只有一句「通过了」 |
| R5 | 时序 | 动作发生在卡交付之后；AC-P10-001 还要求下一包作者不看写作会话，只凭卡与指针 | 写作会话里自读自记、先写结论后补记录、收口后补记当现场 |

### 四种假动作死在哪条

- **只复述**：死在 R3（没有卡外事实），同时死在 R4（只有「清楚／已读」，没有留下的件）。
- **只登记**：死在 R2（没有动作，只有一条登记记录），同时死在 R3（登记不等于读回）。
- **替身／代记**：死在 R1（同一人换角色、同一会话换身份，或写者找独立记录人代记而被具名使用者仍是写者）。
- **已通知**：死在 R2（通知不是动作），同时死在 R4（通知不是留下的件）。

对应到三处载体：决策卡与阶段卡类要求「两人都不在写者集合」；交接类要求「被具名使用者不在写者集合，记录者不得同时是被具名使用者」。
机器口径只借 `runtime/task/delivery-claims.mjs:514-516` 的「signer 不在 authors 集合」，本包不改该文件。

### 卡外事实：照抄卡面六件必须判失败

卡面本来就带首读符号与首改路径（`skills/phase-maker/SKILL.md:83` 就是卡内要求），所以「两样都有」可以被照抄满足。
AC-P10-002 的通过条件因此加一条：读回里必须至少有一项卡面之外的、可在原件定位的事实。
可接受的卡外事实形态：真实行号、当前值、邻接符号、命令输出或退出码、卡面未写的差异（例如真实文件里已有同名段、或某行与卡面描述不符）。
**把卡面六件原样抄进读回、只改日期与名字，必须判失败**；若这条负控被判过，AC-P10-002 失败。

### 借 phase-maker 的刻度

`skills/phase-maker/SKILL.md:83` 要求回读者写出「第一处要读的文件与符号，第一处要改的路径」；`:93` 把「只有 artifact ref 或目录名，
没有首读符号与首改路径」判为坏返回。P10 沿用同一刻度，但把「卡外事实」作为独立条件：

- Phase 类（AC-P10-002）：首读符号＋首改路径＋至少一项卡外事实；前两样在卡面已有，光有它们不算。
- 决策类（AC-P10-001）：首个决定或首处改动＋卡外事实；只写「清楚／已读」判失败。
- 交接类（AC-P10-003）：谁＋做了什么＋留下什么；只写「已通知下游」判失败。
- 文档与用户类（允许的非代码形态）：试拆首卡并写出「卡在缺 X」，或用户使用一次并留下观察；只写「看过」不算。
