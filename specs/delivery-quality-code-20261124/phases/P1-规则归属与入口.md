# Phase P1 — 规则归属与入口

这一阶段让任何项目都能把「一条规范只写一次」变成可建立、可读取、可查出第二处的结构：
`specs/<域>/README.md` 一张五列表加 AGENTS 每域一行指针，一个 `rule-tables` 工具负责建、查、读，
四个阶段的读点与 norm-sync 的写点都先问这张表。
读完这张卡的人应当能开工、能独立验收，也能把它交给 P2、P3 作者与 P6 作者。

「规则表」是 `specs/<域>/` 下含逐字五列表头的 `.md`，列名逐字取自 `decision-log.md:670`：
规则｜正文锚点｜靠什么强制｜状态｜什么时候读。
「域」是 `specs/` 后的第一段路径；「声明」是 `AGENTS.md` 里指向该表文件的链接（带 `#` 的是正文引用，不算声明）。
「零张表」是全项目找不到任何规则表，此时退出码是 3，与 `AGENTS.md` 是否存在无关。
「结构不完整」是表缺、锚点损坏或权限不足时写入的具名结论，同时给提供者，不写成「找不到规范」。
「第二处」是同一条规则正文在两个位置各有一份；本阶段只报不改。

## 哪些节必须写，哪些可以省？

模板的必填节全部在场；只属于末验阶段与写作脚手架的节不落盘。
本卡对应 phase-maker 八步：第 1 步在「开始前读什么」；第 2、3 步由 spec 与决策日志承接；
第 4 步在本节调研表；第 5 步在「首卡纵切」「首卡开工五列」与「真实供件登记」；
第 6 步在七张任务卡；第 7 步在纯指针索引；第 8 步在「下一消费者拿什么继续」。

| 节 | 本文件怎么处理 |
| --- | --- |
| 交出什么 | 写结果、非目标、改动前后、三句、调研表、首卡纵切、首卡开工五列、供件、未知半径、回退、可能冲突的阶段 |
| 开工就绪表 | 写五列增量行，含新建前的负条件与设计原件指纹 |
| 怎么验收 | 写三笔账、七段验收、非 UI 声明与预算 |
| 为什么现在做 | 写现状证据、顺序依据与设计原件指纹 |
| 开始前读什么 | 写设计与代码锚点的读序 |
| 每个文件由谁改 | 写十一处路径、首动作、前后写者与合并责任 |
| 每张任务卡怎么写 | 写七张卡，任务 1 至任务 7 对应 T001 至 T007 |
| 怎么验证 | 写命令面与人读面 |
| 下一消费者拿什么继续 | 写交给 P2、P3 与 P6 的可观察件与回读协议 |
| 机器字段 | 写文件级九个标签，不写写入集 |
| 末验专属检查 | 不写，本阶段不是唯一末验阶段 |
| 写作脚手架与示例 | 不写，它们是模板作者自用的草稿，落盘即删 |

## 这一 Phase 交出什么？

P1 交出「任何项目都能建出唯一规则表、读出结论、查出第二处」的可移植版本，
本仓自己的九个域文件与三张表留给 P6 建。

- **本 Phase 结果**：`node <workflowhub 包根>/tools/cli/rule-tables.mjs` 的 `init`／`check`／`lookup`
  在任意项目上按同一口径建表、报缺、查重；四个阶段的读点与 `norm-sync` 的写点都先经该表；
  `specs/<域>/README.md` 五列表加 `AGENTS.md` 每域一行指针是唯一归属结构；
  四个阶段的读点一律**先建后读**：先确认该域规则表存在，缺表就建或记 `rule_table absent`，
  只有真正读写该域时才建该域，只读阶段与权限不足记 `结构不完整` 并给提供者。
- **非目标**：建本仓的 9 个域文件与三份既有 README 的五列表，可做但本次不选，
  那是 P6 的写集；P1 若代建，七条判据就要依赖本仓当前状态，任何一处文档改动都会让判据变红。
- **非目标**：另立规范根（`norms/`、单份 `rules.md`、根目录 `RULES.md`），可做但本次不选，
  用户已否掉「一个文件装全部」的形状；本阶段反过来把这种形状判成 `RULE_TABLE_MISPLACED`。
- **非目标**：用编辑距离或语义判法抓改词副本，可做但本次不选，
  逐字副本与插空行副本已能抓到，改词限度在「未知半径」逐条写明，不冒充已抓到。
- **非目标**：给检查器加 `--json`、第二套锁或第二套原子写，可做但本次不选，

### 对应原问题/FR

任何项目用 workflowhub 做设计开发时，规范散落、没有唯一归属处：同一条规则在技能默认路径、
域 README、`specs/Improvements.md` 各有一份，读者不知道哪份算数，写者也不知道该改哪处。
这一 Phase 对应 R-001 一条规则只写一次且全部适用入口生效、R-007 方法改动改变施工者动作而旧行不追扫、
R-014 先给合法调用再结构排除错误、R-016 类型或枚举优先且合法入口后限制直连；
承接 FR-CODE-001，落在 AC-P1-001 至 AC-P1-007 与 T001 至 T007。

### 首卡纵切

首卡是任务 1；沿公开入口、装配点、调用者、可见结果、失败信号写，
让没写卡的人能写出首读符号、首改路径与判错动作。

- **公开入口**：`node <workflowhub 包根>/tools/cli/rule-tables.mjs init --root <项目根> --domain backend`；
  同一次开工还会用到 `check --root <项目根>`（本卡已把它当反例入口）。
  命令里没有缺省项目根：`--root` 必填，且必须是已存在目录。
- **装配点**：`argv` 解析 → 入口守卫（按 realpath 比较 `process.argv[1]` 与 `import.meta.url`）→
  `initDomain(root, domain)` 先算两个落点 `specs/<域>/README.md` 与 `AGENTS.md`，
  用 `writeFileAtomic`（`runtime/interface/safe-write.mjs:236`）逐件写，
  整段共用 `withLock(root,"norm-sync")`（`runtime/interface/record-lock.mjs:136`）；
  `AGENTS.md` 只在不存在时整份新建、已存在时在文末追加标记段，原文逐字不动。
- **调用者**：本卡之后的读点调用者——`skills/project-norm-init/SKILL.md` 的「规则的建与读」（T002 写）与
  `workflows/build-code/SKILL.md:96` 每 Phase 开工的 build-code 第 1 步执行者；
  `norm-sync` 的写者（T006）在锁内复用同一结构。
- **可见结果**：打印 `ESTABLISHED specs/backend/README.md AGENTS.md` 退 0；
  文件树恰两份；表文件含逐字五列表头，AGENTS 段含指向该表的一行链接；
  重复执行打印 `ALREADY ESTABLISHED` 退 0；再 `init --domain api` 只多 `specs/api/README.md` 与 AGENTS 一行。
- **失败信号**：只读目录或权限不足打印 `INIT FAILED <path>: <errno>` 退 2，不写半份还报成功；
  无子命令或子命令不认识打印用法退 2，不静默 0；`--domain ../../outside` 或含 `/` 退 2；
  建出第三份文件、建出 `norms/` 或其他规范根、覆盖 AGENTS 原文，三者任一出现即判失败。
- **首读符号**：`runCli`、`parseArgs`、`resolveDomain`、`initDomain`、`buildTableSkeleton`、
  `upsertAgentsPointer`、`deriveSlug`、`matchSlug`。
- **首改路径**：新建 `tools/cli/rule-tables.mjs`、`tests/contract/rule-tables.test.mjs`，
  在 `docs/architecture/move-map.json` 的 `entries` 加一项。
- **判错动作**：建出额外文件就修 `initDomain` 的落点集合；覆盖原文就改追加标记段并逐字比较；
  只读目录报成功就修写入错误分支与 `INIT FAILED`；无子命令退 0 就修 realpath 入口守卫。

### 门红与退 2 的处置落点

- **门红（`check` 退 1）**：逐条违规只能落三种处置之一：① 改正文或改表行（同一 Phase 提交）；
  ② 确认是被引用的第二处，把引用改成链接或按规则 owner 决定加 `--exclude` 并记限度；
  ③ 确认是检查器误报，保留原输出、回本阶段实施者改判法，不删断言换绿。
  处置清单进本 Phase 独立审查件，实施者不能自签。
- **退 2（输入、用法或权限错，不是门红）**：先停本步、不记 finding，按错误行分派：
  缺 `--root` 或 `--root` 不是目录 → 找给根的人（计划负责人或目标项目提供者）；
  `--domain` 越界 → 找调用者改参数；`--exclude` 覆盖已声明表 → 找调用者改排除；
  只读目录 `INIT FAILED` → 找目标项目提供者给写权限，并记 `结构不完整` 与提供者。
  任何人不得手改目标项目的 AGENTS 或表文件来让检查变绿。
- **复跑**：同一 `--root` 与同一 `--domain`，不换夹具；处置完仍红的按有效 finding 回开发修。

### 检查器口径（T001–T005 的实施底稿）

下面这张表与判据清单是实施底稿，实施时按它写代码与自测；
设计稿 §6 是同一事实的展开，冲突处以设计稿为准并在卡上记差异。

| 情形 | 退出码 | 输出要点 |
| --- | --- | --- |
| 全项目零张规则表（含只有 AGENTS 的情形） | 3 | `NOT ESTABLISHED: zero rule tables` |
| `lookup` 无表 | 3 | `rows=0 domain=<域> table=absent` |
| `lookup` 表在而 0 行 | 4 | `rows=0 domain=<域> no_registered_rule` |
| 有违规 | 1 | 逐条打印，末行 `FAIL <n> violation(s)` |
| 干净 | 0 | `PASS tables=<n> rules=<n>` |
| 重复 `init` | 0 | `ALREADY ESTABLISHED` |

| 只读目录里 `init` | 2 | `INIT FAILED <path>: <errno>`，不写半份 |

判据清单（逐条打印，短名进输出，长义进本文）：

| 检查名 | 判什么 |
| --- | --- |
| `INDEX_UNLINKED` | `specs/<域>/` 下有五列表，但 AGENTS 没有链接它 |
| `INDEX_DANGLING` | AGENTS 链接了 `specs/<域>/…md`，但文件不存在 |
| `TABLE_INVALID` | AGENTS 链接的规范文件既不是规则表，也不是任何已登记行的正文 |
| `RULE_TABLE_MISPLACED` | 任意位置（含 `docs/`、根目录）出现逐字五列表头，但不在 `specs/<域>/` 下；围栏代码块内的同形表头不计 |
| `RULE_EMPTY`／`RULE_TOO_LONG` | 规则列为空／超过 40 字 |
| `RULE_DUPLICATE` | 同一规则句登记在两行或两张表 |
| `FORCE_EMPTY`／`STATUS_INVALID` | 靠什么强制为空／状态不在已强制、待落、已退 |
| `ANCHOR_FORMAT`／`ANCHOR_PATH` | 锚点不是「项目根相对路径#slug」／路径不存在或越出项目根 |
| `ANCHOR_AMBIGUOUS`／`ANCHOR_DUPLICATE` | slug 在该文件命中 0 或超过 1 个标题（ATX 与 setext 都算）／同一锚点被两行登记 |
| `BODY_TOO_SHORT` | 正文归一化后不足 8 字，无法判第二处 |
| `BODY_DUPLICATE` | 标题区段覆盖率 ≥0.6，或 8–23 字的短正文整段相等 |
| `BODY_ECHO` | 覆盖率 0.4–0.6，只打印并计数，不计违规、不改退出码 |

判法：正文块＝锚点标题到下一个同级或更高级标题之前；目标区段＝文件按标题切出的连续块（不是按空行切段），
所以中间插空行的副本仍落在一个区段；长正文用 24 字窗口、步长 8；阈值与限制度见设计稿 §6.2 与 §6.4。
