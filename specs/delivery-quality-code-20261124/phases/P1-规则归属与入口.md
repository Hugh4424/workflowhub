# Phase P1 — 规则归属与入口

这一阶段把「任务身份」这条规则收到唯一的新家，四个正式入口里三个接同一判定，
查看可以跨目录但必须说清看谁，写入与收口各留自己的物理绑定。
读完这张卡的人应当能开工、能独立验收，也能把它交给 P2、P3 作者。

## 哪些节必须写，哪些可以省？

模板的必填节全部在场；只属于末验阶段与写作脚手架的节不落盘。
本卡对应 phase-maker 八步：第 1 步在「开始前读什么」；第 2、3 步由 spec 与决策日志承接；
第 4 步在本节调研表；第 5 步在「契约头与写集」；第 6 步在七张任务卡；
第 7 步在纯指针索引；第 8 步在「下一消费者拿什么继续」。

| 节 | 本文件怎么处理 |
| --- | --- |
| 交出什么 | 写结果、非目标、改动前后、调研表、契约头与写集、首卡纵切、五列、供件、半径、回退 |
| 开工就绪表 | 写五列增量行，含指纹与真实根核对 |
| 怎么验收 | 写三笔账、七段验收、非 UI 声明与预算 |
| 为什么现在做 | 写现状证据与顺序依据 |
| 开始前读什么 | 写九份材料与读序 |
| 每个文件由谁改 | 写十个写集路径、首动作与共享写者 |
| 每张任务卡怎么写 | 写七张卡，任务 1 至任务 7 对应 T001 至 T007 |
| 怎么验证 | 写命令面与人读面 |

## 这一 Phase 交出什么？

P1 交出「同一条规则只有一个家，四个入口改一处」的可执行版本。

- **本 Phase 结果**：新建 `runtime/task/task-entry-identity.mjs`，导出
  `resolveTaskIdentity({mode,project,task,taskPath,env,home,cwdIdentity})`，
  失败抛带 `.code` 的错误；`tools/cli/stage-runtime.mjs` 的只读分支传 `read`，
  写与收口保留各自绑定；`core/task-close.mjs`、`runtime/task/task-handle.mjs`、
  `tools/cli/task-bootstrap.mjs` 三处私有身份片段改调同一判定；
  施工模板的「动作」与「文件 / 符号」两处写出规则新家、入口数与调用者；
  四个旧文案子串逐字保留。
- **非目标**：把所有入口的授权合并成一套，可做但本次不选，
  写、创建、收口、只读各保自己的物理绑定；不同授权入口保各自限制。
- **非目标**：让 `tools/cli/check-stage-steps.mjs` 也接外部身份，可做但本次不选，
  它不认外部身份、没有可判坏输入；日后接入条件单列。
- **非目标**：改 `docs/architecture/real-entry-inventory.md` 的过期内容，可做但本次不选，
  它列了四个已无路由的命令，改它会拖进第二轮口径；本包写明理由不碰。
- **非目标**：全仓入口身份矩阵与全仓重构，可做但本次不选，
  不做通用重复扫描；只修本包声明的路径。
- **改动前**：同一条显式身份在主线目录下，`stage-runtime status` 退 1 并报身份冲突，
  `task-close status` 退 0；身份判定散在 `tools/cli/stage-runtime.mjs:95-116`
  的 `resolveWorkflowHubIdentity`、`core/task-close.mjs:87-88` 的内联校验、
  `runtime/task/task-handle.mjs:84-90` 的私有后缀检查；
  `tools/cli/task-bootstrap.mjs:81-82` 只核 manifest；
  `runtime/task/task-entry-identity.mjs` 不存在。
- **改动后**：同一显式身份在主线目录下两入口都退 0 且 task_id、quality_status 相同；
  三组坏输入在两入口给同一具名错误码；写与收口仍拒且码不同；
  跨目标仓只读返回被查任务的 workspace；卡面两处写出新家、入口数与调用者；
  四个旧子串仍在。
- **与相邻 Phase 的边界**：上游阶段 5 先交回复盘口径，本阶段只读不改；
  下游 P2 与 P3 同批开工，P2 在本阶段之后写同一份阶段模板的「非目标」行，
  P3 读本阶段定下的模式语义改收口投影与就绪输出。
  `core/task-close.mjs` 与 P7 共享：本阶段先改身份转调，P7 后改任务类型共享解析。
- **主要风险**：写入口误传只读模式，写入前的目录检查被关掉，可能写进别的任务目录。
  若因它返工，替代走法：模式不给默认值、写入口显式传写模式、验收 4 反例兜底；
  仍不对就回滚整包，不用「只读放宽」扩散。
- **下一步**：P2、P3 作者按本阶段交回的模式语义与模板两处说明接着写；
  不重写本阶段文字，不改 `core/task-close.mjs` 的身份行（P7 后改任务类型行）。
- **动手前必读**：按「开始前读什么？」的读序；先读规格与决策日志，再读设计原件，
  最后读六处真实代码与两份测试。
- **未决事实**：`core/task-close.mjs` 与 P7 的重叠顺序未在本卡锁定；
  影响验收 2、4、7，owner 计划负责人，

### 首卡纵切

首张任务卡沿「公开入口 → 装配点 → 调用者 → 可见结果 → 失败信号」写，
让没写卡的人能写出首读符号、首改路径与判错动作。

- **公开入口**：在真实任务工作区内跑 `node tools/cli/stage-runtime.mjs status`，
  不带 `--project` 与 `--task`；计划步骤投影用
  `node tools/cli/check-stage-steps.mjs --stage=build-code --step=1 --card`
  读回本步。
- **装配点**：`tools/cli/stage-runtime.mjs:95` 的 `resolveWorkflowHubIdentity`
  与其后的 `thinTaskContext` 预检；新模块 `runtime/task/task-entry-identity.mjs`。
- **调用者**：`stage-runtime` 的 `status` 与 `doctor` 只读分支；写与收口分支本卡不动。
- **可见结果**：`status` 退 0，`workspace` 指当前任务根，输出不索要显式身份。
- **失败信号**：退 1 且报 `IDENTITY_INCOMPLETE` 或 `IDENTITY_MISSING`；
  或 `workspace` 指向调用目录、出现 `NOT_A_WORKTREE`。
- **首读符号**：`resolveWorkflowHubIdentity`（`tools/cli/stage-runtime.mjs:95`）、
  `resolveCanonicalTaskPath`（同文件 `:100` 调用）、
  `deriveIdentityFromAuthenticatedWorktree`（同文件 `:102` 调用）。
- **首改路径**：新建 `runtime/task/task-entry-identity.mjs` 并导出
  `resolveTaskIdentity`；在 `stage-runtime.mjs` 只读分支传 `mode:"read"`。
- **判错动作**：入口退 1、workspace 错或出现 `NOT_A_WORKTREE` 时停手，
  保留 stdout/stderr 回计划作者；不改测试换绿、不放宽预检、不动真实任务事实。

**验收 1：任务工作区内不带显式身份跑只读入口。**
