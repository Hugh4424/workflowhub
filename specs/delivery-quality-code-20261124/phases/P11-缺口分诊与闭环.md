# Phase P11 — 缺口分诊与闭环

本卡交给阶段 11 专属作者、独立审查者、独立回读者与 P13 作者。
“缺口”是未完成项，不是“有 incomplete 就失败”。
“四类分诊”是设计问题、实现问题、验收标准问题、资源/外部依赖问题。
“闭环”是每类走对应修复：重设计、修复重跑、回原决定人、写恢复条件或接受限制。
“不硬拒”是有分类、owner、动作、验证即可收口；只有未分类才拒。
本阶段含代码改动，三张卡按红绿判；不新建台账或第二份进度权威。
本卡按 `skills/phase-maker/SKILL.md#八步` 写。

## 这一 Phase 交出什么？

一句话：每个缺口先分类再决定修什么；有分类可收口，未分类才拒。

- **本 Phase 结果**：stage-close 与 build-code 各有四类分诊与闭环路由；
  收口入口对“已分类样本”放行、对“未分类样本”拒绝并点名；
  9 项真实缺口逐条有类别、证据、owner、下一步；四类各至少一例。
- **非目标**：不硬拒 incomplete、不新建台账、不随意放宽验收或扩范围；
  不把资源缺口当实现缺口改代码；不判各条业务质量。

  收口不读分类；无 `gap-triage` 测试。

  未分类项被点名缺分类。

  误放宽验收回原决定人。

- **动手前必读**：`skills/stage-close/SKILL.md:12`、`:24`；`core/task-close.mjs:1253-1261`；
