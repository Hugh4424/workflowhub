# Phase P11 — 缺口分诊与闭环

本卡交给 P11 实施者、独立审查者、独立回读者与 P13 作者。
“缺口”是未完成项，不是“有 incomplete 就失败”。
“四类”是设计、实现、验收标准、资源；归类只问一句：**关闭这条缺口，缺的那件东西是什么**。
“闭环”是每类走各自的路：设计回原 writer 改件，实现回 build-code 修并重跑，验收标准回原决定人改判据，资源写恢复条件或明确接受限制。
“不硬拒”是已分类的缺口可以收口；只有未分类才被拒，并点名缺哪一条。

## 四类判定：问「关闭这条缺口，缺的那件东西是什么」

归类只有一句问法：**这条缺口要关闭，缺的那一件东西是什么**？
按「东西」落类，不按「能不能过」、不按「谁在卡」，**也不走问答顺序**。
旧写法先问「能不能过」、再问「不能过是不是缺资源」，一旦答「不能由本任务改代码」就掉进资源类，
**设计类因此永远到不了**——这是本版必须改掉的地方。

### 判定表（四行，闭集）

| 缺的那一件是 | 类别 | 当场可核的特征 |
| --- | --- | --- |
| **一段代码改动** | `实现` | 有一个可复现的错误行为：RED 命令＋失败输出；改代码能产出它，改完能重跑同一命令 |
| **设计件里的某段写法／某个字段／某条指针／某个路由** | `设计` | 判据成立、代码跑起来无错，只是卡、表头、命令、字段名、指针或路由写错或没写，照它做不出来 |
| **别人／他时／他环境／真实数据的真实产出** | `资源` | 本任务无论怎么改代码都产不出：真实回执、真实首用、真实原件、真实调用、真实周期、外部会话 |
| **判据本身** | `验收标准` | 要动的字在 AC 正文、证据等级或范围里，而不是在卡、指针、字段、路由或代码里 |

**为什么这四类穷尽**：任何「关闭动作」只能落在这四件上——改代码、改设计件的字、等外部真实产出、改判据；
没有第五种可动对象。因此不需要「先问 1 再问 2」的路径，设计类也不会被跳过。
**若缺的不是这四件之一**（例如缺的是一次判断、一次授权、一个人的决定），那它不是缺口而是待决定项：
按 `AGENTS.md`「卡住与升级」走，不进分诊表，也不许拿「其他」占一行。

### 分诊单位：一行＝一个 AC × 一个类别

**一行 = 一个 AC 编号 × 一个类别。** 一个 AC 里含两类就拆两行，编号加后缀：`AC-023(a)`、`AC-023(b)`。
每行独立写类别、证据、owner、关闭动作或恢复条件；不许一行塞两类，也不许用「主要是 X、附带 Y」蒙混。
按这个单位，任务三 9 项拆成 **10 行**：设计 1／实现 1／资源 8／验收标准 0（见「10 行分诊表」一节）。

### 三条防错分边界（只在这三处会摇摆）

1. **`实现` vs `设计`**：先问「有没有可复现的错误行为」。有 → `实现`（哪怕设计也写错了，最近可动项是代码）；
   没有可复现错误、只是照它做不出来 → `设计`。
2. **`资源` vs `验收标准`**：先问「不改判据，这件东西能不能拿到」。能拿到、只是还没拿 → `资源`；
   **永远拿不到、必须改证据等级或范围才算过** → `验收标准`。所以 AC-016／AC-021 现在是 `资源`（原件在原会话里），
   只有当原决定人**真做出**「以转录取代原件」的裁定，才改判 `验收标准` 并转回原决定人。
3. **`设计` 的闭环不能碰归档**：本阶段禁止改 `spec.md`、`phases/index.md`、`decision-log.md`、任务三原件与其它阶段卡。
   所以设计类的关闭动作只能是「回该设计件的原 writer，由其在**下一次真实开工**时改」，本任务不改归档卡；
   原决定人明确接受该限制时按「明确接受限制」记，不冒充已修。

### 与 `AGENTS.md` 「停机分诊」那张表的分工

`AGENTS.md:66` 的「四类分诊只以下表为准」写在**「卡住与升级」节内**，表体在 `:68-73`，管的是「现在就停哪条路径、其余安全工作怎么继续」；
本节的四类管的是「这条缺口归谁闭、闭到什么程度才收口」。两者回答不同问题，**各管各的、不互相替代、不做逐行映射**
（给了映射就等于暗示可以互译，反而制造第二种读法）。

`workflows/build-code/SKILL.md:160` 的「四类分诊只按 `AGENTS.md`「卡住与升级」同一张表落位」**必须加限定**，
否则与 `:161` 后新增的缺口句直接冲突。逐字改为：

```text
停机分诊只按 `AGENTS.md`「卡住与升级」同一张表落位（它只决定停哪条路径）；
收口时每条缺口的归属四类（设计／实现／验收标准／资源）见本步末与 :174，
```

`AGENTS.md` 不动（不在本阶段写入集，且那句话的适用范围就是停机）。

## 机器只判一件

**判据（唯一）**：`plan.gap_triage` 每一条的 `class` 必须是非空字符串且属于四类闭集；违反即拒并**点名**（列出 `id:class`）。

**错误码（唯一新码）**：`GAP_TRIAGE_UNCLASSIFIED`

```text
GAP_TRIAGE_UNCLASSIFIED  every declared gap needs one of 设计/实现/验收标准/资源; unclassified: AC-016:(none), AC-023(a):缺材料
```

**明确不判**：不判 owner／动作／验证是否存在；不判类别是否正确（机器只能判「是不是四类之一」，填错必过）；

「填错必过」是本设计的已知上限，不是漏项——人读那一侧因此加一条硬抽样（见下）。

本节描述写卡阶段的派发预算；执行阶段按内核 R2 的角色（一开发一审查一测试）另外计，不并入本节。

每个 Phase 最多三次派发（写卡阶段）；超过三次要在本卡写明理由与代价，不默认增加。

- **三次派发各做什么**：第一次把调研与设计合并（读材料、给方案、写初稿）；第二次落卡（按初稿写卡并自检）；第三次一次性审查（独立读者只判目标是否对齐、验法与反例是否成立、写集是否越界，不重写）。
- **哪一次与别的阶段并行**：并行面以本卡「与相邻 Phase 的边界」与 `spec.md` 的「谁先谁后？」为准；本卡在该节写明与谁并行，不并行写理由。
- **超过三次要写理由**：本卡写清为什么必须多派、多派的代价与谁批准；写不出理由就不增派。
- **审查只一轮**：同一 Phase 只开一轮独立审查；修复回原派发，受影响方复验，不另开第二轮。
- **回读不属于派发预算**：回读按 `skills/phase-maker/SKILL.md` 的「回读契约」单列，不计入本节次数。
