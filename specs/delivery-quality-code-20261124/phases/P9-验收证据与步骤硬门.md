# Phase P9 — 验收证据与步骤硬门

本卡交给阶段 9 专属作者、独立审查者、独立回读者与 P10/P11/P12 作者。
“证据落点”是一条验收指向的可打开原件路径加行位，不是目录。
“真跑或替代”是命令、读者动作或替代理由；替代要写不能证明什么与 owner。
“步骤硬门”是 11 个声明了 `skill` 的步骤，任一步未完成即阻断收口。
“完成事实”是 `facts.jsonl` 里带 source、命令、退出码与失败签名的证据行。
本阶段改代码，五张卡都按红绿判；不新增阶段或第二份判据。
本卡按 `skills/phase-maker/SKILL.md#八步` 写。

## 这一 Phase 交出什么？

一句话：验收有可打开的证据落点，单步完成有真实生产者，11 步未完成不能收口。

- **本 Phase 结果**：PRD 四行第 4 行有落点与真跑/替代；Phase 卡每条落点可打开；
  `appendStepEvidence` 与唯一 CLI 让单步可判“已完成/未留痕”；接线断言会红；
  `run-checks --task-path` 在 11 步任一步未完成时退 1 并列缺步；收口消费同一判定。
- **非目标**：不统一“命令＋退出码”、不造六个 target 夹具、不要求文档任务有命令；
  不改 `Done` 的 8 值档位语义；不判各步业务质量；不回扫历史任务。
- **改动前**：第 4 行只写“怎样算通过”；Phase 卡落点可写目录；逻辑槽无生产者；
  接线测试不会红；`run-checks` 退 0 而 11 步一步未判；收口不看缺步。
- **改动后**：落点与替代写清；单步证据可由唯一入口写入并判完成；
  删索引判不了完成；缺步退 1 并点名；补齐退 0；未声明 `skill` 的缺口只报告。
- **与相邻 Phase 的边界**：P8 先交四阶段接线与 `steps.json`；本段只补生产者与硬门；
  P10/P11/P12 读同一退出码与缺口清单，不改判据。
- **主要风险**：硬门挡住历史任务再收口；或 TCR 未批就改模板。若返工，
  先只改 `spec-prd:79`，模板句等 TCR；硬门只读本次 `--task-path` 当前事实。
- **下一步**：P10 作者读硬门口径，P11 读缺口清单，P12 读失败分诊。
- **动手前必读**：`spec.md` A.9；`decision-log.md:975-1097`；
  `tools/cli/run-checks.mjs:773-815`；`core/task-close.mjs:1253`；
  四份 `steps.json`；`runtime/task/task-store.mjs:66-115`。
- **未决事实**：
  1. `decision-log.md#包级收敛台账` 不存在，第 9 步恒 incomplete；owner 包 13，
     恢复条件是该节真实落地。
  2. `step-consumer-design.md` 义务列未批，RED 相关步可能判不了 completed；
     owner 该文件维护者。
  3. TCR 批件尚未产生；模板句与 `prd-card-shape` 改动等独立审查，未批则挂起并写缺口。

  不写真实任务库；缺件按 incomplete 记。
- **范围账**：001 证第 4 行；002 证落点可打开；003 证生产者；004 证接线会红；
  005 证硬门。给 P10–P12 的是退出码与缺口清单，写成供件。

**验收 1。** 目标：新 PRD 第 4 行同时有证据落点与真跑/替代，替代四要素齐。
怎么操作：独立读者打开真实任务节第 4 行，逐样找落点、替代、不能证明什么与 owner。
什么条件：真实新 PRD、`spec-prd` 与模板当前字节；未产生记 `incomplete`。

## 回退保留哪些无关工作与原始失败

- **保留无关工作**：已写入的证据行、已通过的其它判据、同文件其它改动保留；
  回退只撤本次失败的一处。
- **保留原始失败**：失败命令的原 argv、cwd、退出码与原始输出保留；
  不删、不改写成通过、不重跑到绿。
- **回退单位**：一个函数或一个退出点一个 hunk；生产者与 CLI 成对回退；
  硬门回退后回到“只 make-decision 具名缺口退 1”。
- **不保留**：隔离根在 `finally` 回收；临时 RED 件只留输出。
