# Phase P9 — 验收证据与步骤硬门

本卡交给 P9 实施者、独立回读者、独立审查者与 P10、P11、P12 作者。
「证据落点」是一条验收指向的可打开原件路径加行位（`路径:行号`），不是目录。
「真跑或替代」是命令与退出码、读者动作或替代理由；替代只限真跑不可能，并写原因、owner、不能证明什么与残余。
「步骤硬门」由报告行的 `skill` 字段派生：声明的步骤任一步未完成即阻断收口，报告里没有对应行＝不适用。
「完成事实」是 `facts.jsonl` 里 `kind="quality_evidence"` 的证据行，带 `source`、`step_slug`、`ref`、命令、退出码与失败签名。
本阶段改代码，三张卡按红绿判、两张纯文档卡按 G-2 写；不新增阶段、不建第二份判据。

本卡不写写入集字段；写入集只作推荐，唯一权威是 `phases/index.md` 的 P9 行（`:19`）。

## 这一 Phase 交出什么？

一句话：验收有可打开的证据落点，单步完成有唯一生产者，声明步未完成不能报告 0、也不能静默收口。

- **本 Phase 结果**：`tools/cli/record-step-evidence.mjs` 与 `runtime/task/task-store.mjs#appendStepEvidence`
  让单步证据有唯一写入口，`check-stage-steps` 能判「已完成／未留痕」；`tools/cli/run-checks.mjs` 的
  `stepCoverageExit` 让声明步缺一步就退 1 并点名 `missing_steps`；`core/task-close.mjs` 的 `closeDelivery`
  在产 plan 之前拒绝缺步、定义不可读与无材料根三种收口；三处 PRD 句、两处 Phase 卡句可读；
  `workflows/build-prd/steps.json` 第 4 步有一个真实可读的 `prd.md#任务卡` 材料项。
- **非目标**：不给 `executeClosePlan` 加门（本轮范围决定，记 R16），可做但本次不选，
  理由是另红 30 例／8 文件、合计 37 例／11 文件，超出本轮范围；把 `sha256` 做成复核侧校验也不做，
  理由是 `sha256` 只在写入时是事实（R8）；统一「命令＋退出码」、造六个 target 夹具、给文档任务硬塞命令

- **非目标**：不新增阶段、不建第二份证据账本、不改 `phase_progress` 游标语义，理由是同一事实只留一处原件。
- **改动前**：`run-checks --task-path` 在 11 个声明步一步未判时仍退 0（只有 make-decision 具名缺口退 1）；
