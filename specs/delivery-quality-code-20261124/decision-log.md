## 4. 每包设计

七包均已按 decision-maker 走完调研、设计、人话卡、冷读六问与对抗九问，并经用户逐包确认。每包的完整十一格卡、回传与审查原件在 `quality/evidence/decision-maker/pN/`；这里只留一句摘要与指向。

### 包 P1：规则归属与入口（已确认）
- 一句话结果：同一条“你是谁”的判断只写一次，三个正式命令同结论；查看可跨目录但只认规范位置。
- 对应需求：R-001、R-007、R-014、R-016、R-021。
- 现状缺口：同输入在 stage-runtime 与 task-close 结论相反；身份判定散在三个 CLI。
- 方案：新建 `runtime/task/task-entry-identity.mjs`，按只读/写/创建/收口模式判；openTask 私有路径检查收进模块；施工卡用“动作/文件符号”写规则新家/入口数/调用者。
- 验收：合法/歧义同输入两入口同结论；坏输入具名诊断；写/收口不被放宽；授权维护可用。
- 风险：模式误标会关掉写绑定；旧回执靠保留文案子串。
- 未决：无。

### 包 P2：错误、默认值与接口取舍（已确认）
- 一句话结果：新增默认值说清依据；缺值不悄悄变空串/0/false；空错误处理写损失；审查固定回答默认值、旧路、删层。
- 对应需求：R-002、R-003、R-013、R-017、R-018、R-021。
- 现状缺口：无默认值/空 catch 检查器；简化审查无两问/深度；审查记录无结构结论。
- 方案：两问与接口深度四问进简化审查；新增行检查器只报空 catch 与 `catch return null/false`；删除票唯一落非目标行；类型优先。
- 验收：本次新增默认全部能说谁定；空 catch/return null/false 报一行；每处绕行有票；审查件有深度结论。
- 风险：误报高于真报则撤；删除票由 build-plan 计划期写。
- 未决：无。

### 包 P3：检查记录与开工就绪（已确认）
- 一句话结果：记录自证身份、删不掉、退不回去；旧/无身份只说未取得；开工真读准备条件。
- 对应需求：R-005、R-006、R-013、R-020、R-021、R-022。
- 现状缺口：双层包装认不出声明门；缺身份回退更早绿件；旧件与坏件同判失败；退出码靠中文。
- 方案：认命令写读同源；没有身份=未取得、不回退；结构化失败码；人判只标未验证不阻断。
- 验收：删最新身份失败且证据指该件；无身份记录未取得；早红后同检查绿通过、别的命令绿仍失败；双层包装能绑身份。
- 风险：历史 close 误拒；工作树不在则永久未取得。
- 未决：无。

### 包 P4：方法接线要求（已确认）
- 一句话结果：把“自动作业验到处理段、无权发送由接收侧确认没收到”写进方法；不装后台、不连真实服务。
