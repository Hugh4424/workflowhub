## 这一 Phase 交出什么？

独立末验者交付九条逐项结论和可执行交接，不把首判原件聚合成虚假全绿。

- **本 Phase 结果**：每条验收都有原件、档位、限制、owner 与恢复条件。
- **非目标**：不重跑全量测试，因为 P7 只补首判未闭环的必要 case。
- **改动前**：P1-P6 分别留下首判与局部证据，尚未统一逐条读回。
- **改动后**：九条结论可回读，AC-C06-2/6 保持部分，AC-C06-5 浏览器面保持 unknown。
- **与相邻 Phase 的边界**：P6 交真实纵切与首判；P7 只消费原件和必要复放。
- **主要风险**：把缺件或 provider 失败写成通过；若发生，撤回结论并恢复原缺口。
- **下一步**：主会话按逐项缺口交接，用户只处理独占决定或真实风险。
- **动手前必读**：`spec.md#Appendix A`、P1-P6 的「下一消费者拿什么继续」。
- **未决事实**：`REVIEW_INPUT`、真实服务与视口为 unknown，由对应审查或运行 owner 提供。

- **范围账**：T012 便宜聚合只读核九条；T013 真实段处理终末 OCR 和具名未闭环。

1. **验收标准**：九条均有成功信号、失败信号和证据；非 pass 项不得计为通过。
2. **场景**：正常是原件齐且同判据成立；反向是缺件、旧证据、同源冒独立或 unknown 被洗绿。
3. **环境与数据**：只读当前任务与固定 PaperBuilder 工作树；必要真实输入由原 owner 提供。

5. **谁判**：未参与实现的独立测试、独立审查与终末 OCR，输入为各首判原件和必要复放件。
6. **失败回修与重验**：分诊者先复现，有效问题回原 Phase/Task；修后只复验受影响面。
