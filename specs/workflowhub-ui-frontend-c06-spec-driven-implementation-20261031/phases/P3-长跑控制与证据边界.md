## 这一 Phase 交出什么？

阶段主会话能在无新事实时停扩、回收真实进程组，并保留原始证据。

- **本 Phase 结果**：预算、停止、冻结与证据规则可执行，真实回收有观察原件。
- **非目标**：不新写看门狗、回收器、全任务时长上限或审查重试策略。
- **改动前**：现有捕获能力已有超时、取消和进程组，但执行材料缺统一边界。
- **改动后**：活动预算与停止规则入卡，空心跳不续命，证据先减少重复采集。
- **与相邻 Phase 的边界**：前序已交成本口径，本 Phase 补实现执行控制。
- **主要风险**：把通用停止套到审查提供者；出现时回退该扩写并恢复原方法。
- **下一步**：后续实现者按同一预算和证据边界实施，不另建控制面。
- **动手前必读**：`runtime/interface/run-command.mjs`、现有定向测试与历史回放。
- **未决事实**：宿主真实回收效果待本 Phase 观察；不支持时记 unavailable。
- **未决事实**：至少八十九份预镜像的精确文件名 unknown（51 是旧快照），由独立读者沿历史原件定位。

简化决定是复用现有捕获、任务游标和证据接口，只改方法、模板与定向测试。

## 这一 Phase 怎么验收？

本 Phase 只首判验收 9，最终聚合不在此重复首判。
三笔账如下，分钟都是临时估算，不是执行读数。

- **成本账**：两张卡串行三十五加四十五分钟，共享准备十分钟。
  一次有界环境复跑预留三十分钟，活动执行合计一百二十分钟。
- **资源账**：复用历史回执、现有捕获接口、合同测试与 POSIX 有界子进程。
  独立测试与审查来自不同上下文，宿主提供真实回收能力。
- **范围账**：只证停止、冻结、空心跳、真实回收、游标和证据身份。
  历史业务结果与审查提供者质量只作供件，不在此承接。

七槽如下。

1. **验收标准**：独立读者能判定每个历史停止点，独立测试能观察真实回收。
   成功是超时、同签名、空心跳、冻结、证据身份与进程组判据全部满足。
   失败是空心跳续命、改门禁换绿、另写回收器或删除不同哈希凑份数。
2. **场景**：一万三千二百四十二秒实跑应在一百二十分钟预算前停扩，
   若进入真实命令则按九十分钟超时回收，不把它写成产品质量失败。
   两个同签名存储写阻断无新根因即停；新根因只凭新证据或批准继续。
   空心跳没有阶段、预计完成或新工作事实时，两次无回停轴并回收。
   真实正例启动子与孙进程，超时得 124、取消得 130，进程与延迟副作用消失。
3. **环境与数据**：POSIX 本机、临时记录目录、现有 Node 与真实进程组。
   开发提供方法差异，独立测试提供有界子孙进程，独立读者提供历史回放。
   临时目录只在进程回收后清理由测试删除；回执、读回与证据清单保留。
4. **用例**：用例一回放 030 的 13242 秒 SIGINT/130（人工中断，不是超时）、
   050/060 同签名、074 新根因和审批等待；24 小时轴实测 24.2h/0 次停止，只能作反事实。
   用例二要求未来门禁变更必须被拒；不能把 132→168 已发生并重跑说成“被拒绝”。
   用例三跑现有捕获基线并补真实子孙回收，记录退出、信号与副作用；至少一项真实 124 才可判 pass。
   用例四识别至少 89 份预镜像（研究时 51；当前 89 份/89 哈希/3.41GB；83 份>35MB、54 份 37.9–42.9MB；“76 份同型”未复现）。
   新规则先减少重复采集；同哈希一份并保留全部 provenance，51 不是当前分母。
5. **谁判**：独立测试判真实进程与合同，独立审查判冻结和证据语义。
   时点为开发期目标测试完成并明确就绪后；审查与测试可并行，修复后受影响方重报。输入为真实差异、回执与历史原件。
6. **失败回修与重验**：方法合同失败回本 Phase 开发，环境失败回宿主提供者。
   修后只重跑受影响合同和一次有界回收，由原独立判定者按新原件重报。
7. **承接**：首判结论和缺口进本 Phase 完成字段与计划证据路径。
   无回收能力记 unavailable，最终验收不得以规则文本替代真实观察。

**效果判据**：独立测试在真实超时和取消后无法再观察到子孙进程或延迟写入。
独立审查能指出至少八十九个不同哈希为何不能去重减量，并核出来源链未丢。
空心跳只经方法回放判定，不为它制造运行时 RED。

- **与其它 Phase 的区别**：本 Phase 交实现执行控制，不交步骤卡或成本模板。
- **依据**：决策日志「工作包 9」与「方向审查后的调整」。
- **依据**：规格「有界执行与真实进程回收」及验收 9 的唯一判据。

## 怎么验证？

本 Phase 开发期目标测试完成并明确就绪后，依唯一七步顺序派审查与测试，可并行；按 P3 的执行协议按可独立并行的验收面派测试代理；有两个以上各自 oracle 的面时至少两个，不足两个时一个并写明理由；
代理不共享写文件，主会话合并结果，冲突保留；普通测试失败和代理冲突不问人，只有 AC/范围、
缺外部原件/凭证或不可逆动作才停。
