## 这一 Phase 交出什么？

阶段主会话只读当前步和必要前置，旧文件不再冒充当前证据。

- **本 Phase 结果**：三个主阶段能按当前步卡执行，显式跳过留下可收口缺口。
- **非目标**：不接通用退出门，不新建步骤账本，不覆盖构建需求阶段。
- **改动前**：检查器展开全步骤，重复表与通用目录留痕掩盖当前步身份。
- **改动后**：卡只给当前步、最多三个路径和具名证据，缺口由收口消费。
- **与相邻 Phase 的边界**：本 Phase 先交步骤与材料合同，后续成本作者在其上补预算。
- **主要风险**：跳步记录变成第二状态机；若出现则退回普通任务原件与现有行。
- **下一步**：成本作者复用同一步骤合同补逐条成本与 Phase 总账。
- **动手前必读**：`spec.md#实现设计全局权威`、`tools/cli/check-stage-steps.mjs`。
- **未决事实**：运行编号来源 unknown；由阶段主会话提供，未提供时用已核 Phase 或提交身份。

精简采用最小路径：复用步骤表、任务原件接口和现有收口，不新增协调状态。

## 这一 Phase 怎么验收？

本 Phase 只首判验收 7，最终聚合不在此重复首判。
三笔账如下，分钟都是临时估算，不是执行读数。

- **成本账**：两张卡串行四十五加二十五分钟，共享准备二十分钟。
  一次受影响重验预留三十分钟，活动执行合计一百二十分钟。
- **资源账**：复用现有步骤表、检查器、合同测试和指定历史材料。
  独立测试与审查来自不同上下文，不新造步骤样本或运行服务。
- **范围账**：只证当前卡、旧证据负例、跳过收口、精简与基线。
  最终验收和其它阶段交付只作供件，不在此承接。

七槽如下。

1. **验收标准**：独立读者仅凭当前卡即可执行指定步骤并指出证据与停止条件。
   成功是当前步、入口、停止、最多三个路径、证据、自查和答复要求齐全。
   失败是仍显示全步骤、旧证据被接受、无具名跳过或缺口被写成完成。
2. **场景**：正例回放决定阶段的第 5、6、8 步，只读当前步与前置。
   反例一放入旧运行同字节文件，预期不认定为当前证据。
   反例二显式跳过但保留原因、负责人和恢复条件，检查器仍退出 0。
   收口读到该未清缺口时必须记未完成，不能写完成。
3. **环境与数据**：本机 Node、临时任务夹具和真实三阶段步骤表。
   开发提供实现，独立测试提供受控旧证据与跳过夹具。
   临时目录由测试在结束时清理；命令回执和读回原件全部保留。
4. **用例**：用例一核当前卡及第 5、6、8 步投影。
   用例二核按步只判本步与前置，并拒绝旧运行同字节。
   用例三核跳过有完整缺口、检查器退出 0、收口记未完成。
   用例四核重复表删除、七个具名证据和只建基线不宣称降幅。
5. **谁判**：独立测试跑合同，独立审查按指定材料复读，均异于开发上下文。
   时点为开发完成且审查发现修完后；输入为真实差异、命令原件与回放件。
6. **失败回修与重验**：目标断言失败回本 Phase 开发，环境失败回环境提供者。
   修后只重跑受影响合同与指定回放，由原独立判定者按新原件重报。
7. **承接**：首判结论和缺口进本 Phase 完成字段与计划证据路径。
   最终验收者只读这些原件，不能以本卡预先填写的档位代替首判。

**效果判据**：未参与实现的读者只拿当前卡，能指出第 6 步首动作、
最多三个读取位置、原证据和停止恢复；需要翻全阶段材料才能回答即失败。
阅读路径、字节、跳步、返工与 Phase 时长只形成基线，不承诺改善比例。

`acceptance_cost_total=45+25+20+30=120 active_min`。
`phase_budget={soft_min:120,hard_min:240,variance_threshold:1.5,source:provisional}`。
实现执行另记 `execution_budget={window_minutes:120,command_cap:50,wait_cap:30,retry_reserve:30}`，不与验收成本混算。
常规用户等待为 0；审查提供者等待单列，不计活动执行也不套通用等待上限。

同一合同命令先让新增目标断言失败，再用同一断言验通过。

| 材料精简与阅读基线 | T002 | GREEN | 同命令退出 0 | ORACLE-P1-BASELINE；`quality/tests/P1-T002-green.output` |

覆盖上限：只证三个主阶段的步骤投影和指定回放。
显式不覆盖：构建需求阶段、真实用户长期节约、跨阶段全部语义完成。

- **风险**：目录内旧文件仍被当作本步证据，或跳过记录形成新状态机。
- **影响**：主会话跳步、旧证据假绿，后续成本和停止判断失去当前身份。
- **缓解**：逐步锚、当前 Phase 或提交身份、旧运行负例和收口负例同时保留。
- **回滚**：原开发只撤本卡相关 hunk，保留其它改动、原输入和失败原件。
- **补救与交接**：接口不符回检查器 owner；任务记录失败回任务接口 owner。
- **触发条件**：退出语义改变、卡显示全步骤、无缺口自动前进或旧证据被接受。

完成判据要求独立合同、指定回放、材料差异和审查原件齐全。
只交基线或未执行独立读回时，验收 7 保持未完成。

## 下一消费者拿什么继续？

成本作者取得当前步骤合同、共享文件状态和缺口消费方式。
后续主会话取得当前卡与按步证据，不取整份历史目录作完成证明。

- 交回检查器与合同测试当前字节、三阶段材料差异及指定回放原件。
- 交回阅读路径、字节、跳步、返工和 Phase 时长基线，不给改善结论。
- 未清跳过逐项带原因、负责人和恢复条件，阶段收口不得写成完成。
