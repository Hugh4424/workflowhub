## 这一 Phase 交出什么？

维护者获得一套可执行的触发、就绪与实现方法，P5 能把随包参考登记进 bundle。

- **本 Phase 结果**：独立读者用三个受控样例能作出触发、补充或停止决定。
- **非目标**：不写 PaperBuilder 规范或代码，因为真实纵切由 P6 在同一工作树完成。
- **改动前**：现有方法有组件质量地图，但缺少统一的就绪短表和四种处置。
- **改动后**：计划与实施共用短表；缺口有来源、补法、知会者、消费者和去向。
- **与相邻 Phase 的边界**：P4 交方法；P5 登记参考；P6 首判真实任务。
- **主要风险**：短表退化为打勾；若独立读者不能决定，缩回缺失来源与首改例。
- **下一步**：P5 将新增参考列入打包清单，P6 在真实页面先写就绪记录。
- **动手前必读**：`spec.md#实现设计（全局权威）`；`decision-log.md#五道判断对账`。
- **未决事实**：真实 PaperBuilder 分支尚未形成；P6 创建后记录，不影响本方法交付。

简化选择是复用现有组件质量方法，只新增一个被其直接消费的参考文件。
本 Phase 不新增技能、检查器、流程节点、持久状态或第二规范权威。

## 这一 Phase 怎么验收？

本 Phase 只供验收 1 的方法输入，不代替 P6 的真实差异首判。
即使结构检查通过，缺独立消费仍不能证明方法有效。

三笔账如下，均为 provisional；活动执行不包含任何提供者等待。

`acceptance_cost_total=30+0+0+0=30` 活动执行分钟（串行+并行最大+共享准备+复验预留）。
`phase_budget={soft_min:120,hard_min:240,variance_threshold:1.5,source:"D-027/D-032 provisional"}`。
用户等待与 provider 等待分别单列，本 Phase 预计均为 0，不计入活动执行。

- **成本账**：实施者与独立读者共 30 分钟；软上限 120、硬上限 240 分钟。
- **资源账**：现有 WorkflowHub 方法、PaperBuilder HEAD 只读事实和三个受控样例。
- **范围账**：只证方法可供 P6 消费；真实页面、规范补充与四维结论属于 P6。

1. **验收标准**：独立读者对缺规范、规范齐、纯后端三样例均能给出有依据的处置。
   成功是每项来源、消费者和恢复条件可定位；失败是猜测、无消费者或把未找到当不存在。
2. **场景**：缺时区规范时应补最小条款；规范齐时可继续；纯后端应记不适用及理由。
   反向样例缺少关键设计值时只能停受影响路径，不能编造取值继续。
3. **环境与数据**：只读当前仓库和 PaperBuilder 提交 `5bdf6f0b` 的源码事实。
   样例由方法作者给出完整输入，独立读者不另找答案；所有读回原件保留在任务质量目录。
4. **用例**：CASE-P4-1 缺规范应得 `supplement`；CASE-P4-2 规范齐应得 `proceed`。
   CASE-P4-3 纯后端应得 `N/A` 与理由；CASE-P4-4 缺关键设计值应得 `stop-affected`。
   判定方式为只能人读，结构命令只作前置。
5. **谁判**：未参与写作的独立读者在方法完成后判定。
   输入是四个方法文件、三个完整样例和本卡观察协议；不需要用户本人到场。
6. **失败回修与重验**：读者指出缺来源或无法决定时回 P4 方法作者修。
   修后只复读失败样例及其邻接条款，原读者重报；不改四种处置或验收含义求绿。
7. **承接**：计划由现有 capture 存 `quality/tests/P4-T007-readback.md`；当前未生成，缺口保持 incomplete。
   P5 读取参考文件与打包责任，P6 读取同一短表和失败恢复条件。

### 三个完整受控样例是什么？

完整输入唯一保存在 [前端实现就绪参考的「受控样例」](../../../skills/frontend-component-quality/references/implementation-readiness.md#受控样例)，按以下具名段落逐项读回：

- 「样例一：时区条款可推导，应先补再实现」：缺规范，预期 `supplement`。
- 「样例二：同一差异输入齐全，可直接实现」：规范齐，预期 `proceed`；同时读取它明确沿用的样例一输入。
- 「样例三：纯后端差异，不建立前端就绪记录」：预期 `N/A` 和理由。
- 「负例：缺关键设计值」：预期 `stop-affected`。
- 「数据判断样例」：逐项读回缺数据、只能采样、必须全量的输入与恢复条件。

独立读者实际输入是上述引用原文、样例明确引用的来源、四个方法文件和本卡观察协议；
按样例逐项列出的来源判断，不从实现答案或预期标签反推规范。各样例中的模拟批准、数据及条款状态仅是受控前提，不是用户真实答复、真实项目批准或已执行测试。
独立读者必须重新执行引用样例及受影响的邻接条款；原失败与原读回保留，不能因更换引用而改写为通过。
