## 这一 Phase 交出什么？

维护者获得三个固定外部包的完整本地规则闭包，以及可验证的现有打包读取路径。

- **本 Phase 结果**：85 个上游 payload 与三个 UPSTREAM 可逐文件核对，resolver 能读回规则。
- **非目标**：不复制其余五个无当前触发条件的包，因为完整闭包不等于数量凑齐。
- **改动前**：Vercel 只有 21 行派生摘要，web 与 better-ui 没有完整固定闭包。
- **改动后**：76 个 Vercel 文件、一个 web 规则体和八个 better-ui 文件均可按需读取。
- **与相邻 Phase 的边界**：P4 交参考文件，P5 登记它和三包；P6/P7 只消费原件。
- **主要风险**：把摘要、旧镜像或许可声明当完整闭包；若发生，退回固定清单逐项重核。
- **下一步**：P6 使用适用规则，P7 对验收 2 只读末验并保持部分结论。
- **动手前必读**：`quality/evidence/2026-11-01-006-wp5-fixed-pin-inventory.json`。
- **未决事实**：上游独立 LICENSE 与历史路径裁决未闭环，owner 分别是项目所有者和 ADR0016 owner。

简化选择是沿用现有组件质量技能的 upstream 与 resolver。
本 Phase 不新增打包器、第二登记权威、后台更新器或许可证文件。

## 这一 Phase 怎么验收？

本 Phase 首判验收 2 的工程闭包，整体最高只记“部分”。
即使全部机器断言通过，权利与历史路径缺口也不能被洗成完整通过。

三笔账如下，均为 provisional；活动执行不包含外部服务等待。

- **成本账**：T008 60 分钟、T009 30 分钟，共享准备 0，受影响复验预留 30 分钟。
- **资源账**：三个固定 codeload 归档、inventory、现有 upstream、bundle 与 resolver。
- **范围账**：只证固定字节、来源登记和现有打包读取；正式发布包与权利合规不在内。

`acceptance_cost_total=60+30+0+30=120` 活动执行分钟。
`phase_budget={soft_min:120,hard_min:240,variance_threshold:1.5,source:"D-027/D-032 provisional"}`。
活动执行合计 90 分钟，加复验预留后为 120 分钟。
用户等待与 provider 等待分别单列，本 Phase 预计均为 0，不计入活动执行。

1. **验收标准**：三包数量、逐文件 SHA、固定提交、UPSTREAM 和 bundle 闭包全部相符。
   成功还包括 resolver 按需读回一条规则；失败包括摘要冒完整源、缺哈希或读取失败。
2. **场景**：正常场景从固定归档导入并读回规则，负控只给 21 行摘要或删掉一个 payload。
   负控必须被同一闭包断言拒绝，许可未知不得使机器闭包被写成权利合规。
3. **环境与数据**：固定归档只读进内存，不执行远端脚本、不安装上游依赖。
   临时归档在逐文件核对与读回后由实施者删除，删前记录哈希；inventory 与执行原件保留。
4. **用例**：CASE-P5-1 用 `node --test --test-name-pattern=ORACLE-P5-CLOSURE tests/contract/ui-skill-contract.test.mjs`。
   CASE-P5-2 用同文件 `-t ORACLE-P5-BUNDLE`，CASE-P5-3 删除临时闭包一项作负控。
   判定方式为机器可判与只能人读；人读核许可偏差和其余外包处置。
5. **谁判**：未参与导入的独立测试运行两组断言，独立审查者读偏差记录。
   输入包括 inventory、最终写集、UPSTREAM、原始 JSON、resolver 输出与负控原件。
6. **失败回修与重验**：闭包差异回 P5 导入者，登记或读取差异回 P5 登记者。
   修后只重跑受影响 oracle 和负控；原失败与旧断言变更审查保留。
7. **承接**：首判与限制存 `quality/tests/P5-T008-*`、`quality/tests/P5-T009-*`。
   P7 读取这些原件，整体仍按规格记部分，不重新全量导入。
