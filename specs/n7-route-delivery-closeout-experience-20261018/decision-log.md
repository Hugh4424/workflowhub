## 工作包与决定

本节回答要交付什么、为何这样做以及失败后由谁处理。本节 ADR 编号是**任务内编号**，与 `docs/adr/` 的正式 ADR 是两套体系，不互相占用。

### 工作包 ① — 五件各归一处

- **要交付什么**：领域词表、工作区与任务、交接、收口与关闭、交付说明与 PR 五件，每件只有一处正文，五个阶段只放指针与必要调用；来源 R-001；消费者是阶段执行者与下游材料作者。

#### D-003 — 五件按"一处正文 + 指针"整理，不合并成一份总纲

- **做什么**：五件各保留当前已有的方法文件作为正文位置（领域在领域方法与其格式附件、交接在交接方法、关闭在关闭方法、交付说明在关闭方法、工作区与任务在标准工作方法），其余位置只留指针与调用条件。
  - 判定"正文位置"的标准：该处写明做什么、边界、失败边界；别处只写何时调用与读哪一节。
- **不做什么**：不把五件合并成一份大文件；总纲只做索引（D-018），不承载第二份规则；不改各件的既有 owner 与写入权威；除 D-018 批准的那份索引外不新增文档。
- **风险**：指针化可能让执行者少读必要上下文；每处指针必须写清"读哪一节、什么时候读"，并在验收里用真实执行者读回核对。
- **改动**：主要落点是各方法文件与五个阶段正文（见「要改哪些文件」）；唯一写主为本任务 build-code 的实施会话，按文件逐份申报；新增文档仅限 D-018。

#### D-004 — 领域词表只留一处规则，删重复复述；不动技能登记

- **做什么**：把领域方法的正文复述收敛为对唯一格式附件的指针，保留"只收领域词、就地更新、边界变化才写"的规则语义。
  - 登记文件（技能清单）只保留登记与描述字段，不再承载领域规则正文；本次不删登记里的描述文字。
- **不做什么**：不改技能清单的登记结构与已有测试断言的字段；不把领域规则搬进新的术语账本。
- **风险**：删除复述可能丢掉只在复述里出现的条件；删前逐条比对，只在两处语义完全等价时删，否则保留并标注差异。
- **改动**：`skills/grill-with-docs/SKILL.md`（领域段收敛为指针）、`skills/grill-with-docs/GLOSSARY-FORMAT.md`（补必要判据）、`docs/standard-workflow.md`（领域入口指针）。写主：本任务实施会话。

#### D-005 — 给"工作区与任务"补一处文字权威

- **做什么**：在标准工作方法新增一节，写清任务如何建（任务 id 决定工作区路径与任务分支名）、写集如何申报、收尾时工作区与任务分支如何按默认安全收口处理；术语表补三个词：工作区、任务分支、业务仓。其它位置（AGENTS 治理段）只留指针。
- **不做什么**：不改任务创建与关闭的实现代码；不新建契约文档、不改目录职责表（避免新增文件与登记）。
- **风险**：文字权威与实现不一致会误导；写完用真实入口（创建与关闭的真实命令与返回值）核对措辞，发现不一致以实现为准并记录。
- **改动**：`docs/standard-workflow.md`（新增一节）、`GLOSSARY.md`（三个术语）、`AGENTS.md`（一行指针）。写主：本任务实施会话。

#### D-018 — 新建一份《交付与收口总纲》，只做入口与边界索引

- **做什么**：新建一份独立文档，把五件的"唯一正文位置、何时读哪一节、失败与授权边界在哪找"集中成索引；各方法正文不动，总纲不承载第二份规则。
  - 读者是阶段执行者与外部接手者：先在总纲找到该读哪一节，再进对应方法正文。

### 工作包 ② — 每阶段收口

- **要交付什么**：五个阶段的结束动作统一为"主会话发起收口"，交接是其中一步；产物可以是具名"本次无问题"；失败与取消如实。来源 R-002、R-003、R-012；消费者是阶段执行者与下游会话。

#### ADR-002 — 五件统一不等于把关闭铺到五个阶段

- **做什么**：把"五件各归一处"限定为每件一处正文 + 阶段指针；关闭（提交、PR、合并、推送、归档、清理）仍只在现有的规划收尾与终末验证两个适用阶段触发，不因为统一就铺到每个阶段。
- **不做什么**：不在每个阶段都调用关闭；不新增关闭入口或第二套关闭流程。
- **风险**：读者看到"统一"会以为五件在所有阶段都执行；总纲与各方法要用"适用阶段"一列写清哪些阶段真的调用，避免误读。现有接线有契约测试盯着，扩面会直接红。
- **改动**：`docs/delivery-closeout-charter.md`（五件的适用阶段列）、`skills/catalog.yaml`（调用关系保持真实）、`docs/standard-workflow.md`（关闭段改指针）。写主：本任务实施会话。

#### D-006 — 复盘方法升级为真正的收口主体，交接成为其内部一步

- **做什么**：把"可选复盘"改为"每个阶段结束时由主会话发起收口"。五条路线的末步统一改名为"收口"（步骤标识与正文同时改），交接成为收口内部的发布动作，不再是独立末步；步数不变，规划阶段的"计划确认"写进该末步内容，确认后才发布交接。
  - 收口内部顺序固定：归纳已做/问题/经验 → 分类与归口 → **记录阶段成本** → 发布交接并读回 → 报告结果。
  - 允许产物是"本次无问题 + 具名依据"；已退役的旧 JSON 复盘产物与其守卫保持不复活。
  - 收口仍只产出事实与人读交接，不阻断推进、不产生质量结论、不成为关闭许可。
- **不做什么**：不新增阶段、门、评分器或进度对象；不恢复旧自动执行器；不改关闭只挂两个阶段的现状（见 ADR-002）。
- **风险**：末步改名会撞钉死测试（步数与末步名）；措辞统一可能把"无问题"写成空话。缓解：同批更新测试并保原保护（D-013）；验收要求"无问题"必须带具名依据，空话按未完成处理。
- **改动**：`skills/stage-reflection/SKILL.md`、`skills/stage-handoff/SKILL.md`、五个 `workflows/*/SKILL.md` 与 `workflows/*/steps.json`、`skills/catalog.yaml` 的调用关系。写主：本任务实施会话；五个 stages.json 逐个申报。

#### D-007 — 收口的失败、取消与无发现用同一措辞

- **做什么**：收口产物用同一个模板，但四类的**必备要素不同、不能互相替代**：本次无发现必含具名依据（只写在交接正文一处，不另在阶段事实重复）；本次有发现但未采纳必含原候选与理由；失败必含原始命令、退出与原件；取消必含已发生部分与未做部分及中断原因。
  - 四类都不写"已完成"；失败与取消不得被读成"本次无问题"；unknown/unavailable 不得写成完成。
  - 顺序固定沿用 D-006：归纳已做/问题/经验 → 分类与归口 → **记录阶段成本** → 发布并读回交接 → 报告结果。
- **不做什么**：不把"无发现"写成"已完成"；不新增状态字段。
- **风险**：措辞统一后仍可能被当成完成声明；验收用真实负例（真实失败一次、真实取消一次）核对读回。
- **改动**：`skills/stage-reflection/SKILL.md`、`skills/stage-handoff/SKILL.md` 的对应段。写主：本任务实施会话。

### 工作包 ③ — 交接里给用户看的部分

#### D-008 — 动作项只留用户能做的决定（采用 ketchup 机制）

- **做什么**：交接的动作项限定为三类加一类：需要用户做的决定、需要用户给的授权、不可逆动作，以及只有用户能提供的信息或凭证；每条给推荐、理由与"不答会怎样"；不知道就写 `unknown`；只链真实存在的产物；代理自己还能做的不进动作项；同一事实不在正文与视觉各说一次。
  - 未答就是保持未决、继续等待真实回复；推荐只在用户答复后才执行，不把沉默当同意、不替用户选。
- **不做什么**：不搬上游的字数上限、视觉规格与固定框数；不加必填字段或机器校验。
- **风险**：标准变严后动作项变少，真实缺口可能被漏报；验收要求"该问用户的必须出现、不该问的不出现"两类负例各一。
- **改动**：`skills/stage-handoff/SKILL.md`（下一步动作与边界两段）、`AGENTS.md`（一行判据）。写主：本任务实施会话。

#### D-009 — 交接补"故意没改 / 潜在风险"的写集说明（采用 Change Summary）

- **做什么**：交接的"核心方案"段补一行写集说明：本次改了什么、**故意没改什么及理由**、**潜在风险与影响面**；写集与真实 diff 的差异要能被独立读者看懂。分工：交接写人读结论，独立审查做逐条比对；两者不一致时以真实 diff 为准并在审查处置里写明。
- **不做什么**：不要求把完整 diff 贴进交接；不搬原子提交与提交信息格式；不新建校验器。
- **风险**：与现有"写集申报 + 独立审查比对"重复；两者分工是：交接给人读结论，审查比对给逐条核对。重复处按 D-015 收一处。
- **改动**：`skills/stage-handoff/SKILL.md`、`AGENTS.md`（写集说明段一句）。写主：本任务实施会话。

### 工作包 ④ — 业务仓经验

- **要交付什么**：经验文件在业务仓真实产生、可追加、可读回、可被后继任务消费，且不越过授权。来源 R-004、R-005、R-006、R-013、R-014；消费者是业务仓维护者与后继任务执行者。

#### ADR-001 — 经验文件的位置与性质：业务仓 `specs/Improvements.md`，经验与待办合一

- **做什么**：经验文件的唯一位置改为「业务仓根下 `specs/Improvements.md`」；一个文件同时承载"下次能改变行动的经验"和"仍需用户决定的未解待办"；本仓现有仓根文件迁入 `specs/`，两个业务仓用同一相对位置。
- **不做什么**：不在仓根保留第二份；不拆成经验与待办两个文件；不新建账本或机器可读状态。
- **风险**：与旧决定（D-012 旧：业务仓根）不同，漏改引用会出现两处位置；迁移时若某仓 `specs/` 目录不存在需先确认可建。
  - 迁移口径（用户选择）：旧文件既有内容搬到新位置，仓根旧文件**直接删除**，不留"已迁移"占位；所有指向旧路径的文字与引用同批改到新位置，漏改即失败。迁移后读回新文件确认内容完整；迁移期间若旧文件被他人改写，保留双方并报告，不覆盖。
  - 风险补充：直接删掉旧路径等于切断旧链接，任何没被搜到的引用都会断；因此迁移前先全仓搜一遍旧路径，把命中列表作为迁移清单，改完再搜一遍确认 0 命中。
- **改动**：`specs/Improvements.md`（本仓，迁移自根文件）、`skills/stage-reflection/SKILL.md`（位置与性质）、`Improvements.md`（本仓根，迁出）、论文仓 `specs/Improvements.md`（新建）。写主：本任务实施会话；论文仓写入逐份申报。

#### D-010 — 经验写入的完整动作：创建、追加、去重、读回、越权记不可用

- **做什么**：
  - 文件不存在时创建；存在时追加，保留旧内容与他人条目，不覆盖。只声称现有安全写入能保证的范围，不新增并发合同或读写器。
  - 写前读回目标文件；若文件在此期间被改动或出现无法归属的内容，保留双方字节并报告，不覆盖、不猜测合并。
  - 写入时机：每个阶段真有可落账的经验就写，不攒到任务收尾。
  - 同一事实不重复记：判据是"**下次要改的那一步 + 现象**"相同，不看来源；重复出现时只追加一行引用，不复制正文。
  - 文件结构：按**业务仓自己的模块**分节，每节一张小表（问题／下次改变的行动／状态）；不设类型列；文件头只放一行指向写作规则的指针。
  - 写完读回，报告实际路径与读回结果；写入失败保留原始错误。
  - 越界或未授权时记 `unavailable` 与原因，不写回工具仓、不扩展范围。
  - 后继任务按真实问题读取相关条目；读取是默认动作、不是判断题（有相关条目就给出，无可用项就写具名理由，不把"没找到"当"没有"）；只有用户明确确认已解决后才清理。
- **不做什么**：不自动清理历史条目、不按时间去重、不写机器状态文件、不在关闭链里新增写手。
- **风险**：去重靠人工判定可能误合；同一事实判定不确定时保留两条并在条目里互相引用，不猜合并。写入目标仓权限不足时成功场景保"未完成"。
- **改动**：`skills/stage-reflection/SKILL.md`（写入方法）、`specs/Improvements.md`（条目形状说明）。写主：本任务实施会话；两个业务仓的写入在验证阶段真实执行。

#### D-012 — 经验条目的质量判据（采用 reflect 筛选与 recall 状态词表）

- **做什么**：条目最小形状（小表三列，按模块分节后不再设类型列）＝问题 / **下次遇到什么情况会改变行动** / 状态（已落账、待用户决定、已解决（用户确认）、unknown）；能被结构或确定性断言消除的错误直接进检查、不进经验队列（结构优先筛选器）；"需要用户批准"的等批准、"可立即落账"的直接写（批准与落账分开）；条目只用普通文字，不新增机器标签。
  - 来源（仓、任务、阶段）仍要能定位，但**不作为判重键**，写在问题句的来源括号或状态里；缺来源写 unknown 而不是省略；未答的条目保持"未决"，不得写成已采纳。
  - 写作规则（按简明语言标准的核心思想，写在收口方法一处）：一条一句、结论先行、同一词同一义、不重复同一意思、不堆形容词；读者要能找到（按模块分节）、能懂（短句与一致术语）、能用（每条给可执行动作）。
  - 说不清"下次怎么改变行动"的条目不收，宁可写"本次无发现 + 依据"；闭合状态用文字说明，没写清楚就是没做完。
- **不做什么**：不固定三路评审、不逐行批准、不建固定表格与归档 tracker；不用条目数量当质量。
- **风险**：判据偏严会导致条目很少；这与"不凑数"一致，但要在验收里证明真实条目确实改变了后继行动。
- **改动**：`skills/stage-reflection/SKILL.md`（判据段）、`specs/Improvements.md`（形状说明）。写主：本任务实施会话。

### 工作包 ⑤ — 交付说明与 PR

- **要交付什么**：交付说明有一处正文权威，含范围（含故意不做）、影响面（含已知红的代价）、验证（真跑结果）；PR 动作仍只在原授权点触发。来源 R-001、R-009；消费者是交付读者与审阅者。

#### D-011 — 交付说明正文收敛到关闭方法，补 Scope／影响面／验证三段

- **做什么**：交付说明的内容合同落在关闭方法一处（何时生成、三段各写什么、多长不给硬限）；实施阶段只写一句事实："本阶段不生成交付说明；交付说明在真正执行关闭的阶段（目前是规划收尾与终末验证）生成；本阶段只备 Evidence 与真实 diff 事实"，不指向未挂在该阶段的技能。补三段：范围（必须写"故意不做什么"）、影响面（含已知红的代价：列出与本卡相关的条目，并明说其余不在本卡范围）、验证（每条一条真实路径与结果）。
  - PR 创建、推送与合并仍只在关闭方法与其既有授权点触发，本卡不新增触发点。
- **不做什么**：不搬强制 ready、提交信息格式、六段固定模板；不把 PR 创建提前到实施阶段；不绕过授权。
- **风险**：正文搬到关闭方法后，实施阶段可能不再写描述；用真实一次交付（本任务自己的 PR 说明）核对三段可读。
- **改动**：`skills/stage-closeout/SKILL.md`（内容合同）、`workflows/build-code/SKILL.md`（改为事实说明）、`docs/standard-workflow.md`（一行指针）。写主：本任务实施会话。
- **交付方式**：本任务自己的交付**真实走一次 PR**（用户选择），按真实授权范围执行 push 与 PR，合并与清理仍在最终确认后；不因本卡是文字改造而用受控样本替代。

### 工作包 ⑥ — 字面统一、测试保全与减法

- **要交付什么**：被钉死的测试同批更新且保护不减弱；修掉悬空验收；重复正文合并后字节不增。来源 R-007、R-010、R-012；消费者是后续维护者与独立审查者。

#### D-013 — 钉死测试同批更新，保护强度不下调

- **做什么**：凡因本卡文字/接线变化而失败的契约测试，同批更新为新的真实事实；**只改被真实事实改变的那部分断言**（末步名、步数、接线集合、引用集合、逐字措辞），其余断言保持原强度；每条改动写清原断言保护的是什么。
  - 预期受影响：关闭技能的契约、两阶段接线断言、规划阶段的收口边界断言、复盘入口守卫、历史条目读取、步数/末步名、技能搬运样本。
- **不做什么**：不删除测试、不把断言改弱（如把"恰为两个阶段"改成"包含"），不为凑绿改被测行为。
- **风险**：更新测试时最容易顺手放松断言；每条改动要在同一个 Phase 里有前后对照说明。
- **改动**：`tests/contract/stage-closeout-skill.test.mjs`、`tests/contract/knowledge-graph-stage-wiring.test.mjs`、`tests/contract/build-prd-review-contract.test.mjs`、`tests/contract/stage-runtime-reflect-entry.test.mjs`、`tests/contract/lessons-jsonl.test.mjs`、`tests/integration/main-agent-cost-closeout.node-test.mjs`、`tests/n2-skill-catalog-portability.test.mjs`。写主：本任务实施会话。

#### D-014 — 修掉指向不存在文件的验收引用

- **做什么**：先核实该引用指向的文件确实不存在（全库查找 0 命中，已确认）。然后把引用改为指向真实存在、且真正验证收口行为的测试；若确实找不到等价测试，就把该条断言改成能核对的事实（例如"收口读回原件存在且内容对得上"）；两者都做不到时，明确记"未覆盖"并写缺口，不让脚本以"通过"的形式呈现。
- **不做什么**：不为了"让引用命中"造一个假测试，也不补一个只为满足引用而写的端到端测试；不改验收脚本的其它判定逻辑。
- **风险**：可能既没有等价测试、也无法改成可核对事实；那就如实留缺口并在验收面标"未覆盖"，不用占位冒通过。
- **改动**：`tests/acceptance/card-03-current.mjs`（引用与说明）。写主：本任务实施会话。

#### D-015 — 减法核算：重复正文收一处，字节不增

- **做什么**：把重复正文合并到唯一位置：总纲里的关闭长段改为指针、五个阶段对交接的重述改指针、领域规则复述收敛；合并前后按方法文件与常驻必读字节记账，给出前后数字，结果须持平或下降（不增即合格）。

- **风险**：减字最容易减掉的正是失败与授权边界；每删一处，先确认该条件在唯一正文位置仍然完整。
- **改动**：`docs/standard-workflow.md`、五个 `workflows/*/SKILL.md`、`skills/grill-with-docs/SKILL.md`、`skills/stage-reflection/SKILL.md`。写主：本任务实施会话。
