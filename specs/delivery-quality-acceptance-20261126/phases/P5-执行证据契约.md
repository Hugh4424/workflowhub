### 四态与诊断子类（AC-05 的判据面）

保留现名，只把实现体与参数扩开；**不新增字段**、不改四类名、不加第五类。

```js
export function checkEvidencePath(token, roots, taskRecordRoot, binding = Object.freeze({}))
// binding = { declared_sha256?: string, facts_sha256?: string[] }（都可缺）
// → Object.freeze({ status, resolved? , reason? })   // resolved 只在 verified；reason 只在非 verified
```

| 状态 | 判定含义 | `reason` |
| --- | --- | --- |
| `verified` | 读到字节，且至少一条「本次锚」与字节哈希相符 | 无（可带既有 `resolution_source`） |
| `missing` | 路径不存在、不是普通文件、或所有声明根下都找不到 | 今天的文案：errno、`not a regular file`、`not found under any declared root` |
| `unverified` | 读不出、读到了但没有本次锚、或形状不是一个可打开路径 | 首词之一：`unreadable:`／`content-mismatch:`／`no-run-binding:`／`not-single-path:` |
| `planned` | 声明为 `planned:` | `declared planned` |

判定顺序（**顺序本身是判据，实现不得换序**）：
① `planned` 声明 → `planned`；
② token 含 `{`／`}`／`*`／`?` → `unverified` + `not-single-path:`（不读字节）；
③ 解析：绝对路径直读；相对路径按 `roots` **逐个扫完**（遇目录、设备、断链这类非普通文件不短路，继续找后续根）；再按 `taskEvidenceRoot`（仅 `quality/` 前缀、realpath containment）取任务根候选；
④ 扫完仍未命中 → `missing`（绝对路径用 errno／`not a regular file`；相对路径用 `not found under any declared root`）；
⑤ **命中普通文件就立刻读字节**（`readFileSync`）：读失败 → `unverified` + `unreadable: <code>`。不保留「无锚不读」的捷径，否则无锚的打不开文件会落成 `no-run-binding`；
⑥ 读到了但两条锚都缺 → `unverified` + `no-run-binding:`；
⑦ 有锚：哈希与声明锚或任一 facts 锚相等 → `verified`；都不等 → `unverified` + `content-mismatch: 声明 <hex8>… 实际 <hex8>…`。

两条锚（第三条「提交绑定」已否，理由记「写集冲突与缺口」）：①声明里的 `@sha256=<64hex>` 与本次字节哈希相符；②路径等于当前任务 facts 的 `quality_evidence` 条目 `ref`／`receipt_ref` 且字节哈希等于该条 `sha256`（`task_record_root/facts.jsonl`，缺文件即空表、不报错）。
两条都只回答「这份文件是不是这一次的」，**不回答内容是否回答了原问题**；后者归内容判读、独立审查与 P7。
