## 具名 findings 与待证边界

1. **F-SEM-01（范围修饰丢失风险）**：U-002-23/24 的父句限定「在 make-decision 的过程中和我一起」。当前 atom 只剩「实现方案」「验收标准」；R-027 及后续 spec/Phase 能指到实现设计和 AC，却未给出这两项在 make-decision 与用户共同讨论的专属正反 oracle。应在 P2 的对应交互/decision-log Task 增加阶段、参与者和失败判据；不能由 P1 的 spec 文档存在代偿。
2. **F-SEM-02（过程义务不等于产品 FR）**：U-002-17/18 在 D-028 被明确限定为本卡行为纪律、通用机制交 CARD-03；当前本卡没有 FR/AC/P/T 全链。P4 的统一“每条来源必须映射 FR/AC”若不区分过程义务，会造成假漏报；若仅靠 D-028 的「已遵守」又会假绿。应保留分类及当前会话派发/阅读行为证据，缺证为 `unknown/incomplete`，不擅自增控制面。
3. **F-SEM-03（37 不是语义去重）**：census 的 exact U/V alias 机制仍保留 V-014、V-015 等语义重叠，且 U-009 混有「继续」指令。因此 37 可作记录/定位分母，不能作为 37 个相互独立、已实现产品需求的计数。汇总必须分别给「来源记录」「实际义务」「别名/修正/过程/非功能」状态。
4. **F-SEM-04（结构核对不能宣称源义通过）**：当前 parser 的 `errors=[]` 只说明 U/V/atom 与 R 索引互相出现。它不检验 U-002 atom 是否忠实于父句的共同修饰、D 处置是否弱化、spec/Phase oracle 是否真能观察目标。P4/T018 已要求独立语义复核，本报告即为一次冷读 finding，不是正式 review verdict；正式 analyzer 仍须保留 semantic unknown、具名差异和当前材料身份。
5. **F-SEM-05（部分已知当前文字截断）**：U-002 的前两段用 `".../prd.md"` 和 `...` 代替路径/上下文，标为「逐字」但无法凭 decision-log 内部证明原始输入字节全保真。按 U-009 可将该文件作为当前授权的需求权威；不要反过来把来源 hash 描述为外部会话真实性证明。

本审计未见 U-002 24 atom 的直接反义、量词颠倒，亦未见 U-005～U-009 被总体漏出 D/R/spec/Phase。结论限于**材料设计追踪**：U-002-23/24 的共同修饰、U-002-17/18 的过程证据、37 项语义去重，以及所有 Task 的实际 RED/GREEN/正式分析/产品行为，均不可标 `achieved`。任何 `consistent` 须由最后材料版本的正式分析、独立语义处置与真实质量读回另证。
