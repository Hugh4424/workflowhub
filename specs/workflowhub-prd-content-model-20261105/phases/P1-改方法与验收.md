## 这一 Phase 交出什么？

写 PRD 的作者拿到一套能落地的结构与方法；独立审查者能用 C1–C7 判一份 PRD 的真假。

- **本 Phase 结果**：spec-prd 与 build-prd 按 7 节 + 2 附录、6 字段、五列地图、覆盖表与旧件保真改写；PRD 与 plan 的验收不再写比例、计数或零值；两份契约测试按新形状断言并用负例证明能红。
- **非目标**：不还原 `prd-v2.md`，不改外部 PRD；不改运行时代码或其它技能。
- **改动前**：模板是 6 字段一页、4 列地图、无附录；SKILL 说「不写校验编号」；build-prd 审四件事、材料包无旧件；契约测试只断言旧形状；plan/PRD 的验收还写读数与计数。
- **改动后**：模板有 7 节 + 附录 B/C、六字段带内容要求、5 列地图、四行带对照物；SKILL 有五处审查与覆盖表节；build-prd 第 1/2/4/5 步补齐；合同要求旧件与附录 B；六个方法文件写同一条验收规则。
- **与相邻 Phase 的边界**：P1 交回模板与方法；P2 只消费它们写 PRD，不改方法。
- **主要风险**：契约测试只证形状，内容丢失仍可能发生；用负例注入与 P2 的内容级回归兜底。
- **下一步**：P2 按 P1 的模板还原 `prd-v2.md`。
- **动手前必读**：`2026-11-05-005-skill-defects.md` 的 §5.1–§5.7；`2026-11-05-004-good-prd-model.md` 的 §1–§4；本任务 `spec.md` 的「实现设计」。
- **未决事实**：无；P1 不依赖用户新答复。

## 这一 Phase 怎么验收？

本 Phase 的验收是「方法真的写进文件」而不是「文件存在」；逐条读，不数行数。

本 Phase 与 P2 共用同一验收协议：契约测试 + 三处负例 + 抽读若干卡，都不统计比例，不设通过阈值。P1 用旧件片段做三份方法负例；P2 用还原后的 PRD 做三份内容负例；抽读在 P1 读方法与样例，在 P2 读五张卡。

### 验收 1：方法与模板换成新结构

目标：SKILL 与模板能让人写出头部 + 7 节 + 2 附录、六字段、5 列地图的 PRD。

怎么操作：读 `skills/spec-prd/SKILL.md` 与 `templates/prd-template.md`，对照 `spec.md` 的「PRD 的节序」「每张任务卡写什么」「任务地图」逐项点；跑 `npx vitest run tests/contract/prd-card-shape.test.mjs`。

什么条件：真实文件字节；测试读模板；不构造样张；审查者不参与写作。

怎样算通过：七节与附录 B/C 都能点到，附录 A 不存在；六字段名齐、没有「下游」；地图五列；四行第 3/4 行有对照物、独立复算、故意弄坏；测试退出 0。

故意弄坏一处：删掉附录 B 的表头，或把「风险与没定」改回「下游」，同一测试必须非零且断言指向缺失项。

真跑还是替代：真跑；测试命令与退出码留证据；不宣称未执行的门为绿。

谁判与证据：未参与写作的独立审查者在开发完成且审查问题改完后判定；读两文件、测试输出与 `spec.md`；结论记本 Phase 证据与 AC-001～AC-006。

失败回修与停止：缺结构回 T001 开发；断言没覆盖要求回测试 owner 补断言；同一原因两次失败停手报主会话。

### 验收 2：流程与合同补上决定清单、覆盖表与旧件保真

目标：build-prd 六步内能读出决定清单、覆盖表与五件事；审查合同要求旧件与附录 B。

怎么操作：读 `workflows/build-prd/SKILL.md`、`steps.json`、`skills/wh-review/contracts/build-prd.md`；跑 `npx vitest run tests/contract/build-prd-review-contract.test.mjs tests/contract/stage-closeout-step-contract.test.mjs`；解析 `steps.json` 看步数与 `completion_evidence`。

什么条件：真实 JSON/YAML 可解析；六步与末步 closeout 不变；不新增 kind。

怎样算通过：第 1 步有决定清单，第 2 步五列，第 4 步覆盖表，第 5 步五件事与材料包；合同写旧件保真、覆盖抽读、`source_facts`、缺旧件 incomplete；测试退出 0。

故意弄坏一处：删掉「旧件保真」一句，或给 `steps.json` 的某步加一个 `completion_evidence`，同一组测试必须红。

真跑还是替代：真跑；`steps.json` 用解析器读，不靠肉眼。

谁判与证据：独立审查者；读三文件与测试输出；结论记 AC-007、AC-008。

失败回修与停止：流程缺项回 T002；合同缺项回 T003；测试断言错回测试 owner；同一原因两次失败停手。

### 验收 3：契约测试与负例证明检查抓得住

目标：两份契约测试能抓住模板与合同的结构丢失，不是只证文件存在。

怎么操作：正常跑两份测试；再做三次模板级注入：删附录 B 表头、删六字段之一、删「不得删条件」句；每次只改测试临时串，不改仓库。

什么条件：真实测试文件；注入不落盘；每次留命令与退出码。

怎样算通过：正常两份测试退出 0；三次注入都非零，且断言指向对应缺失项。

故意弄坏一处：如果任一注入仍绿，说明断言没覆盖该要求，回 T001/T003 补断言并重跑。

真跑还是替代：真跑；注入输出是判据，不是描述。

谁判与证据：独立测试执行者；证据 `quality/evidence/` 下的正常与三次注入输出；结论记 AC-010、AC-011。

失败回修与停止：断言缺失回测试作者；模板/合同缺失回对应开发；注入导致仓库变更即停手恢复并报主会话。

### 验收 4：登记与写集边界

目标：catalog 升到 1.2.0、日期 2026-11-05、bundle 文件清单不变；改动只在写集内。

怎么操作：读 `skills/catalog.yaml` 与 `skills/spec-prd/skill-bundle.json`；跑 `npx vitest run tests/n2-skill-catalog-portability.test.mjs`；跑 `git diff --name-only 6993f2a9`。

什么条件：真实仓库；diff 以基线提交为参照；不清理无关改动。

怎样算通过：版本与日期正确；bundle 文件清单不变；diff 只列 P1 写集与本任务材料；测试退出 0。

故意弄坏一处：把版本改回 1.1.0 或删掉 bundle 一项，登记检查或 portability 测试必须报。

真跑还是替代：真跑 `git diff` 与测试；不靠记忆列文件。

谁判与证据：独立审查者；读 catalog、bundle、diff 与测试输出；结论记 AC-009、AC-012。

失败回修与停止：版本错回 T003；diff 越界即停手，保留越界文件原样并报主会话。

### 验收 5：验收规则与三处方法负例

目标：六个方法文件写入同一条规则；用旧件片段做的三份方法负例都能被判红；示例不示范比例、计数或读数为零。

怎么操作：读六个文件；跑 T004 的结构检查命令；从旧件片段做三份方法负例（删 T06 的 2000/500/600/1200、把黄=允许写成非绿即阻止不披露、把 60 秒对账截止删成 60 秒内收敛）；请独立读者按新规则判这三份；再抽读三张任务卡或 Phase 示例。

什么条件：负例只放任务证据，不改仓库；读者不参与写作；不统计比例。

怎样算通过：六个文件都能点到同一条规则；三份方法负例都被 C2 或 C4 判红；示例只示范可读四行；抽读能判断「做不到、只能数数」的判据为不合格。

故意弄坏一处：删掉任一文件里的规则句，结构检查必须红；把某条验收改回覆盖率口径，抽读必须判不合格；三份方法负例任一被判绿，本 Phase 不合格。

真跑还是替代：结构检查真跑；「能否靠读材料判」只能人读，按抽读与负例记录判。

谁判与证据：独立审查者；读六文件、三份方法负例与抽读记录；结论记 AC-028。

失败回修与停止：缺规则回 T004；示例示范反例回 T004 与模板 owner；方法负例判绿说明规则不可判，停手改规则；两次失败停手。

## 怎么验证？

用真实文件字节与真实测试命令判 RED 与 GREEN；`gate_cmd` 只证明结构可读，不产出内容验收结论。

开工前四要素：验证层是契约测试、`steps.json` 解析与六文件结构检查；命令是下表；预期是 RED 非零、GREEN 0；失败条件是断言未到达、环境失败或越界改动，三类分开记。

| 目标 | Task | 角色 | gate_cmd 与预期退出码 | 判据与证据路径 |
