## 产品总览

### 方向、用户结果与写作授权

目标：让使用 WorkflowHub 的设计者、开发者和项目维护者，自动取得可信依据、正确复用项目资产、完成原创设计或忠实还原，并在真实产品中检查、回修、升级和复用经验。首批是业务应用/工作台，主要验证 React/Next.js；不把其它栈误套 React 专属规则。

母决定为父规划的有效D-001～D-014；D-004仅为被D-014替代的历史。本次新增D-015，专门承接上游M18发布与接入闭环。U019/U020对父规划九卡的确认仍有效；C10是后续用户明确要求的增补，不能冒作原确认已覆盖。实际地图原话见[planning-input.md](/Users/Hugh/Hugh/Knowledge/Projects/workflowhub/tasks/workflowhub-ui-frontend-decision-refresh-20261013/quality/evidence/prd-refs/planning-input.md)。

十项交付的是可复用的原技能适配、方法、必要窄工具、真实接线及最终可分发包；页面/项目样本是验收载体，不以“做出一页demo”或“文件存在”替代能力。独立交付允许依赖已交付上游，不允许等待未来下游替本卡补实现或验收。每卡均承担必要来源核验、接线、针对性验证、独立检查、修复及交接。

规划对象是WorkflowHub的能力/方法改造，本轮没有待设计的业务页面、状态或viewport，故本轮真实UI设计展示为not_applicable。C05及各后续适用任务仍须展示真实原型并取得该原型答复；此处不以规划确认绕过它。

### 范围与非目标

范围：有稿/无稿两路；设计知识消费与受控经验；八类专业规范；设计组件、设计布局、前端组件、前端布局的整理/应用/更新/验证及用户任务模式；独立设计和代码审查；视觉/体验/行为/a11y/性能检查；流程E2E和真实业务E2E；有界回修；固定真基线与同输入效果比较；M18对应的可分发插件、幂等接入、版本更新、完整文档、repo/external manifest、外部依赖兼容矩阵及发布包真实consumer验证。

不做：独立知识网站、全项目全库整理、跨项目统一皮肤/组件库/断点、万能页面IR、实时双向同步平台、后台追踪所有任务、评分放行平台、新stage/gate/进度权威或第二manifest真相。首批不做营销页专项、动态GenUI整套系统；不引入未选定的整族，不把公开短模板当完整技能包。C01按U-008将三份已选能力的完整文字闭包复制至skills/external/，脚本入库不执行，许可状态如实登记；未声明许可的复制风险由项目所有者本人承担。不恢复四个独立试点、P1放行门或全主干禁合并。C10不重做M14～M17，不并入X2/X3/X4，不含未经单独授权的Git push、marketplace/registry上线、部署、物理清理或分发回滚。条件工具不适用不等于删除必需能力；确无合法可行路径时显露具体影响，不能擅自降质或扩平台。
