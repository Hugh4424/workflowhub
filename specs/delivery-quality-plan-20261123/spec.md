# 功能规格：每张交付卡都能当场验证

## 这是什么，给谁用？

计划作者从现有命令行材料入口读到首卡，实施者照卡跑出真实结果。
独立读者看到这条路径如何成功、缺件时卡在哪、谁应修复。
这份草稿只写任务三的产品承诺；它不是计划定稿或实施授权。

## 一页看懂：谁要什么结果，怎么算通过？

用户不必等所有改动完成才知道结果能否验证。
四个阶段共用写卡、派发和审查规则，计划阶段先证明这套做法有用。
接着用它拆任务、演示代码首卡、传递真实方向答复。
每段各自验收，最后一段在真实交付版本上汇总并补必要的未验用例。
验收只在 [附录 A](#appendix-a--验收判据唯一权威) 下定义。

## 为什么做，给谁用？

过去有人把内部函数通过、材料有字或合并成功，当成真实用户已能用。
计划域的历史样本说明：入口未接、供件没交和测试抓不到错都会拖到实施才暴露。
本次让作者在交卡时把这些问题显出来；实施者和验收者不必猜下一步。

### 谁从哪里开始？

场景 1：阶段作者读到同版共用规则，知道什么时候用哪种卡、怎么展示和收尾。
场景 2：独立读者从真实卡读到可接手的输入、输出、风险和判法。
场景 3：主会话派发互不踩写集的单元；准备好的工作补空位，用户答复串行。
场景 4：计划作者在真实入口跑首卡；供件方用接收者的实际方法先读一遍。
场景 5：判据冻结者先证明正常样本和错误样本分得开，再交给实施者。
场景 6：任务作者从已定需求写出可拆成施工段的卡，独立读者能直接接手。
场景 7：代码作者先看目标断言失败，再演示第一条真实路径和消费者读回。
场景 8：方向作者把用户实际答过的话交给下游；未答的仍留待决定。
场景 9：末验者按原件判断哪些结果已交、哪些没有、保留哪些技能及为什么。
验收条款用独立预期判成败；在执行人改实现之前用实际断言证伪。

### 哪些情况要说清楚？

正常和默认行为见各场景；默认值须能回到原出处。
空、缺件、错误装配、权限不足或期限到达时，点明受影响动作、查过的原件与可恢复条件。
进行中与取消只记录已有执行事实；没有网页载入状态，也不新设流程状态。
并发遇同一文件时按依赖交接；范围或权限不明只停相关路径。

## 做成什么样？

作者按下面各项交给接手人；编号与来源、验收、交付段见追踪和附录。

- 需求 1：逐卡交付时当场检查，不能把已经可见的问题都留到末验。
- 需求 2：对照归档要求与模块原案说明接通、待退或保留什么。
- 需求 3：从真实入口验清楚；对本次相关的已交前件核实际结果与局限。
- 需求 4：独立人按首卡当天从公开入口看到结果，坏供件只影响对应调用。
- 需求 5：每个受影响入口写出类型、装配点、调用方和覆盖理由，提供者实读。
- 需求 6：高代价判据先用顺利和卡住样本校准，区分目标错误和装置错误。
- 需求 7：适用卡写当时可得的事实；开工人读五列，猜错的人知道何处返工。
- 需求 8：会改选法的试跑提前；作者只用实际卡生成索引，保留已同意的选择。
- 需求 9：需要跨任务取舍才出完整规划稿，用户明确要求也可写。
- 需求 10：写集是本段允许改的路径集合。计划方用现有报告解释实际差异。
- 需求 11：有业务时限就把约定传进真实调用；超时保持原错误约定。
- 需求 12：施工人先知道规则归谁、合法状态、默认出处、封装和失败退路。
- 需求 13：同一入口和样本用不同合法配置时，各给契约约定的结果。
- 需求 14：方法迁移按已批准范围，原证据、公共入口和唯一进度来源不动。
- 需求 15：先给用户看具体大纲和卡，收尾说明验证结果、缺口及下一步。
- 需求 16：四阶段采用同一质量标准，阶段各只留自己的差异和必要入口。
- 需求 17：任务、计划、代码各有自己的作者或执行方法，方向复用原技能。
- 需求 18：迁移实际调用者，不把只换文档或清单说成接通。
- 需求 19：单元写完立即审；阻塞改动由原审查者复读，不再开新轮。
- 需求 20：单元两路分别给意见；全文终审只看跨单元问题。
- 需求 21：原审查合同按阶段取有用的问题，实际审方案、接线和判据漏洞。
- 需求 22：四技能用同一套派发、接线、提问和维护方式，更新可核到消费者。
- 需求 23：共用规则能直接用于卡、分工、审查、提问、并行和版本维护。
- 需求 24：四技能交出可照做的执行顺序、结果和验证，缺真实消费就披露。
- 需求 25：先展示有人能决定的具体大纲，逐单元给一份白话结果。
- 需求 26：阶段里该用的技能必须实际用，不能用读了同名文档代替。
- 需求 27：逐包依次调研、设计、给用户看卡并独立审，未答不替用户决定。
- 需求 28：不相交的包最多三个；有空位且有就绪包时启动下一包调研。
- 需求 29：聊天卡把实际方案、配套变更和验收写清，不翻译一遍需求了事。

## 打算怎么做？

先复用真实用户入口、读取标记、审查路由和证据保管，再窄改现有读者。
采用共用内核和四个单元方法，不复制阶段整套工作流。
内核与字段各有一个负责人；证据作者只保真实原件和出处。
同一代码或材料文件先写者验收交回真实版本，后写者再取笔。
同文件不同字段也不并行；不增协调账本或锁。
当前规格作者只发布草稿；全局工程和测试设计作者顺序接手同一份正文。

### 哪些不做？

不做业务、页面或路由改造，不做本轮真实浏览器操作。
保留方法将来遇到页面时的原审计责任，旧现页选择仅用历史答复回放。
不扩到后续任务的业务、证据形状、审查强度或发布清理。
不删文件，不实施拟合并技能的切换；后续另凭真实授权和消费者证据。
不新增阶段、提示确认、公共命令、独立任务索引、回执生产者或进度权威。
只增加用户已批准的共用技能与三个阶段方法；原方向技能原位调整。
不全量回归，不重开归档任务，也不为旧检查器误报修改工具取绿。

## 阶段大纲：几个阶段，各交什么？

修订大纲把八个设计包拆成十二段，每段交独立可验结果。
设计包是来源，不是实施段的同义词；追踪见下方映射。
本轮不另立准备段；共用环境或夹具随实际消费者和已有准备入口说明。

## 还有什么没定？

真实装配点、期限值、两合法配置和完整联验仍须核实；没有一项冒已执行。
未决 1：工程作者核首卡入口、供件与消费者，以及共享文件首写和交回位置。
未决 2：本任务先查两配置、期限、争用和高代价样本的实物与契约；独立测试者按原判据核预期。
未决 3：本任务从方向日志及同包原件核两条历史版本差异；并行继续不受影响的规划。
未决 4：P12 登记作者核每项技能的实际读者；镜头最终身份依据批准范围判。
未决 5：两段承接同一包时，旧基线程序的单段诊断与人工覆盖结果并列呈现。

### 接口与失败语义

步骤声明、真实方法及当次读取保持同版；索引声明迁移必须保持一个执行读取权威。

1. 先用真实的旧阶段文件取共用规则与卡字段，集中定义；仍留四阶段各自责任。
2. 把必用步骤、真实步骤锚点、已有读取标记接同一批；隔离合成负控先证明拒绝。至少一个真实动作能接到现消费者，才允许真实声明和技能同批进入；绝不发布只承诺未来能力的空接口。
3. 正常以公开卡、实际技能读取、现捕获和同对象下游读回推出首卡。调用者与提供者回同一对象，缺件点到首个坏步骤；不追加许可或新回执。
4. 当前草稿继续用现契约头作为声明源，索引是从实有卡生成的指针；不是提前换格式。
   后续阶段五仅按用户 008 答复迁新同仓材料：`quality/evidence/2026-11-24-008-build-plan-write-list-scope-reply.md`；SHA256 `f06440885af260b3e20ba960e3ad94384ba5ff2e0da5aebba0acb3bd6879c2ba`。
   同仓新卡用原写入集字段指索引与摘要；现索引的写入集列成为唯一完整声明源。
   `stage-content-contracts.mjs` 解析一次；终链总集、合同原件和逐段审查消费同一结果。
   合法旧卡按原契约只读；坏新指针、坏索引不退回旧卡、不当合法空集。
   只在现审查准备传错坏索引时改原调用，不重写现校验与报告，不增公共命令或门。
   跨仓授权与审批读法原样；不在本次验收范围，不从局部文件反推索引。
5. 材料读写以当前认证工作树，证据用当前真实 Task handle 原件。幂等同字节先比对、复用引用；不同或不明保实际新件。公共发布原持锁原子写仅覆盖单文件，不能当跨文件事务。
6. 分支任务和执行只在实际独立路径下并行。真实共同来源的交回按下表串行；同一文件不同字段也不并写。

十二段仍只落实八个已确认包：前三个各一段；计划首卡与判据各一段；任务写作与审查各一段；代码演示与独立收敛各一段；方向交接与两路/全文各一段；最后汇总全局。

## 有什么风险和未决？

三类最大风险是双权威、空证据和历史真首卡仍受阻。

## 材料导航：在哪个时点读什么？

先读一页结果和对应交付段，制定或修复验收时才读附录。
这里是可再生指针，不记任务进度。

| 时机 | 读哪里 | 为什么 |
| --- | --- | --- |
| 接任务 | 一页结果、场景与阶段顺序 | 找到交付和边界 |
| 写工程或测试 | 实现设计、风险、附录 A | 获得原判据和未定输入 |
| 独立复核 | 来源追踪、附录 A 与所属段原件 | 对上原需、坏例和真实执行 |
| 查看编号 | 附录 B | 反查正文，不另写判据 |
