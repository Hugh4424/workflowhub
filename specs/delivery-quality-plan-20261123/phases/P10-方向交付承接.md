# Phase P10 — 接手人能看到用户原答并判断能否继续

本文件给方向记录者、计划接手作者。
阶段卡只写局部交付；[全局实现设计](../spec.md#实现设计全局权威)与附录判据仍归同一规格。
“供件”是下游真正需要的前序输出；“负控”是只故意破坏目标条件的对照。
“目标红测”是实施前具名目标断言失败；“判定器”是判真假的固定方法。
精确命令、路径和机读标签按原字写，是行宽与标题方式的例外。

## 哪些节必须写，哪些可以省？

开工、验收与接手都在正文；机器字段只交给既有读取者。

| 节 | 状态 | 理由或内容 |
| --- | --- | --- |
| 选节、交付、验收、原因 | written | 可观察结果和原来源 |
| 前置、文件、验证、接手 | written | 实际输入、回修责任和证据 |
| 任务卡与机器字段 | written | 一张完整交付卡及可读字段 |
| 终末检查 | not-applicable | 只由最后一段消费原件 |

## 这一 Phase 交出什么？

真实原答、先后关系、实际供件和缺件到达下游；没答和错批不冒真答。

- 当前：任务二合并不等于七包的真实答复和最终首卡都在。
- 交出：真实原答、先后关系、实际供件和缺件到达下游；没答和错批不冒真答。
- 相邻边界：方向审查者取同一包的来源与摘要，不重复问原选择。
- 有意不做：历史不回写；质询行现只报告原位边界；不新建答复索引。
- 最大风险和替代：本段实施者先查当批原答、版本和实际入口；能在本任务范围补的接手验证就补，仍缺则分别记原答或联合试跑的尝试、影响与恢复条件。

## 这一 Phase 怎么验收？

独立执行者先判本段交付；前段原件只作为供件，末段再统一读回。

**验收 22。** 从[规格附录 A](../spec.md#appendix-a--验收判据唯一权威)读原成功与拒绝条件。
输入：当前同包五件、任务二已合入版本，只读历史七包原件。
操作：从真实方向交接口读原话、质询、当次选择与未决，再让下游按实际读取方式接一张卡；对照空答复和错包批次。
独立者在交回前真跑下节命令，按本条判断通过或失败，预计活动 20 分钟。
原始捕获和读者结论分别在 `quality/tests/p10-scoped-original.json`、`quality/tests/p10-independent-readback.md`；均为计划逻辑位置，由既有捕获返回真实原件。
只判该结果；命令非零须归于目标，而非环境或夹具。
失败回原实施作者或输入提供者；只在条件恢复后用本次同输入复验。
