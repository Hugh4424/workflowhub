本文件给独立终末执行者、维护者及后续清理者。

“供件”是下游真正需要的前序输出；“负控”是只故意破坏目标条件的对照。
“目标红测”是实施前具名目标断言失败；“判定器”是判真假的固定方法。

## 怎么验证？

首判用同一冻结断言、实际独立报告与具名坏例；退出 0 本身不是语义通过。

```bash
bash -c '"/Users/Hugh/.dsh/dsh-runtimes/dsh-next-primary-runtime/dependencies/node/bin/node" tools/cli/build-skill-manifests.mjs --check; first=$?; "/Users/Hugh/.dsh/dsh-runtimes/dsh-next-primary-runtime/dependencies/node/bin/node" tools/cli/check-skill-consistency.mjs --root "$PWD"; second=$?; printf "manifest_exit=%s consistency_exit=%s\n" "$first" "$second"; if [ "$first" -ne 0 ]; then exit "$first"; fi; exit "$second"'
```

从任务认证工作树根运行。所列新测试路径是实施前须先交的生产无副作用定向测试，不声称本轮已存在或已执行。
预期：RED nonzero; GREEN 0。对象仅登记与投影：在真实受影响版本若原检查早已通过，记原本就通过；终末复核本身不造 RED。
实际捕获由既有任务 `captureCommand` 或 public `verify --action=execute` 写到原记录；记录 cwd、真实 argv、退出和输出引用。
两条原命令必须分别捕获，不因前一条失败跳过后一条：`bash -c '"/Users/Hugh/.dsh/dsh-runtimes/dsh-next-primary-runtime/dependencies/node/bin/node" tools/cli/build-skill-manifests.mjs --check'` 与 `bash -c '"/Users/Hugh/.dsh/dsh-runtimes/dsh-next-primary-runtime/dependencies/node/bin/node" tools/cli/check-skill-consistency.mjs --root "$PWD"'`。只读报告中检查阶段来源诊断，另由独立人核六处实际消费者。
手工失败先用同一对象观察，合成对象只限反例。从同一合法样本恢复，再跑同一条命令。

- 手改投影假消漂移。
- 塞入没有调用的依赖。
- 通过目录缺失，或把 unavailable 标 pass。

活动条目与包含沿用、退役条目的全清单分开逐项对读，数字只标历史口径。保保留、接线、改写、合并暂不删、待退役暂不删五种处置的真实消费者和恢复路；三项候选迁移及五弱引用逐项清楚，不切换或删除。发布投影由现生成器原入口生成，不手改；无真实调用不加假依赖。
