## L0 — 结果与变更

### 1. 结果与非目标

本节回答：这一 Phase 交出什么、明确不交什么、为什么现在做？

本 Phase 交出一个可被真实作者使用的计划材料体系，而不是一份“看起来完整”的模板。判断标准不是标题齐不齐，而是：一个新作者只读当前模板、方法和这份 spec，能不能写出完整 spec、独立 Phase 与纯指针 index；现有 reader 能不能接受这份完整产物；一个没有参与写作的读者能不能复述“做什么/为什么/下一步/失败怎么办”；一个工程师能不能按文档写出文件、命令和证据。四项都成立，才算本 Phase 的结果。

为什么现在做：C05 的后续 verify 与 C06 都要消费这套材料；上一版的根因之一就是“结构校验通过”被当成“计划可执行”。本 Phase 把“每节回答什么”“逐文件责任”“共享写主”“回滚与补救”“并行导航”“样本与终末指针”写进模板本身，让下一个作者不用猜。

本 Phase 明确不做以下事情。它们不是遗漏，而是边界：

- 不制作任何 UI 原型，不启动服务或浏览器。原型是 C05 build-code 的受控样本产物，不是本阶段产物。
- 不做外部方法采用、两路设计接线、八维审查方法、文案纪律或 Figma 提示词。这些归 P3。
- 不改派发纪律、三角色、迟到 finding 或成本事件。这些归 P2。
- 不写样本 A/B 的任何文件，不写 `docs/architecture/move-map.json`。前者归 P3 的 T004/T005，后者由 P3 在 P1/P2 汇合后独占 append。
- 不改 `spec.md` 的 18 条 AC、不改 `decision-log.md`、不改 runtime parser 或冻结测试。
- 不把“已有一份完整样例”当成“未来所有作者都能写对”；本 Phase 只证本任务模板与 reader 的兼容和一次独立消费。

### 7. 风险与回滚
