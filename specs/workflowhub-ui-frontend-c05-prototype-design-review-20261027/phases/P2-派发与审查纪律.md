## L0 — 结果与变更

### 1. 结果与非目标

本节回答：这一 Phase 交出什么、明确不交什么、为什么现在做？

本 Phase 交出一套能被执行者直接照做的派发与审查纪律：开发是唯一 writer；开发明确完成并通知后，审查和测试才开始，两者可并行；Standards 与 Spec 由互不继承上下文的两个执行者分别完成；迟到 finding 重开同一 Phase、回同一开发；主会话只收摘要与原件指针；没有新事实时先停重复动作，按现有四类分诊查根因、简化验收或换方法，继续安全工作；不以时长停任务，不新增常驻角色，不做硬预算熔断。规则落地后，用受控重放证明违规会失败，并把 C05 事件来源准备好交给 P4。

为什么现在做：C05 build-code 会按这套规则执行；如果不先把它写成可执行文本，执行时又会靠临时约定，迟到 finding、双轴独立性、2000 字回传和无新事实处理都会漂。P1 与 P2 是这个任务的两条并行腿：P1 管计划材料，P2 管执行纪律；两条都交回后，P3 才能把 UI 设计能力接进来。

本 Phase 明确不做：

- 不写 UI 方法、模板、外部采用或样本。它们归 P1、P3。
- 不做 C05 终末审计，不预填任何实际 Phase 的角色数、轮次、消息、等待或墙钟。审计归 P4。
- 不启动真实 provider，不用真实 provider 的失败或空 findings 证明规则。
- 不新增常驻团队角色、readiness 代理、oracle 代理或 review_host 角色；review_host 只做 OCR 长等待宿主。
- 不改 `tests/contract/phase-team.test.mjs`、`runtime/review/*`、`spec.md` 的 18 条 AC、`decision-log.md`。
- 不写 `docs/architecture/move-map.json`；它由 P3 独占。

### 7. 风险与回滚

本节回答：最可能让本 Phase 返工的是什么、出现什么信号就退回？

- **风险一：改规则时碰坏冻结七步。** 触发：为了写“并行”或“简化”改动 `phase-team.test.mjs` 的语句，或在 build-code 里重排七步。影响：冻结合同失效，整个任务的质量基线被改。缓解：先读冻结测试，改动只加解释不加顺序；每次运行冻结回归。回滚：按 `git diff --name-only` 逐文件退回 P2 base，保留失败原件。
- **风险二：双轴被折进同一人。** 触发：为省代理，把 Standards 与 Spec 写成一个执行者的两栏摘要。影响：独立质量轴消失。缓解：明确“互不继承上下文的两个执行者”；受控重放设负例；审查时核执行者身份。回滚：回原规则 owner 补独立轴，受影响审查重做。
- **风险三：迟到 finding 被丢到终末。** 触发：规则只写“finding 回开发”，没写迟到 finding 重开同一 Phase。影响：修复责任漂移，终末被迫补签。缓解：写清时序与同一开发；重放负例。回滚：回原规则 owner 补时序，受影响的 Phase 重开。
- **风险四：“无新事实”被读成“停任务”。** 触发：规则写成“没有新事实就停”，没有三检查与四类分诊。影响：有解的工作被误停。缓解：写成“只停重复动作，做完三检查后继续安全部分”；负例覆盖。回滚：改回可执行文字，保留原失败。
- **风险五：2000 字回传变成贴原始日志。** 触发：回传正文超限或把日志粘进正文。影响：主会话上下文被占，关键结论丢失。缓解：六项开头、2000 字上限、超长落文件 + 5 行摘要；负例覆盖。回滚：回原执行者重写回传，原件指针保留。
- **风险六：事件来源被预填成审计结论。** 触发：在 P2 写实际角色数、轮次或墙钟。影响：P4 审计被污染。缓解：只写来源、方法、缺项与 owner；实际数字留 P4。回滚：删预填数字，保留来源说明。

回滚共同边界：只回退本 Phase 写集内的文件；不改 runtime、不改 AC、不删冻结测试、不删旧失败；旧规则仍可读。触发信号是“冻结回归失败”“受控重放暴露违规”“双轴/迟到 finding 文字消失”，不是“有人觉得规则太长”。
