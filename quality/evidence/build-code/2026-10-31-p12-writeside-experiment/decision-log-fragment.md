## 每包交付什么，为什么这样定？

工作包 1 交付一套能判效果的验收写法，并先在一个真实 Phase 上证明它判得出效果；只写字段或只让门禁变绿，不能证明验收有效。

### 工作包 1：让一个试点 Phase 的验收能判「做对」和「有效」

本包让独立判定者只读试点 Phase 的验收与原始需求，就能拒绝绿而错、接受做对。
再让真实下游消费者用一次，证明结果有效。
绿而错是所有已列门禁都通过、用户可观察结果却错的交付。
盲判是判定者不知道两份交付哪份是真的，只按验收和原始需求判。
下游消费者是使用本 Phase 结果继续工作的人或下一 Phase 的 owner。

- **要交付什么**：试点 Phase 的验收段落，含用户可观察结果、成功与失败信号、场景、环境与数据、绿而错对照、独立判定协议、消费者与效果观察；
    消费者是 build-plan 作者、build-code 独立验收者、试点 Phase 的下游 owner。
- **成功什么样**：独立判定者在不知道两份交付标签时，正确认出真实交付和绿而错变体；
    理由说出用户可观察差异，并说明为什么已列门禁、契约测试、断言和回归区分不了；
    真实下游消费者在真实场景与数据中完成一次使用，得到该 Phase 的原始需求要求的结果，且不需要作者解释。
- **失败什么样**：判错、两份都接受或都拒绝；
    理由只写「测试通过」「字段齐全」「退出码 0」；
    需要作者解释；
    绿而错变体其实过不了门禁；
    判定前知道标签；
    消费者是作者或实现者；
    消费者只复述「命令通过」；
    该 Phase 改了既有行为却没有改动前基线。
- **谁判**：做对由独立验收子代理或独立 provider 判，上下文与作者、实现者都不同；
    有效由该 Phase 的真实下游消费者判，消费者不是作者、实现者或判定者；
    具体名字未提供，owner=主会话派发时填；
    在实现完成、审查问题修完后判。
- **需要什么环境与数据**：试点 Phase 的真实运行环境和真实数据；
    两份交付各放隔离 worktree；
    原始需求逐字文本；
    独立红队构造的绿而错变体；
    第三方随机编号并密封的盲包；
    判定答卷；
    消费者场景脚本、输入、基线（若改既有行为）和观察记录。
- **怎么判**：红队先证明绿而错变体通过全部已列门禁；
    第三方随机编号 A/B 并封存对应关系；
    判定者只读验收、原始需求与 A/B，先写「用户应看到什么」和「哪类错必须被拒绝」，再判两份并写理由；
    第三方拆封核对；
    消费者按同一场景与数据用一次，记录实际结果与是否求助作者。
- **交付证据**：判定答卷、两份交付的路径与 sha256、红队构造说明、全部门禁原始输出、拆封记录、消费者观察记录，各留一份原件；
    当前未执行，记 `unavailable — 试点 Phase 未选定`。
- **承接**：spec 的 Appendix A 用同号 AC 承接；
    试点 Phase 的「这一 Phase 怎么验收？」写同一判据；
    build-code 终末把结论写入任务事实与具名证据原件。
    本包只交 P1 行，不宣称整条 AC 通过。

**覆盖上限**：只证一个试点 Phase；
    不证全部 Phase，不证跨任务推广，不证真实用户长期效果；
    绿而错只代表红队能想到的一种错法；
    语义判定不能用一条命令重放（见 风险 5）。

**失败恢复**：判不出效果时回本包作者补判据，不回实现者改代码；
    控制无效时回红队重做；
    盲判泄露时回第三方重新编号；
    消费者无法完成时回该 Phase 的 owner 补场景或数据；
    结论只按重验原件改。

#### 决定 1：用绿而错对照、盲判和消费者观察证明验收能判效果

决定 1 选择「独立红队造绿而错变体 + 独立判定者盲判 + 真实下游消费者用一次」，因为只读材料或只看门禁绿，无法证明验收能区分做对与做错。

- **做什么**：为试点 Phase 写清用户可观察结果、成功与失败信号、环境与数据、绿而错对照；用独立红队、盲判和消费者观察验证。
- **不做什么**：不把字段齐全、门禁绿、契约测试通过当效果；
    不让作者或实现者当判定者或消费者；
    不把试点结论冒充全部 Phase 结论；
    不把消费者观察降成再跑一遍门禁。
- **风险**：绿而错变体太弱、判定者宽松、盲判泄露、消费者不独立、只覆盖一个 Phase；分别由红队、第三方、派发者、最终验收 Phase 承接。
- **改动**：试点 Phase 的验收段落与 spec Appendix A 同号 AC；
    唯一 writer=build-plan 作者；
    真实任务路径未提供，owner=build-plan；
    证据路径未提供，owner=build-code 终末。

## 这次覆盖什么，排除什么？

本包只覆盖一个试点 Phase 的验收写法和一次验证，排除其余 Phase 与跨任务推广。

- **目标**：让试点 Phase 的验收能判「做对」和「有效」。
- **范围**：一个试点 Phase 的验收材料、一次盲判、一次消费者观察；其余 Phase 由最终验收 Phase 承接。
- **非目标**：不改产品行为；不新增测试框架；不证明长期用户效果；不把试点结论当全部 Phase 结论。
- **Supersedes**：无。
