## Findings and direct checks

1. **One test file assigned to two cases.** The launcher had split the selection into single-case runner calls, bypassing the runner's batch duplicate-file check. The new shared-target fixture uses two selected cases for one physical test file and a test-owned side-effect marker. Before the guard, `T020-shared-target-red.stdout.txt` had 1 target failure, exit 1: the test actually ran and the outer receipt was rejected only after source changed. The child now resolves every selected target and rejects duplicate physical paths **before** the first run. `T020-shared-target-green.stdout.txt` is 1 passed, exit 0, with no marker.
2. **Raw reporter readback.** The facade previously accepted a child manifest and case record that agreed with each other, without re-reading actual Vitest JSON leaf identity/status/counts. New direct byte tests use a saved real three-target reporter sample. `T020-reporter-readback-red.stdout.txt` recorded 5 failures, exit 1, before the verifier existed. The fixed branch now parses one JSON document per target, checks exact test file path, every full leaf identity and uniqueness, all pass/skip/fail/pending/todo counts, file/suite success, and observed rows against the registered IDs. Recomputed hashes with missing, extra, or skipped raw leaves are rejected. `T020-reporter-readback-green.stdout.txt` is 5 passed, exit 0.
3. **Aggregate/raw disagreement.** The same verifier requires the combined reporter bytes to equal the ordered per-target raw files joined with exactly one newline. The negative test recomputes a valid hash over a different aggregate, and the verifier rejects the byte disagreement. This check is part of the five-test RED/GREEN above.
4. **Outer timeout escape.** The fixed shell command sets `WORKFLOWHUB_TARGETED_INHERIT_GROUP=1`; only that child path makes `targeted-runner` spawn its test children without a detached process group. The outer canonical writer's existing process-group timeout can then terminate them. The existing standalone runner keeps its detached-group behavior. `T020-timeout-red.stdout.txt` was 1 failure, exit 1: after outer timeout, the inner test wrote its delayed marker. `T020-timeout-stable2-green.stdout.txt` is 1 passed, exit 0: the inner test wrote a start marker before timeout, and did not write the delayed marker after the timeout. Intermediate timing attempts are preserved; one was a test-harness 5-second timeout and one fired before the start marker, so neither is counted as proof.
