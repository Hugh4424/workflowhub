# 大白话摘要模板（human-brief）

> 用途：workflowhub 五阶段向人输出进度 / 让人拍板时，统一用这个格式。
> 铁律：这是给人看的，不是质量门。缺了只记录、浮现，不自动卡流程。

## 硬规则

1. 全大白话中文，当对方是高中生，不用专业术语。
2. 禁止出现内部产物名、字段名、编号（如 spec.md、plan-eng-review.md、escalate_to_human、worktree.json、M11/M10 baseline）。要提就翻成人话。
3. 给选项时，每个选项写清"什么意思 + 选了会怎样"，并标出推荐项。

## 七要素（所有阶段都填）

1. 这阶段做了什么
2. 审了几次、结论是什么（没有审查的阶段写"本阶段不涉及审查"）
3. 这个 task 要解决什么
4. 准备怎么做 / 已经怎么做
5. 原始需求覆盖情况（覆盖了哪些、有没有遗漏、有没有额外加的）
6. 现在结果
7. 下一步

## 两种结尾

### A. 决策 gate 阶段（make-decision / build-plan / verify-code）—— 停下等人拍板

七要素之后，加：

```
请确认：
- **推荐：继续** —— 后果：<继续会发生什么>
- 修改后继续 —— 后果：<会按你的意见重做哪部分>
- 暂停 —— 后果：<不推进，保留什么>
```

### B. 自动放行阶段（build-spec / build-code）—— 不停，给人瞄一眼

七要素之后，加一句：

```
本阶段已通过异源审查，自动进入下一阶段。以上仅供你了解进度，无需操作。
```
