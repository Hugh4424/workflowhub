# Test asset inventory (CARD-04 P9/T019)

- **Owner:** project test maintainers. `workflows/build-code/test-asset-inventory.mjs` owns parsing and comparison; T018 owns the `runCapture` option forwarding and return projection.
- **Consumers:** build-code P10 case selection and reconciliation, project test maintainers, and verify-code read-only sampling. Targeted test callers can pass `registeredTestIds` to `runCapture`; the public `capture-tests` CLI currently does not pass them. No production P8 catalog reader or P10 consumer is proven yet.
- **Version:** `workflowhub-test-asset-inventory.v1` return projection. It binds `task_id`, canonical test `receipt_ref`, `snapshot_tree`, `source_digest`, `output_ref`, and `output_hash` to the captured command. It does not alter the persisted `workflowhub-receipt.v1` or add a second ledger.
- **Source:** the canonical receipt's stored raw output, read through the authenticated task handle and checked against its SHA-256. Before recording an inventory, recapture the current worktree snapshot and require its HEAD/tree/commit/source digest to match the receipt. For the literal `node --test --test-reporter=tap <relative-file>.test.mjs` command, parse Node TAP v13's subtest tree, leaf results, plan, and totals. For the literal `npx vitest run <relative-file>.test.mjs --reporter=json` command, require one complete Vitest JSON report, one matching file inside the authenticated worktree, leaf assertions, consistent counts/success/exit, and unique identities. `full_id` is `<file> > <suite> > <test>`; Vitest uses its `ancestorTitles[]` plus `title` instead of its ambiguous space-joined `fullName`. Suite summaries are not runnable IDs. Results retain `passed`, `failed`, `skipped`, `todo`, or Vitest `pending`; zero/truncated/malformed output and duplicate full IDs fail explicitly. Unsupported commands yield `unavailable`, not an empty recorded inventory.
- **Independent registration:** `registeredTestIds` is supplied by the caller, must be unique, and is never inferred from TAP or test source. `unmatched` lists observed runnable IDs absent from registration; `missing` lists registered IDs absent from the captured run; `skipped` lists observed skipped IDs even when registered. These are inventory discrepancies, not business-effect or AC verdicts. The current frozen fixture uses literal IDs. The P8 seed catalog now lists JSON reporter commands and 49 full test IDs across three targets, but this module has no verified catalog-to-`registeredTestIds` adapter or catalog revision binding.
- **Coverage and failure boundary:** this implementation proves the supported Node TAP route and one real Vitest JSON census route in isolated authenticated tasks. The P8 catalog's three registered targets have been checked directly against reporter output; the public capture path does not read that catalog, so P8 revision → captured inventory is not authenticated by this module. Repository-wide Git path discovery, package script and Vitest include/exclude analysis, other reporters/runners, dynamically generated tests, case-to-runner selection, and both sides' uncharted business knowledge remain `unknown` pending their own consumers and evidence. A captured `recorded` inventory does not assert successful tests: individual failure/skip/todo and canonical receipt exit remain visible. Actual target execution and AC effect reconciliation belong to P10.
- **Replacement and deletion:** no existing path-list helper provides full runnable identity, so this does not replace one. Retire this module and document only after an independently reviewed equivalent inventory has a real owner, canonical output/snapshot binding, duplicate and negative-path behavior, and live P10/verify-code consumers; preserve prior facts and references.
