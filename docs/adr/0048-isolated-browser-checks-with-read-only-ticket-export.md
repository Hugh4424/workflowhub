# 浏览器检查一律用隔离实例，登录态经只读票据导出复用

浏览器检查需要登录态时，**不接受**关闭用户正在使用的浏览器去复制 profile，**不接受**在用户真实浏览器里开标签操作（live attach），也**不接受**使用账号密码登录。采用的路线是：一律使用独立实例与独立临时数据目录；需要登录态时，从用户**已在运行**的 Chrome 经浏览器级只读命令导出目标站点所需的票据，灌入该独立实例。票据只存在于隔离运行内，**不得进入日志或证据**（只记数量、域名与属性存在性），成功、失败、取消三条路径都要清理临时票据与临时目录。

这条路线对本仓是反直觉的（表面上「复用登录态」最省事的办法是直接连上用户浏览器），因此记下：它的代价是**设备绑定会话结构性不可搬运**（私钥在安全硬件里、协议无导入导出），这类站点的登录态只能放弃复用，如实记未达成；带分区键的票据需要 https 站点；`SameSite=None` 而无 `Secure` 的票据会被静默丢弃。

## Considered Options

- **关闭 Chrome 后复制 profile**：隔离最强，但用户明确否决；且登录态只是快照。
- **live attach 用户浏览器**：登录态最新，但会在用户真实浏览器里开标签、弹授权与横幅，用户明确否决。
- **账号密码登录**：用户明确否决。
- **只读导出票据到独立实例**：采纳（端到端已用假票据验证）。

## Consequences

- 域名白名单（`--allowed-domains`）与登录态复用互斥，因此登录态走独立通道，白名单不放宽；本地文件目标下白名单不可达，如实写明。
- 「不打扰用户」仍有一个未确认项：连接时是否弹授权框或显示自动化横幅，须在验证时当场目视确认。
