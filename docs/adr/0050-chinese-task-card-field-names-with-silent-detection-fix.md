# 任务卡字段名改中文、修中文识别静默漏检，旧材料靠既有中英对照表继续可读

## Status

accepted（2026-10-16，make-decision 阶段质询后定稿，任务 `n4-writing-templates-research-eval-20261016`）

四类材料与任务卡的写法要统一到机器可读的中文/已认字面，但**替换式全仓改名会越过安全改动边界**。因此走受控方案，只做三件事：**①机器侧只加不改**——保留既有英文字段名与既有中文别名并存，不改错误文案；**②先修中文识别当前的静默漏检**——把「本该被拦住的写法因只硬编码英文标签而漏检」修好，并让一个真实漏检例从「漏检」变成「被拦住」；**③旧材料靠既有中英对照表继续可读**。边界写死：**归档材料与其它正在进行的任务材料一个字不改**；同一批必须同步更新 3 个把模板正文当逐字 oracle 的测试，否则模板字面一变就会静默失真。

## Considered Options

- **替换式全仓改名**（把英文标签整体换成中文，含归档与在跑任务材料）：最"统一"，但会让 335 个归档材料与 22 个在跑任务材料的扫描范围/字面失配，产生未验证的静默变动或响亮报错，**爆炸半径不可控**，不采。
- **只改模板、不动机器侧**：模板写成中文，校验器仍只认英文，结果是新写材料被自己的校验器拦住——把问题从「漏检」换成「误伤」，不采。
- **新增机器标题/结构元数据来表达分层与必留项**：会同时改动生产校验的 required 集合与别名表并新增机器约定，且当前没有真实 consumer；违反「没有当前消费者的重复控制面不新增」，不采。
- **受控方案（只加不改 + 修静默层 + 旧材料走对照表）**：选中。代价是长期**双写法并存**（英文名与中文别名都在），换来的是归档零改动、在跑任务零改动，以及一个真实漏检例被真正拦住。

## 三项判据

1. **难以反转**：真——它牵动生产内容校验、四类模板字面与把模板正文当逐字 oracle 的测试；回退要同时改这三层并重开部署时的兼容取舍。
2. **无背景会意外**：真——读者会看到中文标签与英文标签**同时被接受**、错误文案仍是英文、归档材料里还是老写法，自然会问「到底以哪套为准、为什么不直接全改」。
3. **存在真实取舍**：真——在「一次改干净的全仓替换」与「永远带着两套写法的受控兼容」之间选了后者，并用「先修静默层」支付其中一部分代价。

## Consequences

- **中英对照表成为唯一的字段名权威**：既有别名表（`runtime/stage/stage-content-contracts.mjs` 的字段标签别名表，经 `labelAlternation()` 消费）是机器侧唯一处；新增中文写法只能**追加别名**，不得替换或删除既有英文名与错误文案。
- **两处静默层必须在同一批修好**：按错误文案正则计算的两项 `valid` 标志会让「改了文案」静默变真、掩盖真实缺陷；只修一处等于把风险留在另一处。改名字段而未登记别名则是**响亮**报错（缺任一必填字段即报），两种失败模式必须分开报告。
- **旧材料零改动**：归档材料与其它在跑任务材料沿整篇兜底与既有对照表继续通过，**零字节改动**；这条是验收项，不是口号。
- **逐字测试同步**：3 个把模板正文当逐字 oracle 的测试必须同批更新，并保留一个冻结负例证明真实漏检例「漏检 → 被拦住」，且恢复后仍通过。
- **验收类标题的边界**：只把四类模板的验收类标题统一到机器已认字面，**不**把 `Appendix A — 验收判据（唯一权威）` 追加进识别集合——那会把在跑任务材料的扫描范围从「整篇兜底」改成「节内」，造成未验证的静默变动。
- **与既有决定的关系**：与 [ADR-0043](<docs/adr/0043-document-standards-checks-are-report-only.md>) 同向——检查只报告、不评分、默认退出 0、不接 stage/gate/CI 失败路径；本决定不把统一写法做成门。
