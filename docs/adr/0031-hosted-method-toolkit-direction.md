# ADR-0031：以宿主承载的方法工具包作为重构方向

2026-09-19；方向已由任务 workflowhub-thin-core-rebuild-planning-20260919 的U-007真实选择A确认，本文纳入该任务最终一次整体确认。尚未实施，不改变当前五阶段合同，不授权删除、提交或交付。

WorkflowHub的目标形态是方法工具包：由现有AI助手和子代理执行，框架提供必要方法和窄工具，以实际改动、测试、独立审查及如实披露说明结果，不再承担逐阶段强制机器认证。跨会话接续依赖清晰记录与读取；工作区安全、危险操作授权、真实测试、独立审查和失败披露仍保留。

所否决的产品定位是由WorkflowHub统一承担后台任务、阶段状态、机器核验和自动接续的独立执行平台。当前未证明这些能力是用户必需需求；删除具体kernel/fact graph或更换审查工具仍须后续方案，不能由本ADR直接推导已批准删除清单。未来若出现确切的后台自主执行、跨宿主可靠恢复或机器审计必需场景，可以重新评估这一取舍。

三项判据均成立：以后恢复统一认证/接续需重新引入状态、适配与恢复责任，改变方向有实际成本；没有背景时维护者可能把主动放弃的认证误当缺陷重建；宿主方法工具包与独立平台之间存在真实能力保证与维护成本取舍，用户已选前者。此决定不意味着降低真实交付质量，也不宣称纯技能具有同等自动认证能力。
