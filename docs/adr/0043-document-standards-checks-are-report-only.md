# 文档规范检查只报告不阻断

## Status

accepted（2026-10-14，make-decision 阶段，任务 `skills-framework-redesign-20261014`）

把 ASD-STE100 与 ISO 24495-1:2023 的核心思想落成中文可执行规则时，
**能机械判定的部分做成只报告的检查器**：不评分、默认退出码 0、不接任何 stage／gate／CI
失败路径、未跑即 `unknown`（不得读成通过）、只查可机械判定的项、阈值可注入。
**不可靠的项明确不查**（缩写全称、指代、长定语、被动语态等实测精确率只有 0%–35%），
一段一主题与一句一事只能靠模板骨架，不得假装机器管住了。

## Considered Options

- **只写指引、不做任何检查**：这是现状——唯一规范 WR001 的到达条件是"创建或改写 agent 方法时"，
  因此写 `spec.md`／`decision-log.md`／`prd.md` 时**字面不触发**，36 处指针 + 零挂载 +
  零可执行事实，要求在物理上不可观测。实测这就是要求被遗失的直接原因。
- **把规范做成阻断门**：宪法与 `docs/adr/0037` 均禁止；且实测可靠性不足的规则会大量误伤。
- **把全部规则都塞进检查**：会产出大量误报，最终无人看。

## 三项判据

1. **难以反转**：真——它决定文档规范的整个落地形态，并与 `docs/adr/0037` 的自动化禁令
   形成需要解释的边界。
2. **无背景会意外**：真——读者会问"为什么本仓明明反对自动校验，却又有一个检查器"。
3. **存在真实取舍**：真——在"最强约束（阻断）"与"零约束（只写指引）"之间选了中间档，
   代价是**需要有人看检查结果**；不看就等于多了一份没人读的输出，这一点必须承认为弱点。

## Consequences

- 与 `docs/adr/0037` 的关系必须逐条记帐：`0037` 逐字否掉的是**评分器**与**字数门**，
  不是"任何检查"；ISO 自己也只否定"用可读性公式当判据"。因此本决定不构成对 0037 的推翻。
- 挂载点必须是**文档输出物必经之处**（模板骨架 + 常驻入口 + 检查器三件套），
  每一点都要写明真实 consumer 与删除条件，否则又会变成"只写在某个技能里"。
- 中文句长阈值不得直接沿用外部语料的数字，须先用本仓既有产物重新校准。
