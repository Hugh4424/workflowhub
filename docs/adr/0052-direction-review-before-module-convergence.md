# ADR-0052：复杂路线方向审查前置于逐模块收敛

- 状态：Accepted
- 日期：2026-10-20
- 来源任务：n10-finite-check-wiring-20261020（F 块）
- 相关：N6 make-decision 方法、N8 四级路线、U-022/U-023、r5–r7 审计

## 背景

N6 原始需求把“独立建议”放在逐模块收敛与跨模块核对之后（`specs/archive/skills-framework-redesign-20261014/prd.md:400`），而当前 make-decision 方法第 7 步把方向审查放在第 8/9 步模块分诊与收敛之前。N6 交付只改了第 2/3/4/5/8/9/12 步，第 7 步未动，也没有写“方向审查未完成不得进入模块收敛”的判据；测试、执行器与任务事实都没有顺序覆盖。N10 执行时因此出现了“先问完模块、后做方向审查”的反序。

## 决定

复杂路线的方向审查（第 7 步）必须先于逐模块分诊与收敛（第 8/9 步）：第 8 步前有禁入/回读句，第 5 步只问方向轴问题，被审大纲以可回读的路径+哈希提交，并有一条防止顺序被改回的文本断言。普通路线维持 N8 原设计：不做方向审查，只在模块收敛后做一次细节/方案审；小改动无独立审；规划在任务卡收敛前做方向审。不新增强制门、审批、公共命令或第二套事实面。

## 后果

- 复杂任务在模块细化前拿到独立方向纠偏，减少“细节先定、方向后审”的返工。
- 文本与断言只保证书面顺序与可指认版本，不证明真实执行顺序；没有执行器/时点事实时标未验证，不冒充已强制。
- 普通路线仍没有方向级独立检查，这是按成本接受的边界；若以后要加，需另改 N8 四级合同。
- N6 原始需求“独立建议后置”的字面被本 ADR 覆盖；理由与来源保留，不静默改写历史。

## 备选方案

- 按 N6 原文把方向审后置：与用户选择的早期纠偏相反，未采用。
- 普通路线也加方向审：增加一次审查与成本，和 N8“普通只一次方案审”冲突，未采用。
- 用 review 记录强制 detail 前必须有 direction：会把事实变成准入 gate，违反“事实不是许可证”，未采用。
- 给 facts 加 step/track 顺序字段：新增第二进度权威，未采用。
