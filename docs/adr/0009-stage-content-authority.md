# Stage content authority reuses the existing audit lifecycle

WorkflowHub keeps `steps.json` as expected topology, journal and typed receipts as observed facts, and `audit-aggregator` as the only process-verdict authority. Official Stage publication must authenticate and consume that audit result plus Stage-specific content receipts; it must fail loud on missing, duplicated, out-of-order, tampered, or wrongly bound facts. An independently reviewed, evidence-backed serious problem pauses progression by default; any such problem may continue only after the user sees the specific problem, evidence, consequence, and affected scope, then explicitly accepts that risk in an append-only record.

We reject both prompt-only enforcement and a parallel completion state machine. `make-decision` gets an interaction completion record for its three talk rounds and full grill; `build-spec` gets an ambiguity ledger; decision, plan, tasks, and downstream handoff get explicit content contracts. These records prove presence, order, integrity, and task/stage/snapshot binding, but never user identity, genuine reading, or semantic quality.

User completion cards remain a host-visible projection and are separate from canonical downstream handoff records. The current decision-log is located only through the authenticated ArtifactDir at `specs/<task>/decision-log.md`. The immutable quality-evidence decision bytes are an exact hash-bound publication of that material, not a second current-material authority. A root-level `decision-log.md` is never consumed.

`talk-with-zhipeng` owns the permanent user-question contract: one decision axis, two or three mutually exclusive choices, one recommendation with reason, and explicit meaning, consequence, and risk for every choice, all in plain language without internal identifiers or record vocabulary. Before the first card it must enumerate every currently known direction-changing question. The displayed denominator is the current expected total for the round: questions already asked plus questions still open after re-ranking. It may change only when a real answer adds or removes a question, and the card must explain that change; it must never mechanically equal the current numerator.

`grill-with-docs` must use the same interaction contract whenever goal, scope, solution, risk, or a long-term rule is at stake. Code and documentation can settle facts, but cannot replace the user's decision on those axes. These rules already exist partly as prose, so this change must make real question delivery, visible options, replies, queue re-ranking, and order verifiable instead of duplicating more prompt text. The five Stage-content fixes and these enforceable interaction contracts form one delivery boundary; prior blocked work resumes only after all pass.

Long-term interaction evidence does not retain complete question-card text. It retains the structured card checks, the user's selected option, and a tamper-evident content hash. The canonical decision-log separately records each decision question and final option together with that option's recommendation reason, consequence, risk, and plain-language explanation. This preserves the decision meaning without turning the task record into a raw conversation archive.
