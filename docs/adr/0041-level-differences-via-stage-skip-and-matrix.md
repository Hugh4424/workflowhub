# 级别差异通过阶段跳过与阶段内矩阵共同表达

## Status

accepted（2026-10-14，make-decision 阶段，任务 `skills-framework-redesign-20261014`；
同日按方向审查 4 条 finding 修正）

四级任务的差异由**两件事**共同表达：
① **阶段路由**——小改动级与普通任务级**允许不调用**其后阶段（禁止的是**新增** stage，
**不是跳过** stage）；
② **阶段内技能矩阵与审查档位**——在仍然要跑的阶段内决定做哪些步骤、走哪些审查轴。

**修正记录（必须保留）**：本 ADR 初版把"宪法禁止新增 stage"与
"`runtime/stage/stage-context.mjs:8`、`tools/cli/stage-runtime.mjs:1069` 把 stage 集合钉死为五"
错误地推成 **"不能跳过阶段"**，从而把小改动/普通任务也绑在五阶段上，
**违背原始需求第 6 条**（"不需要其他 stage 和审查"）。
该推论是**关于今天运行时的描述，不是对重设计的永久约束**，已撤销。

## Considered Options

- **只做阶段内矩阵、不跳过阶段**（初版选择）：不用改运行时与守卫，但**不满足用户需求**。
- **把"跳过"实现成"空跑一个阶段"**：能绕开守卫，但那是**假跳过**，仍付全部固定成本。
- **新增一套轻量 stage**：宪法禁止。
- **为每级写独立调度器**：会造出第二个调度权威，宪法禁止。

## 三项判据

1. **难以反转**：真——它约束四级分级的全部实现形态；跳过阶段还会改变下游消费者能否拿到材料。
2. **无背景会意外**：真——读者会问"为什么小改动不跑 build-plan 却能保证质量"，
   以及"既然宪法禁止新增 stage，为什么可以跳过"。
3. **存在真实取舍**：真——在"不动运行时"与"满足用户的减负需求"之间，
   选择了**承担改守卫与测试的代价**。

## Consequences

- 实现任务第一步必须给出**"只跑所需阶段"的最小改动**（含要改的守卫与测试），
  见 AC-001 的前置验证；**不得把"改不动"当成结论**。
- 已知会红的既有守卫：`tests/contract/runtime-facade.test.mjs:58` 遍历含
  `build-spec` 的 stage 列表，而该目录不存在（潜在红，见 OI-009）。
- 判级失误的后果比初版估计更重（跳过阶段后无法回补早期材料）
  → 保留"升级只补没做的步骤"的可回退路径，且判级偏置继续偏保守。
