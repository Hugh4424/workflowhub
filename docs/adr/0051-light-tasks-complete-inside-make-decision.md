# 轻档在 make-decision 内完成方案、实施与审查

## Status

proposed（2026-10-19，任务 `n8-four-level-route-20261019`，make-decision 草稿；待用户最终确认）。
本 ADR 记录方向取舍，不证明实现、验收或质量通过。

## Context

父 PRD 与 ADR-0041 把级别差异表达为「阶段跳过＋阶段内矩阵」，并把小改动/普通任务的实施与测试放在
`build-code` 轻档。用户在 N8 开工阶段明确改口：小改动与普通任务不要任何阶段流转，直接在
`make-decision` 内完成方案、实施、测试与适用审查；同时要求产 spec 与 Phase、合并 mini-task、
普通任务保留一次实现审查并沿用 build-code 的质量与 provider。

N6 已把 `make-decision` 改成三段式（立骨架→逐模块五段→收口）15 步，并明确把四级定义/选择/路由/
技能矩阵留给 N8。N6 同时规定该阶段材料只有 `decision-log.md`，spec/Phase 归 `build-plan`。

## Decision

- `make-decision` 入口变成路由器，按级别选用四套流程：小改动、普通、复杂、规划。
- 复杂流程沿用 N6 交付后的三段式 15 步。
- 小改动/普通流程在阶段内产 spec 与 1–2 个 Phase，确认后实施、跑目标测试；普通再做一次整次实施的
  代码审（材料与 provider 同 build-code）；小改动不做独立审，用目标测试＋真实 diff 与声明写集比对。
- 规划流程细化到每张任务卡（8 字段），方向审＋细节审，两次确认，不产 spec/Phase，不做实施。
- 四级都消费 N6 的调研、大纲、决策、收敛动作；深度可减，动作不可无。
- mini-task 独立路线退役；入口评估函数迁入 `make-decision` 并改名；历史 `mini_task.*` 审查身份
  按用户选择直接删除（明确承担历史校验可能断的后果）。
- 驾驶舱（answer-as-page）普通/复杂/规划使用；小改动不建页，作为具名例外。

## Considered Options

- **沿用 build-code 轻档**：改动小，但用户明确不要阶段流转。
- **新增一个轻量 stage**：宪法禁止新增 stage。
- **轻档只在 make-decision 里写文字、不产材料**：无法满足文件流转与审查材料。
- **单阶段内组合三个后续阶段的高质量核心**（选择）：减少阶段切换，但把材料、审查身份、
  收口与阶段事实的复杂度集中到一个阶段。

## 三项判据

1. **难以反转**：真——一旦 stage 语义、审查身份、材料边界与收口路径按此实现，回退会牵动
   运行时、测试与历史审查身份。
2. **无背景会意外**：真——读者会问「为什么定方向阶段在写代码」「为什么审查记录在 make-decision」。
3. **存在真实取舍**：真——用「单阶段变大、材料边界被覆盖、审查身份要放宽」换「无阶段流转、交付更快」。

## Consequences

- 材料边界覆盖 N6 的「只许 decision-log」：轻档可写 spec/Phase，需在材料合同与验收显式登记。
- 审查身份放宽：允许 make-decision 的实现审；不改 build-code 质量门槛；历史 mini 枚举按用户选择删除，
  历史审查文件可能无法再校验，作为已接受的后果记录。
- 阶段事实仍只有一行 make-decision；不伪造 build-code/verify-code。
- 单阶段收口需参数化确认 stage、接 stage-closeout、PR 正文读 spec。
- 小改动不建驾驶舱页，是「每类都能用」的具名例外，必须在验收里写清。
- N6 未交付前不得实施或最终验收；N6 合入后按 N6→N8 串行读回。
