# ADR-0054：无稿闭环直接用运行中的真实业务服务，并登记数据残留风险

## 背景

C09 前期准备要在没有设计稿的情况下，锁定一条真实业务闭环（定位对象 → 看详情或配置 → 执行一项真实操作 → 读回结果）。本机 PaperBuilder 已经在 `:5176` 跑着真实服务，真实库约 19G，无认证，写入会落到真实数据；它自带的隔离数据根脚本当前没有可用根。用户看过“写入会落真实库、软删行会残留、库被在线服务持锁”这三条风险后，选择直接用正在跑的真实服务。

## 决定

无稿闭环直接用 PaperBuilder 的真实服务，不另建隔离数据根。按 D-004，只对一张合格的已有草稿卡通过同一 `fee-profile` 端点切换到另一个费用来源、读回，再改回原费用来源、再读回；不发起预检、不复制、丢弃或恢复卡片，不启动运行，不改其它对象。服务、卡详情与费用配置均须可读；写前还须证明原 state 为 DRAFT，`run_spec_id`、`readiness_report_id`、`preflight_reason` 原本为空，无 `history_run_ids`、无任何 `start_intent.run_id`，卡可写，原来源与另一来源均符合该端点的选择条件。执行者可自行选择合格卡，无须逐卡再确认；无合格卡、门禁未知或不可恢复时不写，也不以 POST 试写证明门禁。保留三次读与两次不同选择的原始响应；遇拒绝、权限、资源不存在、非法输入、409/库锁或超时即停该路径，不盲重试。改回失败立即报告具体残留，不直连数据库修复，不做第三次写；只读不能冒充真实写闭环。

## 后果

两次真实不同选择使 `preflight_revision` 累计 +2 并改变 `updated_at`；费用来源、profile ID 和版本可恢复，但不能称整张卡原样恢复。每次选择还会把状态置为 DRAFT 并清空预检关联字段，因此仅允许这些字段原空且无运行历史的卡。用户于 2026-10-26 明确授权这一窄范围残留，原件为本任务 `quality/evidence/human-confirmations/2026-10-26-003-build-code-p5-residue-authorized.json`；不把该授权扩大到其它残留或风险。真实库仍可能被在线服务持锁，失败与未知须留原件并报告；本方案不新增卡或软删行，不安排硬删清理。运行服务的代码版本、公开契约与只读可证明范围须在执行前核实；本地源码存在不证明运行进程已加载同版，无受支持的只读方式证明门禁时保留未达成。

## 备选

建隔离数据根最干净，但当前没有可用根、要先花时间建且脚本未真跑过；只做只读闭环零风险，但没有“执行一项真实操作”，不满足原要求；用测试替身或 mock 会直接违反“不得用 mock 冒充业务结果”的约束。

## 依据

- 用户真实选择与风险上下文：`specs/workflowhub-ui-frontend-c09-baseline-preparation-20261025/decision-log.md` 的「真实问答（批次与结论）」与 D-004。
- PaperBuilder 现状与候选：本任务派发记录 D9 回传，真实服务 `:5176`、真实库 19G、三条候选与回滚限制。
- 发布 PRD 第 372、376、382 行对无稿真实业务与“必要外部授权不由本 PRD 预给”的要求。
