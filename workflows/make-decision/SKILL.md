# Make Decision

## 目标与材料

把原始需求变成用户确认的方向，写入当前任务的 `decision-log.md`。本阶段负责 Talk、必要调研、Grill 与决策正文；后续 build-plan 负责规格澄清和实施设计。读取已有材料和原始来源即可开始，历史任务与旧审查只作背景。当前 post 任务使用 decision-log、spec、独立 Phase 文件及纯指针索引；历史材料只读，不重新启用 pre 工作流。

## 方向地图与 fog

在现有 decision-log 大纲地图中组织五段信息，不另建 map 文件、tracker 或第二决策权威；方法中的研究、真实答复和草稿更新都写回同一日志：

- **Destination**：当前方向要解决什么问题，何时达到目的。
- **Notes**：真实约束、适用方法和已明确的偏好；不把假设当决定。
- **Decisions so far**：已决定事项的一行含义及原决定指针，理由仍由原决定正文承载。
- **Not yet specified**：fog 中尚不能精确提问的未知边、依赖及其可能后果；已决定、已能精确提问或已排除的事项不混在 fog 中。
- **Out of scope**：明确不做的事项、理由和原选择来源；范围外不是等待实施的 fog。

**只规划不做**：方向地图只澄清路线，不交付实现或自动创建实施票。fog 不预先切成 ticket 大小；已能精确提问的问题交现有 Talk/Grill frontier，未知依赖等真实答复后重排。本分支每会话最多解一个方向 ticket（即一个方向决策问题，不是 Phase 实施 Task），其它未解问题保原位置；有边界的研究不冒真人决定。HITL 必须询问、等待并消费用户真实回复，agent 不自问自答、不替用户选。取消、未答或来源不足保留原事实和未知，不将它们写成已决定。

## 方法

写decision-log前，先读取 `skills/spec-specify/SKILL.md` 的「技能写作规范（WR001）」唯一正文，再调用本流程对应的材料作者；缺源如实 `unavailable`，保留原问答、确认、权限和失败边界，不复制规范。

全程领域维护：Talk、研究、Grill、写稿或确认中出现已解决的领域术语、含义或边界变化时，按 `skills/grill-with-docs/SKILL.md` 的 `Domain Awareness` 节 就地最小写入 `GLOSSARY.md` 并读回；本步完成前必须有其一——具名写入读回，或本 decision-log 里有来源的 no change 理由；未变保来源充分的 no change，归属或含义冲突交真实 owner 回答。写入方法、懒创建与返回事实归该领域 owner，本阶段只在现 decision-log 记录变化引用、理由或待问来源，逐词核对不延迟成阶段末批量写。

下方两行只显露各步骤原有产物与前提，是可发现性改进，不是新 gate 或审批；细则仍在同一步正文及所指原专业方法。十五步由真实主会话执行，公共 run --action=execute 不会自动执行 make-decision 或代填完成；材料渲染、问题生成与原件保存均不冒真人答复。

1. `load-context`：
   **本步产物**：decision-log.md 中的真实原话、痛点、任务类型、事实/假设、范围/非目标与未决项；逐字 R/U、Talk 与覆盖事实沿现唯一原件 ref。
   **进下一步前**：按真实任务类型和下文分诊/来源方法处理；类型冲突只暂停相关问题，类型变更逐项重处理。真人未答不代填；领域变动沿上方原 owner 写入读回或有源 no change。

   开工先读取并实际消费 `skills/knowledge-graph/SKILL.md`：以当前认证项目/worktree和本次原始需求为输入，按其入口选择查询现图或缺图建代码图；把内部图调研交独立子代理，主会话只收少数有源结论与对本次方向的影响。现图可读直接查询，不先更新；没有图按该方法免费建代码图，文档另按真实候选数量、字节、prompt/dispatch及估算限制告知并等本次真实范围许可，未答/拒绝只停付费路径。缺工具、坏图、无匹配或歧义保原诊断，回普通文件阅读继续本阶段，不增加准入条件。完成时把实际读取来源、改变的假设/候选/问题或无信号理由消费到同一 decision-log 的相应位置；调用次数、查询日志或历史授权不能代替结论/本次答复。

   先记录用户原话、痛点、任务类型、事实、假设、非目标和未决问题，含范围分诊：区分用户痛点、完整旅程、页面、数据状态和成功失败边界。任务类型不明或冲突时，只暂停依赖它的问题并澄清；不靠文件名或旧记录猜答案。规划任务只问会改变方向的问题，不问具体实现形式：文件路径与文件面、函数名、字段名、算法、schema 形状、命令形态、入口参数形态、行号、代码片段；可问要求覆盖哪些测试与实测面，具体命令、记录形状与实测记录由后续 build-plan 设计，普通任务可问影响实现的细节。
   普通/规划是任务性质，mini-task 是独立的交付规模与风险判断。普通任务有实际执行目标时，入口读取 `skills/mini-task/SKILL.md` 评估 mini 候选，并实际调用 `skills/mini-task/scripts/mini-task-runner.mjs` 的 `evaluateMiniTaskScope`：从真实目标、范围、影响与重大架构/迁移/权限/安全风险判断，输入各项带真实依据，保留依据和未决项。把入口评估真实返回的 `status`，以及该返回包含的 `reason`、`expanded_risks`、`choices`，连同「承诺的独立可交付验收单元数」「是否含需要用户在场或真实凭证的动作」记入原日志「工作包与决定」节的一条既有四字段决定；调用命令与返回原件的唯一落点可回读，返回未包含的项明确写“未返回”，不补造值。两项代价事实各带真实来源，缺来源写 `unassessed` 与具名 owner；函数不可用、材料不足或取值缺依据时如实记未评估／未决，不代填。入口事实在第 8 步与第 13 步的既有展示中可读；返回 `paused` 时，两处同批展示至少一条可选拆分路线，路线只是建议，用户实际答复仍沿原确认记录。返回的事实只作判断依据，不是阶段许可。规划任务仍做方向规划。缺事实只澄清相关问题，用户显式提出 mini 也不能把未知补成适合；建议与真实路线选择写进原日志，不自动转换任务。
   用户中途改变任务类型声明时，停止消费旧类型下的问题与产物，直到逐项按新类型重新处理。当前决策保留旧问题引用、重处理原因、新内容位置；只换 hash 或引用不算重处理。不为此新建 schema、控制面、类型状态或记录绑定。
   新日志使用 `skills/decision-log/templates/decision-log-template.md`；先实读模板，再按当前真实来源写内容。主文与原件分工按模板 `## 外置事实索引` 的节级消费者定义；逐字原文、需求索引明细、Talk 批次、grill、调研与审查处置明细只沿唯一原 ref，历史日志保持原文。首次写外置完整 U 原件或主文 OI 之前，读取并执行 `skills/decision-log/SKILL.md` 的「来源与未决问题写法」；覆盖收口前读同节 coverage audit，正文和原件各归该 owner。记录实际读取位置与先后，读了但动作未做仍记未执行；缺来源写具体诊断。

   - U 写入前：用当前 task 绝对基准＋`quality/evidence/decision-log-refs/requirement-change-log.md`（已有原件沿实际唯一 ref）定位真实 U 条目；主文每 U 最小决定、受影响落点与条件 ref 按「来源与未决问题写法」。
   - OI 写入前：定位当前 `decision-log.md#未决项`，按同节 OI 方法写问题与来源、真实状态与处置、解决者及下一步。
   - coverage 收口前：按当前 task 基准定位 `quality/evidence/decision-log-refs/coverage-matrix-5d.md` 或已存在 itemized 唯一 ref，逐 R／U 落点或缺口与真实排除选择沿同节 coverage audit；已有原件不搬移、不复制。

   **Talk 最小内联卡**：首次结构化提问前读取并执行 `skills/talk-with-zhipeng/SKILL.md` 的「问答工具 IO 契约」与「每答重排」，核宿主映射并等待真实回复；无工具或当前模式不可用时发同内容文本卡，记录“本轮降级为文本提问”＋真实原因，不记工具通过或失败。
2. `outline-hypothesis-talk`：
   **本步产物**：同一 decision-log 的粗粒度大纲：每块问题/边界、方向假设及会推翻它的证据。
   **进下一步前**：大纲明确仍待验证，不冒基线、实施承诺或已定方向；模糊处保原备选/取舍和未知，再据它研究。

   主会话通过真实 Talk 产出粗粒度大纲，含每块的「问题与边界」及「方向假设」。标明可修改假设和什么证据会推翻它；不作基线，不在此承诺范围或成本。模糊需求比较至少两个角度及有差异的候选，说明证据与取舍。
3. `research-and-diverge`：
   **本步产物**：内部查图／读文件的有源结论与外部研究报告及 candidates；方法分别归 knowledge-graph／deep-research 原 owner，decision-log 消费关键结论与唯一原件指针。
   **进下一步前**：内部与外部研究分别给实际执行、原文来源，或真实跳过/不可用理由，不能空白。每个候选的摘要、来源 ref、推荐/拒绝和理由可读；无候选保真实原因，研究不替用户决定。

   内部调研是查项目现图并读项目文件，核当前契约、关系与历史经验；由 `skills/knowledge-graph/SKILL.md` 承接。外部调研是检索并阅读项目外来源，由 `skills/deep-research/SKILL.md` 调用检索工具承接。两边各按自己正文的搜前声明、相关性判据和零结果写法交回，未执行与零结果分开。

   本步内部调研再次按 `skills/knowledge-graph/SKILL.md` 查询与当前未知相关的知识及 `specs/archive/` 历史经验，消费开工结论并按新问题补查，不能只在入口挂链接。先按当前职责/写集/consumer选source，经知识方法有界候选选完整ID解释；当前契约与独立历史两通道不硬排archive，宽query/god仅发现且严格限字段/条数/字符，不拿输出前25当相关性。每条拟使用结论回真实 source_file/origin 原文核命题、条件和位置；关系来源不等于端点定义，缓存同条、raw ID缺失或label命中不证明语义。存在当前图质量报告时，按knowledge-graph方法消费其误边/位置漂移/重放限制，未证实不写成事实。把适用历史经验明确落到“原文结论→本次哪个候选/假设/提问改变→具体新内容与理由”；并说明具体多知道什么；与已有建议等价就标重复/补强，不编新增收益。只报查过图不算影响产出。确无相关历史保有源的“本次无历史经验可挖”，无匹配/歧义/工具不可用仍继续普通研究并写覆盖限制；指定历史正例的独立对照与用户判断不因此被免除。不得为普通调研顺手更新、扩大JSON/忽略路径或触发付费抽取；必要时回知识方法先估范围/成本等真实许可。

   围绕大纲每块会改变方向的未知按上述分工开展研究，输入保留「大纲是待验证假设」。外部研究使用 `skills/deep-research/SKILL.md` 的 R0–R5 契约：R0 生成缺口、R1 读一手文本、R2 受限并行深读、R3 三角验证、R4 写 research-report、R5 独立审查。跳过或不可用写真实原因，研究不替用户决定。每份完成的调研报告必须显式声明 `candidates`；每个候选写摘要、证据绑定来源 ref、推荐（含拒绝）及理由，无候选写真实原因。Talk 从唯一 canonical report 读取这些事实，不用摘要或报告引用冒充候选交付。全文仍留原件；决定作者把会改变方向／范围／验收的结论与被排除候选及原因写进本日志正文，其余只给指针；取舍与逐件找回沿 deep-research「消费与所有权」的既有落点。
4. `outline-revision-check`：
   **本步产物**：研究后设计的修订大纲、需求最小索引与独立四查四行结论；两份外置原件是确认输入。
   **进下一步前**：逐块对照研究与假设，保旧判断及更改理由；多数被推翻先重整。四查已确定工作包顺序，太大或太碎时执行者当场改完给用户看。

   方向沟通与全方向调研完成后，才拆需求可核单元并设计大纲。正文每条需求只留编号、原文指针和工作包落点；需求编号永不变，新增在末尾追加，需求与工作包可一对多或多对一，不造主接字段。工作包写目标、边界、与其它工作包的关系、待弄清的问题四样；不适用写理由与依据。只写编号却找不到实际处置不算承接。
   沿当前任务已有 `requirement-index.md` 唯一原件保存完整逐字、按工作包分结构的四类来源（需求原话／选择类答复／文档转述／推断，推断明写“这是推断”）、最后变更批次，以及派生号如 R-002a 的谁接／落在哪／怎么验。原话本不存在与取不到分开；材料复述不冒逐字，原件截断照录不补。逐字答复归该索引，不另开问答原件；已有历史原件只读引用。索引单列“本次任务自己的调研（不是工作包）”，不计交付工作包。`coverage-matrix-5d.md` 保存逐单元归属、落点、验收及来源；两端同号一致。任务库文件是外置事实原件，仓库材料仍只有 decision-log，不新开正文或目录。
   将同原需求、大纲与两份原件交独立助手做前置自检，非质量裁决：覆盖与缺口直接用 `skills/decision-log/SKILL.md` 的 coverage audit；粒度直接用 `skills/spec-plan/templates/phase-template.md` 的拆／并判据，核独立消费者、独立验收、单独删减，同时报应拆与应并，不用工时、行数或验收条数门；原规则管实施边界，此处管大纲工作包，同族不同消费者。依赖沿该模板的单向无环规则。四查正文各一行写结论／依据／缺口，明细只在覆盖表，供 build-plan 与最终验收直接读取；三类缺口（没人接／有承接无落点／有落点无验收）逐条写谁接、何时接。核跨任务牵连并写谁先写谁后写。粒度负例消费归档 `design-execution-efficiency-20261014` 的 P8/T022 真实目标句，不能以单节占比代判。
   完整原文、索引与覆盖表缺任一件时明确缺项，不能仍宣覆盖完整；压缩原话、编号占位、无理由不适用分别报出并恢复受影响内容。
5. `outline-talk`：
   **本步产物**：同一日志中的骨架展示、既有攻击自查原件及用户对此骨架的真实答复或明确待答。
   **进下一步前**：先执行原第6步的轻量攻击自查，再一次展示并等待用户真实回复；未答停草稿，旧答、推荐或模拟不代答。

   主会话先攻击过早锁定、隐藏前提与更小可逆路径，保有来源风险清单，不设否决权。接着一次给用户需求清单及真实来源类型、每工作包四样的大纲、四查四行结论及两份已备外置原件；用户可核结果并确认骨架，工作包次序沿第4步已定顺序，此处不重排。重要问题沿 Talk 一题一个方向轴、后果风险与真实等待；独立问题可合问、依赖题等真实回复，零问题合法但不替代骨架回复。
   打回只改受影响部分，旧答复作废但保留原文，再展示受影响骨架；未答、取消保当前材料与未答项，恢复只消费本题真实新回复，不进入逐包。确认沿现机制保存实际展示与真人答复；字段不支持区分第5/13步用途时如实记 incomplete，不能硬造字段或凭证。第5步只确认骨架，第13步确认最终方向／范围／验收／风险，不重复问同一问题。
6. `adversarial-direction-check`：
   **本步产物**：第5步已执行攻击自查的原件与结果读回，风险仍留原风险／假设位置。
   **进下一步前**：已回读同一次自查；不重复执行，不把用户骨架答复冒成自查结果。

   同一主会话按第5步先、第6步后串行执行，回读过早锁定、隐藏前提及更小可逆路径检查的事实依据和风险清单。第5步真实骨架确认后，在本步显式执行现 `tools/cli/check-decision-log-chain.mjs --file <当前任务需求索引绝对路径>` 与 `--file <当前任务覆盖表绝对路径>`，保存第一次实际 warning/exit 给人看，只报告不阻断；未确认不得冒写该时点完成。缺自查原件如实补做并重核受影响展示，不倒填确认前已做；自查不代第7步独立方向审查、不替用户选择或新增机器门。
7. `direction-advice`：
   **本步产物**：wh-review 原 owner 保存的方向建议、provider/失败/覆盖事实与实际原件 ref；审查输入保持 questions-only 盲审投影。
   **进下一步前**：到达本步先读 skills/wh-review/SKILL.md 的现有接口，沿真实公共 review 或裸入口字节规则提交完整允许材料。答复/所选处置/结论不进入盲审投影；Kill/Recycle 权限与判据缺失不报通过，不可用不冻结同任务讨论，未变范围不追空 findings。

   用 wh-review 独立审查方向与修订后大纲，不审细节；保留原始发现、provider、失败及覆盖限制，未变范围不为追空 findings 重派。方向建议只读取当前 convergence_outline 的 questions-only 投影（仅 ID、类别、问题/未知与来源，显示状态 open），答复、所选处置、证据和结论不得出现在该投影中。 Kill 权限是建议停止无效目标或违反硬约束的方向，由用户作停止决定；Recycle 权限是建议把可修补的假设、来源或选择缺口送回对应调研或方向 Talk。两项权限与判据缺失，不记审查通过；不可用不伪装通过，也不冻结同任务讨论。
8. `module-breadth-confirm`：
   **本步产物**：全部工作包的简单／复杂分诊与入口规模事实展示，保真实回复或未答。
   **进下一步前**：分诊仅决定先补调研或直接收敛，保持第4步顺序，不冒细节已收敛。

   各工作包命名并写一到三句范围，沿已有风险／优先级、第1步入口规模事实及 Talk 范围四维判断哪些先补调研、哪些直接收敛，不另造判据。向用户展示承诺的独立可交付验收单元数、是否含用户在场或真实凭证动作，以及 mini 评估真实返回；缺事实展示缺口，未返回项不补造。返回 paused 时同批展示至少一条可选拆分路线，保用户实际答复或未答。分诊不重新确认或改排已确认骨架的工作包次序。

9. `module-convergence`：
   **本步产物**：逐模块方案/替代/验收/后果、red/blue 争议清单及每条处置或具名未决项，留现决定/处置原位置。
   **进下一步前**：每条 red/blue 争议都已逐项消费，方向或验收分歧交真实用户；新增模块补齐原研究/决定/验收，仅闭包触及的旧决定复评。amend/supersede 保历史，不用泛化摘要冒逐条收敛。

   按已定顺序逐工作包走调研→发散→收敛→就地讨论→定验收，当前包完成再进入下一包，不攒跨包批次；包内独立问题可合问。简单包消费全方向调研并定向读文件，复杂包补有边界调研。简单包免扩散仅两理由：只有一个明显合理方向且其它明显更差，或全方向调研已比较过；写理由与原件。其余用 Talk 扩散透镜，外置候选件至少两个关键决策轴不同的候选及取舍理由，非措辞变体。
   每包正文保方向结论与验收，并建五行小表（调研／发散／收敛／就地讨论／定验收）；每格一句结论＋一个原件指针及本包批次号，注明简单／复杂，不适用写理由。讨论与验收分格，不把两件事压成同句；同批不出现两个包名。新增包重走本包五段并建表，不重跑方向审查，随整体细节审查看；若该路线有真实 accepted_risk 决定，只引用其绑定原件，不能自行接受风险或称无问题。旧包回改只 amend/supersede，标需重评并更新受影响验收格，不重走全五段。

   逐模块澄清未决项，说明方案、替代、验收、后果与风险。方案写到可实现的方向与取舍为止：选哪条路、放弃哪条、接受什么代价；坐标、判定阈值、字段级方案与可粘贴代码由后续 build-plan 写入 `spec.md` 与 `phases/P<n>.md`，本步保留全部既有收敛义务。产出 red/blue 争议清单并逐条给处置，辩论未决项，不压成泛化摘要。普通细节可公开最小合理假设；方向或验收分歧交用户，选项不足回有边界的研究。中途新增需求时，在同一决策日志新增大纲模块，补齐调研、决策、方案与验收标准，不新增步骤。默认新增下游人读决策记录；仅新模块上下文传递闭包触及的旧决策记 `requires reassessment`。`context(p) = requirements(p) ∪ ⋃_{q≻p} solution(q)` 的 `≻` 是 `leadsTo` 传递闭包，此法来自单一学术提案；工程上从触及的最高抽象层向下级联。只追加信息用 amend，改变决定用 supersede 加双向人读链接，保留旧正文；不新增 runtime 状态或许可。
10. `detail-advice`：
   **本步产物**：整体一次 wh-review 细节建议、全部真实 R/U 全文与条件原件的送达事实、OI 终态及 finding 原处置格；不拆逐模块再整体审。
   **进下一步前**：全部模块收敛；全部真实 R/U 在现工作包与决定/写集或唯一覆盖格各有落点或具名缺口、写集每个路径有定序写主（批内同路径互斥，跨批重叠有真实依赖边及具名先后写者）、同一事实文内只有一个值，三者缺一仍未完成。到达本步读 wh-review 现有接口，保全文/顶层 ref 与多个原件真实 body、实际 delivery 和未证 read-confirmed 边界；下文全部风险/处置/分析义务保持。

   全部模块收敛后，对整体做一次 wh-review 细节审查，检查模块间一致性，不拆成逐模块审加整体审。先实读当前 decision-log 全文，包括全部真实 R／U，再按模板 `## 外置事实索引` 的取用条件逐件读本次需要的唯一原件全文；全部 R／U 对账沿 `skills/decision-log/SKILL.md#来源与未决问题写法`，不把主文摘要、编号存在或包外指针当全文已读。
    调用者将当前 decision 顶层 ref／sha256 放 `approved_direction`，触发的 U／coverage 等明确原件 ref／sha256 放 detail 合法的 `context_map`／`evidence_map` 顶层成员；现 `resolveMaterialRefs` 按认证 worktree 或当前 task 双 root 读真实 bytes，现 `runSimpleReview` → `buildReviewMaterials` 将完整正文装入 packet。多个原件逐件复用现读取方法，已读全文连同各自基准与原 ref 放合法成员；嵌套 ref 不被 resolver 递归读取，不能算已送达。按实际 delivery manifest 回读送出的完整成员和来源／脱敏事实；只给摘要或包外 ref 时明确 incomplete，缺原件、越界、跨 task 或 symlink 保原 TASK_FILE_INVALID／读失败，不略过。只取本次条件触发的明确原件，不扫目录、不递归解析 Markdown、不放宽 ArtifactDir writer 根、不把 detail 成员混入 phase profile；送出不证明 provider 已读懂，read-confirmed 未证保 unknown。
    本步完成以全部真实 R 与 U 在现工作包与决定／要改哪些文件或唯一覆盖原件的落点或缺口格各有一个落点，且写集表每个路径有定序写主（批内同路径互斥，跨批重叠有真实依赖边及具名先后写者），且同一事实在文内只有一个值为准——三者缺一即本步未完成。采用的发现、风险、OI 仍在其已有唯一处置格逐项保真实处置及未处置缺口，影响 R／U 时覆盖格引用原格，不要求另造“未落项”。detail 审查逐条 OI 核对终态字段（问题/成功标准、方向/范围/取舍、盲审发现/假设、剩余风险、被拒方案与未决项）是否有真实内容。Kill 权限是建议停止整体目标或范围无法成立的任务，由用户决定；Recycle 权限是建议将可修补的模块间缺口送回对应模块收敛。两项权限与判据缺失，不记审查通过。finding 逐项处置 fixed、rejected_invalid、accepted_risk 或 needs_human；方向或验收分歧交用户，其余有效问题在同任务修。严重问题若不修，展示具体损失并取得绑定风险的真实用户选择。正式确认前用 spec-analyze 准备完整一致性分析与必要修复，不替代确认后的核对。

   在正文既有整体形态节讲清整件事，让读者不读完整日志也能懂要改成什么样；跨包核对另留一小段，逐条给唯一写者／依赖顺序／边界重叠／口径统一的结论。页面承载整体形态时此处给内容与唯一页面指针，不造第二权威。 需要生成或实质更新该页时调用 `skills/answer-as-page/SKILL.md`，传当前材料与task facts、测试/审查原件和真实改动清单、当前步骤及任务库内页面/同目录节点侧车绝对路径；同一页面owner串行更新，只读派生不反写进度。首次基准缺失据实展示，较大变化才更新；具体样式沿已确认模板，真实效果仍须独立页面读回。全部工作包谈完后，在本步再次显式执行现 `tools/cli/check-decision-log-chain.mjs --file <当前任务需求索引绝对路径>` 与 `--file <当前任务覆盖表绝对路径>`，保存第二次实际 warning/exit 给人看，并回读第6步第一次原件；默认仓库扫描不等于读了任务库，只报告不阻断。旧历史时点或事后补件如实记回溯，不能补证当时已备。

## 使用技能与执行分工

按 `skill-deps.yaml` 的 name/path/trigger 直接读取所需方法。Talk、Grill、方向选择与确认由主会话负责；有边界的研究、草稿与独立审查按项目分工委派，重产物保存原件后回传短摘要和路径。方向/细节建议由独立上下文产生，实施者不自判质量；研究、审查、测试的不可用都保留真实原因。

## 人为门与审查点

- confirm：本阶段、build-plan 和 build-prd 收口时，记录用户对实际展示材料的真实答复；未答不算同意。
- authorize：只在 commit、push、merge、archive、cleanup 等不可逆 Git/交付动作前，使用 `runtime/interface/git-authorize.mjs`，执行前核对授权动作、分支与当前 HEAD；HEAD 不一致时拒绝消费旧记录；已有用户授权覆盖当前动作和范围时，按当前 HEAD 重新记录并消费，未覆盖的新增动作或范围才需用户决定。方向确认不授权这些动作，不能声称尚未发生的授权已经完成。
- 三个必留审查点：build-plan 的 wh-review 合并审查、build-code 每 Phase 的 OCR 审查、verify-code 终末 OCR 审查。本阶段方向/细节及 build-prd 文档建议仍由 wh-review 执行，不另建全 Phase 集成审查。

## 安全写入与收口

改动前用工作区/范围核对工具确认目标；需要写文件时使用安全原子写入，有共享记录冲突时使用记录锁。失败明确暴露，保留原始来源，不覆盖历史原件。当前材料说明做什么，实际执行写既有任务事实与质量记录，二者不互相代填。交接使用 `skills/stage-handoff/SKILL.md`，保存并报告该方法返回的实际不可变绝对路径；执行不是门，不要求固定复盘表或每步机器认证。正式阶段事实由现有公共流程负责，本方法不增加 writer、公共命令或生命周期对象。

阶段末统一按收口方法执行一次；交接内容与独立读取沿 `skills/stage-handoff/SKILL.md`「信息来源」「回读结果」「结束条件与边界」，返回其实际不可变路径。局部 Phase 摘要不触发收口，原失败与缺口可见，持续授权不代候选采纳。
