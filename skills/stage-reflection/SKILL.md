# stage-reflection

每个阶段结束由当前主会话发起阶段收口，顺序为归纳→分类与归口→记录阶段成本→发布并读回交接→报告。收口结论供人读，不是事实认证、质量分数、verdict、release/acceptance 或继续工作/close 的门；局部 Phase 摘要不触发 stage 结束，也不扩大物理关闭的适用阶段。

## 方法

写阶段收口前，先读取 `skills/material-writing/SKILL.md` 的「材料写作标准（唯一）」。
再读 `skills/spec-specify/SKILL.md` 的 Q01–Q13 唯一正文，然后执行本方法的写作动作。
消费者是阶段主会话和下游交接读取者；缺源如实 `unavailable`，保留原授权与失败边界。

1. **归纳**：只读本次可见会话事实、当前材料位置、实际测试/审查/失败与用户纠正，写清已做、问题与经验。历史教训作背景；不可见、压缩、截断或缺来源写 unknown，不推断发生过什么。帮助工作的做法、可改进处、阻塞/等待、人工介入原因、可简化内容和现在可安全简化事项，逐类说明已观察、未观察或未知。每条观察给实际来源与把握，未找到消费边不等于零 consumer 或删除授权。
2. **分类与归口**：按「用户选择后的归口」处理检查候选、经验与人判断待办。四类结果互不替代，只在交接正文留一处：无发现写“本次无问题”及具名依据与限制；有发现未采纳保留原候选、来源与理由，未答仍未选；失败保原始命令、退出及原件；取消保中断原因、已发生、未做与未落账项。四类都不写成“已完成”，unknown/unavailable 不冒完成。只有需要独立留档时才保存普通 `quality/evidence/reflection/<stage>.md`，已有原件只引用；未写、写失败与原始原因如实披露，不复制 transcript/输出/秘密或另建 lessons writer。
3. **记录阶段成本**：成本整个 stage 末一次，首笔带 `--start-ref`；每 Phase 不触发。回读结果层五数：墙钟、inputTokens、outputTokens、steps（DSH步骤或Codex响应项按真实来源分清）、subagentCalls；缺项保 unavailable 与原因，不把 materialBytes 当 token，不只报比例。在本次已授权的图更新与非破坏性收口各有实际结果之后、交接发布之前，由阶段主会话执行一次现入口 `node tools/cli/measure-main-agent-cost.mjs --project=<本项目> --task=<本任务> --stage=<当前阶段> --record`。project/task来自当前认证任务；本次收口同一计量窗口只记录一次，同阶段续测沿实际 until 接续非重叠窗口并保留历史行，不要求同 stage 永久只有一行。下面成本边界完整适用；按实际发布状态报告，未发布写“本阶段无记录”及原因，继续交接。
4. **发布并读回**：按 `skills/stage-handoff/SKILL.md` 的「方法」「信息来源」「回读结果」组织收口结论与四类 source，使用原 create-only 发布方法并读回实际路径。该方法保留 13 区块与独立读取职责；只准备正文不冒发布成功，旧件不冒本次成功。发布、写入或读回失败保原件、目标路径与影响，同任务安全工作继续。
5. **报告**：沿 spec 模板验收流程统一提醒 incomplete，逐条列真实尝试 ref、阻塞、提供者与恢复条件；最终报告逐条列缺口，不宣称完成。报告本次收口实际结果、交接绝对路径、经验写入/未写/失败、成本窗口与缺报、未知及未完事项。动作项和写集说明沿交接的唯一内容合同；没有真实执行不报效果完成，收口不授权 Git 或物理 close。

成本边界：执行前核工具真实路径/版本与依赖闭包、认证 checkout、外置 task 访问及原主会话身份。现工具接受三正式stage及build-prd成本标签；后者不新增正式stage。build-prd材料未供为unavailable、无审查事实为no_stage_fact；exit1但已发布的缺报行报告实际窗口与缺口，未发布才写“本阶段无记录”及原因。真实三阶段留账/来源未齐仍incomplete。

首次记录附已有真实开工事件 `--start-ref=<原件绝对路径>#seq=<用户事件seq>` 或 Codex 的 `#item_id=<URI编码UserMessage.id>`，已有账行不重置起点。build-code 由原生 Goal 启动时，可显式用 `#goal_created_at=<创建秒数>&authorization=<URI编码任务内确认ref>&sha256=<确认原件hash>`，取真实 `thread_goal_updated` 初始事件和本任务已有授权原件；不能把 Goal 包装消息伪称 UserMessage。CLI 核任务、主线程、授权目标与邻接 turn，缺失或歧义仍拒绝首行；已有账行不重置起点。首笔缺少/格式非法/未唯一匹配的 start-ref 必须 fail-closed（exit 2，不创建账行）；源文件不可读或解析失败必须 fail-closed（exit 1，不创建账行），不发布污染首行。若已有且仅有一行历史坏首行（from 与起点来源均为 `unavailable:task_start_unavailable`），只允许显式合法 start-ref 窄范围重开，保留旧字节并从真实起点重测，不用坏行 until/boundary；其它已有账行仍拒绝重置。需明确源复跑可附 `--session=<原件绝对路径>`；无参仅用原主会话实际环境及父记录明确后代，不能让子代理环境、工具 cwd 或根 SESSION_ID 冒当前主会话。

读回任务根 `main-agent-cost.md` 的新增 27 列行、旧字节前缀、实际 from/until、来源与缺报。未触发、读取/锁/写入/取消失败都保 CLI 原件并披露实际原因；可写缺口行按实际内容报告，留账失败不阻塞收尾。若将删除唯一工具 worktree，先在工具与原身份可访问时 record 并读回账本，再按既有授权清理；不从已删除入口补记，不假定存续 repo 有同版闭包。交接明确实际 until 之后的物理清理、交接发布与最终回复未计入该笔。成本由主会话在本步骤触发，交接方法只负责发布，不新增共享 writer。

## 单元模式：单元复盘记录

阶段末的收口照旧；单元完成时另记一条「单元复盘记录」，作者当场写，不等到阶段末。
触发点只有一个：单元完成时。单元只有三类：任务分节、一个包、一个 Phase 的设计与执行完成。阶段不是单元——阶段末只汇总，不另记一条。
单元记录是 Phase 内动作，不是阶段门：不改阶段与 Phase 的推进条件；缺记录只让该单元这一条判未完成，不拦后续工作。
一个 Phase 的设计与执行合起来是一个单元，只记一条：设计侧切分不单独发记录，执行完成时由 run-phase 的收尾记，设计信号与切片写进同一条。
写入顺序固定三步，不跳步：

1. **先发摘要**：在聊天里先发不超过五条，每条一句、结论先行；第五条之后的内容并进已发条目并写明合并理由；末尾给记录路径。摘要不复述改动清单，只说问题、改了什么、怎么验。
2. **再写五问记录**：按下面一行模板写一条，落在任务根 `quality/evidence/reflection/`。没写的单元不补写历史，不扫其它任务。
3. **有表才更新状态**：域规则表由 P6 交付；表未交付时状态列只写「命中」「首次」「待 P6 表」三种，不自造列名、不写 `specs` 路径。

记录写完当场核四类落盘（decision-log、spec、phase、提交）是否齐，齐了直接开下一个单元、能并发则并发、不空等后台（来源：R-018）；每条记录另点名它对应任务四的五个根因（P13 漏产、76≠78、T08 零命中、7 条押在任务外、单元无复盘）中的哪一条，写不出对应就写「无」＋具名理由（来源：R-020）。

五问写一行，逐字模板：

`- 问题：<一句话现象>｜以前有没有：<命中/首次/待 P6 表>｜实际改了什么：<改动位置与动作>｜为什么不用更高层：<为什么不在规则或检查层解决>｜怎么证明：<证据指针>`
记录头三行（写在同一文件开头）：总结原文（与聊天里发出的一致，最多五条，每条一句、结论先行；不足五条时写明合并理由）；发出时刻（真实发出那一刻，`%Y-%m-%d %H:%M`）；会话标识（发总结的主会话 id 或 agent 名）。

「怎么证明」只放指针，不贴长文。指针三条硬要求：

- 仓库内的证据写相对路径加锚加行区间，例如 `skills/stage-reflection/SKILL.md:10-26`；
- 任务库里的原件写绝对路径加该文件的 mtime（`stat -f '%Sm' -t '%Y-%m-%d %H:%M' <路径>`，Linux 用 `stat -c '%y'`）；不写「文件内时间戳」——`.output` 这类原件正文里没有时间；
- 写完当场按指针打开读回一次；读不到就把该条判未完成，并保留真实失败。
记录另答三句：①哪条读数变了——`原读数 → 现读数`（两个读数都要能按指针回读）；②哪个候选被驳回——候选｜来源｜理由｜保留位置；③下次改什么——指到下一单元的具体一步。①②至少有一句给实；另一句确实没有就写「无」＋具名理由；两句都只有「无＋理由」的，整条记录判未完成。三组只读行的「无内容写无」不适用于五问与这三句。

只看两样：当前任务的真实材料，和已交付的域规则表。不扫历史任务、不计次数、不评复盘内容好坏。
`specs/Improvements.md` 仍归阶段收口的经验与判断待办写入；单元记录不写它，避免两处各写一份。
阶段末只汇总已有单元记录，不重跑、不计数。
记录文件名 `unit-<YYYY-MM-DD>-<三位序号>-<单元 slug>.md`；序号作用域是本任务＋本目录＋当日，写前取当日最大号加一，撞号用独占写改用下一个号并在记录头加一行撞号说明。
记录另留三组只读行，供 P7 汇总：晋升（规则；落点；旧错原件；失败读数；当前通过）、驳回（候选；来源；理由；保留位置）、未执行（动作；原因；恢复条件）；无内容写「无」。

## 用户选择后的归口

能靠结构或确定性断言消除的错误走检查，需要真实情境取舍的未解问题走判断待办。主会话展示候选的问题、来源、建议与依据，用户决定机械性或判断性及选择；未答保未选，任务实施授权或代理转述不代候选采纳。同一错误类实际发生过两次才称重复；单次或次数不可见如实说明。可直接落账的有源经验不等逐行批准；需要用户作新决定的项保持待用户决定，批准与落账分开。

检查：涉及机械错误时先读现有 check/lint/test 命令与真实 CI/提交钩子，区分已有检查未接线/失效、确需新增与缺来源，未读到的配置保 unknown。用户已选机械候选后，优先 architecture → types → test，再考虑已有 CI 或窄脚本，文档或 agent 规则最后。新检查须在有源真实历史错误上失败再验证当前修复；缺历史字节/场景/执行就写未验证，不用文本、旧报告回放或自造反例冒 RED/GREEN。只有机制真正覆盖原约束、消费者仍承接含义后才删被覆盖散文；未被机制覆盖的规则保留，不为删字新建检查器。未选候选只保有源方案，不自动写生产检查或规则账本/评分平台；改源码、退役需求或不可逆动作仍沿原授权。

机械检查出现可疑通过或同类修正再次发生时，读取 [build-code 终末 检查可信度方法](../../workflows/build-code/SKILL.md#测试充分性与检查可信度) 判断；本处只导航该唯一正文。

经验与判断待办：写经验前先实际读取并执行 `skills/norm-sync/SKILL.md`；已独立验证、合法且有适用目标的变化进入唯一专业规范并更新AGENTS，只清对应已验证且已同步项，不再保旧追加第二份规则。未解决的人判断待办仍沿下文原三列表与用户解决确认；不把验证不足的推断写规范。先核业务仓在已授权写集内，默认读取该仓根下 `specs/Improvements.md` 与相关项原来源。确有能改变下次行动的有源内容才创建文件；没有内容就给具名依据，不造空文件或教训。经验与未解待办合一，按业务仓自己的模块分节，节名用项目/模块名（例如「审查模块」「证据模块」），禁止用任务编号或任务流水命名；来源任务写进条目括号。现有任务命名节保留全部条目，读回标「待迁移」，下次写该模块时仅把节名改成模块名，不删条目、不改他人条目内容。每节三列小表：问题／下次改变的行动／状态；不设类型列。文件头一行指向本方法的写作规则。每条一句、结论先行、同词同义、不重复意思或堆形容词；来源（仓、任务、阶段）写在问题括号或状态，缺源写 unknown，不省略。说不清下次遇到什么情况会改变行动的条目不收；机械错误直接归检查，不塞经验队列。状态用普通文字写“已落账”“待用户决定”“已解决（用户确认）”或 unknown，未答仍未决，不冒已采纳。`specs/Improvements.md` 只收未决事项；已证规则只经 norm-sync 写域表锚点，未登记先登记，不改写第二处正文。

写入：本段仅对尚未同步的未解待办适用，已验证经验先走norm-sync唯一writer。先读目标现字节和他人条目；存在时保旧追加，不存在且有内容时创建。判重键是“下次要改的那一步 + 现象”，不看来源、任务名或时间；重复只追加一行原条目引用，不复制正文。不确定是否同一事实就保两条互引。候选准备、AI起草、读源与用户判断全在锁外完成。最终写入实核业务仓同一物理规范权威根realpath，使用现有 `withLock(projectRoot,"norm-sync",callback)`，与norm-sync对同Improvements的迁移共一root/name；task.withRecordLock不能替代。锁内再次读目标before并核判重：与准备before不同或出现无法归属的字节时，保留当前与本次待写双方并报告，不覆盖或猜合并；原owner只能退出锁后按新事实重准备。before相符才用现有writeFileAtomic原子写并立即读回旧内容/增量/路径。没有可核共同root或授权只停该写入；不嵌套norm-sync/另一锁、不持锁等待child或网络，外层已持相同锁时由该外层唯一writer串行完成，不再重入。appendRecord只保普通事实，不追加经验正文；单文件原子写不代共同锁，不合作外部编辑风险仍保。锁内写后读回必须核对节名：历史任务编号节标「待迁移」；同时核旧内容、增量及实际路径，失败保原始错误，中断保已发生与未落账项。越界或未授权记 unavailable 与具体原因，不回落工具仓、不扩范围。

后继任务：按真实问题默认读取业务仓文件、相关条目与原来源，说明条目如何改变下一次行动；无可用项给具名检索范围和理由，“没找到”不当“没有”。已验证且经norm-sync同步的对应经验项依该方法读回后清理；未解人判断仅在用户明确确认该项已解决后才清理；未答、缺源或未找到不当已解决，保留其它任务字节。目标业务仓由调用方给出，不写宿主/任务绝对路径，不新增机器 reader、状态或附件。

无操作：用户明确不采纳时保原候选与真实选择来源，不创建检查或已选待办。未参与选择、等待时长与问答质量未观测写 not_observed/unknown，不填 0；取消不推断为选择或质量通过。收口不触发新的复盘运行、认证、checkpoint 或持久对象，缺来源/不可用不冻结同任务安全工作。

## 判断词表与完成检查

普通 md 可用 `classification∈{keep|optimize|simplify|merge|remove_candidate|add|needs_evidence}` 描述建议，severity 说明影响、confidence 说明把握而非质量等级，evidence_refs 指实际文件/节；缺来源写限制并降低把握，不补猜。词表供人读，不形成固定结构或必填字段。

交接前逐项说明：六类过程观察的已观察/未观察/未知；每条 observed 的实际来源与把握；unknown 的缺源原因与 not_applicable 的具体理由；四类结果各自必备要素；经验、成本、交接的实际执行/未执行/失败与路径；原失败及覆盖限制。可见状态与来源完整性只记事实，不推质量结论；缺项披露，不作继续工作或 close 的门。没有固定 JSON schema、identity 三件套、13 步机器清单或 run/reflect 认证，不重建旧产物。

写完材料，按 `skills/material-writing/SKILL.md` 的「写完自检」逐条核；核不过就改，不交出去。
