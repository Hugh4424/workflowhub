# stage-reflection

每个阶段结束由当前主会话发起阶段收口，顺序为归纳→分类与归口→记录阶段成本→发布并读回交接→报告。收口结论供人读，不是事实认证、质量分数、verdict、release/acceptance 或继续工作/close 的门；局部 Phase 摘要不触发 stage 结束，也不扩大物理关闭的适用阶段。

## 方法

写阶段收口前，先读取 `skills/spec-specify/SKILL.md` 的「技能写作规范（WR001）」唯一正文，再执行本方法的写作动作；消费者是阶段主会话和下游交接读取者。缺源如实 `unavailable`，保留原授权与失败边界。

1. **归纳**：只读本次可见会话事实、当前材料位置、实际测试/审查/失败与用户纠正，写清已做、问题与经验。历史教训作背景；不可见、压缩、截断或缺来源写 unknown，不推断发生过什么。帮助工作的做法、可改进处、阻塞/等待、人工介入原因、可简化内容和现在可安全简化事项，逐类说明已观察、未观察或未知。每条观察给实际来源与把握，未找到消费边不等于零 consumer 或删除授权。
2. **分类与归口**：按「用户选择后的归口」处理检查候选、经验与人判断待办。四类结果互不替代，只在交接正文留一处：无发现写“本次无问题”及具名依据与限制；有发现未采纳保留原候选、来源与理由，未答仍未选；失败保原始命令、退出及原件；取消保中断原因、已发生、未做与未落账项。四类都不写成“已完成”，unknown/unavailable 不冒完成。只有需要独立留档时才保存普通 `quality/evidence/reflection/<stage>.md`，已有原件只引用；未写、写失败与原始原因如实披露，不复制 transcript/输出/秘密或另建 lessons writer。
3. **记录阶段成本**：在本次已授权的图更新与非破坏性收口各有实际结果之后、交接发布之前，由阶段主会话执行一次现入口 `node tools/cli/measure-main-agent-cost.mjs --project=<本项目> --task=<本任务> --stage=<当前阶段> --record`。project/task来自当前认证任务；本次收口同一计量窗口只记录一次，同阶段续测沿实际 until 接续非重叠窗口并保留历史行，不要求同 stage 永久只有一行。下面成本边界完整适用；按实际发布状态报告，未发布写“本阶段无记录”及原因，继续交接。
4. **发布并读回**：按 `skills/stage-handoff/SKILL.md` 的「方法」「信息来源」「回读结果」组织收口结论与四类 source，使用原 create-only 发布方法并读回实际路径。该方法保留 13 区块与独立读取职责；只准备正文不冒发布成功，旧件不冒本次成功。发布、写入或读回失败保原件、目标路径与影响，同任务安全工作继续。
5. **报告**：报告本次收口实际结果、交接绝对路径、经验写入/未写/失败、成本窗口与缺报、未知及未完事项。动作项和写集说明沿交接的唯一内容合同；没有真实执行不报效果完成，收口不授权 Git 或物理 close。

成本边界：执行前核工具真实路径/版本与依赖闭包、认证 checkout、外置 task 访问及原主会话身份。现工具接受四正式stage及build-prd成本标签；后者不新增正式stage。build-prd材料未供为unavailable、无审查事实为no_stage_fact；exit1但已发布的缺报行报告实际窗口与缺口，未发布才写“本阶段无记录”及原因。真实五阶段留账/来源未齐仍incomplete。

首次记录附已有真实开工事件 `--start-ref=<原件绝对路径>#seq=<用户事件seq>` 或 Codex 的 `#item_id=<URI编码UserMessage.id>`，已有账行不重置起点。首笔缺少/格式非法/未唯一匹配的 start-ref 必须 fail-closed（exit 2，不创建账行）；源文件不可读或解析失败必须 fail-closed（exit 1，不创建账行），不发布污染首行。若已有且仅有一行历史坏首行（from 与起点来源均为 `unavailable:task_start_unavailable`），只允许显式合法 start-ref 窄范围重开，保留旧字节并从真实起点重测，不用坏行 until/boundary；其它已有账行仍拒绝重置。需明确源复跑可附 `--session=<原件绝对路径>`；无参仅用原主会话实际环境及父记录明确后代，不能让子代理环境、工具 cwd 或根 SESSION_ID 冒当前主会话。

读回任务根 `main-agent-cost.md` 的新增 27 列行、旧字节前缀、实际 from/until、来源与缺报。未触发、读取/锁/写入/取消失败都保 CLI 原件并披露实际原因；可写缺口行按实际内容报告，留账失败不阻塞收尾。若将删除唯一工具 worktree，先在工具与原身份可访问时 record 并读回账本，再按既有授权清理；不从已删除入口补记，不假定存续 repo 有同版闭包。交接明确实际 until 之后的物理清理、交接发布与最终回复未计入该笔。成本由主会话在本步骤触发，交接方法只负责发布，不新增共享 writer。

## 用户选择后的归口

能靠结构或确定性断言消除的错误走检查，需要真实情境取舍的未解问题走判断待办。主会话展示候选的问题、来源、建议与依据，用户决定机械性或判断性及选择；未答保未选，任务实施授权或代理转述不代候选采纳。同一错误类实际发生过两次才称重复；单次或次数不可见如实说明。可直接落账的有源经验不等逐行批准；需要用户作新决定的项保持待用户决定，批准与落账分开。

检查：涉及机械错误时先读现有 check/lint/test 命令与真实 CI/提交钩子，区分已有检查未接线/失效、确需新增与缺来源，未读到的配置保 unknown。用户已选机械候选后，优先 architecture → types → test，再考虑已有 CI 或窄脚本，文档或 agent 规则最后。新检查须在有源真实历史错误上失败再验证当前修复；缺历史字节/场景/执行就写未验证，不用文本、旧报告回放或自造反例冒 RED/GREEN。只有机制真正覆盖原约束、消费者仍承接含义后才删被覆盖散文；未被机制覆盖的规则保留，不为删字新建检查器。未选候选只保有源方案，不自动写生产检查或规则账本/评分平台；改源码、退役需求或不可逆动作仍沿原授权。

机械检查出现可疑通过或同类修正再次发生时，读取 [verify-code 检查可信度方法](../../workflows/verify-code/SKILL.md#测试充分性与检查可信度) 判断；本处只导航该唯一正文。

经验与判断待办：先核业务仓在已授权写集内，默认读取该仓根下 `specs/Improvements.md` 与相关项原来源。确有能改变下次行动的有源内容才创建文件；没有内容就给具名依据，不造空文件或教训。经验与未解待办合一，按业务仓自己的模块分节，每节三列小表：问题／下次改变的行动／状态；不设类型列。文件头一行指向本方法的写作规则。每条一句、结论先行、同词同义、不重复意思或堆形容词；来源（仓、任务、阶段）写在问题括号或状态，缺源写 unknown，不省略。说不清下次遇到什么情况会改变行动的条目不收；机械错误直接归检查，不塞经验队列。状态用普通文字写“已落账”“待用户决定”“已解决（用户确认）”或 unknown，未答仍未决，不冒已采纳。

写入：先读目标现字节和他人条目；存在时保旧追加，不存在且有内容时创建。判重键是“下次要改的那一步 + 现象”，不看来源、任务名或时间；重复只追加一行原条目引用，不复制正文。不确定是否同一事实就保两条互引。写前再次读回：发现他人改动或无法归属的字节，保留当前文件与本次待写双方字节并报告，不覆盖或猜合并。使用现有原子写完成读改写，不用 appendRecord 追加同一文件；原子覆盖本身不保证并发不丢失。写后读回旧内容、增量及实际路径，失败保原始错误，中断保已发生与未落账项。越界或未授权记 unavailable 与具体原因，不回落工具仓、不扩范围。

后继任务：按真实问题默认读取业务仓文件、相关条目与原来源，说明条目如何改变下一次行动；无可用项给具名检索范围和理由，“没找到”不当“没有”。只有用户明确确认该项已解决后才清理；未答、缺源或未找到不当已解决，保留其它任务字节。目标业务仓由调用方给出，不写宿主/任务绝对路径，不新增机器 reader、状态或附件。

无操作：用户明确不采纳时保原候选与真实选择来源，不创建检查或已选待办。未参与选择、等待时长与问答质量未观测写 not_observed/unknown，不填 0；取消不推断为选择或质量通过。收口不触发新的复盘运行、认证、checkpoint 或持久对象，缺来源/不可用不冻结同任务安全工作。

## 判断词表与完成检查

普通 md 可用 `classification∈{keep|optimize|simplify|merge|remove_candidate|add|needs_evidence}` 描述建议，severity 说明影响、confidence 说明把握而非质量等级，evidence_refs 指实际文件/节；缺来源写限制并降低把握，不补猜。词表供人读，不形成固定结构或必填字段。

交接前逐项说明：六类过程观察的已观察/未观察/未知；每条 observed 的实际来源与把握；unknown 的缺源原因与 not_applicable 的具体理由；四类结果各自必备要素；经验、成本、交接的实际执行/未执行/失败与路径；原失败及覆盖限制。可见状态与来源完整性只记事实，不推质量结论；缺项披露，不作继续工作或 close 的门。没有固定 JSON schema、identity 三件套、13 步机器清单或 run/reflect 认证，不重建旧产物。

本地偏离：经验与判断项按「用户选择后的归口」写入业务仓 `specs/Improvements.md`，保用户选择、检查与人确认清理规则；不搬上游 `CODING_STANDARDS.md`、规则执行表、自动修复/提交或 pstack 编排器。写作工具调用改为上节 WR001 唯一规范指针，保持现有单一路径与可搬运性。

更新入口：迭代本方法时对照上述三个固定子文件、其更新与更优候选，说明源差和本地偏离后决定采用，不自动追 HEAD。子文件或版本不可核时保具体缺口并交来源 owner；来源核定不证明方法效果或质量通过。
