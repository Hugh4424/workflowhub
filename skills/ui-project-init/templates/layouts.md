## 必填项与填写指引

作者把场景条件与原值源写到同一处。

| 项 | 填写指引 | 反例及原因 |
| --- | --- | --- |
| 场景与意图 | 写用户正在做的事、主区域与已确认来源 | “做一个dashboard”：没有区域优先级 |
| 区域稳定名 | 同一区域全文用同一个名字 | “右栏/侧栏/监测区”混用且无定义：无法定位同一容器 |
| 增长与overflow | 写哪个容器在什么条件下增长或滚动 | “页面自适应”：无法核极值 |
| 真实实现映射 | 引路由、容器、样式位置并标观察状态 | 同一组件export证明跨页同实例：混淆代码复用与资源生命周期 |
| 原值源 | 只链接尺寸/断点拥有者 | 在两份文档抄断点数字：变更后规则冲突 |
| 反例与判据 | 列内容极值、视口条件及可观察失败 | 只列设备名称：不知道测了什么内容 |

## 反例与核对

核对者从一个场景的极值检查区域是否仍可消费。
错误写法：“所有页面统一满屏，内容多了自动处理。”原因：它抹掉不同场景的滚动与增长责任。
可照抄写法：“当 `<主区域内容增长>` 时，`<容器>` 按 `<原样式源>` 滚动。`<操作区>` 保持 `<已确认关系>`。”
读者用长文本、空内容和局部失败各填写一个适用条件；不适用者给理由。样张不代表已经做过视口或浏览器验收。

## 缺口与下一步

作者优先补会迫使renderer猜区域关系的来源。
现在必需：场景意图、主辅关系、真实容器与增长规则。可待补：范围外视口或未观察组合，保验证缺口。确实不适用：无浮层场景的浮层定位，写无该组成的依据。
缺口句式：“缺 `<场景/容器来源>`，因此 `<消费者>` 不能决定 `<布局事项>`；`<布局或页面owner>` 补 `<具体图/原文/观察>`，以 `<可核区域关系>` 完成。”
精确值仍归原源；未确认布局与未知运行效果不能因模板完整而变成已批准或已验证。
