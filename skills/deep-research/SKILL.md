# Deep Research

## 目的与边界

先按调用者提供的当前问题与已确认方向选择分支：会改变产品方向的问题沿 R0–R5 形成普通研究报告，供 `make-decision` Talk；build-plan 或后续阶段方向已收敛的点状疑问用下节轻研究，承接 `spec-research` 原职责。调用者给材料内容、明确问题、允许读取范围及宿主批准的能力，不自行发现 task/storage/repo 路径。两分支不在同一消费场景重复深调研；研究不是 review、质量门或用户确认，也不自行写 `decision-log.md`。

本技能负责外部调研，由本技能按下方工具路由调用检索能力、读取外部来源；内部图与项目文件定位交 `skills/knowledge-graph/SKILL.md`，调用者提供的内部事实仍可作为外部问题的输入。两分支检索前与交回时均执行：

- **搜前声明**：写明要回答的外部问题、需要的支持／反例证据、拟用中英文查询词和来源范围，以及什么原文、版本与适用条件算找到。
- **相关性判据**：逐条核来源是否直接回答该问题、版本／日期和适用场景是否匹配；证据强度沿 R3 的一手／权威二手／推断与 confirmed／supported／disputed／unresolved 口径，缺原文不得仅凭标题或搜索摘要认相关，不新增评分或字段。
- **零结果写法**：实际检索但无可用证据时，写哪个问题、实际词与来源范围、为什么无结果、是否改变方向或仍留哪个未知；缺工具、取消、失败与未检索分别说明，不把未执行称零结果。

研究结论必须绑定来源原文、证据和不确定性。缺工具、缺来源、来源冲突或复核
不可用，都要记录真实事实；不能用搜索摘要、默认知识或空报告伪造完成。

## 轻研究 — 已收敛方向的点状问题

1. 读取调用者提供的规格内容、已定方向和明确问题。每题只处理该规划疑问；若发现必须改变母方向，交回调用者说明双方来源与影响，不自行选方向或强开 R0–R5。
2. 在允许材料内先查已有事实；确需外部来源时按下方批准能力/降级边界定位并读原文。逐题返回证据及定位、备选、建议、取舍和剩余不确定；缺源、冲突、错误或取消保真实原因与已取得的部分事实，不用默认知识补齐。
3. 只返回既有内存 `spec-research-result.v1` 内容，不写正式报告或其它文件；该内存结果不能冒 R0–R5 深报告。无须研究时返回 `status: skipped` 及调用者提供或真实事实支持的理由，说明问题和依据，不声称执行了检索。工具缺席/失败保持 unavailable 或 incomplete 与具体影响，由调用者承接未决。

## R0 缺口问题：从需求框架生成

1. 读取当前需求框架骨架和已确认方向，只从五个维度生成缺口：业务目标、流程/表面、数据/状态、成功/失败/验收、约束/非目标/延期。
2. 每个问题绑定一个决策轴、可能改变的方向和当前证据；不把实现偏好包装成方向问题。
3. 没有能改变方向的问题时返回 `status: skipped`，并写明跳过理由；不能为了显得做过调研而硬开检索。

## R1：迭代检索与原文阅读

1. 外部发现读取仓内 `skills/anysearch/SKILL.md` 方法，再用宿主已批准且实际可用的搜索能力检索；`anysearch` 是方法名，不假定存在同名宿主工具。外发须在真实批准范围内，原文读取用实际可用的 `web_fetch`；每轮记录查询、查询重写、语言和结果范围。
2. 需要外部来源时同时覆盖中英文查询，优先一手来源、规范、原始数据和官方文档。
3. 搜索结果只是候选入口，关键结论必须读取原文页面或文件并记录定位信息；摘要、标题和二手转述不能单独成为证据。引用外部来源时写清版本与回原文的直达链接；版本/签名类事实须实读依赖文件并写出处，取不到写 `unverified` 与具体来源缺口。来源分级与完整取回坐标沿 `skills/catalog.yaml` 唯一登记。
4. 每个问题最多 3 轮检索。连续 2 轮没有新增可改变方向的证据即视为饱和；达到时间盒也必须停止并记录原因。

## R2：并行深读

对仍未饱和的问题并行派独立上下文子代理。每个子代理只读分配给它的来源包，返回来源、关键证据、冲突、置信度和未决项；不得共享未验证结论或把同一来源复制成多个独立来源。并行能力不足时串行深读，并记录降级事实。子代理回传按 `AGENTS.md` 的「### 派发与回传」六项固定开头；研究类另给来源与覆盖。

## R3：三角测量

对关键结论至少做来源类型或立场独立的交叉核对：

- 区分一手来源、权威二手来源和推断，不把同一原始来源的转载算成独立确认；推断就地紧跟“这是推断”及依据。引用保原版本与直达链接，无法核实的版本/签名写 `unverified`；
- 对冲突逐条列出双方证据、时间、适用范围和无法裁出的部分；
- 给出 `confirmed`、`supported`、`disputed` 或 `unresolved`，并保留反例和未决项；
- 结论必须说明它会改变哪个决策轴，不能只堆链接。

## R4：保存普通研究报告

方向分支用 `scripts/research-run.mjs` 的 `runResearch` 注入宿主真实 `search`/`fetch`，经既有 `publishResearchReport` 写到任务约定的 `quality/evidence/research/` 普通 JSON 原件，再以 `readResearchReport` 回读。返回实际文件路径；保留原始失败和旧报告，不用内容 hash 命名、run 认证或 receipt 作为 Talk 输入前提。

同主题多件用主题细分区分，例如「日期-取消语义-官方协议.md」与「日期-取消语义-失败反例.md」，不用序号；按真实主题避免重名。全文唯一原件留在既有证据目录，原件不搬移、不复制。报告包含上述搜前声明、相关性判断和零结果事实，以及问题/决策轴、查询与工具实际使用、读过的来源及定位、关键证据、独立交叉核对、冲突和反例、未决项、适用范围、停止/饱和原因、独立复核事实与覆盖限制。无法量出的指标写 unknown/null 与原因；这些读数不判通过。

出现可供用户选择的候选时，逐项写候选摘要、与原需求关系、原始来源、推荐/不推荐及理由。没有候选写真实理由；缺字段、未读原文、失败或不可用保持 incomplete/unavailable，不用空报告冒充完成。报告没有用户决定或质量 verdict。

## R5 独立复核

由独立上下文复核当前报告的来源与定位、原文阅读、三角测量、冲突和覆盖限制。复核只给
建议和 findings，不给产品方向 verdict。复核不可用时报告
`review.status: unavailable` 及错误类别；这不阻断 Talk，但也不能宣称研究已被独立
复核通过。

## 受控降级状态

首选路由失败时只记录一次 `awaiting_user_approval`，不自动调用兜底。用户明确批准后状态为 `approved`，且必须同时记录 `web_search` 与 `web_fetch` provenance；用户拒绝为 `declined`。`awaiting_user_approval` 和 `declined` 都生成 `unavailable`，后续成功必须写新 `completed` 原件，不能覆盖旧事实。

## 跳过、降级和停止

- 跳过调研必须写：哪个问题被跳过、为什么不会改变方向、依据哪些现有事实；
- 外部工具缺席时可记录不合格调研事实和待补问题，不能用纯 agent 猜测填来源；
- 工具路由、并行能力或网络失败都要记录具体错误和影响范围；
- 满足“每问题最多 3 轮”“连续 2 轮无新增”或时间盒任一条件即停止，并说明是饱和、时间盒还是未完成；
- 本技能不裁定研究 `pass`、产品方向 `approved` 或推进 gate；上节 `approved` 仅是实际兜底外发批准事实。研究事实可作为 Talk 或轻规划输入，但不自动改变决策。

## 工具路由

| 场景 | 工具 | 约束 |
|------|------|------|
| 外部发现 | `anysearch` 方法＋宿主批准的搜索能力 | 核真实能力，记录查询、语言和结果范围 |
| 外部原文 | `web_fetch` | 必须读取原文并留定位 |
| 外部并行深读 | 独立上下文子代理 | 来源包隔离 |
| 内部定位 | `glob` / `grep` / `read` / `git` / `ast-grep` | 只读当前允许材料 |
| 无工具 | `none` | 只记录不合格事实，不伪造来源 |

## 消费与所有权

方向分支由 `make-decision` 消费普通报告的实际路径作为 Talk 输入；全文留唯一原件，改变方向、范围、验收的关键结论，以及被排除的候选与原因，由决定作者写进 decision-log 正文，其余只给原件指针。取舍和来源沿任务既有索引件的内容格登记，不另建字段或对象；轻分支由 build-plan 或已收敛方向后的调用者消费内存结果，仍不写报告。

跨任务找回只保证逐任务可查：按调用者提供的任务材料和 decision-log 既有索引逐件定位原件；现有任务索引已从主干删除，不以它作为找回入口，也不新建跨任务索引。本任务的研究导航沿既有 `requirement-index.md` §5，覆盖与候选分别沿 `coverage-matrix-5d.md`、`research-candidates.md`，由各原 owner 维护；其它任务沿各自已存在的实际落点，缺件写明。调用/登记迁移由原 owner 承接，职责合并不证明旧调用已迁，也不授权提前删除旧薄技能。研究机制被正式替代且没有消费者后，才可按仓库治理规则删除本技能和对应登记；旧报告只读保留。

## 写作与固定来源

来源权威：[catalog](../catalog.yaml#skills.deep-research)；本便携小卡非权威；单技能副本缺catalog时向来源维护者取登记。
创建或改写 agent 方法时，读取 `skills/spec-specify/SKILL.md` 的「技能写作规范（WR001）」唯一规范；保原步骤、条件、权限、失败强度和受保护字面，缺源如实 unavailable，不复制规范。

来源线索：Matt research；采用原文来源、逐事实引用与推断分离；轻分支保本地 spec-research 的明确输入、内存/skipped 和不写文件合同。保本地 R0–R5、批准外发、饱和/时间盒、独立复核不可用与失败原件，不采用上游临时研究分支、额外报告或宿主硬依赖。更新时核固定子文件和本地偏离，不自动追 HEAD。

## 同仓方法依赖

`skills/anysearch/SKILL.md`、`skills/spec-specify/SKILL.md`；按上文实际条件读取，搬运时需同时提供或由调用者提供可读原件。

薄入口：`node skills/deep-research/scripts/research-run.mjs --input <caller输入.json>`。输入含 question、decisionAxis、queries（query/language）、recordDir、taskId、stage；CLI 没有宿主函数时产出 unavailable 原件，不能冒检索。实际检索由模块 caller 调用 `runResearch({ ...input, search, fetch })`；search 返回实际 tool 与 results（url/source_tier），fetch 返回实际 tool、text 与 locator。无真实缺口时不启调研，只写跳过与依据。零结果写 unavailable、error_class=no_results、原因「检索已执行且0结果，非工具不可用」，保查询、工具与空返回；工具缺席与失败独立记 tool_unavailable。三角测量及独立复核由 R3/R5 承接，脚本 completed 仅表示原文已取回并成报告。

唯一消费者是按 R0–R5 调用的 make-decision 主会话与 build-plan；owner 为本技能维护者。等价宿主检索—记录—发布入口接管且正文改指它，或技能退役时删除此薄入口，不新增报告格式或平台。

模块 caller 提供真实 `fallback` 审批状态/requested_route/approval_ref；备用 callable 必须预先声明实际 `search.route=web_search`、`fetch.route=web_fetch`，入口仅按真实调用生成used_routes与tool_usage provenance。awaiting/declined不调用备用能力。现有producer要求approved报告同时有两路实际调用，若search先失败或零结果而fetch未发生，明确抛「出版限制」并保原始原因/内存report，不伪造fetch、不降级审批、不宣称已出版unavailable。单URL可恢复失败保原URL/原因/open_items并继续其它候选及后续查询；明确AUTHORIZATION_DENIED/PERMISSION_DENIED/AUTHENTICATION_FAILED/INVALID_CREDENTIALS/INPUT_INVALID码或401/403停止同一路径，不能凭错误文本猜。完成报告仍保失败缺口；全部不足保真实unavailable。原文tool/text/locator结构异常同样进入失败记法。
