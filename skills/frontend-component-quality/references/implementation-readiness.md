# 前端实现就绪

本参考供 `frontend-component-quality/SKILL.md`、计划作者与 UI 实施者使用。输入是本次真实需求、已接受计划或实际差异、目标项目规范和消费者；输出留在当前任务材料，不另建阶段、状态或质量门。

## 怎样判断与记录？

先按入口的三源判断触发。适用时，在当前任务记录下表；每行填实际来源（路径和稳定节、版本或范围）、状态、缺口的补法与知会者、真实消费者和处置。找不到记 `unknown`、已查范围及 owner，不等于不存在；不适用写 `N/A` 和理由。来源冲突、过期和不可读各记影响与恢复条件。表格是判断记录，单独打勾不算已消费。

| 项 | 来源 | 状态 | 补法 / 知会者 | 消费者 | 处置 |
| --- | --- | --- | --- | --- | --- |
| 领域、视觉、组件、布局、交互、工程、内容、质量八类规范 | 按类填专业源 | 按类填 | 按类填 | 按类填 | 按类填 |
| 前端组件、前端布局、设计组件、设计布局四类资产 | 按类填真实对象及用途 | 按类填 | 按类填 | 按类填 | 按类填 |
| 设计输入 | 已确认设计及范围 | 填实情 | 填实情 | 填实情 | 填实情 |
| 检查命令 | 目标项目实际命令与用途 | 填实情 | 填实情 | 填实情 | 填实情 |
| 测试数据与执行 | 每项 AC 的数据来源、层级和执行者 | 填实情 | 填实情 | 填实情 | 填实情 |

按 `skills/project-norm-init/SKILL.md`「规范职责」找适用专业 owner 与等价实质来源；八类是职责，不要求八个固定文件。逐类核其作用域、规则、版本、owner 和 consumer。资产沿入口的 Map、真实用途与调用核复用或缺口；C03 两链的特定台账只适用其声明范围。代码说明现状，不能反推应有规范或设计值。

按每个影响本次差异的缺口决定：

- `proceed`：所需输入、消费者及检查均可定位；实施并保留实际消费点。
- `proceed-with-gap`：缺口不影响本次差异；写影响、知会者及复核点，缺口继续可见。
- `supplement`：相关缺口可由已确认决定、设计源、测试或平台语义推导；实施者在已有授权和写集内补原专业源的最小条款并知会对应 owner，写来源、适用范围、正反例、消费者及验证，补齐后再实施相关部分。不得把通知变成等待 owner 的前置；超出授权的部分沿现有边界处理。
- `stop-affected`：关键值、来源、消费者或数据无法确定且不可推导；写影响、已查范围、owner 和恢复条件，只停依赖该项的路径，其余安全工作继续。需要产品或设计决定交相应 owner，不猜默认值。

## 测试数据与独立执行

每条 AC 明确独立测试代理、数据来源、层级、是否必须全量及无法取得时的恢复条件。S 是合成或种子数据，M 是生产形状子集，L 是完整数据，仅在最终验收使用一次；不能用样本声称全量。缺数据、缺外部原件或无法采样时保留事实并只停受影响路径；不补造真实数据或把未知写成通过。可独立并行的验收面有两个以上各自 oracle 时，主会话派至少两个独立只读测试代理；不足两个派一个并写理由。代理不共享写入，结果由主会话合并并保留冲突；AC/方向变化、用户独占阻塞资源或严重超授权风险按现有升级规则处理。

## 五道判断怎样对账？

1. **触发**：三源与真实消费者支持 UI 时调用；非 UI 写 `N/A` 及依据。
2. **就绪**：逐项核短表和四种处置，相关可推导缺口先补，不能推导只停受影响路径。
3. **实现**：在真实 diff 中引用规范与组件/布局消费点，以 Map 核消费者、类型、状态和 CSS owner。
4. **检查**：按实际适用项记录类型、定向测试、样式、构建体积等命令、退出和原始输出；浏览器及视觉效果按真实执行情况另记。
5. **优化与审查**：有预算、实测或审查发现才动性能；无预算只测不优化并记 `unknown`。独立审查读真实差异，finding 修根因后只复验受影响面；未运行或不可用不当通过。

### 负例：缺关键设计值

改一张有真实用户和明确消费者的页面，八类来源及四类资产均可读，但新图表阈值颜色既无已确认设计决定，也不能从现有规范、测试或平台语义推导；项目检查命令与合成数据齐备。该阈值影响本次图表，设计 owner 尚未决定。处置 `stop-affected`：停止依赖颜色的实现，告知设计 owner 并请求确认阈值和适用范围；其它不依赖该值的工作可继续，决定到达并记来源后重新判断。不得从现有代码或相似页面猜值。

### 数据判断样例

- **缺数据**：AC 要独立测试代理验证导入映射，所需外部原件不可读，项目无法由已确认合同构造替代；其余输入齐。记 `stop-affected`、缺失原件、提供者及恢复条件“取得可读原件后复测”，停导入验证，其它独立面继续，不写默认数据或通过。
- **只能采样**：AC 需要检查生产形状的记录，owner 已提供合法 M 子集和覆盖说明，独立测试代理可复放；完整数据不可用，且完整验收另有明确要求。当前只报告 M 样本结果与覆盖限制，L 完整面保持 incomplete；取得授权的完整数据与终验环境后由独立测试代理在最终验收运行一次。M 的可继续不等于全量通过。
- **必须全量**：AC 要最终核对全部记录，已确认允许在终验环境使用 L，独立测试代理、来源与命令均可定位。实施阶段只用 S/M 做定向验证；最终验收执行 L 一次并保结果。若 L 届时缺失，停该全量面并记 owner 与取得数据后重跑的条件，不用 S/M 冒充全量。
