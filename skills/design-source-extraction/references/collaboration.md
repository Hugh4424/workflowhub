# 协作与写入权

多写者或共享文件时读本文。读者是 build-code 主会话与独立测试者；
本文只写协作增量，不新增锁、公共命令或第二套写权账本。

## 谁可以写，哪些文件算共享？

一个 worktree 同一时刻只有一个写者。写者是主会话按真实写集指定的开发子代理或主会话本身。
同一文件的任何字段都算共享，不能按字段拆给两个写者并行。
共享文件由原持笔者串行处理，后写者等前写者交回当前字节再改。
生成物另立唯一写入者，消费者不手改生成物。
写集与判据在并发开始前冻结；冻结后只做已声明改动，范围变化先回原 owner。
读别人正在改的文件，等树稳定后再取数；不边跑边取，不把中间态当结果。

## 工作区锁怎么用？

工作区写入复用 `runtime/interface/record-lock.mjs` 的 `withLock(dir, name, fn, {waitMs})`。
`dir` 用当前 worktree 根，`name` 是本次共享写入的稳定锁名，`fn` 里做读改写。
锁在 `finally` 释放；回调抛错也必须释放，失败不换成无锁直写。
同一把锁下的回调区间不交叠；只允许等锁，不允许绕锁。
`openTask.withRecordLock` 只保护任务记录根，不是工作区锁，不能拿来包源码写入。
不新增第二把锁、第二份写权记录或替代的协调状态。

## 两个真实进程要证明什么？

真实互斥须由两个独立进程对同一受控目标文件取证，不是在同一进程里模拟。
目标初始为 0。第一个进程持锁时，第二个进程不等待争用必须收到 `LOCK_HELD`、
以退出码 75 结束，且目标字节仍为 0。
两个允许等待的进程依次进入同一锁回调，各自读改写一次；
结束后独立读取目标应为 2，两笔交易各生效一次，回调区间不交叠。
执行顺序不固定。锁或系统错误保留原输出，不冒目标失败。
未进入同一把锁的外部直写不能证明不存在，必须列为覆盖限制。

## 中断和收尾怎么算完成？

中断的半成品放隔离位置，不送独立验证；接管者重新生成或明确废弃。
只清理自建临时工作区、锁文件和自有进程，不碰他人或真实用户资源。
清理清单写实际临时路径、进程号与锁文件，每项标已移除或已停止。
清理后回读：锁文件不存在、进程不再存活、临时目录已删。
收尾以清单和回读事实为准，不以「应该清掉了」为准。

## 写者记录包括什么？

写者记录是单份 `write-set.json`，至少含：写者身份与写集、共享文件到唯一写者的映射、
锁实现的名称、锁域与逐次锁证明、中断半成品的隔离与送验状态、清理清单。
一个 worktree 只允许一个写者；第二写者即使写不相交文件也失败。
锁证明的 pid/host/nonce/started_at 取持锁时的锁文件；`released_at` 是观察者的
释放时间，不是 record-lock 写的字段，不能把它当锁内声明。
用 `node skills/design-source-extraction/scripts/check-write-set.mjs --dir <目录>` 核。
退出 0 只表示记录自洽；它不证明真实互斥，真实互斥由两个真实进程另行证明。
检查拒绝双写者、缺锁证明、任务根锁冒工作区锁、半成品送验和未清理项。
失败码以脚本输出为唯一来源；本文不复刻错误码清单。

## 向已结束的子代理发消息前做什么？

向已结束的子代理发消息等于让它重新开工，不是只读追问。
发送前由主会话先确认三件事：重启意图、原授权是否仍覆盖、当前唯一写权在谁手里。
既有任务授权已覆盖同范围修复时，由主会话完成该确认，不新增逐次请示。
已有等待确认或停止要求时，仍按真实答复恢复；发消息本身不解除暂停，也不授予写权。
本方法只管协作事实；Git 动作仍归既有 Git 授权，任务记录写仍归任务根锁。
