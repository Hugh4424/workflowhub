# 移植方法

## 这份方法给谁用？

给允许移植后的实施者、独立测试者和后续阶段读者用。
读完要能从设计源生成可改代码，并让每处差异、样式归属与手改都能被独立复核。

## 三类对象怎样分开？

设计源是合法的页面或组件源稿，只读，位置固定为 `specs/design/prototypes/`。
实施夹具是施工期验证用的样本页，位于 `tests/fixtures/<本任务夹具>/`，不是真实设计源；具体路径由所属 Phase 与夹具 README 给出。
移植输出是从登记生成的可改代码，生成到临时目录，设计源与输出必须解析到不同真实路径。

移植件指从设计稿落到目标项目的可改代码。
manifest 指登记来源、目标、允许差异和生成规则的机器可读文件。
作用域选择器限定样式可影响的页面根；特异性预算限定选择器覆盖既有规则的强度。
chrome 指页面或浏览器外壳；宿主外壳不属于移植内容。

## 移植前先读什么？

先读同源 `judgment.md` 的结论与去向；只有直接套用或适配后套用才进入移植。
不能用时按两条去向回原 owner，不在移植里偷偷改方向或换稿。
再读旧 `design-source-extraction.json` 的 `source`、`scope` 与 `freshness`，
判断来源是否仍 current。
最后读目标页真实入口、旧接口与手改文件位置，不从示例路径猜首改位置。

## manifest 登记哪些字段？

| 字段 | 写什么 |
| --- | --- |
| `design_root` | 相对 manifest 所在目录的设计源根路径 |
| `target.scope_selector` | 页面根选择器，所有生成样式都限定在它下面 |
| `target.chrome` | 宿主外壳归属：owner、外壳选择器、内容选择器与依据 |
| `specificity_basis` | 宿主规则实读值、计算样式基线、读取日期与来源状态 |
| `files` | 每个来源文件的模式、来源摘要、导入变化与直接改动 |
| `used_classes` | 页面静态与运行时用到的全部类名 |
| `client_adapter` | 客户端适配类、方法、接口与处理器映射，声明不由运行时注入 |
| `manual_files` | 唯一手改文件路径与哨兵行 |

机器字段集中在文件末尾，写作时按原合同逐项填，不用占位值。

## 逐文件三种模式怎样用？

`copy` 是纯拷贝：目标字节等于来源，只允许登记过的导入行变化。
`changed` 是直接改动：每处改动写行号、来源行、目标行、理由与负责人。
`generated` 只用于样式：从来源样式按作用域规则生成，不登记直接改动。

导入变化只认 `<link`、`<script`、`<style`、`src=`、`href=`、`import` 与 `require(` 行。
直接改动必须有理由和负责人；只有理由没有负责人的改动不算登记。
同一行不能登记两次；行号或来源行对不上时立即失败，不按文本相似度猜位置。
来源文件摘要写进登记；来源变了而登记未更新时，检查直接报来源漂移。

## 作用域与强度预算怎么取？

作用域选择器是页面根；生成样式里每个选择器都要等于它、或以它为前缀。
缺少前缀的选择器会越出页面根，检查报作用域失败。
特异性预算从已读宿主规则和计算样式基线取证，取各分量最大值。
宿主规则逐条记选择器、实读三列特异性与来源行；声明值与按选择器复算不一致时失败。
计算样式基线写真实视口与页面根宽度；缺来源时保持未核实，不自定数字。
生成选择器强度超过预算时失败；预算不足时先补来源，不靠调数字换绿。

## 宿主外壳怎样归属？

外壳归宿主，内容是移植件；两者都写进登记并给依据。
外壳选择器不能出现在生成内容里，也不能登记成内容选择器。
登记里同时缺外壳选择器或内容选择器时，检查报外壳归属缺失。
依据行要能回读到当前来源；读不到就保持未核实，不写通过。

## 样式闭包怎么算？

`used_classes` 是页面类名的唯一清单，包含静态 HTML 与脚本运行时添加的类。
样式里的每个类都必须在这个清单里，否则算未使用样式。
清单里的每个类都必须有样式规则，否则算缺使用样式。
HTML 里出现但清单没有的类也算未登记，不默认忽略。
这样能在生成物里同时抓住多写和少写两端。

## 生成与手改怎样保留？

默认 `--mode=check` 只读登记与设计源，模拟生成并核样式闭包。
`--mode=generate --output <目录>` 真实写出移植件、样式与手改文件。
输出目录等于或位于设计源内时立即失败，不写任何文件。
手改只在 `manual-overrides.css`，首行哨兵必须保留；生成器不覆盖已存在的手改文件。
同一输入重跑得到相同字节；手改文件原样保留，其它文件重新生成。
重跑后手改哨兵丢失或手改被覆盖时，检查失败并保留原失败。

## 客户端适配怎样生成？

适配类、读取与写入方法、接口路径与按钮处理器由本阶段第一次交付，原样生成。
登记写明类名、方法、接口与处理器映射，并声明 `runtime_injection` 为 false。
后续阶段只提供真实服务并核实际页面行为，不向页面注入代码或改已交输出字节。
写结果只在收到真实回执后显示；读取失败不填样例值。

## 失败码以哪里为准？

失败码与退出码以 `check-port-manifest.mjs` 的 `fail(...)` 调用为唯一来源，本文件不维护副本。
读者按脚本实际返回的码与 detail 定位，表格式摘录会漂移，因此不在此重复。

## 这条方法的覆盖上限是什么？

只证明当前登记、样本和生成规则。
不证明任意框架、真实数据、其它视口或真实项目长期使用。
真实设计源仍只从 `specs/design/prototypes/` 读取；原型和夹具不能冒名。
