# 固定视口目视审查

## 这份方法给谁用？

给对实际实施对象做目视的独立设计审查者、独立测试者和后续阶段读者用。
读完要能在固定视口重新采集证据、逐条判差异，并说清机器全绿不等于视觉通过。

## 为什么目视是验收的另一半？

机器校验抓得住几何、结构和覆盖，但抓不住真实的层级、留白、字体观感与状态切换的整体观感。
只看机器会漏掉视觉差异；只用旧原型截图会冒充实实施对象。
所以机器进入条件满足后，必须对实际实施对象重新观察，并由没参与实现的人逐条判。

## 观察对象和视口固定成什么？

观察对象是阶段 2 交付、阶段 3 用同一本地服务交回的实际实施页面，不是原型、也不是旧截图。
固定视口为 1440×1000、设备像素比 1；其它宽度、缩放与真人读屏不覆盖，不作为通过条件。
声明的页面态固定为八态：成功、加载、空、错误、样例写拒绝、真实成功、写回执、错误恢复。
超时在本样本无客户端接缝，只在数据层真实分档，因此登记为 `status: unavailable` 的具名缺口，**不进已观察集合、也不进必测集**，不冒通过。

## 设计对怎样记录？

每对记录设计源路径与摘要、实施输出路径与摘要、实施 URL 和读取时点。
设计源与实施输出必须是两个不同真实路径；同路径自比即失败。
报告打开「核字节」开关（`verify_screenshot_bytes=true`）时，校验器重算 design 与 implementation 的实际字节摘要：实施字节改变后旧报告必须失配（`DESIGN_PAIR_HASH_MISMATCH`），旧原型截图也不能拿来当实施对象证据。

## 差异怎样才算处置完？

差异逐条登记成可核清单，每条只有三种结论：无差异、已修复、附理由接受。
「接受」必须带独立审查者写下的理由，不能只写「接受」两个字；未解决的差异一律失败。
差异状态取值以校验脚本导出的常量（`DIFF_STATUSES`）为唯一来源，本文不复刻枚举。
机器全绿不能代替视觉结论，用户不作为裁判，也不设必须清零。

## 环境身份、对象身份、读取时点凭什么算数？

报告要记录浏览器、字体、设备像素比与读取时点；缺环境身份或缺读取时点即失败。
报告还要带对象身份块（八项）：workspace、service、route、state、viewport、engine、engine_session、object_version；缺项具名报出，不填默认值。
与 `page-audit` 的分工：page-audit 跑五采集器与完整材料/版本链；本报告只保存身份块与差异表，不重跑五采集器、不核版本链，也不生成评分口径。
截图要能回读到本次真实采集的字节摘要；旧原型图哈希登记在 `forbidden_old_hashes` 禁用名单（build-plan 034/039/041/043 旧截图真实哈希），命中即旧图冒用。
报告字节本身进摘要，报告被改过同样失配。

## 缺口怎样处理？

浏览器或服务不可得记不可用，缺截图或结论不得进入通过。
超时等无页面接缝的态，按 `status: unavailable` 具名缺口记录，并写明理由；具名缺口不进「已观察」，不写成通过。
缺口逐项保留，不写成通过；只有独立审查者书面接受后，才允许进入后续阶段并保留在最终缺口清单。

## 这条方法覆盖到哪里？

只证实际实施对象的固定视口和声明状态。
不证其它视口、缩放、真人读屏、性能、真实业务写入或长期效果。
失败码与退出码以检查脚本为唯一来源，本文不复刻副本。

## 校验器用，人可跳过

- 检查命令：`node skills/design-source-extraction/scripts/check-visual-review.mjs --dir <报告目录>`。
- 报告文件：`<报告目录>/review.json`；`verify_screenshot_bytes=true` 时核截图字节并重算 design/implement 字节。
- 校验规则要点：视口固定 1440×1000@1；环境/对象身份/读取时点齐备；`required_states` 必须覆盖固定八态；每个固定态要有截图或 unavailable 缺口；差异状态与理由合规。字段结构与取值以脚本为唯一来源，本文不复刻清单。
- 退出码：0 通过；1 目标失败；2 报告不可用。失败码以脚本唯一来源为准，本文不维护副本。
- 浏览器采集经 `skills/isolated-browser-qa/SKILL.md`；八维语义审查经 `skills/plan-design-review/SKILL.md`。
- 写作规范见 `skills/material-writing/SKILL.md`，本文不复述。
