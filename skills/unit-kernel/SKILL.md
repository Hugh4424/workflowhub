# Unit Kernel — 四阶段共用规则内核

内核版本：v1.0.0

## 本内核是什么

本内核是 make-decision、build-plan、build-prd、build-code 四个阶段共用的**唯一规则权威**。
规则正文只在这里改；四个阶段只按同一版本引用自己消费的条文，不复制条文、不各写一份。

- 四阶段的共用规则、两条工作顺序、十一格卡与五段逐包格式的**人读定义**都在本文件。
- 机器可读的字段语义正文归本内核 `references/unit-fields.json`（P2 已交付）；字段的人读目的与字段精度三档见下文「字段与字段精度」节，两者分工不重复、不互相顶替。
- 本内核不持久化状态，不新增 stage、gate、公共命令或 runtime 行为；它不改变任何既有强制读取。
- 阶段专属动作（步骤编号、产物、角色分工、检查器口径）仍归各阶段正文，本内核不接管。

## 读者、owner 与冲突回报

读者：四个阶段的正文作者与执行者、独立审查者、契约测试者。

- **内核 owner**：本文件的维护者，即原内核作者；owner 载体就是本文件本身，改动只走本文件的版本行与条号，不另设账号、队列或审批对象。
- 与本内核冲突时**以内核为准**；阶段正文里与内核不同的措辞按本内核改写。
- 本内核缺条、条号指错或某阶段真实消费的规则没有正文时，记具名缺口（缺哪条、哪个阶段、谁补），写进本任务的质量原件并交内核 owner，不就地改写、不另起一份。
- 引用只认条号与版本；版本相同不等于条号对得上，指错条号按未接线处理。

## 规则条款表

条号只增不改，裸 `R×` **专指本内核**；引用外部来源的条号必须带来源前缀（例如 deep-research 的 R0–R5 一律写成「deep-research R0–R5」），不得与本内核同记号。

| 条款号 | 主题 | 规则 |
| --- | --- | --- |
| R1 | 审查周期 | 一个被审对象只进一个周期：首审加同一审查者复读最多两轮，周期结束后不重开；迟到有效发现回原执行者修并只复验受影响面，未处置记未完成、不记通过。 |
| R2 | 唯一写主 | 一个对象同时只有一个开发写手，同一文件的不同字段也算共享、由原持笔者串行；派发固定一开发一审查一测试，未就绪不派独立测试与审查、只补就绪空位，两路审的归并归包 3。 |
| R3 | 能定不问 | 事实能定的不问用户；只有两种做法会让用户看到明显不同结果且证据不能定时才问一次，问时给推荐、理由与不答后果；用户问答串行，一次一批，未答不代答。 |
| R4 | 升版核读者 | 先改本内核正文并升版 → 同批改四处接线指针 → 再逐处核四个真实读者的入口版本与消费条款，四处同版且条号可核后才算生效。 |
| R5 | 发现四态 | 发现只按已修、驳回、接受风险、交人决定四态记录并各带理由，对应机器标签 fixed、rejected_invalid、accepted_risk、needs_human；接受风险只认绑定该条发现的真实用户答复。 |
| R6 | 十一格五段 | 十一格卡与五段逐包格式只在本内核定义，四阶段与步骤表只留指针；格名、逐格人读定义、三档写作规模（旧称三档精度）与验收四件见下文「十一格卡与五段逐包格式的权威归口」；字段精度三档与字段人读目的见「字段与字段精度」节，机器矩阵只在 `references/unit-fields.json`。 |
| R7 | 阶段参数 | 阶段参数按十参数表定位已点名的何时、何人、何物；其余项未取得前记具名缺口与 owner，不猜默认值也不猜项名，表见下文「阶段参数十参数表」。 |

## 决策流水线

逐包的设计顺序，五段固定为 调研 → 发散 → 收敛 → 就地讨论 → 定验收；
下面六个动作与五段的对应是：①调研＝调研，②比较方案＝发散，③写卡＝收敛，④白话卡展示与⑤独立冷读、对抗**两步合为「就地讨论」**，⑥定验收＝定验收。

1. **先调研**：本包需要内部还是外部调研先判一次，需要就做并留原件，不需要也写理由。
2. **比较方案（发散）**：至少三个关键决策轴不同的候选，写明取舍与至少一个被否替代的代价；只换措辞不算候选；八类影响面逐类给结论或具名缺口。
3. **写卡（收敛）**：按十一格写方案卡，验收格按验收四件写。
4. **白话卡展示**：在既有问答批次里把卡用大白话发给用户。**证据只认同次用户原答或互动**：只发出、命令有输出、或另存摘要都不算用户看过。
5. **独立冷读与对抗**：由没参与写作的人只读卡，答冷读六问与对抗九问；同一审查者首审加复读最多两轮。
6. **定验收**：通过、失败、至少一个反例、证据四件齐；答不出就改范围或改验收方式。

关卡：先发卡后审查，审查不挡在用户和卡之间；四件不齐不出包；冷读答不出即未收敛。

## 执行流水线

每 Phase 的实施顺序，四段固定为 先证目标失败 → 最薄真实演示 → 独立审查与测试 → 修复：

1. **先证目标失败**：跑冻结的目标测试拿到真 RED，保存命令、退出码与原始输出；导入、环境或配置失败另记，不算目标 RED。无 RED 不进实现；纯材料任务写具名不适用理由，不造仪式性 RED。
2. **最薄真实演示**：只做第一张卡的最小纵切，接到公开入口，用真命令或真页面把真实输入跑到真实输出；内部函数返回不算演示。
3. **独立审查与测试**：实现就绪并明确通知后才派；审查者不是设计者，测试只读执行并保存回执；两者可并行，不共享写文件；未就绪只补就绪空位，不派独立测试或审查。
4. **修复**：发现按 R5 四态处置，有效问题回原执行者同一会话，只复验受影响面；未处置保持未完成，不记通过。

关卡：没有真 RED 不写实现；没有公开入口演示不报 Phase 完成；审查与测试各自明确回报后开发才能最后确认。

## 十一格卡与五段逐包格式的权威归口

十一格卡与五段逐包格式的**唯一完整人读定义在本节**，其它位置只留指针（一行「见内核 v1.0.0 第 R6 条」算指针，出现逐格条文正文即算抄）。
五段的定义见「决策流水线」；十一格逐格定义如下：

| 格 | 人读定义 |
| --- | --- |
| 一句话结果 | 这一包最后让谁看到什么变化，一句话说清。 |
| 对应需求 | 承接哪几条原始需求，用事实与原话，最多 5 条。 |
| 现状缺口 | 现在为什么做不到：谁读不到、哪一步跳过、什么没人处理。 |
| 方案与取舍 | 选哪条路、为什么；至少一个被否替代及理由；接受什么代价。 |
| 边界 | 做什么、不做什么；不做的交给谁。 |
| 数据与状态 | 进来什么、出去什么、状态怎么变，用「谁在什么时候拿到什么」说。 |
| 验收 | 按验收四件写：通过条件（含命令或检查）、失败条件、至少一个反例、证据路径。 |
| 风险与回退 | 先写失败后果，再写触发条件与恢复路径。 |
| 未决 | 真正卡住验收的未决项与谁定、何时定；没有写「无」并给理由。 |
| 白话复述 | 三到五句大白话：改什么、为什么、怎么算成、什么算失败、还有什么没定。 |
| 配套与影响 | 四项各一句结论：配套调整、配套迁移、配套移除、影响范围；没有的写「无」和依据。 |

**验收四件**（七格「验收」的判据，也是「四件」的唯一正文）：通过条件、失败条件、至少一个反例、证据路径；四项都要有真内容，只写「无」或没有内容按缺项算；失败条件必须单独成条，不能只写在反例句里。

**三档写作规模**（旧称三档精度；卡的写法按任务规模取一档，取更严者为准）：

| 档 | 卡的形状 | 来源与代价 |
| --- | --- | --- |
| 小改动档 | 一张十一格卡＋一次冷读六问；不强制完整三角色或对抗九问；配套与影响四项不可省 | 原 decision-maker「轻量任务」与 make-decision 第 9 步小改动条；代价是少一轮独立视角 |
| 普通档 | 完整十一格＋一次方案审（detail 轨）；冷读按该档要求 | 原 make-decision「人为门与审查点」普通路线条 |
| 复杂档 | 完整十一格＋三角色（调研、设计、审查）＋冷读六问与对抗九问，首审加复读两轮封顶 | 原 decision-maker「并行规则」与 make-decision 第 9 步复杂路线条 |

**具名缺口**：「四种单元件」的逐件定义不在本阶段可核范围（原卡 `card.md:25` 只写名字，没有逐件正文）；它属字段语义，见 P2 已交付的 `references/unit-fields.json` 与字段作者，本内核不猜、不补写。

## 字段与字段精度

本节里的「字段」指跨方向卡、任务卡、阶段卡复用的十一个通用字段，**不是**上面十一格卡的另一份名单；两者的旧名对应由字典的 `direction_label` 与 `legacy_aliases` 记录。字段名、三卡精度矩阵、旧别名与真实读者的唯一机器可读正文在 `skills/unit-kernel/references/unit-fields.json`；本节只给人读目的，不复制矩阵。

| 通用字段 | 人读目的 |
| --- | --- |
| 结果 | 这一单元最后让谁看到什么变化：方向卡写可观察结果，任务卡写交付什么，阶段卡写可复算的结果。 |
| 来源 | 承接哪些原始需求、决定或上游供件，用路径:行号、原件或编号指回唯一来源，不复制正文。 |
| 为什么现在做 | 现在做不到的具体缺口与不做的后果，不写成背景综述。 |
| 方案与取舍 | 选哪条路、否掉什么、接受什么代价；任务卡只指向方案来源，阶段卡写到可复算。 |
| 边界 | 做什么、不做什么，不做的交给谁。 |
| 依赖与供件 | 开工需要的输入、上游真供件、谁在何时提供；阶段卡写到可复算。 |
| 验收 | 通过条件、失败条件、至少一个反例与证据落点；阶段卡写到可复算。 |
| 风险与回退 | 先写失败后果，再写触发条件与恢复路径。 |
| 未决与返工半径 | 真正卡住验收的未决项、谁定、何时定；失败后返工到哪一步、不扩到哪。 |
| 配套与写集 | 配套调整、迁移、移除、影响范围与写入路径；任务卡与方向卡指向具体来源，阶段卡写到可复算。 |
| 人话复述 | 三到五句大白话：改什么、为什么、怎么算成、什么算失败、还有什么没定。 |

**字段精度三档**（判单个字段写到什么程度，与上面的「三档写作规模」不是同一件事）：

| 档 | 人读目的 |
| --- | --- |
| 判据 | 能据此判：写明对象、条件、通过信号、失败信号与证据落点，独立读者不靠猜测、不翻卡外就能判真假。 |
| 复算 | 能按步骤复算：写明输入、步骤、命令与结果，另一个执行单元照同一格可重复得到同一结论。 |
| 指向 | 分指到来源：只给可回读的来源指针（路径:行号、原件、卡或决定编号），正文不复制，读者沿指针回到唯一来源。 |

**三卡分派**：方向卡十一项全用判据；任务卡保留六字段加 UI 三段共九行，来源、方案与取舍、配套与写集只给指向；阶段卡结果、方案与取舍、依赖与供件、验收、配套与写集用复算，其余用判据。逐项矩阵与旧别名只由字典 `cards` 提供，本节不复写；三张模板只留形状与指针。

**具名缺口（内核版本）**：本节与 `references/unit-fields.json` 是内核 v1.0.0 之后的内容增量，但本阶段不升内核版本（四个 `workflows/*/SKILL.md` 不在写集，升版须同批改四处接线）。升版与四入口同批核归 P3，owner=P3；未升版前四入口仍按 v1.0.0 读本内核，不把本节当作已接线条文。

## 四阶段接线五行

每个阶段入口各有一个「内核接线」小节，五行按此顺序写，缺一行即未接线：

1. **入口版本**：本阶段引用的内核版本，必须与内核版本逐字同版。
2. **消费条款**：本阶段实际用到的条号，加本阶段走的是哪条流水线（决策或执行），再加用在哪个具名步骤；只列正文真有「归内核 R×」指针的条号。
3. **阶段输出**：本阶段专属产物。
4. **冲突回报**：与本内核冲突时报给内核 owner（本文件维护者），缺条记缺口回报。
5. **升版顺序**：先改内核正文并升版 → 同批改四处接线指针 → 再逐处核四处同版与条号。

## 五条实际反例

| 反例 | 错在哪 | 为什么必须拒绝 |
| --- | --- | --- |
| ① 条号指错却称同版 | 入口写「入口版本：v1.0.0，消费条款 R8」，而本内核只有 R1–R7；或把审查周期指到 R4。版本 token 相同只证明抄了版本号。 | 读者会照错条号执行另一条规则，同版声明还会掩盖这次漂移；按 R4 记未接线。 |
| ② 没有真实风险选择的答复却记接受风险 | 只展示了整理摘要，或拿另一条风险的答复来顶，就把发现记成「接受风险」。 | 承担风险的主体是用户，不是审查者、摘要或代理；无人承担的风险被记成已处置后就不再修，按 R5 只能记未处置。 |
| ③ 事实已能定仍去问人 | 能读 `steps.json`、代码或原件判定的条号、写集、命令，仍发问题卡。 | 把可查事实当成用户决定，既耗用户注意力，答复也替代不了原件；按 R3 记执行错误并改回自己决定写依据。 |
| ④ 内部函数返回冒充公开演示 | 执行流水线只跑内部函数或单测，就宣称最薄真实演示完成。 | 演示的判据是公开入口把真实输入跑到真实输出；内部返回不证明真实消费者能用，按执行流水线记未演示。 |
| ⑤ 把代码实施排在实际目标失败之前 | 先写实现再补红测，或红测因导入、环境、配置失败也当目标 RED。 | 没有真 RED 就不知道实现是否真解决问题；先实现后补测只能证明代码能跑，不能证伪目标行为。 |
| ⑥ 阶段参数缺项靠猜默认值或猜项名 | 十参数表里「何时」「何人」空着，或给第 4–10 项自拟一个列名，直接按惯例派一个开发、按默认步骤开工。 | 缺项和自拟项名都会被后来的读者当成已决定的口径写进材料，接手者无法复核；按 R7 记具名缺口与 owner，补齐前只做不依赖该参数的安全动作。 |

## 版本与升版

- 当前版本 v1.0.0；版本只在本文件声明，四个入口只引用。
- 升版顺序固定三步：**先改本内核正文并升版 → 同批改四处接线指针 → 再逐处核四处同版与条号**。
- 只改指针而版本未升、或版本升了但四处未核，都按未生效处理，记具名缺口。
- 历史版本不保留副本；旧引用由原阶段作者按当时原件只读保留，不在本内核维护版本历史。

## 不做什么

- 不新增阶段、gate、公共命令、schema 或持久对象。
- 不接管任何阶段的步骤编号、产物路径与角色分工。
- 不把字段语义、检查器实现或审查合同搬进本文件；它们各归原 owner。
- 不为了统一措辞改写历史材料、已发布断言或原始失败。
