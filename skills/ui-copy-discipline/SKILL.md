# UI Copy Discipline

## 用户规则（2026-10-27原文，单一正文）

```text
避免不必要的次要标签、说明文字、辅助文案、描述性文字和冗余的微文案。
让布局、视觉层级、间距和清晰的主操作自己完成解释。

具体要求：
- 优先用强视觉层级和自解释的结构，而不是用文字去解释。
- 默认不要添加 slogan 式文字、教学段落，或在每个区块下都加“帮助说明”。
- 如果确实需要补充信息，优先使用 info 图标 + tooltip，而不是始终显示的次要文字。
- 保留必要的表单标签和可访问名称（方便读屏软件）。界面清爽不能牺牲可访问性。
- 危险或不可逆操作（删除、支付、提交永久性变更）必须保留清晰的后果提示。
- 去掉说明文字后，第一次使用的人仍应能看懂：下一步点哪里、点了会发生什么。
- 重写已有界面时：先去掉冗余标签和说明，如果清晰度下降，再优化布局和按钮文案。
```

## 方法与完成边界

四个消费者读取本节同一原文：frontend-prototype-render无稿生成前/后、figma-make-prompt生成时、plan-design-review逐项审查、external/ui-designer/design-review本地适配入口。调用者先列本次任务与实际页面strings，检查布局层级/主操作是否承担解释；逐处删冗余并保必要标签、可访问名和危险后果。tooltip须键盘可达且不能藏关键后果。

未参与实现的首次读者先只看页面，说出下一步点哪里、点了会发生什么；保存其原话、实际动作与结果、卡点和理解核对。缺读者/未运行保持未验证；agent读回不冒真人可用性测试。清晰度下降先改布局/按钮命名，再补必要信息，不用成片教学替结构。四消费者的实际输入与产物位置回当前任务原件，不因路径可读宣称已消费。

ui-gate只引用plan-design-review的七面方法与边界，不整体复制、无独立分数或新gate；有稿保原风格/入口与点击成本，无稿对应完整任务/合成数据/待确认/必要备选，用户测试未做如实写未做。
