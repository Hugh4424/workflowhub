# stage-handoff

每个 stage 末由当前主会话写一份给人读、可复制的交接 md，供用户或下游会话续接。交接不是质量结论、工作许可证、正式材料替身或 reflection 的消费者。

## 方法

1. 读取当前实际材料与已发生的任务/测试/独立审查/Git事实。post 读取 decision-log、spec、相关独立 Phase 与指针 index；历史 plan/tasks 只读。尚未产生的下游材料写 not_applicable，应有却不可读的材料写具体失败；不借旧任务/旧交接补齐。
2. 按需引用原始来源和当前任务位置，说明本阶段做了什么、当前可消费材料、已做/未做、真实测试/审查与发现处置、风险/延期、下一阶段或续跑的具体动作。未回答、取消、failed、unavailable、unknown、stale、incomplete 均照实保留。
3. 用安全写入工具保存普通 `quality/evidence/handoff/<stage>.md`。返回实际绝对路径和必要材料/证据绝对引用，回读文件是否与刚才说明一致。只准备正文但没写入就明确未写。
4. 写入或读取失败时保留原始错误、目标绝对路径及旧交接可能过时的影响，不把旧文件冒充当前成功交接。缺交接只披露，继续同任务不依赖它。

## 结束条件与边界

下一会话能从交接定位实际材料、未知/失败和一个可执行下一步；不复制材料全文或原始测试/review。布局按本阶段需要组织，不要求13有序区块、reflection终态、locks、snapshot/hash或skill-deps认证发布。正式阶段事实仍由既有任务流程记录，本技能不写状态/质量 graph，不把测试GREEN当作人类接受、发布或物理交付。
