# 问题陈述模板

读者：三个阶段开工时写需求陈述的人。
读完要能按八格写清一条需求，每格落到一手载体，而不是拿转述代替。

本件只承载「问题陈述」这一段的八格与填写顺序；格与字段的完整定义指回
`skills/decision-log/templates/decision-log-template-v2.md` 第 2 段与
`skills/unit-kernel/SKILL.md` 第 R6 条，不在此复制判据。

## 八格与填写顺序

按下面顺序逐格写，前一格说不清就停，不往后填。

1. 谁：受影响的人或角色是谁。
2. 什么场景：在什么情况下遇到。
3. 现在怎么坏：今天实际发生什么、哪里做不到。
4. 证据：一手载体的出处、定位、日期、谁说的、什么情境（五件齐）。
5. 影响：坏了会让谁受阻、哪一步被跳过。
6. 不修的后果：不处理会持续造成什么。
7. 成功判据：怎么算这条需求被满足，写通过与失败，不写比例或计数。
8. 边界：做什么、不做什么，不做的交给谁。

## 每格的一手来源落点

每格都要能回指一手载体：出处（文件或答复）、定位（行号或段落）、日期、谁说的、什么情境。
五件缺一件就在该格标「来源不明」，不拿派生件的转述当原话。

## 历史记录去哪找

历史需求与旧陈述只读保留在既有决策日志与需求索引里，按 id 回读，不回填、不重写。
形状与字段仍指回 `skills/decision-log/templates/decision-log-template-v2.md`
第 2 段与内核 R6。
