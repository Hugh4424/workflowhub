# simplicity-guard

## 定位

文档wh-review与代码OCR的同次 advisory lens：只读允许材料/diff，输出共用findings，不调用provider或写任务状态。找删除、复用和缩小机会；无可删内容合法，缺料如实披露，不作继续许可证。额外要求不能凭“以后可能需要”成立。

## 四阶梯决策树

按P0→P3判断，首个可用路径即停：

```
P0：需要存在吗？对应原需、批准方向、已发生故障或硬约束。
    无必要性：YAGNI，不写；有：P1。
P1：仓库/标准库/平台原生/已装依赖已覆盖？
    有：直接用，不重写；无：P2。
P2：已有能力改造可用？
    可：手术式复用，只改必须处；不可：P3。
P3：最小新增。先说明P0-P2为何不可；不确定停下问，不静默假设。
    只写已证问题所需最少代码，不投机；只动必要处，
    只清本次产生的孤儿代码，每行可追溯到需求。
```

## Packet lens contract

在同一packet逐项审新增能力、抽象、模块、入口、状态、证据、迁移与发布机制；finding标明首个可用阶梯P0/P1/P2/P3及具体依据：P0缺必要性则删；P1已有覆盖则直接用；P2能改造则只改必须处；均不可才P3最小新增。检查scope creep、重复能力、无故障/硬约束的理想架构、第二套流程/状态/证据/发布系统及无理由残留旧层。

删改前回答：职责是什么、谁调用/调用谁、边界与错误路径、行为测试在哪里、原理由是否仍有效、git blame的原上下文是什么。核真实caller及动态配置，静态grep零命中不证明无consumer。原理由未知先读源，仍有效就保留。先减再加，已有唯一权威直接承接；搬家、stub或新增无需求validator不算减法。逐处留理由、来源、决定人、承接点/未决及回退位置，沿现退役记录，不建新账本。

对当前方案再问三件事：
- 幂等：同一动作二次执行、中途失败各留下什么状态？沿实际路径和已有owner/原子写/锁核残留与重试条件；“有锁/可重试”不代解释，不另建恢复许可。
- 并发：哪些actor触同一可变文件/状态？串行靠结构性锁、顺序或独占owner，还是口头约定？同文件不同字段仍共享；指出前后writer和现结构，不自动拆状态或换锁。
- 简化：能否消除问题，由已有权威承接？指出实际删掉的协调需求；复制到新文件/validator只是搬家，无承接的必要含义保留。

对照同一输入的输出、错误、边界、副作用及顺序，原测试不改求绿。代码面只审当前diff的范围扩张、重复路径、投机抽象、兼容层、死代码、隐藏失败；不重开accepted产品范围，不按LOC/风格裁决，不删必要测试、输入校验、错误处理、安全或可访问性。

同根因发现沿既有owner处理，保原finding/ref、每路归属、命中路数与是否单源，同源/unknown如实写；不同根因即使词近也分别留，有效单源不丢，不凭路数升严重度。拒绝假阳性给原材料证据和理由。runtime更严格的路径/行锚/规范化issue规则保持，不新建语义聚合器。

有实质实现/维护后果才给具体可执行删减finding，不顺手建框架；无问题不制造finding，不输出verdict、summary或独立结果。direction盲材料不用依赖候选的lens；其余按现stage-skill-plan与完整实际包的适用面消费，不新增注入/审查轮，包内存在不冒正确使用。

## 例外（不适用四阶梯）

信任边界输入校验、防丢数据错误处理、安全措施和无障碍基础保留；其必要性不能被少代码推翻。

## 配套禁止项

改测试换绿、复杂度搬家均拒绝。审查建议不能比问题本身更复杂。bug修根因；删除优先于无理由保留，原理由仍有效时保留。

## 写作流程中的调用点与输出形态

沿既有调用点落现有字段：spec-specify写spec取舍/非目标，spec-plan写Phase范围/写入集/非目标，plan-eng-review复核；decision-log写风险/取舍时读本lens三问。review用删除finding。只报既有删除计数，无配额，不新建字段、模板、文件或第二记录。

空集可写`已读，无可删内容`，不算缺失/跳过；删减决定未引用上述任一调用点结论时记普通finding，不阻断或新增驳回理由。
