# Phase Maker

读者：build-plan 第 6 步的计划作者，以及拿到 Phase 卡后要独立开工的实施读者。
读完要能把已确认决定拆成 Phase、为每张卡写出可执行首动作，并让下一位读者不靠会话就能复读。

## 与 spec-plan 的分工

- 完整写作方法、模板、Task 编号与纯指针索引只读 `skills/spec-plan/SKILL.md`；本技能不复制全文。
- 本技能只承接第 6 步的**首个可执行契约**：拆卡边界、首动作、回读条件与失败边界。
- 与 spec-plan 冲突时，写作方法以 spec-plan 为准；第 6 步的入口、锚与读取回执以本文件和第 6 步 `steps.json` 的声明为准。

## 输入

先实际读到：当前 `decision-log.md`、当前 `spec.md`、第 5 步交回的 UI 六项（非 UI 免）、前序 Phase 卡与 `phases/index.md`、真实代码事实。
缺一项就写具名缺口（缺什么、影响哪张卡、谁补），不拿会话摘要补，不提前写下一 Phase。

## 流程：从上下文到可回读的产出

本节只给阅读与产出的先后，不替代下方方法节，也不与各技能内部的步骤编号对齐（本技能另有八步或六步的方法节时，按那节的编号读方法）。

1. **上下文**：产出是三条 ref——本次会话的真实原话、已登记的研究原件、原始需求条目；缺一条写「未取得」与影响。拒认：拿会话摘要、记忆或「见上文」当 ref。
2. **调研**：产出是内部三处的实际读数——`decision-log.md` 已定、`spec.md` 当前、仓内实现——每处给 ref 与一条推翻条件。拒认：只有结论没有 ref；把已知当调研。
3. **设计**：产出是按本技能产物写的初稿，并至少写一条被否替代与它的适用条件。拒认：只写选中的那条；把模板空格填满当设计。
4. **Talk**：产出是逐轮问答原件，一轮一问、问答串行，**只处理本单元会改变产出的歧义，不再开方向 Talk/Grill**（`workflows/build-plan/SKILL.md:23` 已定 build-plan 阶段不重开方向 Talk）。拒认：攒一批问、自问自答、拿「已确认」代替原话、借本步重开方向讨论。
5. **产出**：产出＝首卡回读六项（目标、操作、成立条件、成败信号含一条必须失败的坏例、真跑或替代边界、执行者与原件）与 `phases/index.md` 的指针行。拒认：只有目录或链接；把「按计划」「按技能」当产出。
6. **冷读／对抗／异源**：产出＝未参与写卡的读者的回读结论与坏返回清单，一轮一处置。拒认：同一人两路、只读不改、发现不处置。
7. **收敛**：产出是可回读的最终件与「未收敛」缺口清单（每条带 owner 与恢复条件），即首卡回读通过、索引可解析无环、未收敛缺口带 owner。拒认：字段齐就记收敛；把缺口留到下一轮。

本节是顺序尺子：八步流程（decision-maker/phase-maker）与展开任务分节（task-maker）的步骤编号、插入步与产物定义不变，本节的七步不另立门。

### 流程六项落点

- 上下文来源：第 1 步读输入；缺项写具名缺口，不拿会话摘要补。
- 谁派调研：build-plan 第 6 步的计划作者；本技能只消费交回的输入。
- 歧义先 talk：方向或验收的歧义回 `skills/decision-maker/SKILL.md#package-convergence`；材料歧义回本技能输入节，够门槛才问。
- 产出形状：第 5 步的首卡回读六项与 `phases/index.md` 指针行。
- 谁审：第 6 步未参与写卡的读者做回读，交回读结论与坏返回清单。
- 怎么收敛：第 7 步首卡回读通过、索引可解析无环、未收敛缺口带 owner。

## 八步：从已确认方向到可回读的 Phase

本锚 `八步` 是计划例外：仓内唯一非 ASCII 锚，冻结测试与第 6 步声明已点名，保持原字，不改写成拼音。

1. **读输入**：逐份打开决定、规格、前序供件和真实代码事实，记下版本或原 ref；读不到写 `unavailable` 与影响，不按记忆补。
2. **定全局设计**：在 `spec.md` 原地扩展实现设计：代码锚、选定方案、接口、全局写集、依赖图、来源→FR→AC→Phase→oracle 追踪、风险与回退。产品叙述和已有验收不动。
3. **切 Phase**：按「一个能独立验收的结果」切，不按文件、层或模块数切；超出决策工作包时写拆分理由。
4. **写契约头**：每个 Phase 写自己的增量与回指全局目标的稳定锚；生成独立 `phases/P<n>-<结果短名>.md`，不复制全局设计或另一 Phase 正文。
5. **写写集**：逐路径写 `NEW` / `MODIFY` / `DO NOT TOUCH`，标前写者、后写者与依赖依据；共享路径只在前写者交回后由后写者接手。
6. **写任务卡**：每张卡写清可检查结果、首个要读的符号、第一处改动、目标测试先失败、通过条件、失败反例、证据落点和恢复路径；同一交付的连续步骤放一张卡的步骤序列，不拆成假独立票。每张卡另写「为什么这条能解决」「对应原问题/FR」「残余/未闭环」三句，形制见 skills/spec-plan/templates/phase-template.md 的「这一 Phase 交出什么？」与「下一消费者拿什么继续？」。
7. **渲染索引**：按 `skills/spec-plan/SKILL.md` 的「纯指针索引（Pure pointer index）」生成连续、可解析、无环的 `phases/index.md`；索引只导航，不承载正文、命令、验收或进度权威。新同仓卡在「写入集」字段只写 `phases/index.md#execution-index` 指针与同源 `sha256=<64 位小写十六进制>`，完整路径集只由索引行声明，不从卡头或局部 Task 列表反推。
8. **回读**：交给一个没参与写作的读者，只给本 Phase 卡、索引和真实输入，要求他说出首读符号、首改路径、目标失败、失败恢复和缺项 owner。答不出就补卡或补输入，不把「文件存在」当回读通过。

## 首卡纵切

本节服务 build-plan 第 6 步，不另开阶段或入口。
首卡是第一张让未参与写卡的人按真实公开入口开动的卡。
它沿一条可观察纵切写：公开入口 → 装配点 → 调用者 → 可见结果 → 失败信号。
首卡不只写步骤路径、文件清单或「等上卡」；卡里要能让没写卡的人写出首读符号、首改路径和判错动作。
入口类型是仓内只读 CLI 子命令，不是内部函数或 Markdown 正文。
实际符号是 `skillFileFor` 与 `declaredSkillRef`（解析步骤声明）、`cardSkillRef`（按卡取声明位置）。
调用方是 `--stage=<阶段> --step=<本步> --card` 的计划步骤投影，以及 `--read-step-skill` 的读取动作。
覆盖本步声明的技能文件、锚与卡路径。
不覆盖技能正文语义、命令是否真执行、其它阶段或步骤的声明；后者各由自身声明与捕获覆盖，理由是不在本步写集内。
读取位置取该步 `skill` 声明，不回退阶段默认。

### 首卡回读六项与三账

每张首卡按首卡回读六项写，缺一项不能交：目标、操作、成立条件、成败信号（含一条必须失败的坏例）、真跑或替代边界、执行者与原件。
三账逐条落到同一张卡。
写集账：核对首动作是否会动未声明的路径。
测试面账：核对公开 CLI、供件读取与拒绝。
决策账：核对规则归属、合法状态、默认出处、封装边界与失败退路。
每条验收的证据落点必须由分节审／Phase 回读／独立审查者实际打开并读回；打不开记 incomplete 并写 owner；目录不算原件。

## 真实供件字段

每条供件写用途、期限、超时错误与来源。
提供者按下游读法实读同一对象，接收者复读同一原件。
缺件只点名受影响调用；旧绿、模拟调用或文件存在都不算供件。
期限在真实入口当场核，超时返回原约定错误。

## 未知半径与实现决策

开工前留下未知影响半径：写清未知影响、受影响的卡号与验收编号、退回谁、哪条验收可能失效。
不现场猜值；影响半径变了就重开对应卡的读回。
实现前交五项：规则归属到唯一文件或条款、合法状态、默认出处、封装边界、失败退路。
缺默认或退路只退受影响改动，回计划作者或原 owner 补，不自行造。

## 回读契约

回读者的最小输出：

- 这一 Phase 独立交付什么结果，谁先消费；
- 第一处要读的文件与符号，第一处要改的路径；
- 目标测试在实现前为什么必须失败，失败的真实信号是什么；
- 写集边界、共享路径的前后写者、越界时停在哪里；
- 缺什么输入、谁补、恢复条件；
- 回退时保留哪些无关工作和原始失败。

回读者只能沿卡内指针读到同一原件；要翻会话、猜符号或自行补产品选择，按回读失败算，退回补卡。

回读者另核卡上「为什么这条能解决」「对应原问题/FR」「残余/未闭环」三句：缺任一句按回读失败算，退回补卡，不代答。

## 坏返回

- 只有 artifact ref 或目录名，没有首读符号与首改路径：不能交，补任务卡。
- 只有全局设计，没有独立 Phase 增量：不能交，先切 Phase。
- 只有 Phase 卡，没有索引或依赖不可解析：不能交，先渲染并核环。
- 用「按计划实现」「测试会过」代替目标失败与 oracle：不能交，补可证伪条件。
- 回读者答不出却由作者代答：不算回读，换独立读者或如实记缺口。

## 效率条款

效率：写卡即含验法与反例，审查只判三样——目标是否对齐、验法与反例是否成立、写集是否越界，不重写卡；回读另按本节「回读契约」的六问＋三句，审查与回读不合并。什么情况下不做：卡上没有可判的验法或反例时，先补卡再送审，不把审查当补写。违反时的表现：审查者动手改卡、把审查与回读合成一轮，或审查意见只有「再完善」。

## 收尾：单元复盘记录

Phase 切完、索引渲染并回读通过，这个 Phase 还不算完成：一个 Phase 的设计与执行合起来是一个单元，等本 Phase 执行完成由 build-code 的 run-phase 收尾当场记一条，这里不另记。
这一节只记一件事：这次按什么信号切的 Phase、切成几段；被否掉的切法写进「驳回」行（候选、来源、理由、保留位置），交给 run-phase 写入同一条记录，不写进「为什么不用更高层」。
五问、摘要上限、记录形状、状态词与证据指针，读 `skills/stage-reflection/SKILL.md` 的「单元模式：单元复盘记录」；此处不复述方法。
本 Phase 设计侧不单独发记录；执行侧缺记录只让这一个 Phase 这一条判未完成，不拦后续 Phase 开工。

## 失败与边界

- 输入缺失：只停依赖该输入的 Phase，其余安全规划继续；缺口写进 Phase 卡与交接。
- 方向或验收要改：停该路径并交原决定人，不自行改 `spec.md` 的产品承诺。
- 模板或索引附件不可读：如实报 `unavailable`、具名 owner 与下一动作，不凭未来路径捏造。
- 同仓读法与索引迁移：旧字面写集卡仍按原字段只读兼容；新指针卡只有索引行写入集列是路径来源。指针错、摘要不符、索引列破损或重渲染冲掉有效路径时，具名停该卡的范围解析，交原索引作者用同一批准输入补齐，或整组退回上一份一致材料再复验；不得回旧卡、取并集、扩整仓读取或返回 `[]` 冒合法空集，合法 `none` 只读段仍可区分。不能保证单源、可再生、旧卡只读兼容或公共行为不变时，撤回本次切换到上一一致版。
- 本技能不新增阶段、检查器、持久状态或第二份计划权威；步骤完成事实仍由现有 producer 与 `steps.json` 决定。

## 可搬运调用

单目录复制本技能时，完整写作方法需由调用者同时提供 `skills/spec-plan/SKILL.md`；缺该原件时明确报缺失，不把本小卡当完整替代。
来源与版本登记以 `skills/catalog.yaml` 的 `phase-maker` 条目为准；正文只给方法，不复制 catalog。
