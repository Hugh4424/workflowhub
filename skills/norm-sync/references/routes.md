# 规范主题路由

输入是已验证变化、真实项目AGENTS索引、精确写集与原owner，不是目录生成请求。沿project-norm-init的五类来源选择唯一现权威；等价实质源优先，缺源给原owner，不以空文件或新路径补许可证。

| 主题 | 路由到原owner | 只引用的相邻事实 |
| --- | --- | --- |
| 设计 | 领域/视觉/组件/布局/交互/内容的现专业正文；UI八子类仍分权 | 精确token/CSS/资产与组件API留原源 |
| 前端 | 工程、DTO/ViewModel、生命周期与质量原owner | 业务资格、接口字段和运行结果各原位 |
| 后端 | 当前架构/组件/存储/并发规范owner | 实现现状不是应然规则，public合同不复制 |
| 接口 | public函数/DTO/HTTP或CLI原合同owner | 具体字段/版本/错误仍唯一源，不强加REST |
| 验收 | 质量/证据/判据原owner及现协议 | AC/原始输出/ledger仍原任务与实现，不复制账本 |

索引只维护用途、读时、路径、owner/consumer和最后更新。跨类冲突给双方原源，先不覆盖；已验证经验同步到正确规则后，只清对应已迁项，未解人判断继续原Improvements规则。没有对应项明确不适用，不动他人条目。

WorkflowHub验收源由specs/acceptance导航现标准方法，T004 evidence与T005 done必须等各自真实生产/消费后才写；本路由不预签。PaperBuilder执行证据只沿specs/quality-governance/README.md与evidence-schema.md及ledger.py，WH norm-delta记录规范变化，不代PB执行账本。具体项目坐标由caller提供，不缓存个人根路径。
