# spec-analyze

只读一致性分析（lens-only / file_only），供阶段主会话收口与修复使用。它不写当前材料、不调用 provider，也不把分析结果当成继续工作的许可证。当前 profile 按下面分支取材料，细节见 [packet-lens.md](packet-lens.md)。

## 材料与责任

- make-decision：原始需求、当前 decision-log、Talk/Grill/审查及本次真实确认。确认前准备可审稿；确认后的阶段末核对依当前 workflow 执行，改变已确认决定才返回准备与真实选择。
- post build-plan：原始声明只读作来源；当前 decision-log、spec（产品与全局实现设计）、每个独立 Phase 与纯指针 index 是实际输入。历史 pre plan/tasks 只读，build-spec 不再是当前阶段。
- build-code：当前材料、实际实现、受影响测试与验收原件。没有实际结果就说明未执行/unknown，不由声明反推。
- build-prd：当前已确认方向、实际展示 PRD/任务地图与真实答复；只检查已产生的规划材料，不编实现验收。
- build-code 终末：实际代码质量由终末独立代码审查负责；本技能不增加一个 provider 审查点。

post build-plan 报告来源到当前材料的具体对应与差异事实，包括结构、引用、原需求遗漏线索和行为表述冲突；独立合并审查裁定需求语义与质量。reported 只表示本分析执行了，不表示语义一致或审查通过。

## 方法

核代码成因（why）时，从真实文件/符号的 git 历史与原决定沿 source→决定→FR→AC 逐级回读；用找到的事实和竞争假设解释代码形状，缺任一环写 `unknown`、影响与原 owner 的下一动作，不能用最近提交或来源路径存在冒完整谱系。

核对时区分直接事实、推断与未检查；推断就地紧跟一句“这是推断”及依据，不分小节、不加新符号约定。

1. 读取本分支实际存在的必要材料；缺必需材料报 material_incomplete 和影响。缺机器 packet、旧 source census 或认证 metadata 不等于缺实际材料。
2. 逐项读原始需求、真实答复及采用的来源，沿 source → 决定 → FR → AC → Phase/Task/消费者核实际落点；列出缺失、部分承接、矛盾、无源增量和显式排除/延期的出处。post build-plan 同时核依赖、唯一文件 owner、结构引用、index 到独立 Phase 的对应、重复正文、孤儿引用和遗漏的测试字段。每个差异引用双方原文与范围；编号出现或结构完整不证明业务覆盖。
3. 按当前分支对照实际结果；build-code 还读实际实现/代码入口、相关测试及执行原件，核 source → FR → AC → 实现/消费者/证据之间的缺口。规划分支只核已有设计落点，不编未来代码或执行结论。逐项保数量与范围限定、否定、顺序、产物形态、失败/取消/权限/范围边界和延期 owner/触发/交接；区分直接事实、推断与未检查。实现存在不证明 AC 行为通过，未读代码或未执行测试明确 unknown/not_run；独立质量裁决另行引用。
4. 每个 Phase/Task 核目标、来源、写集、实际消费者、测试层级/技能、场景/夹具、精确命令/预期退出、oracle、证据、覆盖、停止/恢复和完成条件。index 只检查权威引用/锚点/写集/依赖/消费者，不复制程序或保存执行状态。
5. 返回所有真实发现：材料/节或源码锚点、依据、具体问题、影响与最小修正。主会话在本任务修有效缺口，只复核受影响范围；改变已确认决定先完成可审稿再取得真实答复。未知或分析不可用保留原因，不写 consistent。
6. 在处置发现和最后一次相关改动后，报告当前实际分析结果。仅有依赖/manifest 声明不证明执行；无需身份 hash、snapshot、material revision、quality graph 认证或额外 publication 许可。

## 六类核对的实际落点

六类核对都写在同一份分析原件里，每类给双方原文位置、当前结果、影响和 owner 的下一动作。

在同一分析原件逐类给双方原文位置、当前结果、影响与 owner 的下一动作；不适用写具体对象为何不存在及依据。遗漏回原始要求/真实答复与 spec/Task；矛盾对照数量、否定、顺序、权限及失败强度；孤儿任务反查每卡的来源、FR/AC 与真实消费者；越界对照当前写集和原授权，不把质量事实当授权；消费者沿输入→产物→真实调用或读回；测试充分性逐条件核 oracle、反例、真实输入与证据上限。结构绿、编号命中或文件存在不能代替这六类语义检查，也不能代独立质量裁决。

第七类：读者可用。按 WR001／Q13 观察句长、行宽与术语解释，观察值与无法机械判定项分开。四条子判据是编号重复率、重复重述比例、模板与材料一致、写集与真实 diff；逐项给真实输入、读数或人读依据、例外与缺口。结构读数经 `skills/spec-plan/scripts/check-authoring-budget.mjs` 逐件报告，读数只报告，可读材料退0；缩写解释的语义和改名等价由独立读者核，启发式候选不当完整覆盖。

独立复述沿 build-plan 第11步按实际验收对象选取的完整输入与七段记录，不用七类清单在场代真跑；读者身份、五问原答、原命令及退出码须回原件。分析仍只读，不调用 provider、不写材料、不新增阶段或质量许可证。

## 原始需求覆盖核对

post build-plan 收口前完整执行一次；它是六类中「遗漏」的具体展开，不新增类。
静态读当前 decision-log、spec 与全部独立 Phase 对号，不跑测试或全量验证。

四段是需求、方案、验收、Phase 承接：

- 需求：decision-log「## 原始需求」逐条，不按工作包或合并描述计数。
- 方案：spec 的 FR 或全局设计对该条的落点。
- 验收：spec 的 AC 对该条的判定，写清场景、结果与通过/失败条件。
- Phase 承接：某独立 Phase 的「覆盖 AC」列出该 AC，任务卡给出命令与证据。

四段任一缺失即未覆盖；缺口＝没有人认领的未覆盖。
显式退役或延期的需求要有决定原文与 owner；延期的另写触发条件。
它们不算缺口，但单独列一段「已声明不做」，不许混进缺口清单。
一条 AC 可判多条需求，但要逐条点名；未点到的需求仍算未覆盖。
只被「合并描述」覆盖、没有任何 AC 实际判到的需求，没有决定原文的列入缺口。
另核 spec 每条 AC 至少被一个 Phase 的「覆盖 AC」列出；只挂 spec 的列入缺口。

输出三段：覆盖表、缺口清单、已声明不做。
覆盖表一行一条需求，列序是需求编号、方案落点、AC 编号、承接 Phase 与判定。
缺口清单一行一条缺口，写未覆盖需求或缺承接的 AC 编号、缺哪一段、原文位置与回哪个 owner 补。
已声明不做一行一条，写需求编号、决定原文、owner；延期的再写触发条件。
格式示例（编号仅示意）：

| 需求编号 | 方案落点 | AC 编号 | 承接 Phase | 判定 |
| --- | --- | --- | --- | --- |
| R-001 | FR-03 | AC-05 | P2/T003 | 覆盖 |
| R-002 | FR-04 | 无 | 无 | 缺口 |
| R-003 | 不适用（决定 7） | 不适用 | 不适用 | 已声明不做 |

- 缺口示例：R-002 缺验收与 Phase 承接；`decision-log.md#原始需求`；回 spec 作者补 AC。
- 已声明不做示例：R-003 决定不做；`decision-log.md#决定 7`；owner＝决策作者。

核对成本随需求条数与 Phase 卡数线性增长；修复后只复核受影响条目，不重跑全量验证。
结果并入「结束披露」的 `requirement_coverage`，不另立字段。

## 结束披露

报告以以下六类说明当前事实，名称只供解释，不新增必填字段或机器绑定：

1. `stage_work`：当前阶段实际做了什么。落点／owner：本阶段材料与 task facts；owner＝当前 stage 主会话。
2. `requirement_coverage`：当前来源→FR/AC→设计或实际实现的落点、差异、核对范围与未覆盖项；需求语义覆盖与质量结论引用独立审查。落点／owner：spec.md 的 AC 表与 decision-log.md 的验收面；owner＝规格作者。
3. `upstream_alignment`：上游原文、真实答复与当前结果的对齐依据及具体来源缺口；语义裁定引用独立审查。落点／owner：decision-log.md 的 ## 原始需求；owner＝决策作者。
4. `current_stage_repairs`：当前阶段当场修复了什么。落点／owner：本阶段 findings 处置行；owner＝当前 stage。
5. `remaining_risks`：剩余风险、未决与延期。落点／owner：decision-log.md 的风险与延期交接表；owner＝决策作者。
6. `next_stage_boundary`：下游可直接消费什么、不能自行猜什么。落点／owner：skills/stage-handoff/SKILL.md 的 13 区块交接；owner＝当前 stage。

只在实际检查范围内报告“未发现对应差异”，并列出读过的来源、材料/代码和未检查范围；需求语义及质量结论见独立审查。缺材料、不可用、不一致、严重未修事项都保持可见，不从普通报告推断质量通过、发布或 Git 交付。

创建或改写 agent 方法时，读取 `skills/spec-specify/SKILL.md` 的「技能写作规范（WR001）」唯一规范；保原步骤、条件、权限、失败强度和受保护字面，缺源如实 unavailable，不复制规范。
