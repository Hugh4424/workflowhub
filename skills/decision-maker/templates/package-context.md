# 上下文包（模板）

一个包一份，一页加引用。
只给任务库路径，不给整段会话；缺哪项写缺口和谁补。

## 包

- 包号与名字：`<...>`
- 目标（一句）：`<这个包最后要让谁看到什么>`
- 需求原文与来源：`<原话或原义；ref 与位置>`
- 现状证据（现在为什么做不到）：`<事实；ref>`
- 调研来源与已得结论：`<结论；ref>`
- 前序决定（只引编号和指针）：`<决定编号；ref>`
- 边界与非目标：`<做什么、不做什么>`
- 验收四件：通过条件（含命令或检查）`<...>`；失败条件 `<...>`；至少一个反例 `<...>`；证据路径 `<...>`
- 包级答复（有用户答复时写）：`<原件路径>`；sha256 `<64 位>`；调用 `<真实调用 id>`；哪几问属本包
- 开放问题（谁定）：`<问题；owner；时点>`
- 输出路径（本包材料放哪）：`<ref>`
- 卡模板：`card.md`；卡末机器字段见 `card.md` 的「卡末」段

只给本角色要读的那几份原件和摘要，不附整段会话；没有答复原件就不写答复行，
不拿整体确认或别的包的话补位。

## 供件与缺件

- 实际供件：`<是什么：内容或字段清单>`；谁给：`<提供者>`；在哪：`<原件路径与锚点>`。
- 一个供件一行：写接收者与接收字段；不转写原件正文，只给指针，收件人按指针回读。
- 缺件：`<缺什么>`；尝试：`<谁试、跑过哪条命令或问过谁>`；影响：`<哪一步或哪条验收>`；恢复条件：`<什么条件到了能补上>`。
- 缺件也写谁补、何时补；只写「缺什么」会丢掉尝试与恢复条件，接手人不知道该不该重试。
