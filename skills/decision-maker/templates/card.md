# 十一格卡（模板）

一包一张，每格第一句就是结论，细节放表和原件。
卡正文用人话；行号、命令、sha 等实现细节放附录或原件，必须在卡上出现时当场说明用途。
卡上不出现没解释的内部编号或黑话；编号和内部名称放「对应需求」「验收」，别放进白话复述。

| 格 | 写什么 |
| --- | --- |
| 一句话结果 | `<这一包最后做出什么>` |
| 对应需求 | `<承接哪几条需求>` |
| 现状缺口 | `<现在为什么做不到、缺什么>` |
| 方案与取舍 | `<选哪条路；至少一个被否替代和理由；接受什么代价>` |
| 边界 | `<做什么、不做什么>` |
| 数据与状态 | `<进来什么、出去什么、状态怎么变>` |
| 验收 | 通过条件：`<看到什么算过，含命令或检查>`；失败条件：`<什么现象算失败，必须单独成条，不能只写在反例里>`；反例：`<一个本该失败的实例>`；证据：`<命令输出/产物/路径>`。四项都要有真内容，只写「无」不算 |
| 风险与回退 | `<失败后果；触发；恢复>` |
| 未决 | `<谁定、何时定；没有写无和理由>` |
| 白话复述 | `<三到五句：改什么、为什么>` |
| 配套与影响 | 四项各一句结论：配套调整：`<调用方/配置/文档/测试>`；配套迁移：`<旧数据/旧合同/旧版本>`；配套移除：`<旧开关/旧代码/旧文档/旧测试>`；影响范围：`<哪些包/消费者/现有功能>`。完整四项写日志第十项。 |

## 卡末（校验器用，人可跳过）

机器段只放指针和版本，不放新结论。
卡版本只算本段之前的正文，所以追加或修正下面的绑定行不改卡版本。

- 包号：`<包 N：名字>`
- 设计者：`<写这张卡的角色名>`
- 审查者：`<做冷读和对抗的读者名；必须和设计者不同>`
- source_id：`<U-编号；原件未登记写 未分配>`
- modality：`<允许／要求／建议／拒绝，按用户真实语气>`
- 来源身份：`<用户答复／作者推断>`
- 答复原件：`<任务库路径>`；sha256=`<64 位小写十六进制>`；调用=`<真实调用 id>`；包=`<包 N>`
- 答复原文：`「逐字原话，必须能在答复原件里找到」`
- 选项与风险：`<当时给用户看过的推荐选项和代价，一句>`
- 调研原件：`<路径>`；sha256=`<64 位小写十六进制>`；调用=`<子代理名>@<派发时间>`
- 设计原件：`<路径>`；sha256=`<64 位小写十六进制>`；调用=`<子代理名>@<派发时间>`
- 冷读原件：`<路径>`；sha256=`<64 位小写十六进制>`；调用=`<子代理名>@<派发时间>`
- 对抗原件：`<路径>`；sha256=`<64 位小写十六进制>`；调用=`<子代理名>@<派发时间>`

- 卡版本：`node skills/decision-maker/scripts/validate-card.mjs <card.md> --version`
- 四份角色原件必须是四个不同文件，各自写 `agent:` 与 `dispatched_at:`，合起来等于卡末的 `调用=` 值；
  `dispatched_at` 用真实派发时刻，须可解析且不是未来时间；文件 mtime 不是证据，校验只作 advisory 提示，不判失败。
- 审查原件另写 `reviewer:`、`designer:`、`reviewed_card_sha256:` 三行，值与卡末一致。
- 机器只判形状（四件齐不齐、卡版本对不对、身份是否不同人、答复原话在不在原件里）；审查质量与方案是否成立归人读。
- 只有引用用户答复时才写 source_id／modality／来源身份三行；缺一即来源不可验证。
- 十项正文（含配套与影响）写进决策日志该包，不在这张卡里再写一遍。
