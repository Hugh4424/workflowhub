# 十一格卡（模板）

一包一张，每格第一句就是结论，细节放表和原件。
卡上不出现没解释的内部编号或黑话。

| 格 | 写什么 |
| --- | --- |
| 一句话结果 | `<这一包最后做出什么>` |
| 对应需求 | `<承接哪几条需求>` |
| 现状缺口 | `<现在为什么做不到、缺什么>` |
| 方案与取舍 | `<选哪条路；至少一个被否替代和理由；接受什么代价>` |
| 边界 | `<做什么、不做什么>` |
| 数据与状态 | `<进来什么、出去什么、状态怎么变>` |
| 验收 | `<通过、失败、至少一个反例；证据（命令/产物/路径）>` |
| 风险与回退 | `<失败后果；触发；恢复>` |
| 未决 | `<谁定、何时定；没有写无和理由>` |
| 白话复述 | `<三到五句：改什么、为什么>` |
| 配套与影响 | 四项各一句结论：配套调整：`<调用方/配置/文档/测试>`；配套迁移：`<旧数据/旧合同/旧版本>`；配套移除：`<旧开关/旧代码/旧文档/旧测试>`；影响范围：`<哪些包/消费者/现有功能>`。完整四项写日志第十项。 |

## 卡末

- 校验器用，人可跳过：`source_id`、`modality`、`来源身份`；取值与表头见 `decision-log-template-v2` 的答复索引/卡末。
  三行只在引用用户答复时出现，缺一即来源不可验证。
- 十项正文（含配套与影响）写进决策日志该包，不在这张卡里再写一遍。
