# 决策日志（decision-log）

读者：make-decision 主会话、build-plan 与 build-code 作者，以及回读验收和风险的 verify-code 作者。
读完要能：定位真实需求、已确认决定、写入范围、验收索引与原件；区分示例、实际事实和缺口。

本模板只安排正文，不认证身份或授权。以下示例演示写法，实际日志以本任务真实来源替换；这是写作指引，不是质量门。

## 工作包与决定

本节回答要交付什么、为何这样做以及失败后由谁处理。

### 工作包 ① — 示例结果

- **要交付什么**：决策作者按同一模板记录方向，下游可定位决定、文件与验收索引；来源 R-001；消费者为材料作者。

#### ADR-001 — 示例选择

**决定**：主文保留方向与交接索引，过程事实引用任务库原件；真实确认尚未提供。｜**为什么**：模板与方法共享落点，下游可从决定找到来源与影响。｜**否掉了什么**：在主文重复保存过程全文，因为副本会形成第二处维护来源。｜**后果与风险**：读者需按指针取原件，原件缺失时相应事实保持 incomplete。｜**影响面**：`skills/decision-log/templates/decision-log-template.md` 与 `skills/decision-log/SKILL.md`；消费者为决策作者和下游材料作者。

失败了怎么退：指针缺失由当前作者补齐真实来源；方向冲突交主会话与用户处理，旧决定保留编号与原件指针，引用新的决定。

完成判据：每个工作包有结果、消费者、来源、五字段决定与具名失败恢复路径；实际确认可从指针回读。每个 ADR 全文仅出现一次，其它位置只出现编号。

## 范围与非目标

本节回答目标、工作边界以及退出的事项。

- **目标**：示例目标是让作者使用同一决策形状。
- **范围**：示例只涉及模板与方法文档；实现设计由 spec 承载，执行事实由 task facts 承载。
- **非目标**：历史日志保持原文，作为只读来源；本例没有真实删除、宿主变更或 Git 交付授权。
- **Supersedes**：无；真实替代时一行引用旧决定、新决定与更改理由，明细指向外置原件。

完成判据：目标可观察，范围具体，每个非目标一行理由与去向；被替代主张逐条可定位，历史事实保留。
