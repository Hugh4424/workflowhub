# 决策日志（decision-log）

本文件写给 make-decision、build-plan 与 build-code 作者；读完要能定位需求、决定、写集、验收与原件。
make-decision 做决定，build-plan 写规格与实施阶段，build-code 实施。

> 写作标准：`skills/material-writing/SKILL.md`
> 的「材料写作标准（唯一）」是本文件唯一标准。
> 本文件不复述标准，只说明自己的例外。
> 例外：`任务身份`、`级别与路线`、`原始需求`、
> `验收面`、`外置事实索引`、`大纲地图`、`质量边界`、
> `旧编号对照`、`D-0xx` 是逐字读取的引导词。
> `工作包 N` 标题是机器读取的包标识，保留原词。
> 决定标题写动作动词，不写问句。
> 决定是记录，不是读者问答节。
> 验收标准与档位不自造。
> 写法见 `docs/architecture/test-asset-governance-rules.md`。
> 八值档位只引
> `runtime/evidence/acceptance-evidence-validator.mjs` 的词表。

本模板只安排正文，不认证身份或授权。
示例演示写法，实际日志以本任务真实来源替换。
这是写作指引，不是质量门。
引用外部来源时写清版本与回原文的直达链接。
取不到来源写 `unverified` 与具体缺口。
推断就地紧跟“这是推断”及依据，不单独成节。

本类材料必须留下六类内容，落点见下表。
这是内容覆盖指引，不是全仓固定清单。
它不新增 runtime 标题或字段，也不是质量门。

| 必留内容 | 落点 |
| --- | --- |
| 任务身份和原始需求 | 任务身份；原始需求 |
| 最小大纲与整体故事 | 大纲地图；这次覆盖什么，排除什么？ |
| 当前决定及理由 | 每个包定了哪些决定？ |
| 范围和非目标 | 这次覆盖什么，排除什么？；哪些文件由谁改？ |
| 验收与真实风险 | 验收面；什么风险交给谁？ |
| 用户答复来源与必要原件 | 每个包定了哪些决定？；外置事实索引 |

生成时逐项在落点标状态，声明与实际内容一致才算在场。
状态分已写、不适用、延期；不适用必须写理由和依据。
延期必须写责任卡、触发条件与受影响结果。
延期只声明缺口和承接，不删除标题，也不冒已完成。
内容状态与选节互不代替。
轻、普通、复杂、规划四级路线都保留三样东西。
三样是骨架、收敛与整体故事。
骨架是包与决定的目录。
收敛是每包问题都有结论或具名缺口。
整体故事是一句话的来龙去脉。
单模块可用一项骨架和一段故事。
出现多模块关系、取舍、变更、未决或退役时才展开。
按实际对象展开关系、替代方案或相应节。
没有事项时说明无及依据，不留空壳。
过程材料只在具名读者需要回读时引用既有原件。
已关闭过程不复制进当前决定。

路线由入口调用确定，当前尚未调用，所以没有取值。

- **入口字段（校验器用）**：只在本节写四个字段。
  status、reason、expanded_risks、choices 是字段名。
- **判级事实**：写七项输入判级事实及逐项来源。

  还要写是否含需要用户在场或真实凭证的动作。

- **调用原件**：写实际调用命令。
  返回原 ref 的唯一可回读指向也写在这里。
- **级别选择**：写推荐级别、理由、真实用户选择与来源。
  这些沿当前入口方法写入。
- **改级影响**：写覆盖旧级别或新级别的影响。
  历史追加保留。
- **原始返回**：单份沿唯一原 ref 保存。
  工作包决定只引用本节稳定锚（固定标题）。
  必要决定含义也引用同一节。

返回未包含项写“未返回”，不补造值。
缺来源写 unassessed（未评估）与具名 owner（负责人）。
函数不可用、材料不足或取值缺依据记未评估或未决。
paused（暂停）时在第8步与第13步同批展示拆分路线。
至少一条可选拆分路线；建议不是许可。
原 ref 缺失或不可回读时报告原件不可得、具体缺口与 owner。
这种情况按复杂处理。
不以其它节原值兜底，不另存或复制 raw（原始字节）。
未答不当用户授权，其余安全工作继续。

## 每个包定了哪些决定？

### 决定怎么写

每个决定固定四个父字段。

标题含动作动词，脱离正文可读目标。

### 覆盖结论是什么？

覆盖结论（示例）：需求 1 与 变更 1 均有 决定 1 落点。
真实来源尚缺，由 未决 1 承接；本例不能声明覆盖完成。

覆盖结论的唯一原件是 `coverage-matrix-5d.md`，基准目录见「外置事实索引」。
原件未产生写缺口；已有 itemized（逐项列出）或其它原路径沿原 ref，不搬移、不复制。

唯一覆盖原件复用现有三栏。
三栏是来源、事实与处置、落点或缺口。
每个需求与每个变更各一行。
按先枚举全部真实来源（含后补或非数字顺序的 U），再对照原始需求、回答、调研、Grill、审查结论与决定，最后反查写集有源的顺序；U 是需求变更。
缺编号行或落点空，就是需求遗漏签名。
在该来源的已有格中写缺口，不得默填已落。
缺口格式是“原编号／原来源／缺哪一落点”。
已读却未交的需求或变更，事实栏明写“已投递未执行”。
缺口栏写应落现哪节、缺哪一输出、owner 下一动作。
登记未处置的项必须以缺口出现一次。
finding（审查发现）、风险、OI（未决问题）各归原处置位置。
不属于需求或变更的项，也在原处置格写缺口或“已投递未执行”。
原 ref 与 owner 下一步也要写。
影响需求或变更时，覆盖原件的对应格引用原处置。
不复制全文，不另建未处置清单。
排除需求仍须真实用户选择的理由、影响与去向。
登记为风险不等于已接受排除。

完成判据：每条承诺有可观察用例、成功与失败边界。
证据或具体缺口、承接负责人及对应 UC 也要有。
spec 承接后逐条核对同号。
覆盖矩阵逐项有事实、处置与落点或缺口。
所有真实需求与全部真实变更（含后补项）各有一行。

- **GLOSSARY 读回**：引用已解决术语变更的写入与读回原件。
