# Decision Log

读者：make-decision 主会话与整理决定的材料作者。
读完要能：从真实来源写出下游可消费的决定、索引与条件指针，保留来源并标明缺口。

把当前真实输入整理为一份 `decision-log.md`，供 make-decision 主会话和下游读取。使用 [decision-log-template.md](templates/decision-log-template.md)；模板只安排正文，不认证身份或授权。主会话负责方向问答和最终确认，本技能不代答。

## 写作步骤

本节回答：怎样从真实来源形成可供下游消费的决定。

1. 读取原始需求、已确认答复、约束、调研/Grill/独立发现的真实来源。记录任务类型（规划任务/普通任务）；缺失或矛盾写 unknown，不按路径或旧任务猜类型。
2. 选择最小需求框架：功能用背景→问题→目标→方案→验收→扩展；研究用问题→论断→证据→裁决。混合任务只在既有节点挂研究子项，不另建需求账本。
3. 读取模板 `## 外置事实索引` 的节级消费者定义，按下游实际动作划正文与原件。原始需求的原义、痛点、旅程、成功／失败边界及必要逐字声明留主文；用户声明原件、U 完整变更记录与索引明细在任务库根唯一原件保存，主文保最小决定、来源指针与 U/V/R 关系。不同来源分别记录；来源缺失写具体缺口。
4. 当前未决问题只在本日志维护：目标、完整旅程、页面范围、数据状态、成功失败/取消/权限、非目标与延期均有明确处理或不适用理由。每项写问题、来源、影响、真实处置和需谁决定；open/confirmed/deferred/not_applicable 分开。按真实回复重排，零问题合法。
5. 模糊需求至少比较两个有差异的角度；保留用户候选、来源、与其它候选的差异、关键假设和可推翻条件。多数关键假设被事实推翻时，保留旧判断和更改理由，再整理候选。该讨论不新建候选对象或版本许可证。
6. 写重要决定的风险/取舍前，读 `skills/simplicity-guard/SKILL.md` Packet lens三问，按实际路径回答幂等/半完成、共享状态的结构性串行与消除复杂度；已有权威承接写非目标，必要含义无承接则保留。每个重要决定按下方四字段职责写一次当前正文，保留问题和选择、推荐与理由、真实来源及原话锚点、事实／约束、source→constraint→choice→result 推理、受影响范围、后果与风险、拒绝的替代、未决与延期负责人。按模块保持因果顺序，引用上游决定、FR/AC 与产物；下游所需写集、AC 与必要接口完整留主文，实现细节由 spec 承载。中途新增需求时，在同一决策日志新增一个大纲模块，模块内补齐调研、决策、方案与验收标准，不新增步骤。完成以这些来源与接口可定位为准，原件缺失如实保留。
7. 确认只写用户实际给出的答复及其展示内容/消息定位；未答、取消、拒绝和推测不是同意。当前确认覆盖的范围可继续使用；若改变已确认决定，先准备可审查更改再取得真实选择，不为普通补字反复询问。
8. 保留原始 finding 及 fixed/rejected_invalid/accepted_risk/needs_human 的具体理由、影响和下一步。严重问题未修必须展示实际损失并取得该问题的风险选择，review 不能替用户作决定。
9. 逐项对照原始需求、回答、采用的调研/Grill/发现和决定：每项有落点，或有用户明确选择的排除理由与去向。缺口留在本任务修；决定更正追加新条目，引用被替代条目并保留旧条目引用（编号＋指针），不复制旧正文，不改写历史事实；旧正文此前只在主文时，先保存到任务库根 `quality/evidence/decision-log-refs/` 唯一原件，再指针化。
10. 返回简短人读摘要：决定、来源类型、理由、范围、后果/风险、非目标、未决、领域术语/ADR 结果与下游边界。写了文件就返回实际路径；仅生成正文就如实说明尚未写入。

## 内容边界

本节回答：哪些内容由日志保存，哪些只引用原件。

- 主文保留 build-plan 写 spec 与 phases 要用的需求、方向、写集、AC、必要接口和风险／延期／未决输入；候选讨论、Talk、Grill、逐项对账、审查处置与确认过程只引唯一原件。当前决定推理就近随四字段，不把同一结论在主文和外置件再写两份全文。 代码坐标、判定阈值、字段级方案与可粘贴代码不属主文：坐标归 `spec.md` 的代码锚点节，逐 Task 的坐标与常量名归 `phases/P<n>.md` 的「文件 / 符号」与「动作」，判定阈值与字段级方案归 `spec.md` 的实现设计节；数值唯一来源为生产代码内的既有具名常量。受影响文件与符号名仍留主文。这不是篇幅规定，是内容归属；既有篇幅禁令仍然有效。
- 用模板 `## 外置事实索引` 节级消费者定义逐节回答“下游哪一步读它”：写 spec／phases 的直接输入完整留主文，核来源与过程才读的材料写条件指针。界限按内容，不按长度；有同义载体时按语义读，不能由结构名未逐字命中推义务不存在。
- 分支测试：每个任务都要的留主文，部分分支需要的放条件指针后。模板节名承接任务身份、大纲地图、需求与 U 最小索引、工作包与决定、文件、范围、验收、未决、风险、退役和外置定位；完整需求变更记录整节外置，最终地图按实际顶层标题与顺序生成，自身省略，不以旧“十二节”计数限制新材料。
- 过程原件由 `## 外置事实索引` 给本任务基准目录绝对路径与相对原 ref，读者先核基准再取唯一原件；主文保下游所需结论＋原件定位＋取用条件，不设行数、文件大小、每行字节阈值。以下接收文件位于任务库根 `quality/evidence/decision-log-refs/`；每项到达条件与主文落点如下：
  - `research.md`：写 ADR 的为什么或核对事实来源时读；主文留 research_id 与结论。
  - `review-dispositions.md`：处置 finding、核对 fixed/rejected 理由或 Grill 逐项处置时读；主文留 finding／问题编号与结论。
  - `talk-batches.md`：回读用户某批 Talk 答复时读；主文留 batch_id 与结论。
  - `verbatim-declarations.md`：核对用户原话或共享定义逐字文本时读；主文留编号与原件锚点。
  - `convergence-check.md`：需要目标／范围／方案／验收四行真实答复时读；`## 未决项` 留一行指针。
  - `divergent-candidates.md`：复核被否候选与可证伪条件时读；主文留候选编号与取舍结论。
  - `open-item-outline.md`：核对未决项与大纲节点对应关系时读；`## 未决项` 留 OI 编号、状态与下一步。
  - `coverage-matrix-5d.md`：收口核对所有真实 R 与全部真实 U 的逐项事实／处置／落点或缺口时读；`## 验收面` 留结论、缺口与条件指针。
  - `requirement-change-log.md`：首次写完整 U 变更或需核对真实来源、处置与受影响决定时读；主文每 U 留最小决定、受影响落点及唯一 ref。
  - `requirement-index.md`：按 R 编号定位原义与来源时读；`## 原始需求` 留 source_id、一句原义、来源与落点。
  - `traceability-chain.md`：沿 source→constraint→choice→result 回读决定时读；主文保当前四字段及就近来源锚点，历史全文保持原 ref。
  - `research-candidates.md`：回读候选摘要、推荐与拒绝理由时读；主文留可从报告回读的结论。
  - `final-confirmation.md`：核对用户确认的展示对象、答复与消息定位时读；主文留确认范围与来源。
- 原件已在其它 quality 路径保存时引用该唯一原路径，未产生则写具体缺口；Supersedes 明细、变更全文及 Grill 原件按真实来源引用，不为接收文件名复制已有原件。
- 阶段末一致性准备与确认后核对遵循 `workflows/make-decision/SKILL.md`。方向审查读取问题与客观事实，不混入候选/答案；细节审查读取当前决定与真实处置。本文不把已确认选择当盲审材料。
- 领域术语与 ADR 方法读取 `skills/grill-with-docs/SKILL.md` 的唯一领域 owner：首个真实术语确定后才懒建目标项目 `GLOSSARY.md`，真实多上下文按该 owner 的 map/格式处理；术语载体只记录领域语言，不承载实现设计；尚未迁名的现材料只读作来源，不另建术语真相。ADR 仅在难以反转、无背景会意外、有真实取舍三项同时成立时记录已决定方向，任一缺失跳过。已有决定不重问；新方向争议才向用户提问。
- 退役内容写进模板 `## 退役登记` 的五列：日期、哪张、为什么退役、谁决定、原来的需求编号；决定人列引用真实决定来源，原需求列说明去向；没有实际授权不声称已批准删除。
- 材料、实现、测试、独立质量、Git/物理交付分别报告。来源引用可回读，不依赖 report_sha256、decision hash、固定 schema 或机器 coverage 认证决定能否工作。

## 来源与未决问题写法

本节回答：怎样在 `## 原始需求`、`## 需求变更记录`、`## 未决项` 与 `## 外置事实索引` 保留原义、真实处置和来源，不把写作说明变成必填 schema。

OI 写在 `## 未决项`，一张表、一条一行；列出问题与来源、状态与真实处置、解决者及下一步。open/confirmed/deferred/not_applicable 分开；缺证据标出具体缺口与承接人，零问题写无。方向审查只看问题与事实，细节审查读真实处置；两者使用同一份当前未决项。

U 的完整 `## 需求变更记录` 整节在任务库根唯一 `quality/evidence/decision-log-refs/requirement-change-log.md` 保存，每个真实 U 记录变更、真实处置、原文锚点和受影响决定；已有原路径沿原 ref，不复制。主文每 U 只留最小决定、受影响落点及到达条件指针；V 原文与 U/V/R 索引明细保存一次，主文原始需求及必要逐字声明按模板消费者定义保留。每条引用用真实编号与原件定位，缺来源写具体 unavailable 与 owner。

一条当前 decision entry 按模板四个父字段写：做什么、不做什么、风险、改动；字段职责、字段级结论、子要点与目标句标题读模板 `## 工作包与决定`，来源、约束与拒绝替代理由就近随动作，不丢因果链。多子点数量不设上限，四字段不等于四条要点。普通任务有实际执行目标时，按 `workflows/make-decision/SKILL.md` 第 1 步执行入口评估；事实与调用命令、返回原件唯一落点按同一四字段写一次，供第 8／13 步展示。缺来源写 `unassessed` 与具名 owner，返回未包含的项写“未返回”；真实返回 `paused` 时，拆分路线沿同一决定在既有展示正文内承接。未决负责人、旧决定与详细选项用相邻交接行或原件指针承接。编号与计数复用各事实原 producer：决定集合取当前决定节，写集取该表，AC 取唯一判据权威；重述数字与同号关系引用原锚，不另造计数，不重编号现 N／ADR／D 或改写 legacy 位数。

做 coverage audit：实际枚举所有原始 R 与全部真实 U（包括后补、非数字顺序的 U），按模板 `## 验收面` 的三栏形状逐项读写唯一 coverage-matrix-5d 原件；已有 itemized 原件只沿原 ref。每项有现工作包／写集／决定等真实落点或缺口，再反查每项决定／写集有源；缺行、落点空、已投递未执行或登记未处置均按模板留遗漏签名、原 ref 与 owner 下一动作，没有落点不另建节，未决真实状态留现 OI。采用的 Grill／调研／load-bearing finding／决定仍逐项有真实处置；finding／风险／OI 归各自既有唯一格，未处置也具名写缺口，影响 R／U 时覆盖格引用原格。用户真实选择的排除保理由、影响与去向，不用 review 风险记录替代；完整来源 audit 同时用于当前正文与每个已接受排除。主文仅覆盖结论＋条件 ref，不增字段、台账或推进门。

## 编号写作规则

本节回答：怎样压缩重复而保留条件、原义与真实来源。

1. 先写决定，再给依据，最后写例外与风险；一段一主题，主动说明谁做什么。
5. 用同一术语表达同一含义，不为缩短省略条件、否定、因果或必要解释；必要解释指该决定独有的事实与约束，不含原件正文。
6. 保留机器读取的标题与标签、原始逐字声明及被锁定文字；这些是允许的例外，不能改写去凑短；逐字来源在唯一原件保留，正文必要声明按模板消费者定义保留，其它位置只引用。
7. 当前决定四字段正文只在真实 N／ADR／D 决定标题下写一次，其它节用编号引用；新 ADR 沿现 ADR-NNN 编号，现任务与历史编号原样保留。起草件／Grill／审查处置／Talk 原件保存一次，主文只留必要结论＋路径＋取用条件；历史五字段全文保持原 ref，取消当前同一结论双份存储指令，不把历史原件当第二当前权威。
8. 按 duplication／sediment／no-op 定位重复、过时或无效内容，再沿节级消费者定义改条件指针；保留该决定独有的事实、约束、因果链与冻结字面，不以行数、字节、比例或其它篇幅指标驱动精炼，也不换成预算或评分器。

本节是写作指引，不是质量门。

创建或改写 agent 方法时，读取 `skills/spec-specify/SKILL.md` 的「技能写作规范（WR001）」唯一规范；保原步骤、条件、权限、失败强度和受保护字面，缺源如实 unavailable，不复制规范。

完整来源权威：[catalog条目](../catalog.yaml#skills.decision-log)；正文/小卡是非权威线索，单技能副本缺catalog时向来源维护者取登记。来源：本仓decision-log模板与grill-with-docs领域方法。
