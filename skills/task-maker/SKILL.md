# Task Maker

读者：build-prd 第 4 步的内容作者，以及沿 PRD 任务分节接手规划、实施和验收的下游读者。
读完要能在同一作者、同一稿 PRD 里展开任务卡，并让下游从地图和分节找到真实入口。

## 与 spec-prd 的分工

- 完整 PRD 写作方法、结构、模板与两次内容调用限制只读 `skills/spec-prd/SKILL.md`；本技能不复制全文。
- 本技能只承接第 4 步的**同作者分节与地图供件契约**：接手前核什么、写哪一节、交什么、什么不能交。
- 与 spec-prd 冲突时，PRD 写作方法以 spec-prd 为准；第 4 步的入口、锚与读取回执以本文件和第 4 步 `steps.json` 的声明为准。

<a id="process-context-to-output"></a>

## 流程：从上下文到可回读的产出

本节只给阅读与产出的先后，不替代下方方法节，也不与各技能内部的步骤编号对齐（本技能另有八步或六步的方法节时，按那节的编号读方法）。

1. **上下文**：产出是三条 ref——本次会话的真实原话、已登记的研究原件、原始需求条目；缺一条写「未取得」与影响。拒认：拿会话摘要、记忆或「见上文」当 ref。
2. **调研**：产出是内部三处的实际读数——`decision-log.md` 已定、`spec.md` 当前、仓内实现——每处给 ref 与一条推翻条件。拒认：只有结论没有 ref；把已知当调研。
3. **设计**：产出是按本技能产物写的初稿，并至少写一条被否替代与它的适用条件。拒认：只写选中的那条；把模板空格填满当设计。
4. **Talk**：产出是逐轮问答原件，一轮一问、问答串行，**只处理本单元会改变产出的歧义，不再开方向 Talk/Grill**（`workflows/build-plan/SKILL.md:23` 已定 build-plan 阶段不重开方向 Talk）。拒认：攒一批问、自问自答、拿「已确认」代替原话、借本步重开方向讨论。
5. **产出**：产出＝同一 `prd.md` 的任务卡节六字段（为什么做、交付什么、不做什么、前置／依赖、怎么验收、风险与没定）、五列任务地图与决策覆盖表。拒认：只有目录或链接；把「按计划」「按技能」当产出。
6. **冷读／对抗／异源**：产出＝分节审查两路只读发现与一次处置，一轮一处置。拒认：同一人两路、只读不改、发现不处置。
7. **收敛**：产出是可回读的最终件与「未收敛」缺口清单（每条带 owner 与恢复条件），即地图与任务节双向回读无孤儿、覆盖表落点无空行。拒认：字段齐就记收敛；把缺口留到下一轮。

本节是顺序尺子：八步流程（decision-maker/phase-maker）与展开任务分节（task-maker）的步骤编号、插入步与产物定义不变，本节的七步不另立门。

### 流程六项落点

- 上下文来源：第 1 步读当前决定、来源、地图与真实答复。
- 谁派调研：同一作者；本技能承接第 4 步的同作者分节，不换作者。
- 歧义先 talk：真实地图答复可以确认、拒绝或要求修改；未答仍是 draft，不代答。
- 产出形状：第 5 步的同一 `prd.md` 任务卡节六字段、五列任务地图与决策覆盖表。
- 谁审：第 6 步分节审查两路只读发现与一次处置。
- 怎么收敛：第 7 步地图与任务节双向回读无孤儿、覆盖表落点无空行。

<a id="plan-threshold"></a>

## 规划稿门槛

只有跨任务排期取舍或用户明确要求才写完整规划稿；其余情况不写。与 `decision-log.md` 的规划任务类型一致，不把普通任务伪装成规划任务，也不把已答过或已有文档冒本次试跑。

- **普通单任务，无规划请求**：只产规格与实施卡，不生成完整 PRD 或完整规划稿；实际入口读到「需要明确规划任务类型」时照实停，不写入。
- **跨任务有实际排期取舍**：写完整地图与任务分节；依赖写真实供件与先后，不拿波次当供件。
- **用户明确要求规划稿**：按原要求写完整地图与可复读详情，并引用原要求；历史多任务不能伪造为隔离单任务的实证。

<a id="expand-task-section"></a>
## 展开任务分节：同作者、地图供件

### 接手前先核三件

1. **同一作者**：第 2 步写出地图的人必须就是第 4 步展开详情的人；换作者、按波次切作者都不算。
2. **真实地图答复**：地图已在当前对话实际展示并收到真实答复；答复可以确认、拒绝或要求修改，未答仍是 draft，不进入详情。
3. **可定位的分节**：当前 `prd.md` 能读到 `## 任务卡` 节和具体任务标题（含任务编号或稳定名字），并能在同一稿里找到对应地图行与来源。

三件缺一：只有地图、只有任务标题、或分节与地图对不上，不能交下一位消费者；写明缺哪件、谁补、恢复条件。

<a id="task-section-checks"></a>

### 任务节检查项

字段定义与四要素只以 `skills/spec-prd/templates/prd-template.md#task-section-fields` 的四要素定义为准（同一 PRD 的「任务卡」节照此写）；本节只列交回前逐项检查什么，不复制定义。

- 独立结果：能否单独成立，不靠别卡做完才成立。
- 用户可见：结果是否用户能观察到，而不是内部步骤。
- 前置供件：是否写进「前置／依赖」字段（两者指同一物），提供者、输入形状与下游接收读法齐全，而不是空供件。
- 四行验收：是否每个独立结果一段、四行齐，第 3、4 行有对照物、独立复算者、故意弄坏；第 4 行是否写出 `证据落点：<原件路径+行位>；真跑或替代：<命令与退出码／读者动作／替代理由>。替代只限真跑不可能，并写原因、owner、不能证明什么与残余。`
- 为什么做：是否写清解决谁的什么原问题（引用户原话或稳定编号），而不是只写目标。

### 展开动作

1. 重读当前决定、来源、地图与真实答复；答复改变已确认范围时先处理差异，不把旧地图当已确认。
2. 在**同一份** `prd.md` 的 `## 任务卡` 节逐卡写 6 个 plain 字段：为什么做、交付什么、不做什么、前置／依赖、怎么验收、风险与没定。
3. 每张卡写一条用户能观察到的结果；一个结果写一段四行验收（目标、怎么操作、什么条件、怎样算通过），第 3、4 行必须写对照物、独立复算者和故意弄坏。
4. UI 任务在 6 字段外补接线、视觉、组件三段；接线段写页面区域、数据或动作的真假变化与失败态；视觉段写设计源与视口对照；组件段写复用与沉淀。非 UI 跳过。
5. 同一作者同批写决策覆盖表（附录 B）：行按 `decision-log.md` 六节实有项列，落点只写卡号、共享节名或「不做/后置/被取代」；落点为空即未完成。
6. 写完回读地图：每条地图行都能落到一张任务卡或用户明确选择的排除；反向每张卡都能回到来源。对不上就改，不新增第二份地图。

### 地图即唯一索引

任务地图就是唯一索引：五列地图是找任务的唯一入口，不另建卡目录、第二份地图或独立索引。

- **地图孤儿**：地图行在、同一 `prd.md` 的 `## 任务卡` 里没有对应任务节标题，这条行就是地图孤儿；交原作者本次调用内回修，不能靠另加索引掩盖。
- **落到同一标题**：每条地图行都必须在同一份 `prd.md` 落到任务节标题（同号卡节），别的文件或别处有正文不算。
- **双向回读**：任务节标题也要能回到一条地图行与真实来源；对不上就修同一稿。
- **结果列**：只写用户可见结果，不得写实现细节（实现步骤、手段、模块名、函数名、文件路径）；写成实现就按该地图行点名回修。

### 供件与拒认

- 交给下游的最小供件：同一稿 PRD、任务地图、已展开的任务分节、决策覆盖表、真实地图答复的位置。
- 只有地图，没有任务分节：不能交，下游无法开工。
- 只有任务分节，没有地图或答复：不能交，无法证明范围来自真实确认。
- 分节与地图、决定、来源任一处对不上：不能交，先修同一稿。
- 用「按计划实现」「应该通过」代替四行验收：不能交，补可判条件与反例。
- 无跨任务取舍、用户也没明确要求，却默认写整稿：不做，按「规划稿门槛」只产规格与实施卡。
- 把整理覆盖表当第三次内容调用，或另起第二份 PRD／第二作者：不做，回到 spec-prd 的调用限制。

<a id="sectional-review"></a>

## 分节审查：同节两路与一次处置

本节单点定义分节审查的两路要求、同一卡节摘要算法与处置口径；其他方法文件只引用本节，不各写一份。

### 同节两路与同一卡节摘要

- **两路独立读者**：同一版本卡节交给两路彼此独立的读者，各自只读、互不可见对方的发现；两路看同一卡节版本，界按同一任务／单元／批次，不给两路各发一份改稿。
- **同一卡节摘要**：两路各自对同一卡节的原字节计算 sha256，并附原节摘要；只有两路摘要与同一卡节版本一致，才算看的是同一节。摘要算法只在本节定义一次，`skills/spec-prd/SKILL.md` 与 `workflows/build-prd/SKILL.md` 只写指针，不复制算法。
- **只读返回**：两路只读返回发现，不写正文；写权始终归原内容作者，两路不互相补签，也不由一路替另一路作证。每路返回的原件写实际执行者、会话或来源，判读沿 `skills/unit-kernel/references/review-protocol.md` 的「独立输入」节。
- **同处定义**：两路要求、同一卡节摘要与处置口径都在本节同处定义；改动任一项时同批改本节，不在别处另写第二份。

### 一次处置与两路不全

- **一次处置**：两路发现合到一处，按位置、根因、后果的顺序各写一句；同一问题只处置一次，不按两路各改一遍。
- **保两条原发现**：处置后仍保留两路各自的原发现引用（含路径与位置），两条原发现不合并成一条；另保留有效单源发现，即只有一路发现但经核对成立的有效发现，照原样留下。
- **两路不全口径**：一路失效或两路不全时，记分节审查未过；不拿另一路冒通过，也不以全文审补签。保留原因与原错，写明失效的一路、恢复条件与适用发现；每路原件仍写实际执行者、会话或来源；只有一路可用时，其发现按有效单源发现保留，不等于两路通过。

## 效率条款

效率：调研结论直接落任务卡，不另写中间设计稿；同一结论只写一次，后续只引卡号与节名。什么情况下不做：跨任务排期取舍需要完整规划稿时，按「规划稿门槛」写规划稿，不把中间稿伪装成任务卡。违反时的表现：先交一份设计稿再誊到卡上，两处说法不一致，下游不知道该读哪一份。

## 收尾：单元复盘记录

任务分节写完、卡节审查两路处置完，这个单元就完成，当场记一条。
这一节只记一件事：这次任务分节为什么这样切、哪条卡节摘要在两路审查后被改，以及改的触发点。
五问、摘要上限、记录形状、状态词与证据指针，读 `skills/stage-reflection/SKILL.md` 的「单元模式：单元复盘记录」；此处不复述方法。
少记一条只让这次任务分节这一条判未完成，不影响后续包与 Phase 继续。

## 失败与边界

- 地图答复缺失：保持 draft，保留未决与 owner，不代答、不默认同意。
- 来源缺失或冲突：只停依赖该来源的卡，其余安全部分继续；缺口写进 PRD 与交接。
- 范围或验收要改：交原决定人或用户，不自行改方向。
- 本技能不新增任务卡字段、第二作者、第四检查器或持久状态；完成事实仍由现有 producer 与 `steps.json` 决定。

## 可搬运调用
