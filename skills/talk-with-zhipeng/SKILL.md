# talk-with-zhipeng

> 用大白话按问题组收敛方向、歧义、风险和范围，并把真实回答交给决策记录。

本技能分两层：

- **平台无关核心层**：纯对话收敛逻辑，包括调研摆出、影响排序提问、每答重排、收敛阈值、五类判定、输入护栏、丢弃登记、歧义校正。
- **薄适配层**：只负责对接当前 workflowhub 工作流的产物读写。默认从当前任务的调研与规格材料读取背景，把最小决策事实返回调用方，由调用方写入既有决策产物。

判别器：一段逻辑是否依赖「具体工作流产物的读写」？依赖则入薄适配层；不依赖则入核心层。核心层不得触碰任何工作流私有路径。

## 输入

- 已有调研、规格、计划或代码阅读摘要。
- 用户原始需求、补充回答和可引用的上下文。
- 当前工作流通过受控 callback 提供的命名产物内容。
- 调用方声明的当前问题批次用途与 OI 版本：初始痛点与成功标准、研究后的方向大纲、
  或逐模块收敛中的未决项。批次数量由真实 OI 决定，不预设轮数。

若输入缺失，不直接提问，先进入输入充分性护栏并说明缺什么。本技能只负责 Talk；
Clarify 由 build-plan 的 `spec-clarify` 处理规格歧义，Talk 只处理当前方向问答。

### 问答工具 IO 契约

宿主有结构化问答工具时，每个问题输入必须包含 `question_id`、`axis`、`options` 和
`recommended`；`options` 最多 3 个，每个选项用大白话写清含义、直接后果和主要风险。
工具输出必须包含 `answers`，其中答案只能是选项 `option_id` 或用户的 `free_text`，及其用户真实答复来源。宿主没有问答工具时，改发同内容的文本卡，并如实
记录工具降级事实；不得伪造工具调用、答案或回复凭证。

外部问答工具与内部表示分别处理：适配层先把外部 `recommended`、`option_id`、`free_text` 映射到现有内部 `recommended_option`、`number` 表示，再按现行接口校验。不能把两套字段混发给宿主，也不能把内部编号或字段当作用户回复凭证；实际用户答复仍由可引用的真实会话来源证明。本说明不新增回复认证或持久记录。

## 用户可见的说话方式

简明语言标准：先给结论、短句、主动语态、一次一个动作、不用术语与内部编号、非用不可当场解释；默认读者是没读过本项目且注意力有限的人。用户可见输出同时遵守 [项目表达规则](../../AGENTS.md#用户可见输出)。这些标准用于措辞，不改问答工具机器字段。

给用户看问题标题、说明、选项和推荐理由时，先说现在遇到的实际问题、这次要选什么，以及各选择的直接后果和风险。技术定位与证据留在内部原件，用户文案把它们译成能直接理解的业务影响；按下方 2.1 保持一题一个决策轴、真实题号/总数和互斥选项。

- **大写编号**：问题标题、说明、选项和推荐理由出现 `WP1`、`AC-C01-1` 这类内部编号时，紧跟一句大白话说明它指哪件事、为什么需要用户选择；正常业务名称、API/服务名称及日常题号按真实语义显示。
- **文件名加行号**：出现 `spec.md:12` 这类定位时，紧跟一句大白话说明该处规则影响哪一步、用户要选什么；来源证据仍留原件。
- **下划线字段名**：出现 `question_id`、`quality_status` 这类机器字段时，紧跟一句大白话说明实际含义，例如“这个问题”“这次检查还缺什么”；机器键仍按原工具 IO 使用。

这些要求只约束用户看见的措辞。上方问答工具 IO 契约、下方机器 YAML 示例与外部/内部字段映射仍原样使用，不能因此删键、改名、混发字段或拿文案示范当用户回复。它是现 Talk 的表达分工，不是新检查器、审批或推进门。

**正面示范**（具体选择情境的文字示范，不是本轮实情、提问或答复）：团队要给两处已确认的体验问题排序，本题只选先修哪一处。

> 这轮我们只确定两处问题的处理顺序。当前第1题，共1题。
>
> 你更希望先解决“打开记录详情后，不容易找到返回入口”，还是“记录列表的信息太挤”？
>
> 1. 先把详情页的返回入口说清楚（推荐）。这样先让查看任务有明确的结束路径；列表暂时仍会拥挤。推荐理由是先减少用户在详情页来回找入口的困扰。
> 2. 先整理列表的信息。这样更容易找到想看的记录；详情页的返回入口暂时仍不清楚。

实际提问时，只采用当前已经核实的问题和来源，沿 2.1 给用户可选的后果与风险；示范不生成或预测答案。提问后仍严格按“每答重排”等待真人回复，未答不替用户选，也不为验证这段文案向用户另加确认问题。

## 执行协议

### 1. 建立本轮候选队列

每个动态问题批次都独立开始、独立结束，不得合并或借用旧批次代替。内部先生成完整候选
队列。本技能所称“候选队列”只指问题队列；扩散段的方案候选交调用方写入既有已登记的外置候选对比件，不属本条问题队列禁令范围。按“会不会改变方向”排序，并标记 `待回答`、`已由事实回答` 或 `不适用`。
面向用户只展示本轮用途、当前第几个问题和当前队列总数；队列会随回答重排时明确写
“当前共 N 个，回答后可能变化”。不得把完整候选队列、内部排序或逐项处置倾倒给用户。

候选数量由真实未决问题决定，可以是零、一个或多个；不得设置固定最少或最多问答次数，
也不得为了凑数量制造问题。开始时没有 `high` 或 `medium` 待回答项，可以展示事实和
关闭理由后结束本轮；仍有这类问题时，把互相独立的问题放进同一批次，只有有依赖的问题
才拆到后续批次，并在真实回答后重新排序。

若调研结果缺失，先自检并反馈缺什么，不带着空背景进入追问。

### 2. 影响排序提问

把所有待问问题按「对方向的影响」从高到低排序。影响标尺 5 档：

| 档位 | 权重 | 含义 |
|------|:--:|------|
| high | 5 | 答案直接决定方向 |
| medium | 4 | 答案明显改变方向取舍 |
| low | 3 | 答案只影响细节，不动方向 |
| none | 2 | 答案对方向无关 |
| 已答 | 1 | 已经确定，不再问 |

一次展示一组互相独立的问题，按当前影响从高到低排序。多个决策轴只有在答案互不依赖
时才能放在同一组；有依赖的问题拆到下一组，并在用户回答后重新排序。不得把多个轴
拼成一个“完整方案”或“完整合同”问题；不影响主流程的问题做最小合理假设并说明。

### 2.1 大白话单轴决策卡

面向用户先说业务问题；内部词确需出现时，紧跟一句大白话解释，不能只给内部 ID、hash、receipt、attempt、runner 让用户猜。
问题标题、选项说明及推荐理由到达用户展示时，读取上方「用户可见的说话方式」；机器表示仍沿「问答工具 IO 契约」，两种语域各守原职责。
每张卡只包含：

1. 用日常语言说明本轮用途、当前题号和真实总数；OI 版本由调用方在内部保留；
2. 一组互相独立、每题只含一个决策轴的问题；
3. 影响范围；
4. 每题 2～3 个互斥选项；
5. 每题一个推荐项及推荐理由；
6. 每个选项的直接后果和主要风险。

提问卡不得再写“刚完成”“下一步”“需要你处理吗”或回答后由谁继续等重复段落。

不得让用户开放式填空。若新事实证明所有选项都不成立，承认选项失效，依据新事实重建
候选，而不是要求用户自己写第四个方案。

每轮发出前自检：问题是否仍针对原需；推荐是否把未证假设当事实；问题是否把多个依赖决策轴塞在一起。发现偏移先回原需与事实重写，缺事实先核实。
每轮末尾写“我在问你什么、你为什么要在意”，用一句话说清待决内容及影响；再列“我替你定了这些”，只放不改变目标、方向、范围、验收、风险或长期规则的可逆细节，并说明假设、允许用户否决；没有则写“无”。上述会改变方向的事项必须问用户；代码、文档或已确认事实可回答的问题先自行核实。

### 2.2 扩散透镜（按问题选，不凑数）

先消费已有调研与真实约束，再按当前未决项挑透镜；每项都不适合时可以一个不用，并说明理由。透镜用于发现方案，不把内部方案队列整包当问题卡。

- **反着想（Inversion）**：反转默认做法寻找盲点；默认方案未经质疑时用；反转会违反已确认安全或业务硬约束时不用。
- **去掉约束（Constraint removal）**：暂移预算、时间或技术限制，找被遮住的价值；需区分真实约束与习惯时用；不可撤销的真实限制不假装消失，回到候选前恢复约束。
- **换受益者（Audience shift）**：换一类受益者检查价值；目标用户尚未钉清时用；用户已冻结且改变用户越出范围时不用。
- **与相邻合并（Combination）**：与相邻需求组合检查共同价值；真实消费者与接缝可复用时用；仅为凑功能或造成耦合时不用。
- **简化十倍（Simplification）**：削去实现负担，找仍解痛点的最小做法；复杂度遮住核心价值时用；会删除必要安全、失败处理或验收条件时不用。
- **极限规模（10x version）**：放大使用量暴露瓶颈；规模是已知取舍时用；没有规模需求、只会制造投机架构时不用。
- **内行视角（Expert lens）**：找领域内行会质疑的隐藏假设；已有领域知识与来源可核实时用；只有权威口吻、没有可回读依据时不用。

向调用方返回用了哪些透镜、至少两个关键取舍不同的候选及各自理由；不设固定问题数、变体数或方向数，也不把数量当质量门。简单模块可不扩散，但具名说明：只有一个明显合理方向且其它明显更差，或已在全方向调研比较过。方案与比较理由由调用方写既有候选对比件；问题卡仍只问当前未决的单一决策轴。

### 3. 每答重排

每个问题批次必须严格执行 `ask → wait/pause → real reply → resume → re-rank`：提问交给宿主可见会话后，
暂停依赖这张卡答案的工作；只有收到用户对该问题的真实答复才继续并重排，
把控制权交还用户；等待期间只有不依赖答案的事实核实可以继续。取消或中断时返回已答结论、未答项和暂停原因，当前批次保持未完成；恢复先核本题真实回复，再重排。Agent 生成的答案、默认选择、旧回复或 decision-log 自报都不能充当 reply，
也不能据此进入下一题、改稿或审查。

真实对话中先提问、明确等待用户，
回答来自用户的实际回复；主会话只在收到该问题的真实答复后继续并重排，不需要 round/hash 事件认证。
Talk 的 `ask.questions` 可以是一组问题，但每题必须使用统一问题卡：

```yaml
question_id: scope-boundary
axis: 范围边界
independent: true
options:
  - { option_id: conservative, label: 保守, meaning: "先少做一点", consequence: "范围更小", risk: "收益延后" }
  - { option_id: recommended, label: 推荐, meaning: "直接解决当前问题", consequence: "一次解决", risk: "改动面更大" }
recommended: recommended
recommendation_reason: "当前事实最支持这个选项"
```

用户可以一次回答全部或部分问题；未回答的问题保留，并在下一组中重新排序。聚合结果存在不等于已经收到 reply。

只把用户真实回复视为答案，且只关闭该回复明确回答的具体取舍；含糊赞同、委托、开工指令或答非所问都不能代选。未答清时保具体未决，当场问“如果不用向任何人交代，你真正想要什么”，再给当前单轴选择；反复澄清仍没理解目标时停下说明缺什么，退回目标，不设轮数或置信度门。独立搬运只靠本段也能执行；需要识别信号与分类示例时，可选查阅 [Grill 的 Sharpen fuzzy language](../grill-with-docs/SKILL.md#sharpen-fuzzy-language)，缺该参考不改变本段处理。每收到一批问题的全部或部分回答，都必须：

1. 记录回答及其来源；
2. 更新已知事实；
3. 重新生成并排序本轮全部剩余候选；
4. 标记被新事实回答或变为不适用的问题；
5. 更新下一张卡的题号和当前总数，再决定是否询问新的最高项；不展示完整重排表。

不要沿旧列表机械向下走。Agent 不得模拟、补写或代替用户回答。

下一张卡的总数必须按下面的同一公式重算：

`当前总数 = 本轮已经提出的问题数 + 重排后仍会改变方向的开放问题数`

总数只有在真实回答新增或消除开放问题时才能变化，并记录新增或移除的问题及事实原因。
只把题号机械写成 `2/2`、让分母始终跟着分子走，在仍有开放问题时属于失败。

### 4. 收敛阈值

每答重排后判断是否收敛。只有本轮队列中已没有 `high` 或 `medium` 的待回答问题，
本轮才结束。结束时只展示本轮已收敛的关键结论、问题处理数量、仍保留的风险和
“不再提问”的事实理由，再把完整回答、来源、假设和剩余风险返回调用方。简单任务
可以没有人工等待，但不能省略内部队列记录与面向用户的结束结论。

只要仍有会改变方向的待回答问题，本轮不得结束或提前收敛。

该判据复用影响排序机制，不引入第二套评分系统。

### 4.5 前置检查（外部接口核实 + 命名唯一定义）

五类判定只回答「要不要做」，不覆盖「怎么做的细节是否落地可信」。在进入范围五类判定前，先过两条前置检查：

- **外部接口核实检查**：本次涉及的外部工具/接口，有没有核实过真实调用方式？没有核实（不能只凭文档假设或记忆），直接转 S3 外部调研核实，不得带着未核实的接口假设进入五类判定。
- **命名唯一定义检查**：本次讨论的命名/路径/字段，如果后面会被多处复用，本轮必须钉死唯一定义（值 + 唯一来源文件），不得留到后续阶段各自约定、产生歧义。

两条检查任一未过，均在决策记录里显式标注「未过」及去向（转 S3 / 补充定义），不得静默跳过继续判定。

### 5. 范围五类判定

复杂任务每个工作包按五类逐类写判断，每类标「已答／事实可定／待你定」三档之一，并写「谁来定：代理或用户」：

- **语义与解释权**：点明词义、解释权与仍有歧义处，逐类标档并写谁来定。
- **目标与边界**：点明要交付什么、哪些不做，逐类标档并写谁来定。
- **成败与风险**：点明成败信号与真实风险，逐类标档并写谁来定。
- **验收与证据成本**：沿既有最小可证伪范围、开工前四要素与跳过留痕口径，逐类标档并写谁来定。
- **影响面与顺序**：点明真实消费者、依赖与先后，逐类标档并写谁来定。

讨论前展示本工作包五类结论、分档和谁来定；答错会改验收或改范围的待定项必须问用户，可查事实由代理查，不增加其它审批。讨论后用 3–5 句大白话复述本工作包结果，请用户确认；进入细节审查前把工作包骨架给用户看一次。

保留下列原A–D依据作为各类内部判断线索，每条仍标「证据」还是「主观」，不把它们当作五类的替代：

- **A 真实痛点**：用户原文能直接引用卡在哪 = 证据；从行为推导、非用户原话 = 主观。
- **B 复杂度与 ROI**：有参照 case、改动量可估、ROI 可量化 = 证据；首次做、工程量靠猜、ROI 无数据 = 主观。
- **C 风险与影响范围**：能指认改动边界或列出受影响模块名 = 证据；无法列出具体影响路径 = 主观。
- **D 时机**：项目计划或阶段目标能引用 = 证据；有顾虑但无明确冲突 = 主观。

四选一裁决：可以做 / 可做但缓一缓 / 有风险需限制范围 / 不建议做。附上推翻条件清单，说明满足哪些条件时裁决会改变。

轻量档短路：当范围已明确且显然无需展开五类时，可跳过完整五类分析，直接输出 `verdict=轻量档可忽略`。

### 6. 输入充分性护栏

五类分析之前先自检输入是否够：

1. 需求描述是否足够具体，能判断痛点真实性？
2. 项目背景是否足以评估影响范围？
3. 时机相关上下文是否存在？

缺哪类信息且无法从上下文推断，直接反馈缺什么，不往下跑：

- 缺痛点描述：`缺少用户原始痛点描述，请补充`
- 缺影响范围线索：`缺少项目代码或模块背景，影响范围无法评估`
- 时机完全空白：可降级为「主观」继续，但必须在输出中标注

对需要推断、无法从原文直接读出的前提，在输出前显式回显让人纠正。

### 7. 丢弃台账登记

判定丢弃任何一条原始需求条目，必须登记「理由 + 去向」，禁止静默丢。理由缺失时裁决不成立。

### 8. 大白话聊天

所有提问与回答用大白话。一次给出一组独立关键问题；每题始终使用 2～3 个互斥选项，
说明推荐、后果和风险，用户直接回答编号，不使用开放式填空。

### 9. 歧义校正与方向收敛并行

回答含歧义或自相矛盾时，当场指出歧义并追问澄清，不带着歧义往下走。歧义校正与方向收敛并行进行。

### 10. 结构化字段显式保留

五类结论、四选一裁决、推翻条件、每条结论的「证据/主观」标注，都以结构化字段显式保留，落到决策记录里。

### 11. 返回最小交互事实

候选队列、问题卡、ask/reply/re-rank 过程只用于当前对话内收敛，不形成 run、revision、
latest、ledger 或独立交互历史。动态问题批次结束后，本技能只把当前主会话 完成
当前决策所需的最小结构化事实返回内存：

```yaml
talk:
  status: completed
  round_count: <实际问题批次数，可为 0>
  oi_version: <当前 OI 版本>
  architecture_direction_covered: true
  user_outcome_covered: true
decision_updates:
  - 只保留需要写进 decision-log.md 的结论、依据、风险或未决项
```

`architecture_direction_covered` 与 `user_outcome_covered` 只有在当前批次真实覆盖后才能为
`true`。仍有会改变方向的问题时，当前批次不能写 `status: completed`。本技能不填写 task、stage、snapshot、
decision ref/hash、文件路径或内容 hash；这些绑定由当前主会话 在最终决策完成时组装。

不得返回或持久化完整候选队列、完整问题卡、逐轮问答历史、Grill 历史、secret、token、
password、credential、cookie 或其他秘密。用户真实答案的决策含义进入
`decision_updates`，原始对话仍留在宿主会话，不复制成第二套记录。

## 输出

每条五类结论必标「证据」或「主观」，不得遗漏；「证据」必须有具体原文引用或可验证数据来源。

```text

- 最终 verdict：[可以做 | 可做但缓一缓 | 有风险需限制范围 | 不建议做 | 轻量档可忽略]
- 五类详情：
  - 语义与解释权：[结论]（分档：[已答/事实可定/待你定]；谁来定：[代理/用户]；来源：[证据/主观]）
  - 目标与边界：[结论]（分档：[已答/事实可定/待你定]；谁来定：[代理/用户]；来源：[证据/主观]）
  - 成败与风险：[结论]（分档：[已答/事实可定/待你定]；谁来定：[代理/用户]；来源：[证据/主观]）
  - 验收与证据成本：[结论]（分档：[已答/事实可定/待你定]；谁来定：[代理/用户]；来源：[证据/主观]）
```

## workflowhub 薄适配层

核心层产出的是「调研入 / 最小决策事实出」的纯逻辑。薄适配层只做两件事：

1. **读调研**：从当前 workflowhub 任务约定的相对路径读取调研、规格、计划或测试证据，整理成初始咨询材料。
2. **返回事实**：把最小 `talk` 和 `decision_updates` 返回当前主会话；本技能
   不直接写工作流文件或质量记录。

适配层只负责「从哪读、往哪写」，不含对话收敛判断逻辑。换一个工作流只需换这一层，核心层不动。

## 约束

执行与结束判据分别见「执行协议」和「返回最小交互事实」，五类逐条证据来源要求见「输出」；一个批次的结果不能冒充另一个批次已执行。只处理当前对话相关材料，核心层与薄适配层按本文件开头的职责边界分工。创建或改写 agent 方法时，读取 `skills/spec-specify/SKILL.md` 的「技能写作规范（WR001）」；此处不复制规范。
